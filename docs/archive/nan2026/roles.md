## AI — 도구가 아니라 **역할이 나뉜 팀**

`.claude/agents/`에 정의된 서브에이전트가 실제 작업을 수행한다.
자세한 내용은 [`ai-tech.md`](ai-tech.md).

| 에이전트 | 맡은 것 | 하지 않는 것 |
|---|---|---|
| `spec` | 설계 문서를 읽고 구현 계획을 만든다 | **코드를 쓰지 않는다** |
| `builder` | 계획대로 구현한다 | **계획을 세우지 않고, 완료를 선언하지 않고, 값을 재지 않는다** |
| `verify-run` | 실제로 돌려서 값을 확인 | 코드를 읽지 않는다 |
| `verify-look` | 게임을 띄워 **눈으로** 화면과 설계를 대조 | 수치 검증을 하지 않는다 |
| `verify-read` | 코드를 읽어 **적대적으로 반증**하고, 넷을 뮤테이션해 구멍을 찾는다 | 게임을 띄우지 않는다 |
| `harness-manager` | 넷이 느려지거나 헛돌면 재고 고친다 | **기능 코드를 절대 건드리지 않는다** |

### 경계를 지키는 이유

**만든 사람이 자기 것을 재면 유리하게 읽힌다.**
그래서 `builder`가 "값을 재서 보고"하면 그것은 검증이 아니라 **역할 위반**이고,
그 보고를 판정 근거로 쓰지 않는다.

**검증자에게 builder의 소감을 전달하지 않는다.** "잘 됐다더라"를 전하는 순간
독립적인 눈이 아니게 된다.

**되돌림 3회면 멈추고 사람에게 간다.** 계속 돌리면 검증을 통과하려고 코드를 구부리기 시작한다.

## 판정 권한은 사람에게만 있다

```
AI가 만든다 → AI 셋이 서로 다른 방식으로 검증한다 → 넷이 값으로 잰다
                                                        │
                                                        ▼
                                          사람이 화면을 보고 승인한다
```

**검사 개수는 여기서 세지 않는다** — 이 문서가 들고 있던 `4,179개`는 두 판이나 낡은 값이었다.
수치는 [`ai-tech.md`](ai-tech.md) 13장의 숫자 요약 **한 곳에서만** 센다.

**넷이 초록이라고 재미있다는 뜻이 아니다.** 넷은 "거짓이 아니다"까지만 보증한다.
재미는 사람이 판정하고, 그 판정만 설계 문서의 `Accepted` 절에 들어간다.

## 본선 계획 (48시간)

혼자 48시간을 버티는 방법이 곧 이 하네스다.

- **주제 발표 직후**: 설계 대화 → `docs/plans/1.ready/`에 구현 가능한 문서 한 장.
  `game-planning` 스킬이 이 과정을 담당한다 (대화를 안 본 서브에이전트가 문서를 쓰고, 또 다른 하나가 리뷰)
- **구현 루프**: `build-feature` 스킬 — spec → builder → 검증자 셋 → 판정.
  **단계마다 검증한다.** 끝에 몰아서 하지 않는다 (되돌림 비용이 단계 수만큼 커진다)
- **사람은 판정에만 붙는다** — 화면을 보고 "맞다/아니다"만 하면 되도록 나머지를 자동화해 뒀다
- **AI 에이전트 기획서**: 이 게임은 시뮬이 정수 결정론이라 **AI 동료의 행동을 넷으로 잴 수 있다.**
  "같은 상황에서 같은 판단을 하는가"가 테스트 가능한 명제가 되는 것 — 그 자산 위에 설계한다
