## v2.2 결정 (2026-07-15, 세션 14) — 충격이 룬을 떠난다 (미구현·계획)

> **"그러네, 충격은 사실 문양이어야 하는 건가?"** — 사용자

룬 복합(§4 룬 N개)을 파다가, *"돌 응집 마법 + 충격 마법으로 빠르게 나가게"* 같은 **비대칭 자유도**
(하나가 다른 것에 작용)를 원한다는 게 나왔다. 블렌드 복합으론 안 나온다 — 룬 둘이 그냥 섞일 뿐,
서로 관계를 안 맺는다 = **배치가 무의미 = 스위치**(문양 대원칙 3번 질문 위반). 여기서 경계가 다시 그어졌다:

- 🔴 **룬 = 속성(적에게 무슨 일이) / 문양 = 힘(탄이 어떻게 행동하나).** 이 기준으로 "충격으로 빠르게
  발사"는 **탄의 행동(속도) = 문양**이지 룬이 아니다. 충격은 두 얼굴을 한 단어에 뭉쳤던 것 —
  **넉백(적에게=화살표 충격파가 이미 함) + 추진(탄에게=문양의 자리).** 둘 다 룬이 아니다
- 🔴 **충격이 룬에서 빠진다.** 룬 4종 중 충격만 원소가 아니었다(불·물·바람=원소, 충격=물리력).
  넉백은 §1.5 "위로 그은 화살표=밀어냄"과 중복이었다 → `RuneType {FIRE, WATER, WIND}`
- 🔴 **추진 문양 신설** — "빠르게 날아간다". 그동안 임자 없던 투사체 속도 축이 문양에 붙는다
- 🟢 **뜻밖의 이득: 룬 복합 = 대등 블렌드로 확정.** 비대칭 자유도가 룬끼리가 아니라 **룬×문양**으로
  빠졌으니, 룬 N개는 원소가 섞이기만 하면 된다(수증기 반응 담당). §4 룬 N개 모델이 그대로 맞다 —
  건드릴 게 오히려 줄었다. 대원칙("어휘를 늘리지 말고 조합을") 재확인: 룬(명사)×문양(동사)이 조합의 축
- **시작 = 불 룬 + 추진 문양** (튜토가 "속성 vs 효과"를 처음부터) · **숲 사냥개 카운터 충격→바람** ·
  **흙/돌 룬은 나중**(원소 확장 때 — 사용자 예시 "돌 응집"이 그때 성립)
- **딸린 코드는 룬 N개 마이그레이션과 한 번에.** ⚠ 아직 미구현 — TRUTH §1/§3은 구현 시 갱신

**죽은 것 (정직하게 남긴다):** ~~충격 룬(넉백·점타격)~~ — 원소가 아니었고 넉백은 화살표와 겹쳤다.
힘의 절반(추진)은 문양으로 살고, 절반(넉백)은 화살표 충격파로 흡수됐다. `rune_impact.tres` 폐지 예정.

## v2.1 (2026-07-15) — 문양(화살표) = 착탄 충격파의 방향. **기둥은 규칙이 아니라 결과다**

> **"화살표라는 문양은 적과의 히트 이후의 충격이 어디로 가는가를 정하는 거임. 그래서 그 충격파끼리
> 맞으면 기둥이 되는 거임. 한쪽 방향으로 싹 다 그리면 히트 이후 그 방향으로만 충격파가 가는 느낌인
> 건데? 화살표 하나하나가 효과를 가지는 거지."** — 사용자

- 🔴 **세션 11이 *"맞은 다음 → 비어 있다"*고 남긴 빈칸이 채워졌다**. 마법의 생애가 두 층으로 갈라진다:
  **날아가는 동안**(팅김⚡·유도∿·관통‖, v1.9~) / **맞은 다음**(🔴 곧은 화살표(BASIC) = 충격파 하나가 가는 방향, v2.1 신설). BASIC은 지금까지 "글자가 아닌 폴백"이라 아무 일도 안 하던 값이었는데, 여기서 죽은 값이 살아났다
- 🔴 **기둥은 규칙이 아니라 결과다.** 규칙은 "화살표 = 충격파 하나가 가는 방향" 하나뿐이고, 기둥·폭발은 코드로 정의하지 않는다 — 충격파끼리 부딪히면 저절로 나온다. **"별을 그리면 별처럼 퍼진다"**(v1.8 §4.1, 폐기된 문장)와 정확히 같은 원리
  - ⚠ **"수렴하면 기둥"이라고 코드에 규칙으로 적는 순간 창발이 아니라 규칙이 되고, "몇 개부터 기둥인가"라는 답 없는 질문이 따라온다**
  - **리드 실측**: 진 둘레 화살표 8개가 **밖**을 겨누면 충격파 8개·**기둥 0개** / **룬(중심)**을 겨누면 충격파 8개·**기둥 2개**
- 🟢 **v2.0에서 "소비 중단"한 두 필드가 부활했다.** 탄이 곧 진이므로 적에 닿는 순간 진이 히트 지점에 놓이고, 진 위 화살표들이 각자 제자리에서 제 방향으로 뿜는다: `ArrowData.origin`(충격파 시작 자리) · `ArrowData.direction`(충격파 방향). `SpellDesign.aim_axis`는 여전히 소비 중단이지만 개념은 상수(`UP_AXIS`)로 남는다
- **방위 기준 = 탄이 가던 방향**. 종이 위쪽 = 탄이 가는 쪽 → 위로 그은 화살표는 적을 밀어내고, 아래는 나에게 끌어온다
- ⚠ **방위 가이드(앞·뒤·좌·우)가 되살아났다.** 의미는 매번 달랐다 — **v1.5 발사 방향 → v2.0 폐지 → v2.1 충격파 방향**(세 번째 의미)
- **미정 (억지로 정하지 않는다)**: 팅김·유도·관통 획도 충격파를 뿜는가 — 아직 미정 (→ 정비 세션 A1: 안 뿜는다로 확정)
- **구현 완료**: `src/spell/shockwave.gd`(+`.tscn`, 화살표 1개=충격파 1개) · `src/spell/pillar.gd`(+`.tscn`, 충격파 둘이 만나면 생기는 지속형) · `projectile.gd`(`_fire_shockwaves()`) · `ink_render.gd`(`UP_AXIS` core 승격) · `balance_data.gd`(충격파 4종+기둥 5종 노브) · `drawing_canvas.gd`·`drawing_copy.gd`(방위 가이드 복원). 전 스위트 그린

## v2.0 (2026-07-14) — 방향이 문양 → 지팡이로. 바뀐 건 한 줄, 나머지는 전부 그 연쇄다

> **"마법 발사를 그냥 지팡이로 대체하자. 결국 보는 방향으로 발사가 맞고, 지팡이에 따라 여러 발이
> 나가거나 내 주변에서 전체 방향으로 나가거나가 정해짐."** — 사용자

- 🔴 **지팡이 신설 — 방향 + 발수 축, 구현 완료.** 도안 전체가 캔버스 위쪽 기준으로 회전하던 방식이 사라지고 에임(마우스 방향) 하나가 발사각 기준이 됐다. 새 스키마 없이 `ItemDef.params["wand_pattern"]` 하나 (`Enums.WandPattern { SINGLE, MULTI, NOVA }`). 3종: `wand_basic`(단발) · `wand_fork`(3발 산탄 24도) · `wand_ring`(8발 전방위)
- 🔴 **"문양 1개 = 1발"(v1.9)이 무너졌다.** 방향이 없으면 N개 문양이 같은 자리에 겹친다 → 발수는 지팡이가 갖고, 문양은 그 한 탄에 얹히는 효과가 됐다. 팅김+관통+증폭을 한 장에 그리면 튕기면서 뚫는 강화탄 하나
- 🔴 **진 = 투사체의 모양, 구현 완료.** 세션 11이 "아무도 안 정하는 것"으로 남긴 히트박스 모양(늘 반지름 5의 원)의 빈칸을 진이 채운다 — 히트박스가 `circle_radius`에 비례
- 🔴 **룬은 한 진 안에 하나만.** ~~룬 각도 = 배선~~(v1.9)이 죽으면서 — 방향이 없으니 "어느 문양이 어느 룬을 지배하는가"를 물을 자리가 없다. 대신 **상극(불↔물)이면 증발**(벌인지 보상인지 미정 → v2.1/정비 세션 B1에서 "수증기=결과"로 정리)
- **죽은 것들 (정직하게 남긴다)**:
  - ~~룬 각도 = 배선~~ (v1.9) — `arrow.direction`이 없어져 성립 불가
  - ~~별 진 = 전방위~~ (v1.8) — 전방위를 지팡이가 가져갔다. 진 모양은 이제 탄의 생김새이지 출구의 지형이 아니다
  - ~~캔버스 위쪽 = 조준 방향 + 도안 전체 회전~~ (v1.5) — 회전이 통째로 사라졌다. 세션 11의 미해결 항목(*"앞뒤옆 이게 좀 복잡함. 그냥 마우스 방향으로 나가도록"*)이 해결됐다
  - ~~문양을 방사형으로 8개 그려 노바를 만드는 방식~~ — 죽은 게 아니라 이사했다. 전방위는 이제 지팡이(둘레의 지팡이·8발). 잃은 건 "문양 배치로 직접 설계하는 정밀함", 얻은 건 "잉크 한 방울 안 쓰고 전방위가 나온다"
- 🟢 **`$P` 인식기 교체가 더 이상 선행 조건이 아니다.** $P가 전제였던 유일한 이유는 별·용의 진이었고, 그 존재 이유는 "전방위"였다. 전방위가 지팡이로 간 지금 진 모양은 원 하나로도 이번 주 목표가 굴러간다
- 🔴 **`reach=1.0`의 사거리 배율은 1.0이 아니라 0.85** (세션 12 실측으로 발각). v1.9가 `reach` 도입하며 샘플·구세이브 도안 사거리를 조용히 0.85배로 줄였다. 문서가 "구세이브가 똑같이 날아간다"고 주장했으나 그 테스트는 사거리를 v1.8 값과 비교한 적이 없다. 고치지 않는다 (reach 없는 도안 = 문양 안 그린 도안 = "짧은 문양" 취급이 규칙에 맞다)

- ~~**문양 = 궤적. 외우는 글자 없음**~~ → v1.9에서 폐기. 문양은 글자다
- 🔴 **인식기 $1 → $P 교체가 전제다.** $1은 한붓그리기 전용 — 별·용의 진을 원리적으로 못 그린다 (→ v2.0에서 급함이 내려갔다)
- ⚠ **"전원 1획"은 설계가 아니었다** — `$1`을 고른 데서 딸려온 제약을 기획 의도로 착각해 v1.7까지 문서에 적어 뒀다. 획 수에 제한을 두지 않는다 (사용자 정정)
- **잉크 = 통에서 실제로 나온 양** (길이 × 굵기). ~~진 크기 가산(최대 3배)~~ 폐기 — 큰 진은 둘레가 길어 이미 더 먹는다 (이중 과금이었다). 잉크가 숫자 하나로 통일됐다

## 축 배분 이력 (같은 실수를 반복하지 않기 위해 남긴다)

핵심 서사: **한 부품이 남의 축을 먹으면 정체성을 잃는다.** "이 부품을 크게·다르게 그리면 뭐가
일어나나?"를 물어 빈 축을 채워 왔다. 축을 **네 번** 다시 나눴다.

- **v1.5까지**: 문양 길이가 위력·탄 크기를 정하고, 진은 잉크만 먹는 역할 없는 세금
- **v1.6**: 규모 축을 진에게
- **v1.7**: 농도 축을 룬에게 (룬 그리기가 "4지선다 찍기"였다)
- **v1.8**: 구조 축을 진에게
- **v1.9**: 문양에 어휘를 (규모를 진에 넘긴 뒤 문양 길이가 아무것도 안 정했다)
- **v2.0**: 방향 축을 지팡이에게 (문양이 방향·기점까지 몰래 쥐고 있었다 → 떼어내니 발수도 갈 곳이 없어져 지팡이 신설)

**진단법의 진화**: v1.6~v1.9는 "크게·다르게 그리면 아무 일도 안 하는가?"(=세금) 하나였다. v2.0에서
두 갈래로 늘었다 — "표에 없는 축을 쥐고 있는가?"(=월권, 문양이 방향을 몰래 쥠) · "바꿔도 아무 일도
안 하는가?"(=무의미, 단발 고정 지팡이가 걸릴 뻔). **세금·월권·무의미는 서로 다른 병이고, 진단도 달라야 한다.**
