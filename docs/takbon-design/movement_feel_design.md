# 이동 필 개편 (movement feel) — 설계

> 상태: 설계 (사용자 승인 대기 → architect 리뷰 → 구현)
> 발단 = 사용자: *"뭔가 게임이 느리달까 캐릭터 뛰는 모션도 하나하나 집중이 안 된 느낌?"*
> 진단 대화에서 나온 방향 = **콘텐츠(스펠 다양성)가 아니라 순간순간의 게임 필(game feel)이 밑바닥에 없다.**
> 첫 삽 = **이동 필**(사용자 선택). 대시 = **게이트 유지**(부활 안 함). 걷기 애니 = **주인공 교체 예정이라 이월**.

---

## 1. 진단 (실측)

| 항목 | 현재 값 | 문제 |
|---|---|---|
| **이동 속도** | `player_move_speed = 120 px/s` (balance) | 화면(960px) 가로지르는 데 8초. 탑다운 액션 기준 절반 수준 — **실제로 느리다** |
| **가속/감속** | 없음 (`velocity = dir × speed + _push` 즉시 대입) | 스냅·무게감이 없어 **밍밍**. 딱 붙는 맛도 미끄러지는 맛도 없음 |
| **걷기 애니** | 2프레임 @ 6fps | "뛰는 모션이 안 박힌다" = **2프레임이 뭉갠다.** ⚠ **주인공 교체 예정 → 이번엔 손대지 않음** |
| **대시** | 꺼짐 (`ROLL_ENABLED=false`) | 버스트 동작 없음. ⚠ **의도적 게이트 — 이번에도 유지**(나중에 장비가 이동수단 결정) |
| **이동 주스** | 걷기 먼지(`dust.gd`)만 있음 | 스쿼시·bob 등 "움직인다"를 강조하는 몸짓이 없어 정적 |

**핵심:** 밑바닥(움직임 필)이 굼뜨니 그 위에 뭘 얹어도 다 느리게 느껴진다. 좋은 액션게임은 **그냥 걷기만 해도 시원**하다.

---

## 2. 이번 사이클 범위

> 🔴 **사용자 확정(축소):** *"속도 주스는 안 만들 거임. 가속 감속만 넣어봐."*
> → **가속/감속(B)만** 구현. 주스(C)·속도 상향(A) 은 이번엔 뺀다.

**넣는다:**
- (B) 가속/감속(스냅) — 즉시 대입을 `move_toward` 기반으로. **이것만.**

**안 넣는다 (이번 사이클 밖):**
- ⏸ (A) 이동 속도 상향 → **속도값은 그대로 두되 노브로 남긴다**(사용자가 F5에서 바로 다이얼).
  ⚠ "느리다"의 진짜 원인은 속도값이라, 가속/감속만으로는 굼뜬 느낌이 남을 수 있음 — 사용자에게 고지됨.
- ❌ (C) 이동 주스(body_bob bob/스쿼시) → 만들지 않음(사용자 확정)
- ❌ 걷기/뛰기 스프라이트 재작업 → **새 주인공 올 때**(별도 아트 사이클)
- ❌ 대시/구르기 부활 → 장비 게이팅 설계 유지
- ❌ 적 속도·전투 템포 → **다음 사이클(전투 템포)**. ⚠ 단 아래 §5 참고

## 3. 설계

### (A) 이동 속도 — `120 → 200 px/s` (시작값, 튜닝)
- `src/core/schemas/balance_data.gd`의 `player_move_speed` 기본값 `120.0 → 200.0`.
  (balance.tres가 비어 있어 스키마 기본값이 곧 실제값 — 단일 소스 유지.)
- 발사·좌우향함·모자 배수(`GameState.move_speed()`) 계약 무변경. **오직 밑수치만.**

### (B) 가속/감속 (스냅) — 즉시 대입 → `move_toward`
- **문제:** `velocity = dir * move_speed() + _push`는 0↔최고속을 프레임 내에 순간 전환 → 무게감·스냅 부재.
- **설계:** 입력 구동 속도 `_move_vel`을 목표(`dir * move_speed()`)로 매 프레임 `move_toward`.
  - 입력 있음 → `accel`로 목표까지 가속
  - 입력 없음 → `friction`으로 0까지 감속
  - 최종 `velocity = _move_vel + _push` (🔴 **밀림 `_push`는 지금처럼 additive로 얹는다** — 계약 보존)
- **신설 노브 2개** (balance_data.gd — 속도가 balance라 가속도 같은 곳):
  - `player_accel: float = 2000.0` → 200px/s 도달 ≈ 0.1초 (**스냅**, 무게형 아님)
  - `player_friction: float = 2400.0` → 정지 ≈ 0.08초 (얼음판 아님)
- 🔴 **구르기/밀림/피격 분기 무손:** 구르기 early-return, `_push` decay, hurt 타이머는 그대로. `_move_vel`은
  걷기 분기에만 관여. (구르기가 켜지는 미래에도 `_move_vel`은 걷기 전용이라 충돌 없음.)

### (C) 이동 주스 — 몸통 bob/스쿼시 (신설) + 걷기 먼지 (기존)
- **걷기 먼지 (`dust.gd`, 기존):** 유지. 속도가 빨라지니 `WALK_PUFF_INTERVAL 0.28`을 **속도 비례로 살짝 조밀**하게
  튜닝(손맛 const, 사용자 F5). 구조 변경 없음.
- **몸통 bob/스쿼시 (신설 `src/actors/body_bob.gd`):** Player 자식 형제 노드(`dust`·`juice`·`vfx` 선례).
  - 🔴 **부모의 공개 상태만 폴링**(`velocity`) + `Sprite` 노드에만 손댐 → **player.gd 무수정 = 회귀 0**
    (dust.gd 규약 그대로).
  - **bob:** 걸을 때 `Sprite.position.y`에 작은 사인 오실레이션(±1~2px, 속도 비례 주기). 정적인 2프레임에
    "살아있는" 리듬을 준다. 멈추면 0으로 수렴.
  - **스쿼시(선택):** 출발 순간 살짝 세로 늘림→복귀, 정지 순간 살짝 가로 눌림→복귀(`Sprite.scale`).
    가속/감속을 시각적으로 판다. 과하면 뺀다(손맛).
  - 🔴 **불가침 경계:** `Sprite.material`(히트플래시 셰이더, 세63)·`Sprite.animation`(좌우향함·hurt,
    player.gd 소유)은 **안 건드린다.** bob/스쿼시는 `position.y`·`scale`만 — 서로 독립이라 충돌 없음.
  - **피격 중 처리:** hurt 표시 중엔 bob/스쿼시를 쉬어(중립으로) 피격 프레임을 방해 안 함(부모 공개
    상태로 판별 — `_hurt_time`은 비공개라, 부모에 `is_hurt()` 공개 헬퍼 1개 추가하거나 그냥 velocity로만 판단).
    → 🔴 **결정 필요분:** `is_hurt()` 헬퍼 추가는 player.gd 최소 수정(1함수). architect 판단 요청.
- 🔴 **전부 손맛 const(연출값)** — balance.tres 아님(dust.gd 선례). 사용자 F5 튜닝.

### (D) 걷기 애니 재생 튜닝
- 스프라이트 재작업 없음. 다만 속도가 빨라지면 2프레임 재생이 상대적으로 더 느려 보일 수 있으니
  `SpriteFrames` 재생 `speed 6.0`을 속도 비례로 살짝 올릴지 F5로 본다(씬 값 1줄, 손맛).
- 🔴 **새 주인공 오면 여기서 걷기 4~6프레임 + idle을 붙인다** — 그때 별도 아트 사이클.

## 4. 회귀 위험 & 계약

- 🔴 **발사·저장·룬 해금 사슬 = 무접촉.** 이동만 만진다.
- 🔴 **`_push`(밀림) additive 계약 보존** — `velocity = _move_vel + _push`로 형태만 바뀌고 의미 동일.
  gale 돌풍(세56)이 유일 호출자 — 밀리는 중 조작 살아있음 유지.
- 🔴 **구르기 기계 무손** — `ROLL_ENABLED=false` 그대로, early-return·`_roll_*`·`is_rolling()` 전부 보존.
  나중에 장비 게이트로 켤 때 `_move_vel`과 충돌 없음(걷기 전용).
- 🔴 **`body_bob`은 순수 오버레이** — player.gd 무수정(또는 `is_hurt()` 1함수만) = 세36 순수 오버레이 방식.
- 🔴 **도형 금지 예외 준수:** bob/스쿼시는 스프라이트 변형(그림 아님)이고, 먼지 퍼프는 절차적 VFX(기존 예외).

## 5. 이월 / 후속

- ⏭ **걷기/뛰기 스프라이트 재작업** → 새 주인공 확정 후 아트 사이클(takbon-art). 이번 코드 필은 새 주인공에
  그대로 얹힌다.
- ⏭ **적 속도·전투 템포** → 다음 사이클. ⚠ **주의:** 플레이어가 120→200이면 기존 적이 못 따라올 수 있다.
  이번 F5 확인에서 "적이 하염없이 뒤처짐"이 보이면 **임시로 적 속도도 같이 올려** 체감을 맞춘다
  (EnemyDef .tres 수치 — 다음 사이클에서 제대로 재조율). 이동 필만 보려다 전투가 깨져 보이는 걸 방지.
- ⏭ **대시/버스트** → 장비 게이팅 설계(별도).

- **헤드리스(그물):**

    프로퍼티로 잰다(dust `puff_count()` 선례). 🔴 뮤테이션으로 검출력 확인(bob 계산을 0으로 되돌리면 빨감).
  - 가속: `_move_vel`이 목표로 `move_toward`하는지 — 공개 프로퍼티 관측 또는 순수 헬퍼로.
- 🔴 **헤드리스가 못 잡는 것 = 이 사이클의 본질(손맛):** "빠릿한가·bob이 살아있나·스쿼시가 과한가·
  적이 못 따라오나" 전부 **사용자 F5**로만 확정. 속도·accel·friction·bob 진폭/주기·먼지 간격은
  전부 튜닝 노브(§7).

## 7. 손맛 튜닝 노브 (사용자 F5로 다이얼)

| 노브 | 위치 | 시작값 | 방향 |
|---|---|---|---|
| 이동 속도 | balance `player_move_speed` | 200 | ↑ 빠릿 / ↓ 묵직 |
| 가속 | balance `player_accel` | 2000 | ↑ 즉각 / ↓ 미끄러지며 붙음 |
| 감속 | balance `player_friction` | 2400 | ↑ 딱 멈춤 / ↓ 얼음판 |
| bob 진폭 | body_bob const | ±1.5px | ↑ 통통 / ↓ 차분 |
| bob 주기 | body_bob const | 속도비례 | — |
| 스쿼시 세기 | body_bob const | 약 | 0이면 끔 |
| 걷기 먼지 간격 | dust `WALK_PUFF_INTERVAL` | 0.28→속도비례 | ↓ 조밀 |
| 걷기 재생 fps | player.tscn SpriteFrames | 6→? | 속도에 맞춤 |

## 미결 (architect 리뷰 확인 요청)
1. `body_bob`이 부모 `Sprite`를 `get_parent().get_node("Sprite")`로 잡는 게 허용 결합인가
   (dust는 current_scene, juice는 camera를 잡는 선례 — Sprite는 부모 자식이라 조금 더 안쪽).
2. 피격 중 bob 억제를 위해 player.gd에 `is_hurt()` 공개 헬퍼 1개 추가 vs velocity만으로 판단(무수정) — 어느 쪽.
3. 가속/감속 상수를 balance(스키마 export)에 둘지 vs 연출 const로 둘지 (속도는 balance라 일관성상 balance 추천).
