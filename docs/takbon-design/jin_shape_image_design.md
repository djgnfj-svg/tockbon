# 설계: 진 모양을 이미지로 등록 (밑그림 데이터화)

> 🟢 **세83 대화로 확정.** 사용자 요청: *"내가 원하는 모양이 있는데 그걸 이미지로 내가 등록하고 싶은거임 —
> 저렇게 일일이 코드로 하는게 한계인가?"* → **아니다.** 밑그림은 점열 하나라 출처를 안 가린다.
>
> 확정된 것: ① 대상 = **진 윤곽**(밑그림 + 셀 미리보기가 같이 바뀐다) ② 등록 = **PNG를 채워 그리면
> 게임이 바깥 테두리를 딴다** ③ 리드가 초안을 만들고 사용자가 나중에 디테일을 잡는다.
>
> ⏸ **같이 나왔지만 여기 범위가 아닌 것 = 「그리기 단계 제거」**(사용자: *"조립이 맞음 모든걸 조립으로"*).
> 사용자가 *"다시 본질로 돌아가서 데이터화하는 부분만"*이라 해 **보류**했다. 이 설계는 그리기가
> 남아 있든 없어지든 **양쪽 다 성립**한다(§6). 그 결정은 별도 세션.

---

## ① 왜 되는가 — 구조적 근거 (코드 실측)

`trace_scorer.gd`는 `set_guide(pts: PackedVector2Array)`로 **점열만** 받는다. 모양·종류를 전혀 모른다.
그래서 점열이 코드 계산에서 오든 PNG 윤곽에서 오든 **시스템이 구분하지 않는다.**

지금 진 윤곽의 유일한 생산자 = `RingBoard.jin_guide_pts(shape, ctr, r)` — `Enums.JinShape` 8종을
`match`로 계산한다(`_jin_poly(3/4/5/8)` · 타원 `JIN_ELLIPSE_X=0.68` · 꽃 `PETALS=6, DEPTH=0.13` · 렌즈).
**그 숫자들이 코드 상수라 새 모양 = 리드가 `match` 갈래 추가**였다. 이게 사용자가 지적한 한계다.

소비자는 **정확히 두 곳**이고 둘 다 같은 함수를 부른다 — 그래서 「셀에서 본 모양 = 손으로 그을 모양」이
구조적으로 안 갈라진다(세48 계약):
- 판(밑그림) — `ring_board._build_guide` / `compose_guide_paths`
- 책 셀(미리보기) — `ring_book.jin_icon_paths` (세83)

→ **`jin_guide_pts` 한 곳만 갈아끼우면 판·셀이 같이 바뀐다.** 새 배선이 필요 없다.

### 저장·발사 무관 (회귀 0의 근거)

`RingDesign`은 score·ink·구성 int만 싣는다 — **가이드 기하는 저장·발사에 안 실린다.**
모양을 통째로 갈아도 옛 도안은 안 깨진다(앞으로 그릴 때의 손 궤적만 바뀐다).

## ② 사용자 작업 흐름 (이게 최종 목표다)

```
1. Aseprite에서 원하는 진 모양을 「채워서」 그린다        (도넛처럼 그려도 됨 — 바깥 테두리만 쓴다)
2. assets/jin_shapes/<이름>.png 로 저장
3. data/jin/<진>.tres 의 shape_image 에 그 PNG를 물린다
4. 끝 — 판의 밑그림도, 책 셀 미리보기도 그 모양이 된다
```

색·선 굵기·안티엘리어싱은 **게임이 칠하므로 무관**하다(실루엣만 본다).

## ③ 스키마 (리드가 core에 반영)

`src/core/schemas/jin_def.gd`에 필드 **둘**:

```gdscript
## 🔴 진 윤곽 이미지 (세83). 채워 그린 실루엣 — 게임이 바깥 테두리를 따 밑그림 점열로 쓴다.
## 비어 있으면 절차 도형(guide_shape)으로 폴백한다 → 옛 진 회귀 0.
@export var shape_image: Texture2D = null

## 셀 미리보기에서 룬 자리 표식의 배율 (세83에 상수로 넣은 값을 진마다 조절 가능하게).
@export var icon_rune_scale: float = 1.6
```

⚠ `guide_shape`(enum)는 **은퇴하지 않는다** — 이미지 없는 진의 폴백이자, 지금 진 3종이 전부
`guide_shape=0`(원)이라 **그대로 두면 콘텐츠 회귀가 0**이다. 파라미터 5개 안(대화 중 제시)은 각하 —
이미지가 그 상위집합이라 둘 다 만들면 모양 정본이 둘이 된다.

⚠ PNG **import 설정 = Lossless**(`.import`에서 압축 무손실). 손실 압축이면 경계 픽셀이 흔들려
추출 점열이 미묘하게 달라진다.

## ④ 추출 파이프라인 (`ring_board.gd`에 static 신설)

```
PNG (Texture2D)
  ↓ get_image() · 알파 > 0.5 를 「안」으로 본다
① 바깥 경계 추적 (Moore 이웃 추적)        — 가장 큰 덩어리 하나. 구멍·분리 조각은 무시
  ↓
② 호 길이 기준 균등 리샘플 → GUIDE_CIRCLE_N(72)점 + 닫음 1 = 73점
  ↓ 🔴 점 수·간격을 절차 도형과 **똑같이** 맞춘다 — 채점 밀도 규율(§5)
③ 정규화: 중심 = 경계의 무게중심 · 배율 = 최대 반지름이 r 이 되게
  ↓
PackedVector2Array (지금 jin_guide_pts와 형식 동일)
```

`jin_guide_pts`는 **래퍼가 된다**:

```gdscript
static func jin_guide_pts(shape: int, ctr: Vector2, r: float,
		img: Texture2D = null) -> PackedVector2Array:
	if img != null:
		var pts := _guide_from_image(img, ctr, r)
		if not pts.is_empty():
			return pts
		# 추출 실패는 조용히 넘어가지 않는다 (세50 침묵사 함정)
		push_warning("진 모양 이미지에서 윤곽을 못 땄다 — 절차 도형으로 폴백: %s" % img.resource_path)
	… 기존 match 그대로 …
```

⚠ **인자 기본값 `null`이라 옛 3인자 호출이 전부 그대로 산다** — 세48이 `shape` 기본값으로 쓴 트릭과 같다.

### 캐시

`Db`가 진을 로드할 때 **한 번만** 뽑아 들고 있는다(진 몇 종이라 비용 무시). 매 프레임 추출 금지.

## ⑤ 지켜야 할 규율 (전부 이미 있는 계약)

| 규율 | 값 | 왜 |
|---|---|---|
| 점 수 | 73 (72등분 + 닫음) | 완성도 = 「가이드 점 중 몇 %를 드러냈나」 → 점 수가 모양마다 다르면 **채점이 모양마다 유불리**를 갖는다 |
| 간격 | 균등 (호 길이) | 정밀도 = 최근접점 이탈. 간격이 들쭉날쭉하면 붓 자국과 정합이 깨진다(세25 화살촉 사건의 원리) |
| 닫힘 | 마지막 점 = 첫 점 | 진은 룬을 담는 **그릇**이라 터진 도형은 그릇이 아니다 |
| 중심 비움 | 중심까지 최소 거리 ≥ 0.45r | 안에 룬이 들어간다(룬 최대 0.27r). 위반 시 **경고만** 하고 쓴다 — 거부하면 사용자가 그린 게 조용히 사라진다 |

🔴 **경고는 반드시 시끄럽게**(`push_warning` + 테스트 그물). 세50 함정 = 「파일은 만들었는데 Db가
말없이 건너뛰어 두 세션 내내 죽어 있었고 전 스위트가 그린이었다」. **"PNG를 넣었다"를 완료로 치지 마라.**

## ⑥ 「그리기 제거」와의 관계 (보류 건과의 정합)

이 설계는 **양쪽 다 성립**한다:
- 그리기가 **남으면** — §5 규율(72점 균등)이 채점 때문에 필요하다. 지금 설계 그대로.
- 그리기가 **없어지면** — 채점이 사라지니 §5 규율도 사라진다. 점 수를 늘려 **더 정밀한 모양**을
  쓸 수 있게 되고, 추출 파이프라인은 리샘플 단계만 느슨해진다. **버려지는 작업이 없다.**

## ⑦ 검증 계획

`tests/test_ring_trace_auto.gd` ⑳(raw static 절대치)·㉑(배선 도달)이 이미 있다. 여기에 얹는다:

1. **합성 이미지로 왕복** — 코드로 원/삼각 실루엣 `Image`를 만들어 추출 → 절차 도형과 **모양이
   일치**(최대 이탈 < 허용치). 이게 파이프라인의 심장 그물이다.
2. **규율 전수** — 추출 점열이 73점 · 닫힘 · 균등 간격(인접 거리 분산 < 허용치) · 중심 비움.
3. **폴백** — `shape_image=null`이면 기존 절차 도형과 **점 단위 동일**(회귀 0의 직접 증명).
4. **깨진 입력** — 빈 이미지·전부 투명·점 하나 → 크래시 없이 폴백 + 경고.
5. **판↔셀 일치** — 이미지 진에서도 `jin_icon_paths[0]` 윤곽 == 판의 밑그림(세48 계약 유지).
6. 🔴 **뮤테이션 필수** — 리샘플을 「등간격 아님」으로·중심 정규화 제거·폴백 제거를 각각 되돌려
   **정확히 몇 개가 빨개지는지** 확인 + 원상복구.

⚠ 헤드리스가 **못** 잡는 것: 뽑힌 모양이 **손으로 그을 만한가**(꺾임이 손에 걸리나) · 셀에서 읽히나.
사용자 F5가 최종 판정.

## ⑧ 열린 항목 (구현 중 정할 것)

- 이미지 해상도 권장치 — 너무 작으면 경계가 계단이 된다. 실측 후 문서에 박는다(예상 128~256px).
- 도넛(가운데 뚫린) 그림을 그렸을 때 **바깥만** 쓴다고 알릴 자리 — 책 UI 안내문 or 문서.
