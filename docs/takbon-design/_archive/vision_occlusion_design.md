|---|---|
| 플레이어 | `vision_near_radius` = **220** |

| 상황 | 결과 |

## §2 판정 — `src/core/vision.gd` 하나만 고친다

### 2-1. 🔴 왜 거기인가

`is_seen`이 **부채꼴 판정의 단일 소스**이고 머리말이 이유를 이미 적어 뒀다 —
*"「내 부채꼴」과 「적 부채꼴」은 완전히 같은 수학이다. 각자 짜면 T5를 새로 심는다."*
⇒ **차폐도 거기 넣으면 양쪽에 자동으로 걸린다.** 🔴 **호출자에서 따로 재지 마라.**

**성능**(F1 정정): 적 10마리 × 48개 × **호출 2자리**(F2) ≈ 프레임당 **960회** 선분↔원.
곱셈 몇 번짜리라 싸다. ⚠ 초고의 *"적 수 × 21"*은 **4.6배 과소**였다 — 결론은 살고 근거만 바뀐다.

### 2-2. 서명

```
## occluders = (x, y, r) 의 배열 — z가 반경이다. 3D 좌표가 아니다.
static func is_seen(origin, aim, target, fan_deg, fan_range, near_radius,
                    occluders: PackedVector3Array = PackedVector3Array()) -> bool
```

- 🔴 **`(x, y, r)` 관례를 서명 위에 못 박아라**(F13) — 안 적으면 다음 사람이 `Vector3`를 3D로 읽는다.
- 🔴 **노드를 넘기지 마라** — 이 파일은 *"노드도 씬도 시간도 모른다"*가 계약이다. 순수 값만 받아야
  그물이 노드 없이 표를 짤 수 있다.
- **기본값이 빈 배열이라 기존 호출이 안 깨진다.** 실측(F12): 리포 전량 27건 중 **실제 호출은 3곳** ·
  파일로는 **테스트 2장 + src 2파일**뿐이다. ⚠ 초고의 *"그물 27곳"*은 주석까지 센 grep 건수였다.
- `PackedVector3Array`인 이유 = **CoW라 인자로 넘겨도 복사가 아니다**(F13 — *"값 타입이라 매 프레임 안 만든다"*는
  틀렸다. 매 프레임 안 만드는 이유는 §3-2의 캐시다).
- ⚠ **머리말에 「인자를 늘리는 건 왜 계약 위반이 아닌가」를 한 줄 덧붙여라** — 그 파일이
  *"인자를 줄이지 마라"*를 방어선으로 적어 뒀는데, **늘리는 쪽은 그 방어선의 반대편이 아니다**
  (수치를 밖에서 주입한다는 정신이 그대로 유지된다).

### 2-3. 🔴🔴 판정 순서 — **주변시가 차폐보다 먼저다**

```
① dist <= near_radius            → 보인다   ← 🔴 차폐를 안 본다 (ⓑ의 심장)
② aim이 영벡터                    → 보인다   (fail-open · 기존)
③ dist > fan_range               → 안 보인다 (기존)
④ fan_deg >= 360                 → ⑥으로    (세105 float32 가드 · 기존)
⑤ 부채꼴 밖                       → 안 보인다 (기존)
⑥ 시선이 엄폐물에 막힘            → 안 보인다 ← 🔴 신설
⑦                                  보인다
```

🔴🔴 **①이 이 설계에서 가장 중요한 한 줄이다.** 차폐를 ①보다 앞에 두면 **나무 뒤에서 달려오는 늑대가
코앞까지 안 보이고**, `vision_design` §4-1이 막으려던 *"안 보이는 데서 맞았다"*가 그대로 돌아온다.
**①을 아래로 내리지 마라.** ⚠ 이 순서 자체가 그물의 대상이다(§7 [3]).

🔴 **④가 산다는 것도 계약이다** — *전방위여도 차폐는 받는다.* 그러려면 §2-4를 먼저 처리해야 한다.

### 2-4. 🔴🔴 착수 0단계 — `_detects`의 360° 우회를 걷어라 (F3)

지금 `forest_enemy._detects`:

```
if angle >= 360.0:
    sense = maxf(sense, r)          # ← 세105 float32 우회
```

`sight_angle` 키가 없는 몸은 폴백 360° ⇒ **감지 거리 전체가 「주변시」로 승격**되고,
①이 **차폐 면제**이므로 ⇒ **그런 몸은 나무를 통째로 무시한다.** 그리고 **§2-3 ④와 정면으로 어긋난다.**

🔴 **그 우회는 이미 중복이다** — `vision.gd`에 `if fan_deg >= 360.0: return true` 가드가 들어 있다
(세105 `1cb4b8b`). **두 경로의 답이 오늘은 같아서 무해했고, ①에 「차폐 면제」라는 새 뜻이 붙는 순간 끝난다.**

**처방**: 그 두 줄을 **걷는다.** 검출자 = `test_perception_auto [1]`ⓐ(*"등 뒤에 둬도 온다"*) —
걷은 뒤 그게 초록이면 안전하다.

### 2-5. 🔴🔴 안개에는 목록을 **넘기지 않는다** (F4 — 초고와 방향이 반대다)

`vision_overlay.lit_at()`의 선언된 계약(그 함수 머리말):

> 🔴 공개 관측점 — 지금 이 좌표가 「밝은 쪽」인가. **그물과 화면이 같은 문을 지나게** 한다.

ⓓ가 차폐를 **화면에 안 그린다**고 확정했으므로, `lit_at`에 occluders를 넘기면
**화면은 밝은데 관측점은 「어둡다」고 답한다** = 관측점이 더 이상 화면을 안 비춘다.
memory `takbon-verify-tools-can-lie`가 세104에 *"**전제가 틀리면 그물이 그걸 굳힌다**"*로 적은 자리다.
🔴 게다가 `test_vision_overlay_auto [7]`은 **프롭이 없는 `_lone_fog`**로 재서 **조용히 통과한다.**

✅ **결정적 실측: `lit_at`의 라이브 소비자는 0곳이다**(부르는 건 그물뿐) ⇒ **안개는 목록이 필요 없다.**
⚠ 나중에 ⓓ를 뒤집어 셰이더에 그림자를 넣기로 하면 **셰이더와 `lit_at`을 같이** 열어라 — 그때만 필요하다.

### 2-6. 시선 ↔ 엄폐물 교차 (순수 기하)

선분 `origin→target`과 원 `(cx, cy, r)`의 교차. 표준 방식:

- 선분에 대한 원 중심의 **수직 발**을 `t ∈ [0,1]`로 clamp → 그 점과 중심의 거리가 `r` 이하면 막힘.
- 🔴 **양 끝점이 원 안이면 통과로 친다**(O6) — 안 그러면 「나무를 껴안으면 아무것도 안 보인다」가 된다.
- ⚠ **여유(epsilon)를 넣지 마라** — **거리 제곱 비교**라 세105에 밟은 float32 함정이 여기엔 없다.
  `sqrt`도 쓰지 마라(제곱끼리 비교).

## §3 엄폐물 목록 — 누가 나르나

### 3-1. 🔴🔴 소유는 **`PROP_TABLE` 하나다** (F6)

초고는 그룹을 씬이, 반경을 표가 소유하게 두고 **둘을 잇는 줄을 안 적었다.**
소비자는 그룹을 훑어 **노드**를 얻는데 노드는 반경을 안 든다 ⇒ `takbon-rules` §4의
**「열쇠와 문」 함정**이 그대로 재현된다(표에만 넣으면 **거짓 손잡이** · 그룹에만 넣으면 **반경 0 no-op** · **둘 다 에러 0**).

⚠ **리포의 기존 관행도 반대다** — `props` 그룹은 **방이 붙인다**(`_spawn_props`의 두 줄).

**확정**:
> **방이 `props`를 붙이는 그 두 줄에서 `occluders`도 같이 붙이고, 같은 줄에서 `set_meta(&"occlude_r", …)`를 새긴다.**
> `PROP_TABLE`에 `"occlude": 34.0 / 26.0 / 0.0 / 0.0` 한 칸을 더한다.

⇒ **단일 소스가 `PROP_TABLE` 한 곳**이고 **새 엄폐물 = 표에 숫자 하나**(0이면 안 가린다)가 된다.
🔴 **선례가 같은 파일에 있다** — `LANDMARK_ID_META` 머리말: *"**노드를 만든 그 줄에서** 붙으므로
어긋날 자리가 구조적으로 없다."*
⚠ **표를 core로 올리자고 하지 마라** — `ring_board`의 기하 static을 core로 못 올리는 것과
**같은 이유로 의존 방향이 뒤집힌다**(배치는 field의 일이다). `vision.gd`는 값만 받으므로 경계 문제가 없다.

### 3-2. 캐시 — **적은 `_ready`에 구워도 되고 씬 자식은 안 된다** (F5)

- 🔴 **선례가 같은 파일에 있다** — `_home`이 *"`_ready`가 아니라 첫 `_physics_process` 틱"*인 이유

## §4 인지 표시 — `?` → `!`

### 4-1. 지금 무엇이 문제인가

느낌표 기계는 **이미 있다**(`forest_enemy._show_alert_mark`). 문제는 **뜨는 조건**이다 —
지금은 **「내 시야 밖」 적에만** 뜬다. 눈앞의 늑대가 경계 중인지 확정인지는 **소리 말고 신호가 없고**,
그게 사용자가 말한 *"으르렁하고 아우가 눈에 안 보임"*이다.

### 4-2. 계약

| 언제 | 무엇 | 색·크기 |
|---|---|---|
| **ALERT 진입** | `?` | 노랑 · 작게 · 뜬 채 **유지** |
| **CHASE 진입** | `!` | 빨강 · **크게 팝** · 짧게 떴다 사라진다(지금 동작) |
| 경계가 풀림 | 사라진다 | — |

- 🔴 **`?`는 유지하고 `!`는 스쳐 지나간다.** `?`가 사라지면 「지금 안전한가」를 알 수 없어 **숨는 판단이
  도박이 된다** — 차폐가 들어오면 **바위 뒤에서 기다리는 동안 유일한 정보**다.
- 🔴🔴 **`_visual`의 자식으로 달지 마라 — 형제여야 한다.** 자식이면 시야 알파에 물려
  **몸이 안 보일 때 표시도 같이 사라진다.** 이미 그 계약으로 배선돼 있고(`test_alert_mark_auto [3]`이
  유일한 검출자다) **차폐가 들어오면 결정적이 된다**.
- 🔴 **F8 — 이건 「조건 넓히기」가 아니라 기계 교체다.** 지금은 **한 번 떴다 사라지는 팝**인데
  `?`는 **상태를 따라 유지·전환·소멸**해야 한다. 수명 타이머 대신 **인지 상태 전이에 물려라.**
- 🔴 **F7 — 예정된 빨강이 있다**: `test_alert_mark_auto [1]`ⓑ가 *"시야 안 적에는 안 뜬다"*를 단언한다.
  조건을 넓히면 **그 항목이 빨개지는 게 정상**이다. 착수자가 「내가 뭘 깼나」로 헤매지 않게 **미리 적어 둔다.**
- **크기**: 지금 것이 *"스샷에선 작아 보였다"*(BACKLOG `N31`). **키운다 — 값은 F5.**

### 4-3. 도형인가 그림인가

🔴 **판단의 정본은 `_build_alert_mark` 머리말이다** — 거기 이미 명문화돼 있고
*"실게임에서 어색하면 답은 코드가 아니라 `takbon-art`의 스프라이트"*라는 문까지 열어 뒀다.
**이 문서는 그걸 가리키기만 한다**(F18 — 같은 말을 두 벌로 두면 T5다).

9. 🔴 **`vision_overlay`는 목록을 안 받는다** · `lit_at()`이 셰이더가 그리는 것과 정확히 같다(O9)

11. 🔴 표시가 **`_visual`의 형제**다(§4-2)

**뮤테이션**
- 주변시 검사를 차폐 **뒤로** 옮긴다 → **[3]만** 빨개져야 한다(O1 격리)
