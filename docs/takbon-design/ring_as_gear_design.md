# 마법진을 장비처럼 착용 — 「한 화면에서 같이 관리」

> **세100 사용자 확정 · architect 리뷰 반영 완료.** 발단 = 세98 사용자 원문:
> *"마력 주입 이후 인벤토리에 마법으로 써 들어가는 거 ㅇㅇ 마법진을 장비처럼 착용하자"*
> → 세100에 *"한 화면에서 같이 관리"*로 좁혔다.
>
> 🔴🔴 **이 설계가 겨냥하는 것은 자료구조 통합이 아니라 화면이다.** 실측이 그 길을 먼저 닫았다 —
> 인벤토리는 `{id: 개수}` 사전이라 **개체마다 다른 물건을 담을 자리가 원리적으로 없다**(§0).
> 도안이 별도 갈래인 건 실수가 아니라 **필연**이고, 사용자가 느낀 불편은 **탭이 갈려 있는 것**이었다.
>
> 관련 정본: `docs/GDD.md` §4(장비) · `docs/BACKLOG.md` N18·N7 · `takbon-rules` §3(펜 보정 체인) ·
> 앞선 결정: 세42(장비 5부위) · 세86(`equip_design` 단일 소스) · 세83(그리기 폐지 → 펜 축 휴면) ·
> 세84 #21(문구 사본 3벌을 `ItemText`로 합침 — §2-2가 그 병의 **목록판**이다).

## 0. 착수 전에 — 지금의 실체 (세100 실측)

**소지품이 세 갈래로 갈려 있다.**

| 갈래 | 실체 | 개체별 데이터 | 화면 |
|---|---|---|---|
| 아이템 | `GameState.inventory` = **`{id: 개수}` 사전** | ❌ | Tab **소지품** 탭 |
| 배움(룬·진·고리) | `GameState.codex` = `{id: true}` | ❌ | 조립 책 |
| **마법진 도안** | `GameState.ring_designs` = **`Array[RingDesign]`**(리소스 인스턴스) | ✅ | Tab **마법진** 탭 |

🔴 **도안을 인벤토리 사전에 넣는 길은 막혀 있다** — 도안은 룬·진·층·점수·잉크가 **장마다 다르다.**
사전에 넣으면 같은 이름 둘이 `×2`로 합쳐져 **개별 식별이 불가능**해진다. 그래서 이 설계는 **저장 구조를 안 건드린다.**

✅ **반대로 「장비처럼 착용」의 절반은 이미 돌고 있다** — `GameState.equip_design`이
「중복 장착 정리 · 보관 밖 도안 거부 · null 해제」를 지는 **단일 소스**고, Tab 마법진 탭이 그것을 부른다.
✅ **`EQUIP_SLOTS`도 단일 소스가 지켜지고 있다** — 하드코딩된 `3`이 리포에 **0곳**이고
HUD 슬롯·1·2·3 키·Tab 슬롯 행·세이브 복원이 전부 그 상수에서 파생한다.
✅ **EventBus 신규 시그널이 0건이다** — 도안 장착도 장비 착탈도 `equipment_changed` 하나를 쓰고,
그게 곧 자동 저장 트리거다. **새 시그널을 만들지 마라.**

🔴 **그래서 이 설계의 작업은 대부분 UI 층이고, core 변경은 열 줄 남짓이다.**

## 2. 데이터·스키마 변경 — core 몫

🔴 **원칙**: 저장 포맷을 **한 글자도 안 바꾼다.** 바뀌는 건 **해석**(어떤 부위를 낄 수 있나)과 **화면**뿐이다.

### 2-1. `Enums.ItemKind` — 끝에 둘 추가

```
enum ItemKind { INK, PAPER, WAND, ROBE, CHARM, MATERIAL, FRAGMENT, PEN, HAT, BAG, BOOTS }
                                                                        ↑9    ↑10  (신설)
```
🔴 **반드시 끝에 붙인다**(E10). PEN(7)·HAT(8)은 **값도 `.tres`도 그대로 둔다** — 착용만 막는다.

### 2-2. 🔴🔴 착용 부위 정본을 **core 한 벌로 올린다** (필수 범위)

**지금은 같은 목록이 네 벌이다**(실측):

| 자리 | 무엇 |
|---|---|
| `GameState.equip_gear`의 허용 배열 | **낄 수 있나의 판정** |
| `tab_panel.EQUIP_KINDS` | 소지품 탭 착용줄 **표시 순서** |
| `workshop_panel.EQUIP_KINDS` | 공방 벤치 착용줄 |
| **`ItemDef.category()`의 `match`** | `WAND·ROBE·CHARM·PEN·HAT → &"equip"` **분류** |

🔴 **넷을 손으로 맞추면 갈라진다** — 공방에선 끼는데 시트에선 안 보이는 상태가 되고 **에러가 0**이다.
⚠ 이건 세84 #21(문구 사본 3벌을 `ItemText`로 합친 건)과 **같은 병이 목록에 남은 것**이고,
🔴 **지금이 그 목록이 실제로 바뀌는 유일한 타이밍**이다. 안 올리면 같은 병을 같은 프로젝트에서 재발시킨다.

**→ 정본 = `src/core`의 새 파일 한 장**(`equip_slots.gd` — `item_text.gd`·`codex_text.gd`·`grade_colors.gd`의 형제).
그 파일이 지는 것 = **부위 목록 + 표시 라벨 + 순서 한 벌**. 위 네 자리가 전부 그것을 읽는다.

- 🔴 **`Enums`에 두지 마라.** `Enums`는 **값의 정의**이고 허용 목록은 **정책**이다. 정책을 enum 옆에 두면
  「끝에만 덧붙여라」(저장 호환)라는 규약이 **정책 변경에도 걸린 것처럼** 읽혀 E10의 구분이 흐려진다.
- ⚠ **순수 static · Db 무참조여야 한다** — `ItemDef`는 `class_name` Resource라 오토로드를 못 본다
  (`-s` 컴파일 함정). 목록이 `ItemKind` 정수 + 문자열뿐이라 이 제약은 자연히 만족한다.

### 2-3. `EQUIP_SLOTS` — 한 줄, 단 **그물 수리를 같은 커밋에**

```
GameState.EQUIP_SLOTS: 3 → 2
```
✅ HUD 슬롯·1·2·3 키(`player_caster`의 `for i in EQUIP_SLOTS`)·Tab 슬롯 행·세이브 복원 루프가
**전부 이 상수에서 파생**한다.
✅ **옛 세이브의 3번 슬롯 도안은 조용히 사라지지 않는다** — 로드 루프가 `EQUIP_SLOTS`까지만 돌고
보관(`ring_designs`)은 전량 복원되므로 **격자에 남는다.** `_prune_ring_files`도 `ring_designs.size()` 기준이라 무관.

🔴🔴 **그러나 `test_save_auto`가 `ring_equipped[2]`를 두 곳에서 짚는다 = out of bounds.**
**이건 빨간 테스트가 아니라 런타임 에러다** — `takbon-verify §3`의 정본대로 **`-s` 스크립트는
런타임 에러가 나도 `OK`를 찍을 수 있고**(세22·23에 두 번 밟았다), 그 파일 **뒤쪽 검사가 통째로 안 돌면서
초록으로 보인다.** → **수리를 0단계와 같은 커밋에** 넣고, 고칠 땐 `ring_equipped.size()` 파생으로 써라
(⚠ **같은 파일의 다른 자리는 이미 그렇게 하고 이유를 주석으로 적어 뒀다** — 두 자리에서만 규율이 안 지켜졌다).

🔴 **의미 손실을 같이 처리해라**: *"슬롯3이 비었다"*는 **바람 룬 도안 시드 재발 감지기**였다
(`takbon-verify`가 `test_save_auto`의 심장으로 지목한 항목). 슬롯이 둘이면 그 검사가 사라지므로,
남은 `ring_designs.size() == 1` + *"슬롯2가 비었다"*가 그 역할을 **전부 지는지 명시로 확인하고 주석에 적어라.**

### 2-4. 도안 이름 — 🔴 **「말」 함수 셋을 core로 같이 올린다**

```
「진 이름」 「룬 이름」 「문양 이름들」 마법
예: 일반 불꽃 확산 폭발 마법 / 혼 물 관통 마법 / 불 마법(문양 0개)
```

| 규칙 | 값 |
|---|---|
| 문양 나열 상한 | **3개**. 넘으면 뒤에 `…` (칸 폭 150px) |
| 문양 0개 | 진·룬만 — `일반 불꽃 마법` |
| 중복 문양 | 같은 문양이 두 번이면 **한 번만 적는다**(`확산 확산` 방지) |

🔴🔴 **이름 함수만 core에 두면 문구 사본이 네 번째로 생긴다.** 지금 `rune_word`·`glyph_word`·`_strip_symbol`이
**`tab_panel`의 static**이고 core는 hud를 참조할 수 없어서, core의 새 함수가 **이름을 Db에서 다시 뽑게 된다.**
⚠ **그리고 `test_ui_text_auto`의 사본 스캔에 안 걸린다** — 그 스캔은 `_effect_text`·`_wand_pattern_text`·`count_text`
이름만 찾는다.

**→ `rune_word` / `glyph_word` / `_strip_symbol`을 core로 옮기고 `tab_panel.spell_formula`가 그것을 부르게 한다.**
그러면 **나열식 이름(E7)과 수식(E9)이 같은 어휘를 쓴다** — 「소지품 탭엔 `확산`인데 마법진 탭엔 `확산⋔`」 같은
갈라짐이 원천적으로 안 생긴다. Db 접근은 **`codex_text.gd`의 `_db()` 런타임 조회 패턴**을 그대로 쓴다.

🔴 **`display_name` 필드는 이 이름의 소유자가 아니다.** 지금 라이브 생산자가 상수 `"고리 마법진"` 하나만
넘겨 **모든 도안이 동명이인**이다. 이름은 **조립 내용에서 매번 파생**시킨다(저장 안 함) — 그러면
저장된 옛 도안도 자동으로 새 이름을 얻고 **마이그레이션이 0**이다.

🔴 **소비자가 둘이다 — `hud.gd`를 빠뜨리지 마라.** `hud._draw_selected_detail`이 좌하단에
`"슬롯 %d · %s ..."`로 **`display_name`을 직접 그린다**(= 지금 화면에 늘 *"슬롯 1 · 고리 마법진"*이 떠 있다).
Tab만 고치면 **화면마다 다른 이름**이 된다. ✅ core 배치(위)가 이걸 가능하게 한다(hud는 tab_panel을 preload할 수 없다).

⚠ **덤으로 고칠 것 둘**: `GameState._make_seed_ring(rune_type, name)`이 **`name` 인자를 본문에서 안 쓴다**
(시드 도안에 이름을 붙이려고 인자를 고쳐도 아무 일도 안 일어난다) · 그 결과 `ring_design.gd`의 `display_name`
주석이 *"시드 3장만 '불/물/바람 마법진'"*이라고 **거짓을 적고 있다**(T4) — 같이 고쳐라.

### 2-5. 신발 — `.tres` 한 장 + 🔴 **`move_speed()`의 부위 상수**

```
data/items/boots_basic.tres
  kind = 10 (BOOTS) · display_name = "낡은 가죽신" · grade = 1
  params = { "move_speed_mult": <hat_basic과 같은 값> }
```

🔴🔴 **`.tres`만 만들면 신발은 죽은 채로 태어난다.** 실측:

```gdscript
func move_speed() -> float:
    return balance.player_move_speed * (1.0 + gear_param(Enums.ItemKind.HAT, "move_speed_mult", 0.0))
```

**이 `HAT`을 `BOOTS`로 안 고치면** 신발이 화면에 *"이동 속도 +15%"*라고 적으면서 **실제로는 아무 일도 안 한다**
= 화면이 참인 척하는 거짓 손잡이(T3 + T8). ✅ `run_speed()`는 `move_speed()` 파생이라 자동으로 따라온다.

✅ **검출자는 있다**: `test_workshop_auto`가 `equip_gear` → `move_speed()`를 재고 `test_feel_auto`가 걷기·달리기
비율을 잰다 — **끄지 말고 BOOTS로 갈아 끼워라.**
🔴 **단 `test_feel_auto`는 `if walk_hat > walk:` 가드 뒤에 있다** — 모자가 속도를 못 올리게 되면 조건이 거짓이 되어
**검사가 통째로 건너뛰어지고 조용히 초록**이다. **빨개져 알려 주는 그물이 아니라 스스로 꺼지는 그물**이라,
갈아 끼울 때 **가드를 걷어라.**

⚠ 획득 경로는 **공방 레시피**(모자와 같은 자리)로 세운다 — 안 그러면 **도달 불가 해금**이 또 생긴다(세97 N15).
✅ **아트는 필요 없다**(실측): 착용줄·격자·공방 행이 **전부 텍스트**고 기존 장비 어느 것도 `params.sprite`가 없다.
⚠ **단 나중에 드롭 보상으로 돌리는 순간** `drop_pickup`이 **등급색 마름모 폴백**으로 떨어뜨린다(세54 도형 금지 위반) —
그때는 `takbon-art`를 먼저 태워라.

### 2-6. 🔴🔴 격자 「마법진」 구역 — **`CATEGORY_ORDER`에 줄을 넣는 걸로는 안 된다**

**실측**: `_grid_sections()`의 루프는 `groups`를 **인벤 사전에서만** 만든다
(`_grouped(GameState.get_inventory_snapshot())` → `ItemDef.category()`로 가름) → **도안은 `groups`에 영원히 안 들어온다**
→ `CATEGORY_ORDER`에 `[&"design", "마법진"]`을 넣어도 `if not groups.has(cat): continue`로 **매번 건너뛴다.**
🔴 **한 줄 넣고 「했다」고 보고하는데 화면엔 아무것도 없다.**

**올바른 처방 — 선례가 같은 파일 안에 있다.** 「가방」 구역이 정확히 그 패턴이다:
**`CATEGORY_ORDER` 루프 밖에서 `_section_layout`을 한 번 더 부르고 `hidden`·`next_y`를 직접 갱신한다.**

- 🔴 **창고 카테고리 루프보다 「먼저」 얹어라.** 뒤에 두면 창고가 길 때 `if hidden > 0: … continue`에 걸려
  **구역째 접힌다**(§1의 세로 실측대로 접힘이 일찍 온다).
- 🔴 **`_section_layout`을 그대로 재사용하면 그 자리에서 죽는다** — 그 함수는 카드를 `entry["id"]`·`int(entry["count"])`로
  만든다. 도안 엔트리엔 그 키가 없어 **런타임 에러**다. **레이아웃 함수도 도안용으로 갈라라**(그리기만이 아니다).
- 🔴 **카드 엔트리에 종류 태그를 실어라** — 안 그러면 `_gui_input`의 격자 루프가 `_is_equippable(card["id"])`에서
  false를 받고 **`accept_event()`만 한 채 무반응**이 된다(G19).

⚠ **엽전 선례는 「같은 증상 다른 원인」이다** — `coin`의 `params.cat = "money"`가 `CATEGORY_ORDER`에 없어
지금도 격자에 안 뜨는 건 맞지만(실측), **엽전은 아이템이라 `groups`엔 들어간다.** 도안은 `groups`에조차 안 온다.
**처방을 그대로 옮기면 안 되는 이유가 그것이다.**

### 2-7. 펜·모자 잔재 정리 (E12)

| 무엇 | 처리 |
|---|---|
| 레시피 4장(`craft_pen_basic`·`craft_pen_mid`·`craft_pen_high`·`craft_hat_basic`) | **걷는다** — 공방 목록에서 사라진다 |
| 아이템 4장(`pen_*`·`hat_basic`) | `.tres`는 **남긴다**(옛 세이브의 창고에 들어 있다). **분류만 `&"equip"` 밖으로** 옮겨 「장비」 칸에 안 뜨게 한다 |

🔴 **`takbon-rules §3`의 펜 보정 체인은 하드 계약이고, 이 변경이 그 「되돌림 스위치」를 반쪽으로 만든다.**
`balance.skip_drawing = false`로 되돌려도 **펜을 낄 수 없어 보정이 영구 0**이 된다.
→ 방향은 사용자 확정이므로 뒤집지 않는다. 대신 ⓐ `takbon-rules §3`에 **「세100에 착용이 막혔다 — 되돌리려면
허용 목록도 같이」**를 적고 ⓑ §7 되돌리기의 "E4만"에 **그리기 되돌림과 한 세트**임을 적는다.
🔴🔴 **그리고 검출력이 없다**: `test_ring_trace_auto`가 `gs.equipment[ItemKind.PEN] = &"pen_high"`로 **직접 대입**해
`equip_gear`를 우회한다 → **펜이 도달 불가가 돼도 영원히 초록**이다(T2의 교과서 사례).
그 검사에 **`equip_gear` 경로 한 줄을 덧대** 「지금은 못 낀다」가 명시로 보이게 해라.

## 3. 마이그레이션 — 옛 세이브가 조용히 깨지지 않게

🔴 **저장 포맷을 안 바꾸므로 「형식 마이그레이션」은 없다.** 대신 **의미가 바뀐 셋**을 로드에서 정리한다.

| # | 상태 | 지금 두면 | 처리 |
|---|---|---|---|
| **M1** | `equipment`에 **PEN·HAT이 끼워진 채** 저장돼 있다 | 🔴 **조용히 착용 상태로 남고 효과도 계속 적용된다** — `gear_param`은 `kind`로 바로 읽고 **로드는 허용 목록을 검증하지 않는다.** 착용줄엔 안 보이는데 스탯은 붙는 유령 | **로드 뒤 1회 정리**: 허용 밖 부위는 **해제 + 창고 반환**(`add_item`) |
| **M2** | `ring_equipped_paths`에 **슬롯이 3개** | ✅ 안전 — 복원 루프가 `EQUIP_SLOTS`까지만 돌고 3번째 도안은 **보관에 남는다**(실측 확인) | 없음(확인만) |
| **M3** | 모자를 끼고 있던 플레이어의 **이동속도** | 해제되면 느려지는데 **원인이 안 보인다** | 신발을 **공방에서 만들 수 있게** 열어 둔다(§2-5). 새 게임 시드로 줄지는 **미결**(§6) |

🔴 **M1을 어디에 두나 — 설계가 정한다**(안 적으면 dev가 `_ready`나 `GameState`에 붙여 **두 번 환불되는 자리**가 생긴다):
**`save_manager.load_game` 안, `_loading = true` 구간에 둔다.** `_queue_save()`가
`if _loading or not _ready_to_save or _save_queued: return`으로 시작하므로, 그 안에 두면
`unequip_gear`/`add_item`이 쏘는 `equipment_changed`·`inventory_changed`가 **저장을 안 건드리고 매 부팅 멱등**이다.

⚠ **`SAVE_VERSION`을 올리지 마라** — 형식이 그대로고, 로더에 **분기 코드가 아예 없다**
(`version > SAVE_VERSION`이면 경고 한 줄). 올려도 아무 일도 안 일어나고 **「마이그레이션이 있다」는 착각만 남는다.**

## 6. 미결 (F5·사용자가 정한다)

- **마법 칸이 2개로 충분한가** — 원소 반응(룬 2개)은 한 도안 안에서 나므로 2칸으로도 조합은 되지만,
  *"불/물/바람을 번갈아"*가 하고 싶어지면 3칸이 그리워질 수 있다. **`EQUIP_SLOTS` 한 줄이라 되돌리기는 싸다**
- **신발을 새 게임에 지급하나** — 지금 모자는 지급이 아니다. 안 주면 첫 판 이동속도가 기본값이고, 주면 「얻는 재미」가 준다
- **도안 이름의 문양 상한 3개가 맞나** — 칸 폭 150px 기준 추정이다. 실제로 4층짜리를 만들어 봐야 안다
- 🔴 **마법 줄 + 착용 줄 + 격자가 한 화면에 다 들어오나** — §1 세로 실측이 빠듯하다(격자 가용 226px = 4줄).
  **접힘이 어디서 오는지는 F5로만 보인다**
- **격자에 도안이 몇 장까지 쌓이나** — 삭제 API가 리포에 **0건**이다(`clear()`뿐). 20장이 되면 격자가 넘치는데
  **버리기**를 붙일지는 그때 정한다
- **가방 용량** — 별건 설계(E6). 「몇 칸이냐 · 넘치면 못 줍나 · 화면에 어떻게 보이나」

## 7. 되돌리려면

- **전부** — `EQUIP_SLOTS`를 3으로, `equip_slots.gd`의 목록을 옛 5부위로. **저장 포맷을 안 바꿨으므로 세이브는 그대로 산다**
- **E3만** — `EQUIP_SLOTS = 3`(한 줄) + 그물의 `.size()` 파생이 자동으로 따라온다
- **E4만** — 목록에 PEN·HAT을 되돌린다. `.tres`도 enum 값도 안 지웠으므로 **그 자리에 그대로 있다**.
  🔴 **단 이건 「그리기 되돌림」과 한 세트다** — `balance.skip_drawing`을 되돌릴 땐 **펜 착용도 같이 열어야**
  보정 체인(`takbon-rules §3`)이 산다(§2-7)
- **E7만** — 이름 함수를 안 부르고 `display_name`으로 되돌린다(저장을 안 했으므로 잔여물 0)

⚠ **되돌림이 안 되는 것 셋** — **소지품 탭 재배치** · **마법진 탭의 상세 전용화** · **펜·모자 레시피 삭제**는
코드·데이터 변경이라 상수를 되돌려도 안 돌아온다. 그 셋만 손으로 되돌린다.
