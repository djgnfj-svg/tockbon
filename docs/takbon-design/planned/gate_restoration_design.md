## §0 한 줄

**보스를 잡아 얻은 재료를 마을 한가운데 부서진 마법문에 바치면 칸이 하나 차고, 마을에 빛이 한 단계 돌아온다. 칸을 다 채우면 문이 온전해지고 그 자리에서 최종 챕터가 열린다.**

## §1 발단 — 무엇이 비어 있었나 (실측)

세95가 엔딩을 *"문양을 다 모아 마법진을 복원 → 최종 보스"*로 확정했고 `PROGRESSION §4`가 그걸 받아 적었다.
그런데 **잴 대상이 없었다.**

| 실측 | |
|---|---|
| `GlyphDef`에 `unlock_id`가 **없다** | 스키마 머리말이 부재를 명문으로 선언한다 |
| 문양은 **낱개로 못 고른다** | 세71에 개별 문양 탭이 은퇴했다. 책은 `Db.all_glyphs()`를 받아 **색·이름 사전으로만** 쓴다 |
| 기념비는 **완전히 정적** | 스크립트 0장 · 라이트 0개 · `InteractZone` 0 · 진행도를 읽는 코드 0 |
| 최종 챕터 `.tres` | **없다** |

🔴 **그래서 「문양을 되찾는다」는 세계관도, 진행도도, 엔딩 판정도 전부 데이터가 0인 채였다** — 에러 0 · 전 스위트 그린으로.

### 🔴 이 설계가 세계관 문서 §2를 정정한다

`world_and_visual_design.md` §2는 진행도의 분모를 **문양-고리(`GlyphRingDef`) 전체 수**로 파생시키라고 적었다.
**그 판단을 각하한다.** 사용자 확정: *"5개의 보스 재료가 좋지 않을까"* · *"굳이 소모템을 넣을 필요 없이"*.

| | 옛 판(세95) | 이 문서(세101) |
|---|---|---|
| 분모 | 문양-고리 전체(지금 5) | 🔴 **최종 전 챕터 수**(지금 3 · 목표 7) |
| 바치는 것 | (바치는 개념 없음 — 해금 상태를 읽기만) | 🔴 **보스 전용 재료** |
| 기념비 | 표시만 | 🔴 **창구 + 진행도 + 최종 입구** 셋을 겸한다 |

**왜 갈아탔나**: 고리는 대부분 **공방에서 재료로 사는 것**이라 「되찾았다」가 안 읽힌다.
보스 재료는 **한 판을 끝까지 밀어야 나오는 것**이라 한 칸의 무게가 다르다.

⚠ **`world_and_visual_design.md` §2와 `PROGRESSION.md` §4에 이 문서를 가리키는 스텁을 남겨라** —
안 남기면 다음 세션이 **옛 분모로 착수한다**(문서 간 파생은 코드에 안 나타나서 `grep`으로도 안 걸린다).

## §3 문이 무엇을 겸하나

```
        ┌─ 숲길 문(ForestGate, gate_arch.png) [E] ──→ 챕터 선택  (최종 챕터는 여기 안 뜬다 · §7)
마을 ───┤
        └─ 부서진 마법문(Monument) [E] ──→ ⓐ 보스 재료를 바친다 → 칸이 하나 찬다
                                          ⓑ 지금까지 찬 칸을 본다
                                          ⓒ 다 차면 여기서 최종 챕터로 들어간다
```

🔴 **두 문은 별개 노드다.** 숲길 문은 나가는 길, 부서진 마법문은 되돌리는 자리.
⚠ **노드 이름 `Monument`와 자식 `Sprite`를 바꾸지 마라** — `test_base_auto [11]`ⓓ가 `Monument/Sprite`로 찾고 `_sprite_top`도 그 이름을 쓴다. 화면 문구만 「부서진 마법문」으로 쓴다.

### 3-1 바치기 = [E] 한 번 → 패널

`workshop_panel`이 이미 *"재료를 확인하고 → 버튼 → 소비하고 해금"*의 형태다. **그 형태를 그대로 따른다**(새 UI 언어 0).

- **칸 목록** — 「보스 이름 · 요구 재료(보유/필요) · 상태」. 상태 셋 = **바쳤다 / 바칠 수 있다 / 재료가 없다**.
- 🔴 **보이는 칸 = `chapter_panel.is_chapter_open(ch)`이 참인 챕터뿐이다**(ⓗ). 그 너머는 **줄 자체를 안 그린다.**
  → 분모가 화면에 안 드러나므로 *"아직 얼마나 남았지?"*가 끝까지 안 밝혀진다.
  → 🔴 **판정이 챕터 잠금과 같은 단일 소스를 탄다** — 「문에는 보이는데 챕터는 잠겼다」가 구조적으로 불가능하다.
- **문구의 단일 소스**(takbon-rules §3 — 공방·정제대가 **인자가 거꾸로인 사본**을 각자 들었던 자리다):
  - 보유/필요 = 🔴 **`ItemText.count_text`** — 직접 `"%s %d/%d"`를 쓰지 마라.
  - 보스 이름 = `Db.get_enemy().display_name`(`chapter_panel._draw_card`와 같은 경로).
- ⚠ **모달 변수를 하나 더 두면 `_open_chapter_panel`·`_show_dialogue`의 가드에도 전부 더해라** —
  `base.gd`의 모달 규약은 `_overlay`·`_dialogue`·`_chapter_sel` 세 변수이고, 하나만 빠뜨리면 **조용히 겹친다.**

## §4 칸 수 — 🔴 상수로 박지 마라

**칸 수 = 최종 챕터를 뺀 챕터 수**에서 파생한다.

- 지금 = **3칸**(ch1·ch2·ch3) · 목표 = **7칸**. 챕터를 만들 때마다 **문이 저절로 넓어진다.**
- 🔴 **상수 `7`을 박으면** 챕터를 늘려도 문이 안 자라거나, 없는 챕터 칸이 영영 빈다(감사 T5 「파생 대신 복제」).

### 🔴 4-1 파생 함수는 **하나**다 — `Db.gate_chapters()`

**칸 수(§4)와 숲길 문 목록(§7)이 같은 함수에서 나온다.** 그래야 「칸은 3개인데 카드는 4장」이 **구조적으로 불가능**해진다.

- ⚠ **`Db.chapters_sorted()` 자체는 전량 그대로 둬라** — `is_chapter_open`의 prev 탐색이 그걸 쓰고,
  거기서 최종을 빼면 **잠금 사슬 계산이 달라진다.**

### 4-2 「최종 챕터」를 어떻게 가리나

`ChapterDef`에 **`is_final: bool`**(기본 `false`) 한 줄 — 리드 몫(core 스키마). **core 신설은 이것과 §5-2의 `@export` 하나뿐이다.**

- ⚠ **`order`가 가장 큰 것 = 최종**으로 **추론하지 마라.** 챕터를 늘리는 동안 매번 최종이 바뀌어
  「방금 만든 평범한 챕터가 최종이 된다」가 조용히 일어난다.
- ⚠ **`reward_unlock`이 비었나로 판정하지 마라** — 지금 데이터에도 빈 값이 있을 수 있다.

## §5 바치는 것 = 보스 재료

**챕터 보스마다 전용 재료 한 종.** 규칙만 확정하고 재료의 이름·성격은 **몬스터 정리 사이클**에서 따라온다(ⓖ).

| 규칙 | |
|---|---|
| **보스 1마리 = 전용 재료 1종** | `data/items/<재료>.tres` 한 장 + 보스 `.tres`의 `DropEntry` 한 줄 |
| **확정 드롭** | 🔴 **진행을 운에 걸지 않는다**(세57 원칙 · 세99에 사용자가 제단 초안을 같은 이유로 각하했다). ✅ `DropEntry` 기본값이 이미 `chance 1.0 · min 1 · max 1`이지만 **의도를 남기려면 명시로 적어라** |
| **봉납은 영구 1회** | 바치면 그 칸은 영영 찬다 |
| **여벌 재료** | 두 번째부터는 그냥 재료다 — 쓸 데는 경제 정리 때 정한다 |

✅ **「보스 `.tres`에 한 줄」은 진짜로 한 줄이다** — 전용 씬 보스(`snake_boss.tscn`)도 `forest_enemy.gd`를 그대로 물어 **`_roll_drops` 단일 소스**를 지난다.
⚠ **기존 보스 드롭은 건드리지 마라** — 장비·공방 레시피가 그걸 요구한다(ⓖ가 정리할 자리다).
⚠ `item_id`를 쓰는 줄이라 `unlock_id`·`until_unlock` 배타 짝(takbon-rules §5)에 안 걸린다.

### 5-1 🔴 봉납 상태를 어디에 저장하나 — **codex를 쓴다 (신규 저장 필드 0)**

봉납 = **`EventBus.codex_unlocked.emit(&"gate_offer_<챕터id>")`** 한 발.

- ✅ 저장 스키마 변경 0 · 마이그레이션 0. `save_manager`가 codex 키를 **전량** 직렬화·복원한다(리뷰 실측).
- 🔴 **`GameState.codex`에 넣는 유일한 문이 그 시그널이다**(직접 대입하는 공개 함수가 없다) — 우회하지 마라.
- ⚠ **시드에 넣지 마라.** `test_save_auto`가 시드 집합을 **명시 열거·정확 일치**로 잰다(G7).

**수신처 7곳 전량 실측 — 여섯은 미지의 id에 정확히 no-op이다:**

| 수신처 | 봉납 id를 받으면 |
|---|---|
| `GameState._on_codex_unlocked` | `codex[id]=true` + `advance_quests(UNLOCK, id)` ✅ |
| `SaveManager` | `_queue_save()` — ✅ 오히려 원하는 동작(봉납 즉시 자동저장) |
| `Hud._on_codex_unlocked` | `CodexText.kind_of`가 `&""` → 문구가 빈 값 → **조용히 return** ✅ **그게 맞다**(칸이 차는 게 눈앞에 보이므로 토스트가 겹친다) |
| `base._refresh_gate_mark` · `base._on_station_unlocked` · `workshop_panel._on_unlocked` | 무해 ✅ |
| 🔴 **`Audio._on_unlock`** | **id를 안 보고 무조건 운다** → ⓘ대로 **전용음 wav 한 장**을 붙인다(§6-4) |

⚠ **`goal == UNLOCK`이고 `target`이 빈 퀘스트를 만들지 마라** — 봉납 7회가 그걸 7번 진행시킨다.
✅ 지금 `data/quests/*.tres` 5장 중 UNLOCK은 0장이라 안전하다(미래 방어로만 적는다).

### 5-2 요구량 = `balance`의 `@export` 한 줄

**전 칸 1개씩**(ⓙ) — 보스 하나 = 재료 하나 = 칸 하나. 규칙이 한 문장이라 설명이 필요 없다.

- 🔴 **자리는 `balance_data.gd`의 `@export`다**(코드 상수로 박으면 사용자가 F5로 못 조인다).
  ⚠ 세98 실측: `balance.tres`는 껍데기라 「balance에 넣는다」의 실제 작업은 **스키마 `@export`**다.
- **값은 사용자가 플레이하며 조인다.**

## §6 보상 — 바치면 무엇이 좋아지나

### 🔴 6-1 빛 한 단계 — **호출 경로부터 이어라**

`base.gd`에 `Dusk`(CanvasModulate) 색조를 진행도로 미는 기계가 **이미 있다**(`TINT_RUINED` → `TINT_WHOLE`).

🔴 **그런데 가드를 고치는 것만으로는 안 돈다**(G12). 호출 사슬이 이렇다:

```
codex_unlocked → base._on_station_unlocked → (표에 없으면 첫 줄에서 return)
                                            ↓ 안 닿는다
                                        _refresh_stations() → _refresh_village_tint()
```

**처방 = 봉납 전용 수신자를 하나 둔다**(`_on_gate_offered` → 색조 갱신 + 둘레 불 갱신).

- 🔴 **`STATION_UNLOCKS`(건물 축)와 봉납(문 축)을 섞지 마라** — 섞으면 함수 이름이 하는 일과 어긋나 T4가 된다.

  세95가 *"두 곳에 두면 갈라진다"*고 각하한 자리다. **값을 복제하지 않으면 그 경고를 안 밟는다.**
