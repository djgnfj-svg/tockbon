**적은 「보는 쪽」을 갖고, 아직 나를 못 본 동안 자기 구역을 배회하며, 발견은 한 박자(경계)를 거쳐 짖음으로 확정된다.**

## §1 사용자가 확정한 것 (이 일곱이 설계의 전제다)

| # | 확정 | 왜 이걸 골랐나 |
|---|---|---|
| ⓐ | **감지 = 부채꼴 + 근접 원 + 소리** | 내 시야 설계와 **대칭**이라 공평하다. 나무 `collision_layer = 0` 계약을 안 건드린다 |
| ⓑ | **못 본 적은 자기 구역을 배회한다** | 보는 쪽이 계속 바뀌어 「틈이 열릴 때까지 기다렸다 지나간다」가 생긴다 |
| ⓒ | **발견 = 경계 한 박자 → 짖음** | 그 사이 벗어나면 없던 일 = 「아슬아슬하게 피했다」 |
| ⓓ | **경계 진입에도 작은 소리(큰읏)** | 🔴 **시야 밖 적은 몸이 안 보인다** — 소리가 유일한 통보다 |
| ⓔ | **마법 소리 = 위력할수록 크게** | 조립이 **전투 밖(잠입)까지** 의미를 갖는다 |
| ⓕ | **기습 배수** — 못 본 적을 치면 피해가 는다 | 「뒤로 돌기」가 회피가 아니라 **전술**이 된다 |
| **ⓖ** | 🔴🔴 **늑대는 지금 거리(220)를 지킨다 — 다만 「멀리서 알아채는 종」은 앞으로 온다** | 사용자 원문: *"늑대는 그래도 되는다 다른몬스터은 멀리서 알아채는 몬스터도 있을듯함"* → §8-1 |

🔴 **ⓐ가 이 설계를 싸게 만들었다.** 차폐(나무가 가림)를 골랐다면 `tree.tscn`의
**`collision_layer = 0` 계약**을 깨야 했고, 그 주석이 *"다른 Area2D가 이 나무를 주우면 드롭·피격 판정에 섞인다"*고
박아 둔 자리다. **방향만으로 회피가 성립**하므로 프롭 물리는 한 줄도 안 건드린다.
⚠ 그 자랑의 뒷면이 **§8-5**다(배회하면 그 「안 부딪힘」이 처음 화면에 나온다).

🔴 **ⓔ가 코어 재미 잣대를 통과하는 이유**: 지금까지 위력은 **전투 안에서만** 의미가 있었다.
소리를 위력에 묶으면 *「한 방에 잡고 조용히」* 대 *「다 불러내고 광역으로」*가 **조립 단계의 선택**이 된다
— 「다르게 조립하면 판이 종류로 달라지나」(세43 진단)의 새 축이다.

🔴🔴 **ⓖ가 이 설계에서 가장 값진 답이다.** 「보장을 종 전체에 매지 마라」는 뜻이고,
그래서 §8-1은 **상수가 아니라 종별 규칙 + 그물**로 착지한다.

## §2 상태 다섯

```
 ┌──────────────────────────────────────────────────┐
 │  PATROL   구역 배회 · 보는 쪽이 천천히 돈다        │◀────┐
 └───┬──────────────────────────────────────────────┘     │
     │ 부채꼴 / 근접 / 소리에 걸림                          │
 ┌───▼──────────────────────────────────────────────┐     │
 │  ALERT    멈춰 이쪽을 본다 · 🔈 큰읏 (alert_sec)   │──벗어남─┤ (없던 일)
 └───┬──────────────────────────────────────────────┘     │
     │ 버티면                                             │
 ┌───▼──────────────────────────────────────────────┐     │
 │  CHASE    🔊「아우—」 짖고 추격                     │     │
 └───┬──────────────────────────────────────────────┘     │
     │ lose_sec 동안 감지 실패                             │
 ┌───▼──────────────────────────────────────────────┐     │
 │  SEARCH   마지막 본 자리로 가 두리번거린다          │     │
 └───┬──────────────────────────────────────────────┘     │
     │ search_sec 경과 → 구역으로 복귀                     │
     └───────────────────────────────────────────────────┘
```

**SEARCH가 「따돌렸다」를 만든다.** 즉시 복귀면 도망이 너무 쉽고, 안 놓치면 세88의 그 고장
(*"전부 남쪽 입구로 모인다"*)이 돌아온다.

### 🔴🔴 2-b. 인지는 **어느 AI 갈래의 호출도 건너뛰지 않는다** (C2)

`takbon-rules` §5의 하드 계약이 *"AI 거리 게이트(leash)는 「이동 대입만」 감싼다 — **`return` 금지**"*(세88)이고,
코드가 **세 자리에서** 그 이유를 스스로 적어 뒀다(*"`return`으로 끊으면 아래 `_contact`와 분산 타이머가 멀리서 멈춘다"*).

⇒ **인지 상태는 갈래를 안 끈다.** 갈래는 **그대로 매 틱 돈다**. 인지가 바꾸는 것은 딱 둘이다:

| 인지가 바꾸는 것 | 안 바꾸는 것 |
|---|---|
| **속도 목표**(어디로 갈 의지를 세우나) | 갈래 호출 자체 · `_cool` · `_status.tick` · `_regen` |
| **돌진 사이클의 진입 허용 여부** | `_contact`(접촉 피해) — **아래 확정 참조** |

🔴 **확정: `_contact`는 PATROL에서도 켠다 — 부딪히면 아프다.**
안 켜면 `test_chapter_auto [2b]`가 재는 *"적→플레이어 피해 채널"*이 **잡몹에 대해 무증상으로 사라진다**
(그 그물은 보스로만 잰다). 그리고 「늑대 몸에 부딪혔는데 안 아프다」는 세계관으로도 안 읽힌다.

⚠ **ALERT→CHASE 진입 시 `_charge_state`가 어디서 출발하나**를 구현이 정해야 한다 — 권장 = **APPROACH**.

## §4 「보는 쪽」 — 이 설계를 지탱하는 한 값

- **보는 쪽 = 이동 방향.** 멈추면 마지막 방향을 유지한다.
- 🔴🔴 **회전에 속도 제한(`turn_rate`)이 걸린다.** 이게 없으면 적이 **즉시 뒤를 돌아봐서**
  「돌아가기」가 통째로 성립하지 않는다 — **안 ⓐ 전체가 이 한 값에 얹혀 있다.**
- 🔴 **윈드업·돌진 동안 「보는 쪽」은 `_charge_dir`에 고정한다** — 고개가 계속 돌면 방향 락이 거짓말이 된다.

### 4-b. 기존 방향 수단과의 관계 (L12 정정)

*"적에겐 방향 개념이 아예 없다"*는 **절반만 맞다.** 있는 것 셋: `_face(dir)` · `_snake_dir` · `_charge_dir`.

🔴 **`_face`를 재사용하지 마라** — `_visual.rotation`을 돌려서 **늑대가 옆으로 눕는다**(뱀 머리 전용이다).
좌우 반전은 플레이어와 같은 `flip_h` 규약을 쓴다.
⚠ **hound 시트가 반전에 견디는지는 `takbon-art`가 확인할 일**이다(`ART_SPEC`의 광원이 왼쪽 위 고정이라
`boss_room.gd`가 프롭에 대해 *"좌우 반전으로 변화를 주지 않는다"*고 적어 뒀다 — 배우는 다르지만 규격은 같다).

## §5 소리 = 위력

```
  약한 마법 (quality_t↓)     🔈 ··○··          좁게
  센 마법  (quality_t↑)     🔊 ····◯····      숲을 깨운다
```

✅ **배선 재료가 이미 다 있다** — `RingDesign.to_assembly()`가 **`score`를 이미 들고 다니고**,
`EventBus.ring_cast_requested(assembly, origin, aim_dir)`가 그 Dictionary와 **발사 위치를 함께** 나른다.
⇒ **EventBus 시그널 신설 0 · 스키마 신설 0**이다.

🔴🔴 **반경 = `f(RingPower.quality_t(assembly.score))` — raw `score`를 쓰지 마라** (C4).
그 함수 머리말이 이미 경고한다: *"`score`를 그대로 `lerp`에 넣지 마라 — **하위 70%가 통째로 죽는다.**
조립 점수의 실사용 범위는 `assemble_score_base`(0.70)~1.0이라 무난한 진이 이미 중간값이 된다."*
raw를 쓰면 맨 진↔퍼펙트 반경비가 **1.43배**뿐이라 「조용히 한 방」 대 「숲을 깨운다」가 성립하지 않는다.
리포트·시전 시간·이동 배수가 전부 이 함수를 지나므로, 소리만 안 지나면 **혼자 다른 축**이 된다(T5).

- 🔴 **`assembly.get("score", <기준선>)` 가드가 필수다** — `test_audio_auto`가 `ring_cast_requested.emit({}, …)`로
  **빈 사전**을 쏜다. 가드가 없으면 SCRIPT ERROR가 나는데 **`-s` 테스트는 런타임 에러가 나도 「OK」를 찍는다**(grep에만 걸린다).
- 소리를 들은 적은 **발사 지점**을 향해 ALERT에 들어간다(플레이어 위치가 아니다 — 쏘고 옮기면 흘린다).
- ⚠ **착탄(`spell_impact`)이 아니라 발사(`ring_cast_requested`)다.** 소리는 총구에서 난다.

## §6 기습 — **직격만** 받는다

**`take_hit()` 안에서 적이 자기 인지 상태를 보고 스스로 배수를 곱한다.**

```
  if _percept != CHASE:  damage *= ambush_mult
```

✅ **호출자를 한 곳도 안 건드린다**(실측 확인 — `ring_spell_system`·`ring_carrier`·`projectile` 무변경).
회귀 위험이 구조적으로 0인 자리다(세36 퀘스트 오버레이의 결).

🔴 **M9 정정 — hp를 깎는 자리는 셋이다**: `take_hit`(직격) · `take_reaction_damage`(반응 버스트·연쇄) ·
`_wire_status`의 `on_dot` 람다(DoT 틱). **기습은 직격만 받는다 — 반응·DoT는 일부러 제외한다.**
⚠ *"유일한 진입점"*이라고 적으면 다음 사람이 「유일하니까 여기 다 넣어도 된다」로 읽고 반응 피해까지 옮긴다.

**넣는 자리 둘** (L15):
- ⓐ **`EventBus.enemy_hit` emit 앞** — *"`enemy_hit`은 최종 피해"*가 계약이다.
- ⓑ **`if damage <= 0.0` 조기 반환 뒤** — 앞에 두면 0에 곱해 무해하지만 「기습이 도는 자리」가 둘로 읽힌다.
- ✅ 곱셈 **순서**는 무해하다 — `weakness_mult`·`armor_reduction`·`dispersed_resist`가 전부 곱이라 교환법칙이 선다.

⚠ **허수아비(`dummy_target.gd`)에도 `take_hit`이 있다** — 세56의 *"두 몸 복제 계약은 그물도 두 개"*.
**허수아비엔 기습을 안 넣는다**(인지가 없다). 이걸 적어 두지 않으면 다음 사람이 「복제 계약이니까」로 옮긴다.

## §7 데이터 축 — 「새 적 = `.tres` 한 장」을 지킨다

전부 **`EnemyDef.params`**(적별 성격이라 balance가 아니다):
`sight_range` · `sight_angle` · `sense_radius` · `turn_rate` · `patrol_radius` · `patrol_speed` ·
`alert_sec` · `lose_sec` · `search_sec` · `ambush_mult`

**`balance_data.gd`에 `@export` 1개**: 소리 반경 계수(전역 규칙 · 난이도를 바꾸므로 balance가 맞다).
⚠ `data/balance.tres`는 **6줄짜리 껍데기**라 실제 작업은 `.tres`가 아니라 **`@export` 한 줄**이다(선례 = `extract_hold_sec`). **리드 몫.**

### 🔴🔴 7-b. 하위호환 — 「키가 없으면 **정확히 옛 동작**」 (C3)

이 파일은 그 계약을 **세 번 명문화**했다(`_setup_frames`·`_idle_fps`·`_apply_hitbox`). 인지도 같은 규율을 따른다.
**이 표 하나가 그물 표의 절반을 없앤다** — 인지 키가 0개인 몸이 **그물 6파일에 주입**되기 때문이다.

| 키 부재 시 | 값 | 결과 |
|---|---|---|
| `sight_angle` | **360°** | 부채꼴이 무의미 = 늘 본다(옛 동작) |
| `sight_range` | `aggro_range` 승계 | 옛 거리 그대로 |
| `sense_radius` | 0 | 부채꼴 360°가 이미 덮는다 |
| `turn_rate` | **∞** | 즉시 회전 = 방향 개념 없음(옛 동작) |
| `patrol_radius`·`patrol_speed` | **0** | 🔴 **배회 안 함** — `disperse_period`·`regen_per_sec` 관용구 그대로 |
| `alert_sec` | **0** | 한 박자 없음 = 즉시 CHASE(옛 동작) |
| `lose_sec`·`search_sec` | 0 | SEARCH 없음 |
| `ambush_mult` | **1.0** | 곱셈 항등 |

## §8 🔴 조용히 깨질 자리 (착수 전에 반드시 읽어라)

### 8-1. 🔴🔴 `aggro_range`는 **은퇴가 아니라 `sight_range`로 이름 승계**다 (C1 · 사용자 확정 ⓖ)

초고는 *"게이트가 두 겹이 되니 은퇴"*라고 적었다. **걱정은 옳고 처방이 틀렸다.**

`vision_design` §4-1의 심장이 **`vision_near_radius`(220) 대 `aggro_range`**이고,
220은 *"바탕 종 aggro의 **최댓값**"*에서 **파생한 값**이다. `hound_alpha`의 **등 뒤 60px**(= 280 − 220)가
그 차이고, **세101에 사용자가 직접 확정한 그 종의 유일한 정체성**이다.
⇒ 키를 지우면 `params.get("aggro_range", 0.0)`이 0을 돌려줘 **바탕 조건은 자명 통과 · 스토커 조건은 빨강**이 된다.
「시야」가 *"F5 튜닝 중에 네임드의 정체성이 값 하나로 증발하고 아무도 모른다"*고 경고한 바로 그 사고를
**인지 설계가 대신 일으킨다.**

🔴 **처방 = 이름 승계.** 게이트가 두 겹이 되는 문제는 **키를 지워서가 아니라 읽는 자리를 하나로 줄여서** 푼다.
`vision_design`의 파생원·60px·`STALKERS` 그물이 **한 단어 치환**으로 전부 산다.

#### 🔴🔴 8-1-b. 그리고 보장은 **상수가 아니라 종별 규칙**이다 (사용자 확정 ⓖ)

「시야」의 보장은 ***"주변시 ≥ 감지거리 ⇒ 나를 쫓기 시작한 적은 반드시 보인다"*** 다.
부채꼴이 220을 넘으면 **늑대가 「나에게 안 보이는 채로」 CHASE에 들어간다** — 안 보이는 데서 맞는다.

사용자 확정 ⓖ가 이걸 이렇게 갈랐다:

| 종 | `sight_range` | 규칙 |
|---|---|---|
| **`hound`**(바탕) | **220 승계** | ✅ 보장 안. 「돌아가기」의 재미는 **거리가 아니라 `sight_angle`이 진다** |
| `hound_alpha`(네임드) | 280 승계 | ⭕ 일부러 밖 — 등 뒤 60px(`STALKERS`에 이미 등재) |
| **앞으로 올 「멀리 보는 종」** | > 220 허용 | 🔴 **`STALKERS`에 반드시 등재**한다. 미등재로 220을 넘기면 **그물이 빨개진다** |

🔴 **불변식(그물)**: **`sight_range > vision_near_radius`인 종은 `STALKERS`에 명시돼 있어야 한다.**
이게 「시야」 §4-1 그물의 자연스러운 후계고, *"바탕이 하나뿐이라 이 값은 취약하다 — 잡몹을 늘리는 날
aggro가 220을 넘으면 보장이 조용히 깨진다"*는 그 문서의 경고를 **실행 가능한 형태로** 바꾼 것이다.
⚠ **「멀리 보는 종」을 실제로 넣을 때** 그 종을 `always_visible`로 할지(= CHASE 중엔 보인다)는
**그 종의 설계에서 정한다** — 지금 정하지 않는다.

#### 8-1-c. 실효 은퇴 범위는 **한 곳뿐이다** (L11 정정)

`aggro_range`를 읽는 자리는 여섯이다: `_ai_chase` · `_ai_charge` APPROACH · `_ai_hover` leash ·
`_ai_boss_snake` leash · `_ai_boss_gale` DRIFT leash · **`_ai_boss_gale` 연사 사거리 게이트**.
초고의 열거는 hover/snake/gale **자체가 leash**인데 별개로 세었고 여섯째를 놓쳤다.

🔴 **인지가 실제로 대체하는 자리는 `_ai_charge` APPROACH 하나다** — chase의 유일한 실데이터는
보스(`slime_elite`)고 hover는 실데이터가 0장이다. **작업이 보이는 것보다 훨씬 작다.**

### 8-2. 보스 셋은 이 설계 밖이다 — **코드 분기가 아니라 「데이터 규율」이다** (C3-b)

`snake_boss` · `gale` · **`slime_elite`**. 🔴 마지막이 함정이다 — 이름이 「엘리트」라 잡몹으로 읽히지만
**`ch1.tres`의 `boss_enemy_id`**다(`vision_design`이 초고·리뷰 **둘 다** 오분류했다).

🔴 **그런데 `forest_enemy`는 자기가 보스인지 모른다.** 몸이 아는 축은 `params.ai` 하나이고
`slime_elite`엔 그 키조차 없다(기본 `chase`). **⇒ `boss_enemy_id`로 런타임 분기를 만들 수 없다.**
유일하게 실행 가능한 형태는 **「보스 `.tres`에 인지 키를 주지 않는다」**이고,
§7-b 덕분에 그게 자동으로 옛 동작이 된다. **그물은 「보스 셋에 인지 키가 없다」를 정적으로 잰다.**

### 8-3. 배회 반경 < leash 반경

`dungeon_structure`의 **구역 배치**가 배회로 흐트러지면 「깊이 들어간다」가 사라진다(세88의 그 고장).

### 8-4. 허수아비는 **무영향**이다 (확인함)

마을 연습장 표적은 `forest_enemy`가 아니라 **`dummy_target.tscn`이라는 별개 씬**이다 ⇒ 순찰을 켜도 안 걸어다닌다.
⚠ `vision_design`이 짚은 *"허수아비도 `enemies` 그룹이다"*는 **가시성 쪽 함정**이고 다른 축이다.
⚠ 다만 **`take_hit` 복제 계약은 살아 있다** — §6 참조.

### 8-5. 🔴 배회하면 **늑대가 나무를 관통하고 서로를 통과한다** (M10)

실측: 적은 `collision_layer = 4` / **`collision_mask = 1`**(world)인데 **방 안에 layer 1 물체가 하나도 없다**
(프롭은 전부 `collision_layer = 0`이고 `test_landmark_road_auto`가 *"프롭에 `PhysicsBody2D`가 0개"*를 단언한다).
적끼리도 서로의 mask에 없다. **지금은 무증상이다** — 어그로 전엔 멈춰 있고 후엔 직선으로 달려들어 겹침이 순간이라서.
**배회를 켜는 순간 이 둘이 처음으로 상시 화면에 나온다**(둥지 둘레 늑대 다섯이 한 몸처럼 겹친다).

🔴 **물리로 풀지 마라** — 나무에 충돌을 주면 ⓐ가 자랑한 *"프롭 물리 무변경"*이 바로 깨진다. **값으로 푼다**:
- **`patrol_radius ≤ PROP_CLEAR_SPAWN`(=100px)** — 프롭이 스폰에서 100px을 비우므로 그 안이면 나무를 안 만난다.
- 겹침은 **자리마다 배회 위상을 다르게**(스폰 인덱스 기반 위상차) — 새 스키마 0.

⚠ 둘 다 **잠정이고 F5가 정한다.** 다만 「생각조차 안 한 자리」로 두면 사용자가 첫 F5에서 바로 본다.

### 8-6. SFX 두 장 + **거리 감쇠**가 이 설계의 일부다

`audio.gd`에 hound/bark/growl/howl이 **한 줄도 없다**(실측). 필요한 것 = **큰읏(경계)** · **짖음(발견)**.
🔴 **둘이 뚜렷이 달라야 한다** — 같게 들리면 ⓒ·ⓓ가 만든 2단계 긴장이 통째로 무너진다.

🔴 **L13 정정**: *"`match` 한 줄"*은 낡았다 — `audio.gd`는 **파일명이 곧 id인 지연 로드**다(레지스트리를 안 늘린다).
**진짜로 필요한 손질은 `test_audio_auto.IDS` 갱신**이다(그 목록이 **명시 17종**이라 자동으로 안 는다 = 새 소리에 그물이 0개인 채 착지한다). **리드 몫.**

🔴 **거리 감쇠 확정(리드 판단 · M8)**: `Audio`는 **`AudioStreamPlayer`(비위치) 풀 8개**라 방 반대편 늑대가
코앞처럼 들린다 — ⓔ가 성공해 여러 마리가 동시에 짖으면 **통보가 아니라 잡음**이 된다.
⇒ **적 몸에 `AudioStreamPlayer2D`를 붙이되 스트림은 `Audio`의 캐시에서 얻는다.**
「새 소리 = wav 한 장」과 「`Audio`가 유일한 재생 경로」를 **둘 다 안 깨고** 거리만 얻는다.

### 8-7. 시야 설계와의 접합 — **판정은 독립, 출력은 겹친다**

「내가 적을 못 본다」와 「적이 나를 못 본다」는 **서로 무관한 판정**이다. 한쪽을 다른 쪽에서 파생시키지 마라.
다만 **화면에 나타나는 결과는 겹친다**: 시야 밖 적의 ALERT는 몸이 안 보여 통째로 투명하다
— 그래서 ⓓ(큰읏)가 **선택이 아니라 필수**고, §8-1-b의 불변식이 **그 겹침을 관리하는 자리**다.

## §10 검증 계획

**기본 다섯**
- **보는 쪽** — 적을 한 방향으로 움직인 뒤 `turn_rate`만큼만 돌았나. 🔴 뮤테이션: `turn_rate`를 ∞로 → 빨개져야 한다.
- **부채꼴** — 같은 거리·다른 각도 두 지점에서 감지가 갈리나. 🔴 각도 판정을 `true` 고정 → 빨개져야 한다.
- **소리** — score를 흔들면 반응하는 적 수가 달라지나(in-memory 주입 · 세61 수법).
- **기습** — 같은 damage를 PATROL 적과 CHASE 적에 넣어 결과가 갈리나.
- **배회 반경** — leash 밖으로 안 나가나(§8-3).

**🔴 리뷰가 더한 넷 (없으면 계약이 선언만 남는다)**
1. 🔴🔴 **「인지 키가 없는 몸은 정확히 옛 동작이다」**(§7-b) — 주입 몸으로 *"부채꼴 밖에서도 온다 · 배회 안 한다 · 즉시 온다"*를 잰다. **하위호환은 이 파일이 세 번 명문화하고도 그물은 한 번도 안 세운 축이다.**
2. 🔴 **보스 셋에 인지 키가 없다** — 정적 스캔. §8-2를 강제하는 **유일하게 실행 가능한 형태**(코드가 못 가른다).
3. 🔴 **소리 반경이 `quality_t`를 지난다** — 맨 진(0.70)↔퍼펙트(1.0) 반경비가 **1.43배보다 크다**. C4를 되돌리면 정확히 1.43이 나와 빨개진다(= 뮤테이션 검출자).
4. **`_home`이 스폰 자리다** — `add_child` **뒤**에 좌표를 준 몸으로 잰다(M6). 이 리포 그물 관용구가 그쪽이라 실전이 곧 재현이다.
5. **`sight_range > vision_near_radius`인 종은 `STALKERS`에 있다** — §8-1-b의 불변식(사용자 확정 ⓖ의 그물판).

**뮤테이션**
- `alert_sec` → 0 : 「한 박자」 검사가 빨개져야 한다.
- `ambush_mult` → 1.0 : 기습 검사**만** 빨개져야 한다(격리 확인).
- 🔴 `_contact`를 CHASE 안으로 옮긴다 : **C2의 검출자.** 잡몹 접촉 채널엔 지금 그물이 0개라 **1번 그물이 이것도 잡아야 한다.**

**🔴 헤드리스가 못 재는 것**(= F5·MCP): 배회가 「살아있다」로 읽히나 · **큰읏과 짖음이 구별되나** ·
경계 한 박자가 「피할 수 있다」로 느껴지나 · 부채꼴 밖으로 도는 게 **가능하되 쉽지 않나** · 늑대 다섯이 겹쳐 보이나.
