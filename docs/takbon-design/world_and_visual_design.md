## 1. 세계관 — 한 줄

> **망한 마법 마을 터에, 마지막까지 살아남은 마법은 문 하나뿐이다. 그 문이 나를 불렀다.**

### 골격 (사용자 확정)

| | 무엇 |
|---|---|
| **여기** | 옛 마법 마을이 있던 자리. 전부 무너지고 잔해만 남았다. |
| **문** | 이 땅에 유일하게 남은 **살아있는 마법**. 숲으로 통하는 유일한 길이자, 나에게 말을 거는 유일한 존재. |
| **서고** | 🔴 **문과 함께 살아남은 두 번째 것.** 비문이 남아 있어 내가 「떠서 쓸」 수 있는 근거다(§1-말 참조 — 기술 제약에서 왔지만 세계관이 받아들였다). |
| **나** | 문이 소환한 자. 🔴 **이 세계의 마법을 배운 적이 없다.** |
| **왜 망했나** | 마을의 마법진이 깨지며 **마법이 땅으로 새어 나갔다.** 숲과 짐승이 그것을 먹고 뒤틀렸다. |
| **숲** | 새어 나간 마법이 고인 곳 = 마을을 삼킨 폐허. |
| **적** | **마법을 삼킨 자연.** 뱃속에 마을의 조각이 들어 있다. |
| **하는 일** | 문 너머에서 조각을 **떠 와**, 마을을 한 채씩 되돌린다. |
| **끝** | 새어 나간 마법을 전부 거둬 제자리에 놓으면 **마을이 완성되고 게임이 끝난다.** |

### 🔴 이 세계관이 공짜로 설명해 내는 것

이 게임은 지금까지 **메커닉에 이유가 없었다.** 세계관이 정해지자 전부 설명된다:

| 게임이 하는 일 | 지금까지의 이유 | 이 세계관에서의 이유 |
|---|---|---|
| **주운 조각을 이어 붙여 마법을 만든다** | 없음 (그냥 그런 게임) | 🔴 **나는 여기 사람이 아니라 배운 적이 없다.** 완성된 마법을 못 쓰고, 남이 새겨놓은 것을 **떠서(탁본)** 흉내 낼 뿐이다 |
| **제목이 「탁본」이다** | 근거 소실(세83 그리기 폐지) | 🔴 **회복된다** — 「떠 온다」는 이제 그리기가 아니라 **파밍·조립 그 자체**를 가리킨다 |
| 적이 재료·두루마리를 떨군다 | 드롭표 | 뱃속에 마을 조각이 들어 있었다 |
| 적이 죽으면 마나로 터진다 (`enemy_feel_design`) | 연출 취향 | 🔴 **삼킨 마법이 돌아오는 것**이다 |
| 숲에 부품이 떨어져 있다 | 없음 | 마을이 삼켜진 자리다 |
| 마을에 공방·정제대가 있다 | 편의 시설 | 되돌려 놓은 마을의 일부다 |
| 죽으면 가방이 증발한다 | 익스트랙션 장르 관습 | 거둔 마법이 다시 숲으로 흩어진다 |
| 문(`ForestGate`)에서만 나갈 수 있다 | 씬 전환 지점 | **살아있는 마법이 그것 하나뿐이다** |

### 「탁본」의 재정의 (제목 회복)

- **옛 뜻** (세16~83): 조립한 마법진을 **손으로 따라 그어** 떠낸다. → **폐지됨**(`balance.skip_drawing`).
- **새 뜻** (이 문서): 🔴 **나는 이 세계의 마법을 모른다. 남이 새겨놓은 것을 떠서 쓴다.**
  숲에서 줍는 고리·룬·진 = 폐허의 비문에서 **떠 온 것**. 조립 = 뜬 것을 잇는 것.

> ⚠ 이 재정의는 **손 긋기 축을 죽이지 않는다.** `skip_drawing`을 false로 되돌리면 「직접 떠낸다」가 문자 그대로 부활하고, 세계관은 그 모드에서 **더 잘 맞는다**. 스위치의 양쪽 모두를 설명하는 서술이다.

### 화자 = 문 (NPC 재배치)

- 지금 퀘스트를 주는 존재는 `Npc`(길잡이)다. 🔴 **망한 마을에 사람이 서 있는 건 세계관과 안 맞는다.**
- → **문이 화자를 맡는다.** 나를 부른 존재가 나에게 시키는 것이 가장 자연스럽다.
- → **주민은 「진행도」로 바꾼다.** 초반 마을엔 아무도 없고, **되살린 건물마다 사람이 하나씩 돌아온다.**
- 🔴 **화자를 옮기면 같이 닿는 것**(리뷰 실측): `base.gd` `_ready`의 온보딩 sticky 줄
  *"길잡이에게 [E]로 말을 걸어라…"*가 **거짓 지시**가 된다 — 「안내문에 없는 조작을 적지 마라」는 하드 계약이고
  `test_ui_text_auto`의 say 수명 절이 sticky를 잰다. `_on_npc_talk`·`_refresh_npc_mark`의 연결 5개도 함께 정리 대상.

> ⚠ 대사 본문·주민 배치는 §2의 「별도 설계」로 넘긴다. 여기선 **방향과 닿는 자리**만 확정한다.

### 🔴 서고는 처음부터 온전하다 (기술 제약 → 세계관이 받아들임)

리뷰 실측: **`Desk`(책상)와 `bld_library.png`(서고)는 같은 물건**이고, 첫 퀘스트 `q00_first_draw`가 책상에서 정산된다. `base.gd`가 `_desk.interacted`를 **조건 없이** 연결하며 책상엔 codex 게이트가 애초에 없다(브리지 목록이 `refine`·`craft`·`shop` **셋뿐**인 게 그 증거다).

→ **서고를 잔해로 만들면 게임이 시작 즉시 막힌다. 협상 대상이 아니다.**
→ 🟢 세계관은 이걸 **받아들였다**: 문과 서고, **둘만 살아남았다.** 「비문이 남은 서고」가 있어야 「떠서 쓴다」가 성립하므로 §1의 재정의를 오히려 뒷받침한다.

## 2. 마을 성장 — 원칙만 (상세는 별도 설계)

### 🔴 방아쇠 = 퀘스트를 깨면 저절로 선다

사용자 확정. **창고에서 재료를 빼는 별도 결제 단계가 없다.**

🔴🔴 **세66과 갈라지는 지점을 못 박는다.** 세66에 사용자는 *"건설 안 할 거고 해독대도 과함"*이라며 이 방향을 **뒤집었다.** 지금 요청이 그때 거부한 것과 **구조적으로 다른 이유**:

| | 세37 (세66에 거부됨) | 이 문서 |
|---|---|---|
| 방아쇠 | 재료를 모아 자리에서 [E]로 **산다** | 퀘스트를 깨면 **선다** |
| 플레이어가 하는 일 | 재료 모으기 → **결제** | 이야기 밀기 |
| 성격 | **노동** | **보상** |
| 실패 모드 | "재료가 모자라 못 지음" 벽 | 없음 |

→ 🔴 **"모아서 사는 단계"를 절대 되살리지 마라.** 그게 세66이 거부한 것이다.
   `balance_data.gd`에 자리만 표시된 `station_build_costs`는 **되살리지 않는다**(표시는 유지 — 왜 비었는지가 거기 적혀 있다).

### 🔴 무엇이 살아 있고 무엇이 없나 (리뷰 실측 — 초고를 뒤집은 자리)

| 부품 | 상태 |
|---|---|
| 저장·퀘스트·해금 사슬 | ✅ **공짜로 따라온다** — `station_*`은 codex라 `GameState._on_codex_unlocked`·`SaveManager`·`Audio._on_unlock`이 **범용 경로로** 이미 처리한다 |
| 퀘스트 → codex 해금 경로 | ✅ **이미 있다: `QuestDef.reward_unlock`.** `GameState._complete_quest`가 id를 안 가리고 emit한다 → 🔴 **core 스키마 변경 0 · 시그널 신설 0** |
| `q03_build_refine` · `q04_build_craft` | ✅ `data/quests/`에 실재 · `test_quests_auto`가 **진짜로** 잰다(자명 통과 아님) |
| 🔴 **codex → 잔해/온전 전환 + 상호작용 게이트** | ❌ **0곳. 100% 신규 작성이다.** `_station_interact`·`_refresh_station`·`NOT_BUILT_MOD`는 세66에 **전부 삭제**됐고, `base.gd`는 `_refine_zone`/`_craft_zone`/`_shop_zone`을 `_ready`에서 **무조건** 연결한다 |
| 인터림 브리지 | ⚠ **생산자는 여기 한 곳뿐**(확인됨). 하지만 **비운다고 텅 빈 마을이 오지 않는다** — 실제로 일어나는 일은 ⓐ q03·q04가 영영 정산 불가 ⓑ NPC 머리 위 [!]가 영구 점등, **딱 둘이다** |
| `_station_interact` (재료 결제 [E]) | ⚫ 은퇴 — **되살리지 않는다** |
| `station_build_costs` (balance) | ⚫ 세85에 걷힘 · 자리만 주석 표시 — **되살리지 않는다** |

→ 🔴 **브리지 제거는 착수 지점이 아니라, 신규 코드가 준비된 뒤 마지막에 하는 일이다**(§8).

### 🔴 별도 설계로 넘기는 것

이 문서는 **원칙까지만** 확정한다. 아래는 다음 설계 사이클의 몫이다:

- 건물 목록과 순서 (몇 채를 · 어떤 순서로 · 무엇을 깨면)
- 문의 대사 본문·인격
- 주민 복귀 연출

⚠ **q03·q04의 거취는 미룰 수 없다** — §8 참조. 미루면 그 사이 빌드가 **깨진 온보딩**을 갖는다.

## 3. 화면 비주얼 — 단일 규칙

> 🔴 **마법 = 빛. 빛은 있어야 할 곳(마을)에 없고, 없어야 할 곳(숲·짐승)에 있다.**

이 한 줄이 화면 전체를 정리한다. **모든 비주얼 판단은 이 규칙으로 내린다.**

| 무엇 | 어떻게 보이나 | 왜 |
|---|---|---|
| **마을(초기)** | 🔴 **채도가 빠진 회보라 · 밝기는 유지** | 빛이 빠져나간 곳 |
| **문** | 첫 화면에서 **유일하게 색과 빛을 가진 것** | 마지막까지 살아남은 마법 |
| **되살아난 건물** | 색이 돌아오고 **발밑에 빛 웅덩이** | 마법이 제자리로 |
| **숲** | 과포화 · 있어선 안 될 곳이 반짝인다 | 새어 나간 빛이 고였다 |
| **적** | 🔴 **몸 어딘가에 마법 빛이 박혀 있다**(공통 시각 언어) | 삼켰다 |
| **적의 죽음** | 그 빛이 터져 나온다 | 돌려준다 (`enemy_feel_design`의 「마나로 터짐」) |
| **플레이어** | 빛을 **안 가졌다** — 지팡이만 빛난다 | 나는 이 세계 마법을 못 쓴다. 빌려 쓸 뿐 |

### 🔴 폐허를 어떻게 그리나 — 색만 빼고 밝기는 유지

사용자 확정. **어두운 폐허를 각하한다.**

- 세73 결정(*"밝게 유지 + 빛 웅덩이만. 어두운 던전·그림자 각하"*)과 **안 싸운다.**
- 게임 초반 몇 시간이 어둡지 않다 — 첫인상이 침침해지지 않는다.
- 🔴 **진행도가 화면에 바로 보인다** — 색이 돌아온 면적 = 얼마나 왔나.

### 🔴 구현 수단 — 셰이더 0개 (실측 확인)

프로젝트 전체에 셰이더는 `src/actors/hit_flash.gdshader` **한 장**이고, 그대로 둔다.

| 필요한 것 | 수단 | 비용 |
|---|---|---|
| 🔴 **화면 전체 색조 = 진행도** (사용자 확정) | **`base.tscn`에 이미 있는 `Dusk`(CanvasModulate)** 를 해금된 `station_*` 수에 따라 **보라 → 중립으로 lerp** | 노드 0 · 셰이더 0 · 아트 0 |
| 폐허 건물의 낮은 채도 | 🔴 **아트로 처리** — 잔해를 저채도 회보라로 그린다(§5) | 어차피 새로 그릴 것 |
| 되살아난 뒤 색 | 온전한 건물 스프라이트 = **지금 있는 것 그대로** | 0 |
| 국소적 색 회복 | 건물마다 `PointLight2D` 빛 웅덩이 하나 — `lamp.tscn` 선례 그대로 | 노드 1개 |

- ⚠ **`CanvasModulate`는 채도를 못 뺀다**(곱하기뿐). 그래서 「전역 채도 필터」 길은 애초에 막혀 있다.
  🟢 **그러나 「보라 쪽으로 미는」 것은 된다** — 그리고 `Dusk`는 **이미 `Color(0.9, 0.88, 0.96)`으로 옅은 보랏빛을 얹고 있다.** 손잡이가 이미 꽂혀 있었다.
- 🔴 **밝기 유지 원칙 = 각 성분을 0.9 이상으로 둔다.** 그 안에서만 색조를 민다.
- ⚠ 바닥 타일 아트(시든 잔디 변형)는 **이번에 안 만든다** — `_grass_variant()` 훅이 있어 나중에 얹을 수 있다. **지금은 YAGNI.**

### 팔레트 — 제안 (승인 대기)

`ART_SPEC.md`가 세18 이래 *"Apollo 46 하드 제한은 소프트 음영과 충돌 → 완화 검토(미확정)"*로 **8세션째 미결**이다. 이 문서에서 닫자.

**제안: Apollo 46을 「기준색」으로 유지하되, 음영 중간톤은 자유롭게 뽑는다.**
- 물체의 **고유색**(로브·잎·돌·불꽃)은 Apollo에서 고른다 → 화면 통일감이 유지된다
- 그 색의 **명암 단계**는 Apollo 밖이어도 된다 → 소프트 음영이 가능해진다
- 🔴 **폐허 램프는 §5의 회보라 대역을 정본으로** → 잔해 5장이 한 벌로 보인다

## 4. 첫 화면 (게임을 켜면 보이는 것)

```
   회보라의 조용한 폐허, 밝은 낮
```

### 🔴 문의 맥동 = 노드 타입을 안 바꾼다

`forest_gate.tscn`의 `Sprite`는 **`Sprite2D`**다. 프레임 애니를 넣으려면 `AnimatedSprite2D`로 **타입을 바꿔야** 하는데, 더 싸고 어휘도 하나로 유지되는 길이 있다:

> **`PointLight2D` 자식 하나**를 달고(`lamp.tscn`이 쓰는 `light_soft` 텍스처) `energy`를 트윈으로 맥동시킨다.
> 스프라이트는 **정지 1장**, 프레임 0장, 노드 타입 변경 0. §3의 *"건물마다 빛 웅덩이 하나"* 규칙과 **같은 물건**이다.

### 🔴 잔해를 그리는 규칙 (relight 함정 — 리뷰 실측)

`tools/relight_sprites.lua`의 `shade()` 첫머리에 이 분기가 있다:

```lua
if s<0.06 then h=250 s=0.14 end
```

**순수 회색조는 채도 0이라 전 픽셀이 여기 걸린다.** 게다가 `shade()`는 `if step==0 then return r,g,b end`로 중간 밴드를 건너뛰므로, 결과는 **「중간톤은 무채색, 명암부만 청보라」인 두 얼굴 스프라이트**가 된다.

> 🔴 **잔해를 순수 회색조로 그리지 마라. 채도 s ≈ 0.10~0.18의 저채도 회보라 램프로 그려라.**
> 그 대역 안에서 그리면 필터가 램프를 **뒤집지 않고 얹기만** 한다. (h=250 근처는 우리가 원하는 회보라와 **우연히 같다** — 피할 게 아니라 활용한다.)

- 🔴 **relight 강도는 `doPng(경로, 0.5)`다** — `1.0`이 아니다. 적용 목록이 건물을 **MILD(0.5)** 로 분류한다(*"건물은 이미 입체적이라 0.5"*). 1.0으로 돌리면 잔해만 음영이 두 배라 **다른 세대 아트로 보인다.**
- ⚠ 새 PNG는 **반드시 relight를 거친다** — 안 거치면 나머지 45장과 입체감이 안 맞는다(`ART_SPEC.md` 세69 절).
- ⚠ 잔해 프롭의 `Body`는 기존 스테이션과 같은 **`collision_layer = 1`(world)** 을 물려받는다. §4 제약 ⓑ와 함께 지킬 것.

### 적의 「삼킨 빛」

- 🔴 **새 스프라이트를 다시 그리지 않는다** — `enemy_feel_design.md`가 이미 **적 48px 재작**을 설계했다. 그 작업에 **"몸 어딘가에 마법 빛 한 점"**을 규격으로 얹는다.
- 🔴 **보스 2종엔 별도 지시가 필요하다** — `enemy_feel_design.md`가 `gale`·`snake_head`를 *"이미 64px이라 재작 대상 아님"*으로 **명시 제외**했다. 「전 적 공통 시각 언어」가 그 둘에 안 닿으므로, 보스는 **기존 시트에 빛 점만 덧그리는 별도 작업**이다.
- ⚠ 빛 점을 **거의 흰색으로 찍으면** 위 `s<0.06` 분기에 걸려 청보라로 강제 변환된다. **룬 색(불=적 등)에 맞추려면 반드시 채도를 실어 찍어라.**
