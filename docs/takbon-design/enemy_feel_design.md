> 🔗 짝 문서: `hunt_loop_design.md`(사냥 흐름) — 독립적으로 착지 가능하다(리뷰 후 의존 해소, §1 각주)

## 0. 왜

사용자 진술 (세87):
> *"죽었을때 마나로 돌아가는 연출로 모든 몬스터를 그렇게 처리할까 하고, 몬스터 크기를 좀더 키우고 싶고, 몬스터가 공격할때 눈에 뛰게 공격했으면 좋겟음 피하는 맛이 있게"*
> *"공격예상 범위가 나오는게 좋을듯"*
> *"애니메이션도 몬스터마다 만들어주는데 죽는것은 마나로 돌아가는 형식의 폭발하는 걸로 해줘"*

`hunt_loop_design.md` §0이 **「터지는 게 밋밋하다」의 나머지 절반**으로 미뤄 둔 것이 이것이다.

**실측한 현재 상태 — 셋 다 「기계는 있는데 안 쓰거나, 구조가 막고 있다」:**

| 요청 | 현재 | 진짜 원인 |
|---|---|---|
| 죽으면 마나로 | `_spawn_death_puff()` Polygon2D 링 | 죽음의 시각 언어가 **적마다 없고 링 하나로 통일**돼 있는데, 그 링이 「마나로 돌아간다」를 안 말한다 |
| 몸집 키우기 | 적 스프라이트가 전부 **32px** | 플레이어는 **48px**. ART_SPEC도 48px — **적만 규격 미달**이다. `params.size`로 키운 beetle 1.5·slime_elite 1.9는 **32px를 확대**한 것이라 도트가 뭉갠다 |
| 공격 눈에 띄게 | 텔레그래프 기계는 있다(`_set_telegraph`) | 🔴 **쓰는 적이 hound·snake·gale 3종뿐**이고 잡몹 4종은 **접촉 피해**다 |

### 🔴 「피하는 맛」이 없는 구조적 이유 (실측)

```gdscript
func _contact(player: Node2D, dist: float) -> void:
    if dist > _param("attack_range", 18.0) or _cool > 0.0:
        return
    _cool = _param("attack_cooldown", 0.9)
    var dodging: bool = player.has_method(&"is_rolling") and bool(player.call(&"is_rolling"))
    if not dodging:
        GameState.damage_player(_param("contact_damage", 4.0), global_position)
```
`forest_enemy.gd:546`

- **예고가 0이다** — 사거리 안 + 쿨 끝 = **그 프레임에 즉시 피해**
- **위치로 피할 수가 없다** — 유일한 회피가 구르기 무적(`is_rolling`)
- 🔴 **그런데 구르기는 지금 꺼져 있다** — `player.gd:25`의 `ROLL_ENABLED` 게이트(기계는 전부 살아 있고 입력만 막혀 있다). ⇒ **플레이어에게 회피 수단이 0이다**(리뷰 실측)
- **때리는 애니메이션 자체가 없다** — `_setup_frames`가 굽는 건 `idle`·`hurt` 둘뿐

즉 잡몹은 *"붙으면 아프다"*이지 *"공격한다"*가 아니다.

## 1. 확정된 결정 (사용자 승인 완료)

| # | 결정 | 비고 |
|---|---|---|
| ① | **적 스프라이트를 48px급으로 다시 그린다** | scale로 늘이지 않는다. 재작 김에 **공격 프레임도 같이** |
| ② | 🔴 **죽음 = 마나 폭발로 전 몬스터 통일 — 순수 연출** | 몸이 터져 사라진다 → **죽음 애니를 적마다 안 그린다**(아트 6장 절약) |
| ③ | **적마다 분명한 공격 모션** | 「멈춤 → 예고 → 가격 → 빈틈」. 몸통박치기는 남긴다 |
| ④ | **공격 예상 범위를 화면에 표시** | 예고 동안 바닥에 닿을 범위가 그려진다 |
| ⑤ | **연습장에 죽는 표적을 둔다** | 새 손맛을 **마을에서 확인**할 수 있게(세52 「연습장 파리티」 원칙) |

### 🔴 철회된 결정 — 「처치가 주 마나 회복원」

대화 중반에 *"처치가 주 회복원"*으로 정했다가, 리뷰가 **보스 처치 직후 포탈을 타면 날아오던 파편이 씬 전환으로 증발한다**(+40 손실)는 문제를 드러내자 사용자가 ***"마나는 포션으로 채우거나 자동 회복으로 하자"*** 로 방향을 바꿨다.

**확정: 마나 회복은 지금 그대로**(`mana_regen_per_sec = 2.0`)**. 처치는 마나를 주지 않는다. 마나 폭발은 순수 연출이다.**
**포션은 이번 범위 밖**(§10).

✅ **이 전환으로 리뷰 지적 넷이 통째로 해소됐다**: `balance` vs `params` 배치 논쟁 · `in_expedition` 마을/원정 분기(및 「두 몸 그물」 부담) · 파편 도착 회복의 씬 전환 증발 · `hunt_loop` 착지 뒤로 미루는 게이트. **이 설계는 이제 `hunt_loop`과 독립적으로 착지할 수 있다.**

## 2. A. 몸집 — 48px급 재작

### A-1. 🔴 하드 계약: 프레임은 정사각형이다

`_bake_strip`(`forest_enemy.gd:194`):
```gdscript
var side := tex.get_height()                 # 프레임 한 변 = 시트 높이
var count := maxi(1, tex.get_width() / side) # 프레임 수 = 폭 ÷ 높이
at.region = Rect2(i * side, 0, side, side)
```
→ **가로로 긴 프레임(64×48 같은 것)은 만들 수 없다.** 시트 = **정사각 프레임을 가로로 이어붙인 스트립.**

### A-2. 새 규격

**원칙: 덩치는 `params.size`(확대)가 아니라 캔버스 크기로 낸다.** 도트 밀도가 일정해진다.

| 적 | 현재 시트 | 현재 프레임 | **새 프레임** | **새 시트** | `params.size` |
|---|---|---|---|---|---|
| slime | 128×32 | 32² ×4 | **48²** | 192×48 | 1.0 (변화 없음) |
| mist | 128×32 | 32² ×4 | **48²** | 192×48 | 1.0 (변화 없음) |
| hound | 256×32 | 32² ×8 | **64²** | 512×64 | 1.15 → **1.0** |
| vine | 192×32 | 32² ×6 | **64²** | 384×64 | 1.35 → **1.0** |
| beetle | 128×32 | 32² ×4 | **64²** | 256×64 | 1.5 → **1.0** |
| slime_elite | 128×32 | 32² ×4 | **96²** | 384×96 | 1.9 → **1.0** |

🔴 **프레임 수는 현재와 같게 유지한다** — 애니 속도가 `6.0` 하드 고정(`_bake_strip:201`)이라 프레임 수가 곧 길이다.
⚠ 보스 2종(`gale` 384×64 · `snake_head` 256×64)은 **이미 64px**이라 재작 대상이 아니다.

### 🔴🔴 A-3. 히트박스는 캔버스를 안 따라온다 — **데이터로 내려야 한다** (리뷰 치명①)

**초안이 *"의도적으로 커진다"*고 적은 것은 정반대였다.** 실측:

- `forest_enemy.tscn:5` — `CircleShape2D radius = 9.0` **전 적 공용 단 하나**
- `forest_enemy.gd:166` — `scale = Vector2(s, s)`가 **루트 scale**이라 `CollisionShape2D`도 같이 스케일된다(`:154` 주석: *"덩치가 곧 히트박스"*)
- ⇒ **히트박스 반경 = `9.0 × params.size`. 캔버스 크기는 1픽셀도 기여하지 않는다.**

| 적 | 현 히트박스 r | 새 r (size 1.0) | **변화** | 겉보기 변화 |
|---|---|---|---|---|
| slime · mist | 9.0 | 9.0 | 0% | +50% |
| hound | 10.35 | 9.0 | **−13%** | +74% |
| vine | 12.15 | 9.0 | **−26%** | +48% |
| beetle | 13.5 | 9.0 | **−33%** | +33% |
| slime_elite | 17.1 | 9.0 | **−47%** | +58% |

지금은 히트박스 지름/몸 너비 = `18/32 = 0.56`이 **덩치와 무관하게 일정**하다(둘 다 같은 scale을 탄다). 캔버스로 덩치를 내면 그 비가 slime_elite에서 **0.19**로 무너진다 — **96px 우두머리인데 맞는 몸은 지름 18px** = *"몸통을 뚫고 지나간다"*.

🔴 **조용히 깨진다** — 히트박스 반경 그물이 **0곳**이다. `test_ring_spell_auto`·`test_chapter_auto`는 적을 탄 정면에 두고 쏘므로 반경이 반토막나도 전부 초록이다.

**대책:**
1. **`params.hitbox_radius`** 신설(없으면 프레임 한 변에서 파생 — `_attach_shadow`의 `side * FRAC` 관용구)
2. 🔴 **`CollisionShape2D.shape`를 세울 때 반드시 `.duplicate()`** — `pillar.gd:51`이 *"형상 리소스는 씬 인스턴스들이 공유하는 물건"*이라고 **이미 밟은 함정**을 적어 뒀다. 안 하면 **마지막 스폰의 반경이 전원에게 적용**된다(에러 없이)
3. 🔴 **`attack_range`도 같이 올려라** — 월드 px라 size와 무관했다. `slime_elite`의 `attack_range 26`은 60.8px 몸에선 "몸에 닿으면"이었지만 **96px 몸에선 플레이어가 몸 속으로 26px 파고들어야** 발동한다
4. 그물: 「히트박스 반경 == 프레임 한 변 × k」를 **6종 개별로** 잰다(합계 말고 — 세85 교훈)

✅ **자동으로 따라오는 것**(리뷰 확인): `_attach_shadow`(idle 첫 프레임 한 변에서 파생) · `_pop()` 팝 scale(`_visual`에만 걸린다).
⚠ **넉백은 상대적으로 약해 보인다** — `KNOCKBACK_IMPULSE 140`은 월드 속도라 덩치와 무관. 몸이 커지면 「밀린 거리/몸 크기」가 줄어든다. F5 튜닝 목록(§9).

## 3. B. 죽음 — 몸이 마나로 **터진다** (순수 연출)

**기존 `_spawn_death_puff()`(Polygon2D 링)을 교체한다.**

```
적이 죽는다
  ① 몸이 그 자리에서 푸른 마나로 터진다      ← 스프라이트가 폭발과 동시에 사라진다
  ② 마나 파편 6~8개가 사방으로 튄다
  ③ 잠깐 멈췄다가 플레이어 쪽으로 빨려온다   ← 0.25~0.35s (짧게)
  ④ 도착하며 사라진다                        ← 🔴 마나 수치는 안 준다(연출만)
```

**규격:**
- **색** = 마나 푸른색 통일. 🔴 룬 속성별로 가르지 않는다 — 색을 가르면 *"무슨 마나인가"*라는 없는 축이 생긴다
- **크기·파편 수 ∝ 덩치** — 🔴 **파생원은 「프레임 한 변」 하나다**(48/64/96). ⚠ 루트 scale은 §2-A-2에서 전부 1.0이 되므로 **정보가 없다**(초안이 둘 다 든 것은 모순이었다 — 리뷰 지적)
- **보스**는 더 크고 파편도 많다
- 🔴 **z_index는 50을 유지한다** — `vfx.gd:48`이 `VFX_Z := 55`의 근거로 *"death_puff(50) 위로"*를 든다. 바꾸면 그 주석이 거짓이 된다(감사 T4). 못 지키면 `vfx.gd`·`dust.gd` 인용을 **같은 커밋에** 갱신

✅ **파편 소유자 문제는 이미 해결돼 있다**(리뷰 확인) — `_spawn_loose`·`_spawn_death_puff`·`_fire_gale_shot` 셋 다 `get_tree().current_scene`에 붙이는 관용구가 확립돼 있고, `:499`가 *"적이 죽어도 탄은 남는다: 유언 탄"*이라고 이름까지 붙여 뒀다. **`queue_free()` 타이밍은 새로 발명할 게 없다.**
✅ **교체의 코드 의존 0곳** — `_spawn_death_puff`를 밖에서 부르는 곳이 없다(호출은 `_die` 한 줄). 참조는 전부 주석 8곳.
✅ **절차적 VFX = 도형 금지 규칙의 명시적 예외** → **새 아트 0 · 새 씬 0.**

### 🔴 B-2. 그래서 죽음 애니메이션은 몬스터마다 안 그린다

| | 죽음을 적마다 그리면 | **마나 폭발 통일 (확정)** |
|---|---|---|
| 아트 | death 시트 **6장 추가** | **0장** |
| 새 적을 넣을 때 | death 시트를 또 그려야 한다 | **공짜로 따라온다** |
| 언어 | 적마다 다르게 죽는다 | **"적 = 마나 덩어리"가 일관되게 읽힌다** |

⚠ **`hurt`는 여전히 적마다 필요하다**(맞는 반응은 살아 있는 몸의 것) — §6-2 선택 항목.

## 4. C. 공격 — 「멈춤 → 예고 → 가격 → 빈틈」

### C-1. 구조

`hound`만 갖고 있는 4단계 상태기계(`ChargeState.APPROACH/WINDUP/DASH/RECOVER`)를 **잡몹 전체의 기본 규약으로 올린다.**

```
접근 ──(사거리 안)──▶ 예고(windup) ──▶ 가격(strike) ──▶ 빈틈(recover) ──▶ 접근
                      │멈춘다         │피해 판정       │느리다·무해
                      │붉게 달아오름  │               │= 반격 창
                      │범위 표시(§5)  │               │
                      ▲ 여기서 걸어 피하면 흘린다
```

🔴 **빈틈(recover)은 「피한 보상」이다** — 없으면 예고는 그냥 딜레이다.
🔴 **구르기가 꺼져 있으므로(결정 ⑥) 「걸어서 피하기」가 유일한 회피**다. → **밸런스의 전부가 관계식 하나에 걸린다**(값이 아니라 관계로 잰다, 세79 교훈):
> **`플레이어 이동속도 × windup_sec ≥ 범위 반경 + 여유`**
이게 깨지면 예고가 **피할 수 없는 딜레이**가 된다.

### C-2. 적별 배치

| 적 | 공격 | 예고 | 범위(§5) | 비고 |
|---|---|---|---|---|
| **slime** | 몸을 부풀렸다 짓누른다 | 0.45s | 자기 발밑 **원** | 느려서 걸어 피할 수 있다 |
| **beetle** | 껍질을 세워 들이받는다 | 0.55s | 앞쪽 짧은 **직선** | 덩치가 커 예고가 잘 보인다 |
| **vine** | 덩굴을 뻗는다 | 0.5s | 자기 중심 **긴 원** | 고정 포탑이라 사거리가 길다 |
| **mist** | 안개를 내뿜는다 | 0.4s | 자기 앞 **부채꼴** | 거리 유지형 원거리 견제 |
| **hound** | *(기존 돌진 유지)* | `windup_sec` 0.5 | 돌진 **경로 직선** | 이미 4단계 — 범위 표시만 |
| gale·snake | *(기존 유지)* | 기존 | 돌풍 **부채꼴** · 러시 **경로** | 범위 표시만 |

⚠ **몸통박치기(접촉 피해)를 전부 없애지 않는다** — 「닿으면 아픈」 압박은 남긴다. 다만 **접촉 피해를 낮추고 공격 피해를 높여** 역할을 가른다. 수치는 F5.
🔴 **slime·vine의 범위 반경은 `test_status_auto`의 스텁 거리(120·150px)를 보고 정해라** — §9의 함정 참조.

### C-3. 공격 애니메이션 — 🔴 `hurt` 선례는 **절반만** 맞다 (리뷰 중요)

**굽기는 선례 그대로** — `params.attack_sprite`를 `_setup_frames`에 갈래 추가(스키마 변경 아님).
⚠ **`hurt_sprite`는 경로가 없으면 `push_warning`을 내지만(`:186-188`) `attack_sprite`는 내면 안 된다** — 없는 적(gale·snake)이 정상이다.

**그런데 재생·복귀는 선례가 안 맞는다:**

🔴 **문제 ① — 「예고 동안 [1] 프레임에 머문다」가 불가능하다.**
`_bake_strip`이 `set_animation_speed(anim, 6.0)`을 **하드 고정**하고 프레임별 지속시간이 없다. `play(&"attack")` 한 번이면 3프레임이 **정확히 0.5초**에 흘러간다. 예고는 적마다 0.40~0.55s이고 **`.tres`로 조이는 값**이라, 조이는 순간 그림과 판정이 어긋난다(§5-D-3이 막으려는 실패의 애니메이션 판).
→ **상태기계가 `_visual.frame`을 직접 세운다**(`play` 대신 `set_frame`). 3프레임이면 이게 가장 단순하고 **「그림 = 상태」**가 되어 단일 소스 철학과 결이 같다.

🔴 **문제 ② — attack과 hurt가 `animation_finished` 한 자리를 놓고 싸운다.**
`_play_hurt`(`:894-909`)가 `animation_finished.connect(_back_to_idle, CONNECT_ONE_SHOT)`을 쓰는데 `is_connected` 가드가 있어:
- attack이 먼저 연결해 두면 **hurt가 복귀를 등록 못 해 hurt 프레임에 굳는다**
- **예고 중에 맞으면** `_play_hurt`가 예고 자세를 덮어써 **사용자가 읽어야 할 포즈가 사라진다**(붉은 텔레그래프는 셰이더라 남지만 실루엣이 죽는다 — §6-3이 강조한 바로 그 정보)

→ **「지금 무슨 애니를 보여주나」의 소유자를 하나로**(공격 상태기계 > hurt > idle 우선순위). `_back_to_idle`이 그 소유자에게 물어보고 복귀한다.

## 5. D. 공격 예상 범위 표시

### D-1. 무엇을

예고 동안 **바닥에 닿을 범위가 그려진다.** 예고가 끝나면 사라지고 그 범위로 판정한다.

| 모양 | 쓰는 적 |
|---|---|
| **원** | slime · vine |
| **직선(띠)** | beetle · hound |
| **부채꼴** | mist · gale |

**연출:** 얇은 붉은 테두리 + 반투명 채움 → **예고 동안 안쪽부터 차오른다**(남은 시간이 보인다). 다 차는 순간 = 가격.

### 🔴🔴 D-2. 어디에 붙이나 — 초안의 z 관용구가 반대였다 (리뷰 치명②)

초안: *"z=0 + `move_child` 앞쪽 관용구(`_attach_shadow`가 쓰는 그것)"* → **앞 절반(음수 z 금지)만 맞고 해법은 정반대다.**

- `_attach_shadow`의 `move_child(shadow, 0)`은 **적 자기 자식 목록** 안의 순서다 → Visual보다 앞 = 몸 아래. ✅
- **`get_tree().current_scene`에 붙이면 뒤집힌다** — `Ground`(불투명 ColorRect, z=0)가 **씬의 첫 자식**이라 `move_child(…, 0)` = Ground **앞**에 넣기 = **Ground가 통째로 덮는다**
- 그냥 `add_child`(맨 뒤)면 적·플레이어보다 나중에 그려져 **몸 위에 얹힌다**
- z = −1은 Ground 뒤로 숨는다(`shadow.gd:10` 실증)
- ⇒ **씬 레벨에 「적 아래·Ground 위」라는 자리가 지금 z 좌표계에 없다**(Ground·적·플레이어가 전부 z=0, 트리 순서만 다르다)

**확정 — 적의 자식으로 붙이고 `move_child(…, 0)`**(그림자와 같은 자리. Ground 위·Visual 아래가 공짜).

🔴 **단 `top_level = true`가 필수다.** 안 걸면 루트 scale을 상속해 **그려진 반경이 판정 반경의 배수**가 되고, 그 순간 §5-D-3(표시=판정)이 자기 자신을 배신한다. 선례 = `snake_body.gd:44-45`(*"마디는 top_level이라 루트 scale 무영향"*).

🔴 **이미 라이브에 심어져 있는 지뢰의 재발 자리다** — `_show_gust_ring`(`:518-532`)이 링을 적 자식으로 붙이면서 `top_level`을 안 건다. gale은 `size`가 없어 지금은 무해하지만, **§4-C-2가 snake(씬 scale 1.5)에 러시 경로를 얹으라고 한다** → 얹는 순간 **경로가 실제의 1.5배**가 된다. **같이 고쳐라.**

✅ **`_show_gust_ring`이 이미 이 패턴의 답이다**(리뷰) — 적 자식 + on/off 토글 + 적이 죽으면 같이 죽는다 + 지연 생성. 여기에 `top_level` + 반경 데이터화만 얹으면 된다.
⇒ 🔴 **§7의 EventBus 신규 시그널이 불필요하다.** 적 자식 소유면 **신규 시그널 0 · 새 파일 0**이고, `vfx.gd`로 옮기면 **취소·소유·수명을 새로 발명**해야 한다(`vfx.gd`의 스포너 5개는 전부 「쏘고 잊는」 1회성이라 **밖에서 취소하는 경로가 0곳**이다).

### D-3. 🔴 표시와 판정은 한 곳에서 나와야 한다

**그리는 값과 때리는 값이 갈리면 「보이는 것 ≠ 맞는 것」이 된다** — 감사 T8·T5, 그리고 세23의 *"리포트는 140 적고 130으로 때린다"*와 같은 결.

**구체안** (리뷰 제안):
1. core에 값객체 **`AttackShape`**(모양 enum · 반경 · 각도 · 길이 · 폭) + 🔴 **`contains(origin, facing, point) -> bool`** 한 함수를 **같이** 둔다. `ring_power.gd`가 리포트·발사에 같은 함수를 주는 그 구조 그대로다
2. 적의 `_shape_now()`가 **객체 하나**를 만들어 ⓐ 표시에 넘기고 ⓑ 가격 순간 `shape.contains(...)`로 판정한다. **값을 두 번 적지 않는다**
3. 🔴 **`contains`는 월드 좌표로** 받아라(표시가 적 자식이면 로컬이라 scale·rotation이 낀다 → `top_level`)

⚠ 현재 판정은 `_contact`(`:546`)와 `_resolve_gust`(`:483`) **두 곳에 흩어져** 있고 형태가 **스칼라 하나 vs `dist` 비교**뿐이라, 부채꼴·띠는 지금 구조로 표현할 수 없다.

1. **마나 포션** — 사용자 결정 *"포션으로 채우거나 자동 회복으로 하자"* 중 포션 갈래는 **이번 범위 밖**. 새 축(아이템·제작·단축키·HUD)이고, `hunt_loop`의 재료·제작 경제에 자연스럽게 얹힌다
2. **몸통박치기 피해 vs 공격 피해 비율** — 방향만 정했고 수치는 F5
3. **hurt 시트 6장** — 선택 사항(§6-2)
4. **BOLT·EARTH·GRASS 피격음 3종** — `audio.gd:139` match가 세 줄뿐이라 나머지 셋은 **무음**. 적을 손보는 김에 같이 할 수 있다
5. **`params.size`의 남은 용도** — 캔버스로 덩치를 내면 대부분 1.0이 된다. 같은 스프라이트의 대·소 변종에 쓸지 결정
6. **구르기(`ROLL_ENABLED`)** — 이번엔 안 켠다(결정 ⑥). 나중에 켜면 회피 축이 하나 늘고 예고 길이를 다시 조여야 한다
