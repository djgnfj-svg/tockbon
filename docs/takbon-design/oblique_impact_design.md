# 오블리크 탑뷰에서 마법 임팩트 표현 — 발사체 그림자 + 두 겹 착탄

> 세77 (2026-07-24) 설계. takbon-design 대화로 확정.
> 발단 = 사용자 *"마법 임팩트를 만드는데 탑뷰에서 잘 표현할 수 있나 고민중"* →
> 진짜 질문 = *"방향에 따라 날아가는 모양이 달라야 하나?"* → 시각 관점 = **약간 ¾ 오블리크**.

## 결론 (원래 질문의 답)

**발사체를 방향별로 다시 그릴 필요 없다.** 불덩이는 앞뒤 없는 에너지 덩어리라 **회전 한 방**이면
모든 방향이 읽힌다(세72 구현이 이미 `_fireball.rotation = _velocity.angle()`로 하고 있다). 방향별
아트(원소×4~8방향)는 아트 폭발만 부르고 얻는 게 없다.

오블리크에서 발사체가 붕 떠 보이는 진짜 원인은 방향이 아니라 **높이감 부재**다 — 해결은 방향별
아트가 아니라 **바닥 그림자 하나**. "다르게 보이는 것"은 방향이 아니라 **원소별 색·꼬리**로 준다.

## 원칙 검토 (탁본 기획 잣대)

- **코어 재미(그리는 것) 영향 0** — 발사 결과 연출만 손댄다. 그리기·조립·채점 무손.
- **회귀 위험 구조적 0** — 순수 렌더 오버레이. 그룹 무가입·충돌 없음·발사 계약 무변경.
- **데이터/절차 주도** — 도트 아트 신설 0. 둘 다 절차적 VFX(도형 금지 규칙의 명시적 예외:
  `shadow.gd`·`death_puff`·`vfx.gd` Line2D와 같은 "빛 이펙트"다).
- **원소 확장 대비** — 임팩트 두 겹 구조는 색·모양만 갈아끼우면 물·번개로 확장(지금은 불 하나).

## A. 발사체 바닥 그림자

**목표:** 오블리크에서 불덩이가 "지면 위에 떠서 가로지르는 중"으로 읽히게. 순수 탑뷰와 달리 ¾에선
위/아래로 갈 때 회전만으론 "바닥으로 꽂힘/솟음"처럼 애매한데, 바닥에 붙은 그림자가 이를 해소한다.

**구현 = `shadow.gd` 재활용 (신규 스크립트 0):**
- `src/spell/ring_carrier.tscn`에 `Shadow`(= `shadow.gd`) 노드를 자식으로 추가.
- 위치 `(0, +SHADOW_DROP)` — `SHADOW_DROP ≈ 8px`. 이 아래 오프셋이 **불덩이가 바닥에서 뜬 높이**를
  암시한다(오블리크 높이감의 핵심 한 방).
- `radius_px` = 불덩이 코어보다 약간 작게(≈ 9~10px). 그림자는 `FLATTEN 0.45`로 이미 타원.
- 🔴 **층위 근거 = z_index (트리 순서 아님).** `ring_carrier.tscn`의 `Fireball`은 **`z_index=2`가 명시**돼
  있어 z가 트리 순서를 이긴다(architect 리뷰 (a)). 그러니 **Shadow에 `z_index=0`(또는 1, Fireball 2 미만)을
  명시**하고 "Fireball z=2보다 낮아 밑에 깔린다"로 근거를 삼는다. 트리 순서에 기대지 마라 — 나중에 z를
  건드리면 조용히 깨진다. (shadow.gd의 "z 음수 금지"는 여기 무해: Fireball이 +2라 Shadow 0이면 충분히 아래.)

**왜 회전 걱정이 없나:** 캐리어의 `node.rotation`은 영원히 0(계약, `ring_carrier.gd` 주석). 스프라이트
회전은 `_fireball`(자식)의 로컬 회전이라 `Shadow`(형제)에 영향 0. → 그림자는 방향 무관하게 납작 유지.

**규모(`_scale`) 대응:** 불덩이는 대개 `_scale = 1.0`. 규모 진이 오면 그림자도 커지는 게 자연스럽다.
🔴 **캐리어가 `Shadow.scale`을 직접 대입하지 마라** — `shadow.gd`의 `scale = Vector2(s, s*FLATTEN)`이
**타원 눌림(FLATTEN) 단일 소스**인데, 캐리어가 scale을 대입하면 눌림이 날아가 그림자가 **원**이 된다
(architect 리뷰 (b)). 추종이 필요하면 **`shadow.gd`에 공개 세터 `set_radius(px)`를 얇게 추가**해 눌림
수학을 shadow.gd 안에 유지한다(`src/actors` 모듈 파일 = core 스키마 아님, 기존 호출자와 가산 호환).
**우선은 고정 크기로 두고, 캐리어는 Shadow.scale을 아예 안 건드린다.** per-scale 추종은 F5 후 세터로.

**손맛 const (F5로 조인다):** `SHADOW_DROP`(높이 오프셋)·그림자 `radius_px`·`SHADOW_ALPHA`(기존 0.35).

## B. 오블리크 착탄 두 겹 (`vfx.gd._on_spell_impact` 확장)

**현재:** `_spawn_pop`(납작한 속 찬 원 Polygon2D) + `_spawn_sparks`(방사 틱). 전부 평면·방사형이라
"바닥에 꽂혀 위로 터졌다"의 **높이감이 없다**.

**바꿀 것 = 두 겹으로:**

1. **바닥 데칼 (지면 파장)** — 세로로 눌린 타원(그림자의 `FLATTEN`과 같은 결)이 작게 시작해 퍼지며
   페이드. 지면에 붙은 그을음/충격파. → 신규 헬퍼 `_spawn_ground_decal(scene, pos, col)` 또는 기존
   `_spawn_ring`에 `scale.y` 눌림 인자를 얹어 재사용. **타원 = 오블리크에서 "바닥"의 신호.**

2. **솟는 플레어 (수직 불꽃)** — 세로로 길쭉한 버스트(폭<높이)가 착탄점에서 **위로 살짝 올라가며**
   (`position.y -= RISE`) 페이드. → 신규 헬퍼 `_spawn_flare(scene, pos, col)` 또는 **`_spawn_pop` 재활용**
   (속 찬 원에 비등방 scale(폭<높이)+상승 트윈을 얹으면 플레어가 된다 — 도형 신설 회피, dev 판단).
   **세로 길쭉 + 상승 = 오블리크에서 "높이"의 신호.** Polygon2D/Line2D 절차 도형(VFX 예외).
   🔴 **플레어는 `_spawn_pop`보다 가볍게**(폭 좁게·수명 짧게) — 이유는 아래 다중 착탄 계약 참조.

**층 순서(중요):** 바닥 데칼(아래) → 솟는 플레어(위). z는 기존 `IMPACT_Z=54` 계열 유지(반응 링
`VFX_Z=55` 아래). 데칼을 플레어보다 살짝 아래 z 또는 먼저 add_child.

**색:** 기존 `_rune_flash_color(rune_type)` 재사용(룬색의 lightened 파생). 새 색 테이블 0.

**🔴 다중 착탄 계약 (architect 리뷰 ② — 문서가 틀렸던 자리):**
`spell_impact`는 **착탄 지점마다** emit된다 — 발신원이 **둘**이다:
- `ring_carrier.gd:204` — 캐리어 몸통 착탄 (1회)
- `projectile.gd:361` — **발산(RADIATE)·관통 탄이 뚫는 적마다** (`_deal_damage`, 최대 6~8회)

즉 발산 진 한 방이면 `_on_spell_impact`가 **1(캐리어) + N(탄)회** 불린다(`test_spell_vfx_auto [5]`가
*"발산 진 → spell_impact ≥ 2"*로 못 박음). 지금 팝도 이미 N번 터지지만, **더 무거운 연출(솟는 플레어)로
바꾸면 N개 플레어가 동시에 솟아 "도배"로 읽힐 위험**이 생긴다. → **플레어를 가볍게**(폭 좁게·수명 짧게)
잡고, 🔴 **검증은 발산 진(다중 탄)으로 F5** — 빈 진(단일 착탄)만 보면 이 부담을 못 본다.

**보존 계약 (건드리지 않는다):**
- 반응 버스트(`reaction_burst`, z55, 실반경 외곽선)와 착탄(z54, 작은 팝)의 **시각 분리** 원칙 유지
  (형태·크기·수명·z가 달라 "박혔다 → 퍼졌다"로 읽힘, 세59 §2-D). 두 겹 내부 순서는 데칼(아래)→플레어(위)를
  z 명시(데칼 53/플레어 54)나 add_child 순서로.
- `spell_impact` 발신원 무변경 — vfx가 **받는 연출만** 바꾼다.
- `test_spell_vfx_auto`는 vfx의 `spell_impact` 연결과 emit 수만 검증 → 시각 변경엔 안 깨짐.
  (검증 = 헤드리스 스위트 그린 + SCRIPT ERROR 0 + **발산 진으로 F5 실게임 겉보기** — 손맛·도배는 헤드리스가 못 잡음.)

**손맛 const (F5):** 데칼 `FLATTEN`·최종 반경·수명 / 플레어 폭·높이·`RISE` 상승량·수명.

## 안 하는 것 (YAGNI)

- 발사체 방향별 스프라이트 아트 ❌ (회전이 답 — 이 설계의 결론).
- 발사체 수직 이동 시 스프라이트 세로 스쿼시 ❌ (그림자가 높이감을 전담).
- 원소별 임팩트 분기(물·번개 전용 플레어) ❌ (지금 불 하나. 구조만 색/모양 교체 가능하게 남긴다).
- 그림자 per-scale 정밀 추종은 규모 진이 드물어 **F5 후 필요하면** 추가(우선 고정 크기 허용).

## 구현 담당

- **A·B 둘 다 리드/`takbon-dev` 영역** (절차 VFX + tscn 배선). **takbon-art 불필요.**

  `src/actors/vfx.gd`(두 겹 착탄) · (선택)`src/actors/shadow.gd`(공개 세터).
