# All three keys are empty squares — there is no fixed basic attack

**Status**: valid — decided by the user 2026-08-14, **stated three times** because the question kept being
asked back.

## What was decided

**Left click, right click and `space` are three squares, and the player puts an active in each.** `bite` is
not the basic attack; it is **the active you are handed first**, and binding something else over it throws
it away. `space` carries the only restriction: movement actives only.

**Binding is done by the player, in the `Tab` panel** — which slot's active goes on which key. The body's
eleven slots and the three keys are **two separate layers**, and a part being worn does not decide where it
fires from.

## What wasn't chosen

| Rejected | Why |
|---|---|
| **Left click permanently is the basic attack** | Then the head slot decides left click and the player never chooses. The user rejected this reading three times |
| The slot deciding the key (head → left, back → right, legs → `space`) | It reads as tidy and it removes the decision. Two parts worth binding to the same key is where the interest is |
| A separate skill list next to the body | There is no inventory in this game, and a skill list is one |
| Dragging to bind | Three rows. Click-then-click is enough, and dragging is a whole input model |

## What's tied to it

- **`Tab`**, which is the only place binding happens, and which the user may later split onto `C`
- **Digesting a bound part clears its key.** A binding pointing at a slot that no longer holds that part is a
  dangling index that reads fine and fires nothing
- **The opening minute.** With `bite` in slot 0 the hands are never keyless — planning principle 1

## Conditions to reopen

**If the panel turns out to be where the game stops.** If binding is fiddly enough that players stop
rebinding, the slot-decides-the-key rule is the cheap fallback and it is written down above.
