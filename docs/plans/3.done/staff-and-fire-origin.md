# 지팡이 — 그림과 발사 원점

**상태**: done — **사용자 통과이되 「살짝 짜친다」가 붙었고 그게 무엇인지 안 물었다**(「판정」 절)
**다시 열 이유**: 지팡이 그림이나 발사 원점을 고칠 때만.
**한 줄**: 지팡이가 선에서 그림이 되고, **지형에 막히면 그림·끝 색·발사 원점이 한 덩어리로 짧아진다.**

## 왜

두 가지가 **같은 값 하나**에서 만난다. 따로 고칠 수 없어서 한 문서다.

**① 지팡이가 아직 `draw_line` 이다.** `character-sprite` 가 「단계 4를 안 하고 닫았다」고
스스로 적었다 — 막힌 것도 버린 것도 아니고 **순서가 밀린 것**이다.

**② 벽에 붙어 쏘면 벽 *반대편* 이 파인다.** 사용자가 화면에서 봤다 —
「벽에 붙어서 발사했을 때 조금 이상하다」.

원인은 값 하나다:

```
tip_px() = 몸 중심 + 조준방향 × STAFF_LEN_PX(36)
             ↑ 몸 반폭 10px         ⇒ 몸 표면에서 26px 앞
타일 한 장 = 32px                    ⇒ 26 < 32  ⇒ 총구가 벽 한복판에 들어간다
```

 **그리고 시뮬은 그걸 정상으로 여긴다.** `spell_sim._walk` 가 **시작 칸을 일부러 안 본다**:

> **시작 칸은 검사하지 않는다.** 지난 틱에 이미 봤고, 첫 틱의 시작 칸은 지팡이 끝이다 —
> 캐릭터가 벽에 붙어 있으면 **거기서 바로 터지는 게 맞다.**

**그 주석은 틀리지 않았다 — 전제가 깨진 것이다.** 「지팡이 끝」이 벽 *앞* 에 있을 때만 참인데
26px이라 벽 *안* 이다. ⇒ 탄이 벽 안에서 태어나 **다음 셀부터** 검사를 받고, 벽 반대쪽 면에서 터진다.

 **그래서 시뮬을 안 고친다.** 고칠 곳은 「지팡이 끝이 어디냐」 하나다.

## 동작

### 지팡이 끝을 구하는 규칙 — 이 문서의 전부다

```
① 피벗   = 손 높이 (몸 중심에서 아래로 조금)
② 최대 끝 = 피벗 + 조준방향 × STAFF_LEN_PX
③ 피벗 → 최대 끝 사이를 훑어 **고체 셀을 만나면 그 직전까지** 자른다
④ 하한   = 몸 상자의 **마지막 안쪽 픽셀**. 그 아래로는 안 줄어든다
⑤ 잘린 끝이 **그림의 끝이자 끝 색의 자리이자 발사 원점**이다
```

 **⑤가 계약이다. 셋이 갈라지면 이 기능이 죽는다.**
`character_view.gd` 가 이미 못 박아 뒀다 — 「그림과 발사 원점이 갈라지면 **「쏜 데서 안 나간다」**로
보이고, 그건 **스샷으로만 드러난다**」. ⇒ **끝을 구하는 함수는 하나뿐이어야 한다.**

**④의 하한이 안전한 이유를 적어 둔다**: 몸 상자 안은 **캐릭터가 지금 서 있는 자리**라
지형이 없는 것이 보장된다(`_box_free` 가 매 프레임 그걸 지킨다). 하한을 상자 밖에 두면
「하한까지 줄였는데 거기가 벽 안」이 되어 원래 문제가 그대로 돌아온다.

 **여기 「몸 상자 **표면**」이라고 적혀 있었고 한 픽셀 틀렸다**(2026-08-05, 계획 §0-② 에서 실물 확인).
`_box_free` 가 실제로 지키는 범위는 `[px, px+W_PX−1] × [py, py+H_PX−1]` 이라 **표면(`box + 크기`)은
이미 다음 셀**이다 — 바닥에 선 캐릭터로 밟아 보면 `floori(800/4) = 200` 이 바닥 셀이고 **고체**다.
⇒ 표면으로 짜면 옆·위는 멀쩡하고 **발밑에만 옛 버그가 그대로 남는다. 에러가 안 난다.**

###  계산을 어디에 두나 — `src/view/` 가 아니다

지금 `tip_px()` 는 `src/view/character_view.gd` 에 있다. **거기 두면 그물이 못 잰다** —
씬을 세워야 하고, 헤드리스에서 픽셀이 없다(`character-sprite` 판정 기록: `SubViewport` 텍스처가 NULL).

⇒ **끝을 구하는 순수 함수를 `src/actor/` 에 둔다.** 격자와 피벗과 조준을 받아 끝 px를 돌려준다.
화면은 그것을 **그리기만** 하고, 발사는 그것을 `aim.fire_cmd` 에 **넘기기만** 한다.

 **`character.gd` 의 `pick_state`·`_box_free` 가 이미 그 어법이다** — 순수하고 static이라
씬 없이 값으로 잰다. 「눈으로만 볼 수 있는 것」을 하나라도 줄이는 것이 이 배치의 전부다.

**`aim.gd` 의 정수 경계는 안 건드린다.** 여전히 float px가 들어가고 정수 커맨드가 나온다 —
이 문서가 바꾸는 것은 **어떤 float px를 넘기느냐**뿐이다.

## 화면

### 지팡이 그림

| 값 | 정한 것 | 근거 |
|---|---|---|
| 모양 | **끝에 작은 고리**, 고리 안은 비어 있다 | 사용자가 후보 넷을 보고 판정(2026-08-05) |
| 색 | **검붉은 자주** — 캐릭터 후드와 같은 팔레트 | 〃 |
| 크기 | 폭 **36px**(= `STAFF_LEN_PX`) · 높이 16px | 캔버스 40×20은 **갈래가 부풀고 봉이 1px 실이 됐다**(실측) |
| 뻗는 자리 | **손 높이 — 가슴 아래** | 사용자 판정. 몸 그림에 팔이 이미 모여 있는 자리다 |

 **그림은 이미 들어와 있다** — `assets/character/wizard_staff.png` (36×16, `.import` 같이).
후보 24안 중 **조건 셋을 다 통과한 것**으로 골랐다(2026-08-05):

```
알파 bbox  x 0~35 · y 1~8      ⇒ 폭을 꽉 채운다 (끝이 35 = 폭−1)
끊긴 열     0개                 ⇒ 지팡이가 두 조각이 아니다
높이        8px                 ⇒ 회전해도 몸을 덜 덮는다
```

**24안 중 18개가 여기서 떨어졌다.** 흔한 실패 둘: **고리와 봉 사이가 4~5px 끊겨 있다**(고른 것과
같은 프롬프트인데도 났다) · **bbox가 폭에 못 미친다**(x 0~32 등) ⇒ 그러면 **눈에 보이는 끝과
`tip_px()` 가 몇 px 어긋나고 그건 스샷으로만 드러난다**(`net_sprite` 주석이 미리 적어 둔 함정이다).
 **그림을 갈아 끼울 때 이 셋을 반드시 다시 재라.**

 **색이 갈색이 아닌 것은 취향이 아니라 계약이다.** 지형이 나무 `0x6B4524` · 돌 `0x5C574F` 라
`fx_tuning` 이 「지형과 색상환에서 멀어야 눈이 즉시 가른다」를 못 박았다.
**지금 `STAFF_COLOR`(0.55, 0.40, 0.24)가 정확히 나무 지형 색이다** — 나무 위에서 묻힌다.
이 변경이 그걸 같이 고친다.

###  총구 구슬을 지운다 — 끝이 물드는 것으로 대신한다

**사용자 판정**(2026-08-05): 「총구 구슬을 지워줘. 별로야. 그냥 지팡이에서 나가는 게 좀 좋을 거 같아.」

|  | 전 | 후 |
|---|---|---|
| 무엇을 꼈나 | 구슬 **크기** = 층 수 · **색** = 맨 안쪽 문양 | **고리가 그 색으로 물든다** |
| 못 쏜다 | 회색 빈 고리 | **고리가 회색으로 죽는다** |

 **두 축 중 크기가 사라진다. 알고 지우는 것이다.**
`fx_tuning` 이 「크기 = 층 수 · 색 = 맨 안쪽 문양」을 **일부러 두 축으로** 뒀고 이유를 적어 뒀다 —
「하나로 합치면 **「층이 늘었다」와 「순서가 다르다」가 뭉개진다**」.
⇒ 고리는 크기를 못 나르므로 **남는 축은 색 하나**다.

**잃는 것을 정확히 적는다: 문양을 넣고 뺀 차이가 쏘기 전 화면에서 안 보인다.**
색이 나르는 것은 **맨 안쪽 문양**이라 「확산→폭발」과 「확산」이 **같은 색**이다.
 순서(확산→폭발 vs 폭발→확산)는 **여전히 색이 나른다** — GDD가 「순서가 화면에 안 보이면
플레이어는 규칙을 영영 못 배운다」고 적은 자리는 **안 깨진다.**

⇒ **되살리고 싶어지면 크기가 아닌 다른 축을 찾아라**(고리 굵기 · 고리 개수 · 끝의 밝기).
값을 어디에 실을지는 **미정**이다.

### 무엇을 보고 됐다고 아나

- 벽에 붙어 쏘면 **벽 앞면**이 파인다 (지금은 반대편)
- 벽에 다가가면 **지팡이가 눌려 짧아지는 게 보인다**
- 조합을 바꾸면 **고리 색이 바뀐다**. 룬을 비우면 **회색으로 죽는다**
- 지팡이가 **손에서 나가는 것**으로 읽힌다 — 배 한가운데가 아니다
- 위·아래를 조준해도 어색하지 않다

## 경계

### 이 문서가 안 다루는 것

- **UI 개편** — 사용자가 「지팡이 먼저」로 미뤘다(2026-08-05). 디버그 HUD·체력·조립창 셋 다
- **팔 스프라이트** — 몸 그림에 팔이 이미 그려져 있다. 지팡이만 별도 레이어다
- **불 실루엣 외곽선** — `character-sprite` 단계 5. 여전히 사각 테두리다

### 극단값

| 상황 | 어떻게 되나 |
|---|---|
| 벽에 **완전히** 붙어 벽 쪽으로 쏜다 | 하한(몸 상자 표면)까지 줄고 마법이 몸 옆에서 터진다 |
| **발밑**을 쏜다 | 지팡이가 땅 위에서 멈추고 발 옆에서 터진다 ⇒  **자기가 맞는다.** GDD가 「발밑을 쏘는 것이 이제 **위험이기만 하다**」고 이미 정한 자리라 **맞는 거동이다** |
| 천장 아래에서 **위**로 쏜다 | 같다 — 지팡이가 천장에 눌린다 |
| 격자 **밖**에 있다 | `aim.fire_cmd` 의 원점 클램프가 이미 막는다. 안 건드린다 |
| 지팡이가 **대각선**으로 벽 모서리를 스친다 | **미정** — 훑기가 Bresenham이면 모서리를 스쳐 지나간다(`_walk` 주석과 같은 함정) |

## 기존 것과의 상호작용

###  반드시 따라오는 것

| 무엇 | 왜 |
|---|---|
| `tests/nets/net_damage.gd` 의 `FEET_CY = FLOOR_CY + 5` |  **「중심에서 36px 아래 = 바닥 속」에 의존한다.** 클램프가 들어가면 발밑 원점이 **바닥 위**가 되어 이 값이 거짓이 된다. 그 파일 주석이 「+4도 초록이었다 — 그물은 이걸 못 가른다」고 적어 뒀다 ⇒ **손으로 다시 유도해야 한다** |
| `fx_tuning` 의 `MUZZLE_*` 여섯 · `muzzle_radius()` · `muzzle_tint()` | 구슬이 사라지므로 쓰는 쪽이 없어진다. **`GLYPH_TINT` 는 남는다** — 고리 색이 그 표를 그대로 쓴다 |
| `fx_tuning` 의 `STAFF_COLOR` · `STAFF_WIDTH_PX` | 선이 그림이 되므로 없어진다 |
| `character_view.gd` 의 `draw_line` · `draw_circle` 넷 | 〃 |

### 안 건드리는 것

-  **`src/sim/` 전체.** `_walk` 의 「시작 칸을 안 본다」도 그대로다 — 위 「왜」가 이유다
-  **`character.gd`.** `character-sprite` 가 「화면만 만진다」로 그은 선이 그대로 산다
- **`aim.gd` 의 정수 경계.** 넘기는 값만 바뀐다
- **`recoil()`.** 반동은 조준 방향에서 나오지 원점에서 나오지 않는다

### 새로 나는 것

- `assets/character/wizard_staff.png` (+ `.import`) —  **둘 다 커밋한다**(`.godot/` 이 gitignore라 uid가 끊긴다)
- 에셋 자리는 **`assets/character/`** 다. 사용자 결정(2026-08-04)이고 다시 고민하지 않는다

## 비용

**① 격자 훑기가 60Hz로 는다.** 36px = **9셀**이다. `character.gd` 가 이미 매 프레임
`_box_free`(6×9 = 54칸)를 **세 번** 훑으므로 9칸은 그 옆에서 싸다. **안 쟀다.**

**② 렌더는 무시할 만하다.** 스프라이트 한 장이 는다.
`character-sprite` 가 「이 게임의 렌더 부담은 셀 격자와 불·폭발이지 캐릭터가 아니다」로 이미 갈랐다.

**③  진짜 비용은 「끝이 세 곳으로 갈라지는 것」이다.** 그림 끝 · 물드는 자리 · 발사 원점.
비용이 아니라 **함정**이고, `character-sprite` 가 같은 것을 「진짜 비용」으로 적었다.

## 판정

1. **벽에 붙어 쏘면 벽 앞면이 파이나** —  지금은 반대편이 파인다. **이 문서를 연 이유다**
2. **지팡이가 벽에 눌려 짧아지는 게 보이나** — 벽에 다가가는 동안 화면에서
3. **그림 끝과 발사 자리가 같나** —  스샷으로만 드러난다(`character-sprite` 위험 ③)
4. **고리가 조합 색으로 물드나** — 조합을 바꿔 가며
5. **룬을 비우면 고리가 회색으로 죽나** — 「지금은 못 쏜다」가 화면에 남았나
6. **지팡이가 손에서 나가는 것으로 읽히나** — 배 한가운데가 아니라
7. **위·아래를 조준할 때 어색하지 않나** — `character-sprite` 판정 6이 「볼 것이 없다」로 남긴 자리다
8. **발밑을 쏘면 발 옆에서 터지나** — 그리고 자기가 맞나

**1·2·6·7은 눈이다.** 3·4·5는 픽셀로 잴 수 있다(`character-sprite` 의 846칸 거울 대조가 그 어법).
 **끝을 구하는 함수가 `src/actor/` 에 있으면 1과 8은 그물이 값으로 잰다** — 위 「계산을 어디에 두나」.

###  결과 — 2026-08-05, **사용자가 게임을 켜서 눈으로 확인**

**통과.** 사용자 원문:

> **잘되는데? 근데 살짝 짜치기는 하는데 이정도면 될듯**

**「이정도면 될듯」이지 「완벽하다」가 아니다.** 유보가 하나 붙었고 **그것이 무엇을 가리키는지는
사용자가 말하지 않았다.**  **아는 척해서 채우지 않는다** — 아래 「짜치는 것의 후보」가 추측이고,
**어느 것인지 확인된 바 없다.**

**확인 범위 — 정직하게 적는다:**
- **사용자가 실제 게임을 직접 조작해서 봤다**(스크린샷이 아니라 플레이). 새 코드로 재시작한 창이다
-  **판정 1~8 중 어느 것을 봤는지는 모른다.** 사용자는 한 문장으로 답했고 항목별로 말하지 않았다
  ⇒ **「전부 통과」로 읽지 마라.** 확인된 것은 **「전체 인상이 통과」**까지다
-  **`verify-look` 을 이번엔 안 돌렸다**(사용자 지시: 「검증은 헤드리스만, 내가 마지막에 체크」).
  ⇒ **픽셀 대조도 스크린샷 기록도 없다.** 다음 세션이 볼 수 있는 화면 증거가 **하나도 없다**
- **판정 3(그림 끝 = 발사 자리)은 원리적으로 스샷이 재는 것인데 아무도 안 쟀다.**
  대신 **구조로 막았다** — 끝을 구하는 함수가 `Staff.tip_px()` 하나뿐이고 화면·발사가 둘 다
  그것을 부른다(main이 코드로 확인). **갈라질 방법이 원리적으로 없다**는 것까지고,
  「그 값이 화면에서 맞는 자리에 그려진다」는 여전히 눈의 몫이다

**「짜치는 것」의 후보 — builder가 스스로 확신 없다고 적은 것들이다.  어느 것인지 확인 안 됐다:**
1.  **조준 기준이 어긋나 있다.** `aim_dir()` 은 **상자 한가운데** 기준인데 지팡이는 **4px 아래**
   (`PIVOT_DY_PX`)에서 나간다 ⇒ 조준선과 지팡이 방향이 그만큼 다르다.
   **마우스가 캐릭터에 가까울수록 크게 벌어진다.** 계획에 없어서 안 고쳤다
2. **봉이 벽에 눌려 짧아질 때 픽셀 계단** — 29px 그림이 임의 폭으로 눌린다
3. **회색 링(못 쏠 때)이 돌벽 위에서 묻히나** — 안 쟀다
4. **링 상수 넷의 자리 맞춤**(`INSET 4` · `R 3.5` · `PX 2` · `RING_W 7`) — 링이 그림의 고리와
   겹쳐 보이는지는 **원리적으로 그물이 못 잰다**
5. **`LEN_PX` 36 · `PIVOT_DY_PX` 4** — 둘 다 「눈으로 정할 값」인데 **계획이 준 값 그대로**다

⇒ **다시 열 때 여기부터 물어라: 「어디가 짜쳤나」.**

## 미정

- **`STAFF_LEN_PX` 를 36으로 둘지** — 피벗이 몸 중심에서 손 높이로 내려가면 화면에서 조금 짧아 보인다.
   **눈으로 보고 정할 자리다**
- **손 높이가 몸 중심에서 몇 px 아래인지** — 몸 그림의 팔 위치에서 나온다. 그려 보고 맞춘다
- **고리가 물드는 범위** — 고리만인가, 고리 + 그 앞 몇 px인가. 그림이 정해져야 정한다
- **층 수를 나르던 축을 되살릴지, 되살린다면 어디에** — 위 「총구 구슬을 지운다」
- **대각선으로 벽 모서리를 스칠 때** — 위 「극단값」
- **왼쪽을 볼 때 지팡이가 몸 앞인가 뒤인가** — `draw_set_transform` 복원 함정이 여기 그대로 걸린다
  (`character-sprite` 뮤테이션 4: **복원 줄을 지워도 그물이 전부 초록이었다**)

## 0. 계획을 세우며 실제로 잰 것

계획의 근거 셋은 **말이 아니라 실물에서** 나왔다. 다음 사람이 다시 재지 않게 여기 남긴다.

### ① 지팡이 png의 열별 알파 (`assets/character/wizard_staff.png`, 36×16 RGBA)

```
캔버스 36×16 · bbox x 0~35 · y 1~8 · 끊긴 열 0개
봉   x  0~28   y 3~6   (두께 4px)
고리 x 29~35   y 1~8   (높이 8px · 벽 두께 2px · 안이 비어 있다)
```

 **봉의 중심선(4.5) · 고리의 중심(4.5) · bbox의 중심(4.5)이 셋 다 같다.**
⇒ **그림을 y=4.5에 앉히면 180° 회전(= 왼쪽 조준)이 실루엣을 그대로 둔다.** 「왼쪽을 볼 때」 미정이
**그리는 순서**의 문제로만 줄어드는 것이 이 값 하나 덕이다.
이 셋이 어긋난 그림으로 갈아 끼우면 **왼쪽을 볼 때만 지팡이가 어깨 위로 뜬다** — 단계 2의 그물이 잰다.

### ②  하한이 「몸 상자 **표면**」이면 안 된다 — 표면은 빈칸이 아니다

문서 ④가 「하한 = 몸 상자 표면」이라 적었고 그 안전 근거를 `_box_free` 로 들었다.
**근거는 맞는데 경계가 한 픽셀 틀렸다.** `character.gd:508-512` 가 실제로 지키는 범위는

```
[px, px + W_PX − 1] × [py, py + H_PX − 1]      ← 마지막 픽셀이 −1이다
```

이고, `px + W_PX` · `py + H_PX` 는 **다음 셀**이다. 바닥에 선 캐릭터로 실제 값을 밟아 보면:

```
상자 y 768~799 (셀 192~199)      바닥 셀 200 = px 800~803, 고체
표면(y = 768+32 = 800) → floori(800/4) = 200 = 고체        ✗ 여기서 태어나면 옛 버그 그대로다
마지막 안쪽(y = 799)   → floori(799/4) = 199 = 빈칸        ✓
```

 **⇒ 하한은 `box + 크기 − 1`(마지막 안쪽 픽셀)이다.** 표면으로 두면 아래를 볼 때 원점이
**바닥 셀 안**에 앉고, `_walk` 가 시작 칸을 안 보므로 **이 문서가 여는 버그가 발밑에만 그대로 남는다.**
왼쪽·위 모서리는 `box` 그대로가 맞다(`floori` 가 그 픽셀을 상자 셀로 매핑한다). 비대칭이 정상이다.

### ③ `src/actor/` 는 `fx_tuning` 을 못 읽는다 — 그래서 길이가 이사한다

`net_layers.gd:26` 이 `"res://src/actor": ["res://src/view", ...]` 를 금지한다.
⇒ 끝을 구하는 순수 함수가 `src/actor/` 에 사는 순간 **`Fx.STAFF_LEN_PX` 를 못 읽는다.**
남는 길은 「인자로 받는다」와 「이사한다」 둘인데 **이사가 맞다**:

- `fx_tuning.gd:5-6` 이 스스로 「여기 값은 계약이 아니다 — **화면에만 닿는다**」고 적었는데
  `STAFF_LEN_PX` 는 `character_view.gd:72` → `stage.gd:248` → `aim.fire_cmd` 로 **세상에 닿는다.**
  이 문서가 그 위에 지형 의존성까지 얹으므로 어긋남이 load-bearing 이 된다
- **선례가 이미 있다**: `character.gd:73-76`(`MOVE_SPEED_PX`·`GRAVITY_PX`…) · `character.gd:162-163`
  (`RECOIL_*`)이 전부 `src/actor/` 에 사는 손맛값이다 ⇒ 실제 규칙은 「손잡이는 두 tuning 파일」이 아니라
  **「세상에 닿는 손잡이는 그 세상 코드 옆에 있다」**다
- `CLAUDE.md` 의 「연출 상수는 전부 `fx_tuning`」은 **안 깨진다** — 이사하는 값이 연출이 아니라는 것이 위 논거다

## 1. 끝을 구하는 자리 — 답 셋

### 답 1 — 어디에 어떤 시그니처로

**`src/actor/staff.gd` (새 파일, `RefCounted`, 순수 static).**

```gdscript
const LEN_PX := 36.0        ## fx_tuning 에서 이사. png 폭과 같아야 한다 (그물이 잰다)
const PIVOT_DY_PX := 4.0    ## 손 높이 — 몸 중심에서 아래로. 눈이 정할 값이다(미정)
const SCAN_STEP_PX := 2.0   ## 훑기 간격.  셀(4px)의 절반 — 이보다 크면 셀을 건너뛴다

static func pivot_px(box_x: int, box_y: int) -> Vector2
static func tip_px(grid: CellGrid, box_x: int, box_y: int, dir: Vector2) -> Vector2
```

- **인자가 격자·상자·방향뿐이다.** 씬도 캐릭터 인스턴스도 없다 ⇒ 그물이 값으로 잰다
  (`character.gd` 의 `pick_state`·`camera_center` 와 같은 어법)
- `dir` 은 **단위벡터로 받는다. 안에서 정규화하지 않는다** — 호출부가 이미 했고
  두 번 하면 「어디서 정규화하나」가 두 곳이 된다. 0벡터면 `pivot_px()` 를 그대로 돌려준다
- `Character.W_PX`·`H_PX` 는 preload 로 읽는다(같은 폴더다)

알고리즘 — 문서 「동작」의 ①~⑤ 그대로:

```gdscript
pivot   = (box_x + W_PX*0.5, box_y + H_PX*0.5 + PIVOT_DY_PX)
min_len = pivot 에서 상자의 **마지막 안쪽 픽셀**까지의 광선 거리   # §0-② — 표면이 아니다
d       = min_len
while d < LEN_PX:
    nd = minf(d + SCAN_STEP_PX, LEN_PX)
    if grid.is_solid(cell(pivot + dir*nd)):  break
    d = nd
return pivot + dir * d
```

 **돌려주는 점은 「고체가 아닌 것을 실제로 확인한 마지막 표본」이다.** 이게 계약이고 그물이 그걸 잰다 —
「빈 셀에 있다」는 값이지 「클램프를 부른다」가 아니다.
`min_len` 자체는 표본을 안 뜬다. 뜰 필요가 없는 것이 §0-②의 결론이다(상자 안은 `_box_free` 가 지킨다).
`LEN_PX < min_len` 인 극단(지팡이가 몸보다 짧다)에서는 **하한이 이긴다.** 그래도 상자 안이라 안전하다.

### 답 2 — `net_damage.FEET_CY`

 **상수를 다시 유도하지 않는다. 지운다.** 대신 `_firing_down_does_not_lift_me` 안에서
**`Staff.tip_px()` 를 불러서** 원점 셀을 뽑는다.

```gdscript
var tip := Staff.tip_px(g, ch.x, ch.y, Vector2.DOWN)
var feet_cx := floori(tip.x / float(Tuning.CELL_PX))
var feet_cy := floori(tip.y / float(Tuning.CELL_PX))
t.ok(not g.is_solid(feet_cx, feet_cy), "발밑 원점이 빈 셀이다 (배치의 전제)")
```

**왜 유도가 아니라 호출인가.** 그 파일이 스스로 「+4도 초록이었다 — 그물은 이걸 못 가른다」고 적었다
(`net_damage.gd:159`). 손으로 다시 유도하면 **같은 함정에 값만 새로 넣는 것**이다 —
`FEET_CY` 는 애초에 **단언이 아니라 배치**였고, 배치는 실제 코드에서 나와야 낡지 않는다.
(`_blast_r_px`·`_aim_row`·`_blast_cx_beside` 가 이미 그 어법이다.)

**그래도 값을 손으로 한 번 확인해 두면 builder가 결과를 알아본다.** 손유도는 이렇다:

```
상자 y 768~799 · pivot.y = 768 + 16 + dy = 784 + dy
아래 조준 ⇒ min_len = (768 + 32 − 1) − (784 + dy) = 15 − dy
바로 다음 표본 y = 799 + 2 = 801 → 셀 200 = 바닥, 고체 ⇒ 즉시 멈춘다
tip.y = 799  ⇒  floori(799/4) = 199 = FLOOR_CY − 1        ← dy 와 LEN_PX 에 **무관하다**
```

 **그리고 이 검사의 배치 근거가 바뀐다. 주석을 반드시 같이 고쳐라.**
`net_damage.gd:966-968` 이 「상자 **아래**라 탄이 상자를 안 지난다」고 적었는데, 클램프가 들어오면
원점 셀(199)은 **상자의 마지막 줄**이다 ⇒ **탄이 상자 안에서 태어나 자기가 맞는다.**

- 그게 **맞는 거동**이다 — 문서 「극단값」이 「발밑을 쏘면 자기가 맞는다」를 확정으로 적었다
- 이 검사가 재는 것(**세로 0** · **가로 반동은 산다**)은 **안 변한다.** hp를 안 보고, 넉백이 없어
  맞아도 안 밀리고, `ELEM_NONE + GLYPH_NONE` 이라 지형도 안 변한다
- 옛 주석을 그대로 두면 **거짓이 남는다.** 「상자 안에서 태어난다 · 그래서 맞는다 · 재는 것은 안 변한다」로 고쳐라

### 답 3 — 총구 구슬을 지우면 무엇이 같이 없어지나

 **팀 지시의 「`MUZZLE_*` 여섯」에 예외가 둘 있다. 그대로 지우면 `circle_window.gd:322` 가 깨진다.**

| `MUZZLE_PX` · `MUZZLE_PER_LAYER_PX` | **삭제** | 크기 축이 사라진다 |
| `MUZZLE_GLOW_RATIO` · `MUZZLE_GLOW_A` | **삭제** | 겉 무리가 사라진다 |
| `muzzle_radius()` | **삭제** | 위 넷이 없어지면 몸이 없다 |

**이름을 안 바꾸고 남기면 「총구」라는 이름이 총구 없는 리포에 남는다** — 이 리포가

## 2. 화면 쪽 — 어떻게 그리나

### 봉과 고리를 따로 그린다 ( 통째로 늘리면 안 된다)

지팡이가 눌리면 길이가 `LEN_PX` 보다 짧아진다. 그림을 **통째로 x축 스케일**하면 고리가 타원으로
찌그러지고, 그 위에 얹을 색 링(원)이 안 맞는다. ⇒ **봉만 줄이고 고리는 원래 크기로 끝에 붙인다.**

```
 draw_set_transform(pivot, dir.angle(), Vector2.ONE)
   ① 봉   region x 0~28  →  Rect2(0, −ANCHOR_Y, maxf(0, L − RING_W), 16)
   ② 고리 region x 29~35 →  Rect2(L − RING_W, −ANCHOR_Y, RING_W, 16)
 draw_set_transform(ZERO, 0, ONE)        ←  반드시 되돌린다
   ③ 링   draw_circle(tip − dir*RING_INSET, RING_R, staff_tint(...), false, RING_PX)
```

- **①②는 회전 좌표계 안, ③은 월드 좌표계다.** `tip` 이 이미 월드 px라 그게 자연스럽고,
  **복원 줄이 어디에 있어야 하는지가 코드 모양으로 드러난다**
-  **그래도 복원을 그물이 못 잡는다** — `character_view.gd:131` 이 실측을 적어 뒀다
  (복원 줄을 지워도 전부 초록). **지키는 것은 주석과 눈뿐이다**
- 봉이 짧아지고 고리가 그대로인 것이 **판정 2(눌려 짧아지는 게 보인다)의 정직한 그림**이다

###  색을 `modulate` 로 나르지 못한다 — 그래서 링을 덧그린다

`CanvasItem` 의 `modulate` 는 **곱셈**이다. 봉이 검붉은 자주(≈0.4,0.1,0.2)인데 청록 틴트를 곱하면
`(0.18, 0.085, 0.20)` — **거의 안 변한다.** ⇒ 판정 4(조합을 바꾸면 색이 바뀐다)가 화면에서 죽는다.
그리고 이 노드는 재질이 없어 가산 합성도 못 쓴다(`character_view.gd:170-171` 이 적어 뒀다).

⇒ **틴트는 픽셀을 덮어써야 한다 = 링을 위에 그린다.** ③이 그것이다.

**사용자가 지우라고 한 것과 다른 것이다.** 지운 것은 **구슬**(채워진 원 + 겉 무리 + 크기 축)이고,
이건 **그림의 고리 자리에 정확히 겹치는 빈 링 하나**다 — 문서 표의 「고리가 그 색으로 물든다」가 그것이다.
 **크기 축은 되살아나지 않는다**(반지름이 상수다). 남는 축은 색 하나라는 문서의 결정이 그대로 산다.

### 상수 (전부 §0-① 실측에서 나온다)

```gdscript
const STAFF_SHEET := "res://assets/character/wizard_staff.png"
const STAFF_ANCHOR_Y_PX := 4.5   ## 봉 중심선 · 고리 중심 · bbox 중심이 전부 여기다 (실측 y 1~8)
```
