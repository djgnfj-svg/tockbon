## 0. 🔴 **역할 축 재설계** (세션 11 · 사용자 고민 중 — *"기초적인 규칙이 있어야 하는데"*)

**지금 최우선 미결.** 다른 어떤 구현보다 먼저 정해져야 한다 — 진 모양·룬 N개보다도.

### 축 표가 거짓말을 하고 있다

| 부품 | 표에 적힌 것 | **실제로 정하는 것** |
|---|---|---|
| **진** | 규모 (1개) | 위력 · 탄 크기 · 사거리 — **3개를 혼자.** 갈라 쓸 수 없다: 큰 위력을 원하면 큰 탄과 긴 사거리가 **딸려온다** |
| **룬** | 속성 + 농도 (2개) | 그대로 (2개) — 유일하게 정직하다 |
| **문양** | 방식 + 세기 (2개) | + **방향** + **기점** = **5개.** 축 밖에서 새고 있다 |

사용자: *"앞뒤옆 이게 좀 복잡함"* — **복잡함의 정체가 이것이다.** 그리고 **방향은 그림으로 읽기
어려운 축**이다: 거꾸로 그으면 정반대로 날아가는데 그린 사람은 모른다 (세션 11에 실제로 겪음 →
화살촉을 붙여 완화했으나 **축 자체는 그대로**).

### 아무도 안 정하는 것 — 빈 칸

| 요소 | 지금 | 비고 |
|---|---|---|
| **속도** | `projectile_base_speed` 260 **고정** | 느린 탄/빠른 탄이 없다. **빈 자리가 정확히 여기 하나** |
| **착탄 후 처리** | **아무 일도 안 일어난다** | 탄이 사라지고 상태이상만 붙는다 |
| **히트박스 모양** | **언제나 반지름 5의 원** (크기만 진 규모로 배율) | 그린 획은 그 위에 얹힌 **그림일 뿐**. **보이는 모양과 맞는 모양이 다르다** |
| 화상 지속시간 | 3초 고정 | 세기만 변하고 길이는 안 변한다 |
| 여러 발의 퍼짐 | 없음 | 발수를 늘려도 각자 그린 방향으로 |

### 사용자가 짚은 뼈대 — **두 층**

> *"날아가는 처리랑 맞은 다음에 퍼짐 처리가 고민이네"*

- **날아가는 동안** → **문양**이 정한다 (팅김·유도·관통) ✅ 채워져 있다
- **맞은 다음** → 🔴 **비어 있다**

**룬이 그 빈 칸에 맞는다.** 속성이 이미 *"무엇으로 때리는가"*인데 지금은 상태이상 숫자로만 나타난다:

| 룬 | 착탄 후 |
|---|---|
| 불 | 터진다 (범위 폭발) |
| 물 | 고인다 (장판) |
| 충격 | 밀어낸다 (넉백은 이미 있다) |
| 바람 | 빨아들인다 / 흩어진다 |

**규칙을 안 늘리고 빈 칸만 채운다.** 축이 이렇게 갈린다:
**진 = 얼마나 크게 / 룬 = 무엇으로, 맞으면 어떻게 / 문양 = 어떻게 날아가서**

### 미결 (사용자 결정 필요)

1. **방향을 마우스에 넘길 것인가** — 넘기면 문양이 "방식 + 세기" 둘로 깨끗해진다. 잃는 것:
   *"뒤쪽으로 견제탄 심기"* 같은 배치 설계. **문양 여러 개일 때 어떻게 할지가 함께 정해져야 한다**
   (부채꼴로 퍼뜨림 / 전부 겹침 / 문양 1개로 제한)
2. **속도를 무엇에 물릴 것인가** — `reach`(길이)는 이미 사거리·반사수를 정한다. 길이에 속도까지
   얹으면 **길이 하나가 셋을 정하게** 된다 (또 다른 과부하). 후보: 필압 · 그은 속도 · 획 굵기
3. **퍼짐 범위를 무엇이 정할 것인가** — 진 규모(큰 마법 = 큰 폭발)가 자연스럽지만 룬 농도도 후보
4. **진이 3개를 혼자 쥔 것을 그대로 둘 것인가** — 위력·크기·사거리를 갈라 쓸 방법이 없다

## 1. ✅ **"문양이 너무 빈다"** — 해결됨 (v1.9). 남은 건 **구현 순서**다

> 이번 주 목표: **마법진을 만들어서 원하는 대로 출력하기.** 여기가 그 핵심이었다.

### 결론 — 세 축이 다 찼다 (GDD v1.9로 승격 완료)

원래 진단은 "문양만 정체성이 없다"였는데, **실은 축 배분이 통째로 어긋나 있었다.**
세션 8~10에서 사용자와 함께 재배분해 **전부 채웠다.**

| 부품 | 모양이 정하는 것 | 크기가 정하는 것 | 상태 |
|---|---|---|---|
| **진** | **구조** — 원·별·용 | **규모** — 위력·탄 크기·기준 사거리 | 규모 ✅ 구현됨(v1.6) / **구조 ⚠ 미구현 — $P 선행** |
| **룬** (N개) | **속성** — 원소·상태이상 | **농도** — 상태이상 세기 (÷ 진) | 농도 ✅ 구현됨(v1.7) / **N개·배선 ⚠ 미구현 — $P 선행** |
| **문양** (N개) | **발동 방식** — 팅김⚡·유도∿·관통‖ | **세기** — 사거리 배율·반사 횟수 (÷ 진) | **✅ 전부 구현됨 (v1.9, 세션 10 — 커밋 a9d6146)** |

**핵심 통찰 (전부 규칙을 안 늘리고 나왔다):**
- **"진을 뚫고 나가는가"가 곧 의미의 경계다.** 나가는 획 = 탄, 안 나가는 획 = 속성.
  ⚠ 단 이건 **종이 위의 문법이지 탄의 행동이 아니다** (v1.9) — 팅김도 획은 곧게 뚫고 나가지만
  **탄은 벽에 튕긴다**. v1.8까지 문양이 직선뿐이라 두 층이 겹쳐 보였을 뿐이다
- **진의 모양이 곧 출구의 지형이다.** **별 진 = 전방위.** 별을 그리면 별처럼 퍼진다
- **진 안은 룬만.** 구조 글자를 진 안에 넣는 안은 기각 (진은 좁고, 룬과 농도를 깎아먹는다)
- **세 부품 전부 "모양 = 무엇을 / 크기 = 얼마나"** (v1.9). 배울 규칙이 셋이 아니라 **하나**다.
  그리고 크기는 셋 다 **진 대비 비율** — 잉크 상한이 자연히 제동을 건다
- **룬의 위치가 룬과 문양을 잇는다** (v1.9 배선) — 왼쪽 룬이 왼쪽 문양을 지배한다

### ✅ 끝난 일 — **문양 글자 + 세기** (v1.9, 세션 10 · 커밋 a9d6146)

`glyph`(팅김⚡·유도∿·관통‖·기본) + `reach`(획 길이 ÷ 진 반지름). **죽어 있던 문양 길이가 살아났다.**
`magnitude`는 v1.6에서 "소비 금지"로 묶어 둔 필드인데 여기서 되살아났다 (**위력이 아니라
사거리**라 축 위반이 아니다). 손그림 인식률 100% · 사용자 플레이 확인 완료.

> 🔴 **순서를 바꿨다 — 아래 "1번이 모든 것의 전제"는 문양엔 해당되지 않았다.**
> $P를 먼저 갈라는 근거는 *"1획용으로 구부린 글자는 다획에서 다시 그려야 한다"*인데
> **팅김·유도·관통은 애초에 1획이 자연스럽다.** 구부릴 게 없었다.
> **다획이 진짜로 필요한 건 진(별·용)뿐이다.**
> **교훈: 문서의 결론이 아니라 그 근거를 확인할 것.**

### 🔴 남은 일 — **이 순서를 지켜야 한다**

**1. 인식기 $1 → $P 교체** (**진 모양·룬 N개의 전제**)
- **$1은 유니스트로크 = 한붓그리기 전용.** **별 진·용의 진을 원리적으로 그릴 수 없다**
- **$P** (Vatavu·Anthony·Wobbrock 2012) — 획을 점 구름으로 본다. 다획 지원, 회전 불변 on/off,
  $1보다 견고, 템플릿 형식이 비슷해 **매칭 함수 교체 수준**
- 🔴 **진짜 비용은 인식이 아니라 UX**: **"이 획이 앞 글자의 연장인가 새 글자인가"** —
  1획 시절엔 없던 문제다. 시간(멈추면 끝)·위치(겹치면 같은 글자)·명시적 입력 중 택일.
  **잘못 끊으면 그린 대로 안 나온다 = 게임 정체성이 무너진다** (GDD 리스크 8)
- ⚠ **회귀 위험**: 룬 4종은 지금 **99.5%**, 문양 4종은 **100%**다. $P가 이 수치를 떨어뜨리면
  안 된다 — 교체 후 **양쪽 스트레스 테스트를 다시 돌려 실측할 것**

**2. 진 모양 축** — 원 → 원·별·(용). 닫힌 도형이면 원이 아니어도 된다 (안/밖 판정은 그대로 성립)

**3. 룬 N개 + 배선** — 스키마를 `Array[RuneInstance]`로, `angle`(위치 방위각) 신설
   (TECH_SPEC §4.0-a). **세이브 마이그레이션 1회**
   - 🔴 **이때 `circle_radius`도 배열로 열 것** — **중첩 진**(아래 §1-6)이 오면 어차피 필요하다.
     **지금 안 열면 마이그레이션을 두 번 한다**

### 미결 — 억지로 정하지 않은 것들

1. ✅ ~~**"팅긴다"(벽 반사)**~~ → **v1.9 해결.** 별도 축이 필요 없었다 — **문양 글자**가 답이었다.
   *억지로 정하지 않고 미룬 것이 옳았다*
2. ✅ ~~**룬 각도**~~ → **v1.9 해결: (a) 배선.** 룬을 진 안 어디에 두었는가 = 그 룬이 지배하는 방향.
   문양은 각도상 가장 가까운 룬의 속성을 싣는다 (룬 1개면 전부 그 룬 → 하위 호환)
   - 🔴 **함정을 피해 갔다**: 쓰는 값은 **룬이 놓인 위치의 방위각**이지 `indicative_angle()`(글리프
     회전각)이 **아니다**. 회전각을 썼다면 불△(3회 대칭)이 120도 돌려도 눈에 똑같아 플레이어가
     영원히 알 수 없었다. **위치는 눈에 보인다** — 방위 바늘도 필요 없다
3. ✅ ~~**룬 2개의 피해 계수**~~ → **v1.9: `fill` 가중 평균** (룬 1개일 때 지금과 정확히 같다 →
   하위 호환. 진하게 그린 룬이 피해 성격을 더 지배한다는 뜻도 된다)
4. **원소 반응(증기 등)은 룬 쌍이 아니라 상태이상 레이어에** — 룬 쌍에 걸면 N²로 폭발한다.
   상태이상(화상·젖음·넉백·흐름)에 걸면 **룬이 늘어도 규칙 수가 안 늘어난다.**
   적의 `_statuses`는 **이미 Dictionary라 상태이상을 여러 개 동시에 갖는다** — 그쪽은 준비돼 있다
5. **문양 어휘 확장** (MVP 3종 이후) — 폭발◇ · 분열Y · 설치/지속형.
   🔴 **설치·지속형은 "날아가는 탄"이라는 틀 자체를 깬다** (사용자가 이 이유로 MVP에서 뺐다).
   나머지 3종은 전부 *날아가는 방식*인데 설치만 결이 다르다 — **별도 설계가 필요하다.**
   MVP 3종을 손으로 만져 본 뒤 다시 본다

6. 💡 **중첩 진 — "진 안에 진을 그리고 룬을 각각 넣는다"** (사용자 아이디어, 2026-07-14)

   > *"룬 2개 같은 경우... 진 안에 진을 그리고 룬을 각각 넣는 경우도 있을 듯"*

   **v1.9의 배선(룬 각도)과 나란히 놓이는 두 번째 배선 수단**이다. 지금 배선은 *"왼쪽 룬이 왼쪽
   문양을 지배한다"*(방위각)인데, 중첩 진은 *"어느 진에 속했느냐"*로 룬을 묶는다 — **위상 배선**.

   **왜 자연스러운가 (규칙을 안 늘린다):**
   - 인식기는 이미 **안/밖**으로 의미를 가른다 (§4.0). 진이 겹치면 **"몇 번째 껍질 안인가"**가
     저절로 생긴다 — 새 규칙이 아니라 **기존 규칙이 중첩을 만나면 나오는 결과**다 (별 진과 같은 논리)
   - **규모 축과 맞물린다**: 안쪽 진은 작으니 규모가 작다. 그래서 **"작고 빠른 탄 + 크고 느린 탄을
     한 장에"** 가 가능해진다 — 지금은 도안 하나에 규모가 하나뿐이다
   - 문양이 **어느 진을 뚫고 나가느냐**로 그 탄의 규모·속성이 정해진다. 이것도 기하에서 공짜로 나온다

   **미결 (구현 전에 답해야 할 것):**
   - 안쪽 진을 뚫었지만 바깥 진 안에 머무는 획은 **룬인가 문양인가?** (지금 규칙으로는 판정 불가)
   - 마나·잉크 비용은 진마다 무는가, 합치는가
   - **UX**: 진 두 개를 그리는 게 손으로 즐거운가, 번거로운가 — 만져 봐야 안다

   🔴 **지금 당장의 실무 함의 — 스키마를 진 1개로 못 박지 말 것.**
   `SpellDesign.circle_radius`는 지금 **스칼라 하나**다. 중첩 진이 오면 배열이어야 하고, 그러면
   **세이브 마이그레이션을 또 해야 한다.** 어차피 룬 N개(§1-3) 때문에 마이그레이션을 한 번 하므로,
   **그때 진도 함께 열어 두면 공짜다.** 구현은 미루되 **구조는 막지 않는다.**

## 2. 보정 — "약간 보정이 필요한 듯" (사용자, 세션 7)

다음 세션은 **무엇의 보정인지부터 물을 것.** 후보:

- **인식 보정** — 룬 인식률은 세션 7에 96.7% → **99.5%**로 올렸다(불△ 감김 게이트 재설계 +

- **필압 보정** — 마우스 누적형 합성 상수(`P_MIN 0.35 / P_MAX 1.5 / SPEED_REF 750 / TAU 0.35`).
  머물렀을 때 굵어지는 정도·속도가 손에 맞는지
- **거부 UX** — 순서 위반·인식 실패 시 획이 사라지는 게 답답한지 (잉크는 안 깎이지만)
- **캐스팅 손맛** — 마법진 연출 0.4초, 투사체 속도·크기 배율

## 3. ~~곡선 궤적~~ — **폐기 (v1.9)**

**문양이 글자를 택하면서 임의의 곡선 궤적은 버렸다** (GDD §4.3). "그린 모양=궤적"과
"그린 모양=글자"는 같은 획에 못 얹는다 — 지그재그가 *지그재그로 날아가라*인지 *팅겨라*인지
인식기가 가를 수 없다. **v1.9는 글자를 택했다.**

- **궤적이 죽은 게 아니라 글자가 궤적을 정한다** — 유도∿는 휘어서 따라가고, 팅김⚡은 벽에서 꺾인다.
  잃은 것은 **"내 맘대로 S자"** 하나다
- **`ArrowData.path`는 계속 쓴다 — 먹선 렌더 전용**(비주얼). "내가 그린 획 그 자체가 날아간다"는
  세션 7의 연출은 유지된다. **날아가는 길만 글자가 정한다**
- **사거리 문제는 `reach`로 해결됐다**: 아래 세 안 중 **(B)를 골랐다** — 문양 길이 ÷ 진 반지름 =
  **사거리 배율**. 진이 기준 사거리를 주고 문양이 배율을 정하므로 **축을 도로 뺏지 않는다**
  - ~~(A) 그린 길이 = 사거리 (절대값)~~ → 축 위반 위험 (사거리는 진의 축)
  - **(B) 진이 정한 사거리에 배율** ✅ **채택** — 룬 농도(`rune_fill`)와 정확히 같은 문법
  - ~~(C) 모양은 그대로, 끝나면 접선 직진~~ → 궤적을 버렸으므로 무의미

## 3.5 제작대(책 펼침) — 남은 조각 (세션 8 신설)

`src/drawing/forge_panel.gd`는 만들었고 시험대(`tests/test_forge.tscn`)에서 돈다. **본편 배선은 아직이다.**

- **거점 이젤 배선** — 지금 `base.gd`의 이젤은 `scene_change_requested(&"drawing")`으로 **씬을 갈아탄다**
  (옛 `drawing_room`). 이걸 forge 오버레이로 바꾸면 거점에서도 ESC 왕복이 된다.
  ⚠ **선행 조건이었던 무료 수리 버그(BUG-2)는 세션 8에서 고쳤다** — 이제 배선해도 안전하다
- **종이 등급을 고를 수단이 forge에 없다** — 항상 최저 등급 자동. 옛 드로잉룸엔 드롭다운이 있었다.
  그래서 지금은 마나 감면·내구 보너스가 붙은 상급 종이를 **의도적으로 쓸 방법이 없다**(GDD §5 무력화).
  왼쪽 페이지 상단에 종이 칸을 두는 게 자연스럽다
- 배선이 끝나면 `drawing_room.gd`·`test_drawing_main.gd`(옛 시험대 UI)와 `design_book.gd`(옛 한 줄 책자)를
  정리한다 — 지금은 forge와 **종이 선택 로직이 중복**돼 있다
