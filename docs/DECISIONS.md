## 게임 정체성

- **장르 = 2D 탑다운 익스트랙션 로그라이트** (세35). 원정을 나가 얻고, 살아 돌아와야 갖는다.
  **왜**: 「마법을 만드는 것」에 목적이 없어 만들 이유가 없었다 — *"주지 말고 얻게"*.
  가방 = 이번 판 전부이고 죽으면 증발한다(`bag_lost`).
- **제목 「탁본」의 근거를 회복했다** (세89). 뜻 = **남이 새겨 놓은 것을 떠서 쓴다** — 파밍·조립 자체가 탁본이다.
  **왜**: 세83에 손으로 긋는 행위가 폐지되면서 제목이 근거를 잃었다. 되돌린 게 아니라 **뜻을 옮겼다.**
- 🔴🔴 **세계관 = 「오래전 큰 마법진이 깨져 문양이 세상으로 흩어졌다. 나는 뒤늦게 그걸 주우러 온 자다」** (세95, 사용자 확정).
  **끝 = 문양을 다 모아 마법진을 복원하고, 그 힘으로 그것을 깬 자(최종 보스)를 잡는다.**
  **왜 세89를 각하했나**: 세89는 *"망한 마을을 한 채씩 되돌려 완성"*이 목표였는데, 세90에 마을을 셋으로 줄이며
  `STATION_UNLOCKS`가 비어 **「마을 완성이 엔딩인데 되살릴 게 0채」**가 됐다. 사용자: *"컨셉 자체가 안 끌린다"* ·
  *"이런 게임에서 세계관은 곁다리라 대충만"* · *"마법진이 깨지며 문양이 흩어진다 — **이누야샤**처럼"*.
  🔴 **버린 게 아니라 엔딩을 옮긴 것이다 — 곁다리(마을) → 코어 재미(문양 = 조립 부품).**
  한 번의 보상이 ⓐ 새로 조립할 것 ⓑ 엔딩 한 칸을 **동시에** 친다. GDD §7 *"주지 말고 얻게"*가 그대로 성립.
  🔴 **「최종 보스」가 비워둔 칸 둘을 공짜로 채운다** — *왜 깨졌나*(그것이 깼다) · *왜 아무도 안 모았나*(그것이 있어서).
  🔴 **모든 비주얼 판단의 잣대 = 「마법 = 빛. 빛은 있어야 할 곳(마을)에 없고, 없어야 할 곳(숲·짐승)에 있다」**
  — 세89에서 **통째로 생존**했다(적 몸에 박힌 파편이 빛나는 그림이라 새 컨셉과 오히려 더 맞는다).
  정본 = `docs/takbon-design/world_and_visual_design.md`. ⚠ GDD 반영은 아직(§9가 개정을 제안하고 🔒 허락 대기).
- **2D · 싱글 · 데스크톱으로 확정** (세75, 사용자: *"멀티 안하기로하자"*).
  되돌리려면: 멀티 스킬 3종을 git 이력에서 되살린다(세75에 삭제 = 방향 포기 신호였다).

## 마법 모델

- 🔴🔴 **그리기(탁본)를 폐지했다 — 조립만으로 마법이 맺힌다** (세83).
  **왜**: 세16에 *"핵심 재미 = 그리는 것"*으로 지었는데, 자유도가 **전투에 안 나타났다**(세43 진단 — 다르게 그려도 전투가 안 달라짐).
  🔴 **단, 스위치다** — `balance.skip_drawing`(기본 `true`)을 `false`로 되돌리면 손 긋기·채점기·펜 보정이 그대로 살아난다.
  **되돌리려면**: 그 한 값. 묻는 건 **`RingPower.skip_drawing()` 하나로**(직접 `BAL`을 읽으면 한 곳을 되돌릴 때 갈라진다).
  ✅ **세96에 GDD가 따라왔다** — §2의 심장이 **「조립 + 그 결과가 화면에 보이는 것」**이 되고,
  손 긋기는 §3의 **휴면 단계 각주**로 내려갔다. 🔴 **세83~96 내내 진실원을 열면 폐지어가 적혀 있었다.**
- **마법진 = 고리 조립 모델** — 진(그릇) · 룬(중심) · 문양(고리 칸).
  **왜**: 「그린 그림을 인식」하면 결국 4지선다가 된다. 부품을 **조합**해야 자유도가 결과로 나온다.
- **마법진은 날아가지 않는다 — 공식이다** (세72). 진이 날아가던 옛 모델을 은퇴시키고, 진은 **해석 규칙**이 됐다.
- **층(밴드) = 연산 순서** (세79 M1) · **융합진은 룬 2개 → 한 발에 두 속성 → 반응**(세81 M2) ·
  **문양 효과·표현은 데이터로**(세82 M3 — 새 문양 = `.tres` + `GlyphCode` 값 하나).
- **층은 「선」이 아니라 「띠」다** (세86). 문양이 동심원 선을 밟지 않는다.
  🔴 띠는 **모티프 크기에서 파생**한다 — 상수를 베끼면 문양을 키울 때 다시 겹친다.

## 루프 · 진행

- 🔴🔴 **던전을 「지점을 밟고 살아 나오는 곳」으로 확정했다** (세99, 사용자 확정 여덟 · 정본 = `docs/takbon-design/dungeon_structure_design.md`).
  **왜**: 사용자 원문 *"내가 생각하는 구현이 아니라 AI가 대략적으로 구현해 놓은 상태여서 수정 필요"* —
  던전은 **기획 없이 얹힌 얼개**였다(챕터 셋이 같은 씬 · 몹 좌표가 `.tres`에 손으로 박혀 랜덤 0).
  확정 = **열린 맵 + 탈출구 여럿 · 탈출이 목표(보스는 선택) · 지점(폐허·둥지·제단) · 지형 고정 + 몹 굴림 + 네임드 확률 ·
  꾹 눌러 탈출 · 챕터마다 무대.**
  🔴 **세57 「뼈대는 확정, 살은 랜덤」이 여기서 비로소 절반을 채운다** — 그전엔 뼈대도 살도 다 확정이었다.
  🔴 **진행 보상은 굴리지 않는다** — 제단이 문양-고리를 주려던 초안을 **사용자가 각하**했다(세57 *"언제 얻을지 설계를 못 해 불안하다"*가 돌아온다).
  **되돌리려면**: 신설 필드를 비우면 지금 동작으로 돌아온다(설계 §9). ⚠ 단 **출구 다중화·목표 줄은 코드라 손으로** 되돌린다.
- **숲 원정을 은퇴하고 챕터(보스방)로 갈았다** (세58-B). `forest.gd`/`forest.tscn`은 **삭제됐다**.
  새 챕터 = `data/chapters/*.tres` 한 장. ⚠ `forest_enemy`는 이름만 옛 것이고 **범용 적 몸**으로 살아 있다.
- **건설을 은퇴했다** (세66). 스테이션은 **짓는 게 아니다**.
  후속(세89): **폐허로 시작해 퀘스트를 깨면 건물이 되돌아온다.**
  🔴🔴 **「열쇠(퀘스트 `reward_unlock`)」와 「문(`base.gd`의 `STATION_UNLOCKS`)」은 짝이다** — 어느 쪽만 살려도
  조용히 깨지고(영영 잔해 / 죽은 보상) **에러 0 · 기존 세이브엔 옛 값이 남아 F5로 안 드러난다**(새 게임에서만 죽는다).
- 🔴🔴 **시작 지급을 청산했다 — 3키(`rune_fire`·`jin_single`·`gr_radiate5`) + 완성 도안 1장뿐** (세88).
  **왜**: 시드가 있으면 챕터 보상·공방 제작·두루마리 드롭이 **소급 완료로 덮여 조용히 죽는다**(세58에 실제로 그랬다).
  🔴 **되살리지 마라.** ⚠ **만질 땐 두 곳이다** — codex만 걷어도 `to_assembly()`가 도안을 읽고 **codex를 안 봐서** 그대로 나간다.
- 🔴 **길잡이 NPC를 은퇴시키고 문이 화자·정산을 겸한다** (세95, 사용자 확정).
  **왜**: 새 세계관이 *"깨진 지 오래 · 그 뒤로 **아무도 안 모았다**"*인데 **사람이 서 있으면 「왜 그동안 안 주웠나」**가 생긴다.
  마을이 **셋**(문·책상·기념비 + 연습장)으로 더 줄어 *"마을 간단하게"*라는 요청에도 맞는다.
  🔴 **`npc_guide.tscn`·`.png`는 남긴다** — `base.tscn`에서만 뺐다(「주민 복귀」를 나중에 볼 여지 + `.tscn`은 로드만 안 되면 비용 0).
  🔴🔴 **[E] 하나에 두 일(정산 + 챕터 선택)을 태울 때 조용히 깨지는 자리가 넷이다** — 정본 = 설계 §2의 표 ⓐ~ⓓ.
  특히 **ⓑ**: 챕터 패널 열기를 `box.finished`에만 걸면 **대사 줄이 비는 경로에서 마을 밖으로 못 나가는 소프트락**이다.
  ⚠ **이 배선은 원래 무그물이었다**(실측: `test_quests_auto`는 씬을 안 띄우고, `test_base_auto`의 게이트 검사는
  기존 연결 하나로 이미 충족) → 옮기며 **`test_base_auto`에 정산 그물을 새로 세웠다.**
- 🔴 **진행도 = 기념비(깨진 마법진)에 문양이 하나씩 채워진다** (세95). 세89의 「건물이 서면 색조가 밝아진다」를 **안 쓴다**.
  **왜**: 진행도와 엔딩 조건이 **같은 물건**이어야 한다(다 차면 문이 마지막 길을 연다). 두 곳에 두면 갈라진다.
  🔴 **칸 수를 하드코딩하지 마라 — `data/glyph_rings/`에서 파생한다.** 파생식에 **`unlock_id == &""` 분기 필수**
  (스키마가 *"빈 값 = 항상 보유"*라 규약하는데 `is_unlocked(&"")`는 false다 → 빈 키 고리가 생기면 **엔딩이 도달 불가**, 에러 0).
  ⚠ 시작 시드가 `gr_radiate5` 한 장이라 **새 게임은 1/5가 켜진 채 시작한다**(시드를 옮기지 마라 — 「두 곳」 함정).
- 🔴 **마을은 셋이다 — 캐릭 + 마법문 + 마법 제작대(책상)** (세90, 사용자 확정).
  **왜**: 물건이 여섯 채 + 장식 22개라 산만했다. 지운 건 **「마을에서 여는 길」뿐**이고 프롭 씬·패널·레시피는 전부 살아 있다.
  **되돌리려면**: `base.gd`의 `STATION_UNLOCKS` 머리말 ①~④(씬 노드 + 표 + 퀘스트 `reward_unlock` + connect가 **한 덩어리**).
  ⚠ 이때 **배치 계약이 세89와 정반대로 뒤집혔다**: 세89는 *"온전한 건물은 첫 화면 밖"*이었는데, 마을이 줄자 그 계약이
  화면을 **빈 공터**로 만들어 → 「문·책상·길잡이가 첫 화면에 **통째로** 든다」로 바꿨다(`test_base_auto [11]`).

  ⚠ **예외 = 절차적 VFX**(`death_puff`·`vfx.gd` Line2D·진/문양 가이드선)는 애초에 그림이라 도형이 맞다.
- **아트 방향 = 숲마녀급 소프트 도트** (세18) · **납작하게 그리지 마라, 처음부터 입체로** (세69).
  격차는 크기가 아니라 **디테일·음영**이다. 기준 = 건물 스프라이트(`bld_*`).
- **없던 어휘 셋을 세웠다 — 제작 칸 · 표시 배율 · 화면 키** (세90). 「비율」의 정본이 이 셋이다.
  **왜**: GDD의 *"캐릭터 48px"*이 **프레임 크기**였고 실제 그림은 28px였는데 **문서에 실루엣을 적은 곳이 0**이라 아무도 몰랐다.
  🔴 같은 세션에 세운 「제작 32px + 표시 ×2」를 **같은 세션에 각하했다** — 그게 「배경과 따로 논다」를 더 벌렸다(밀도 1.49 → 0.37).
  → **표시 배율 ×1** · AI 작업 부담은 **픽셀 수가 아니라 색 수로** 줄인다. 정본 = `visual_language_design.md`.
- **주인공을 오리지널로 다시 그린다** (세90). penzilla 구매 에셋을 쓰던 걸 접었다(라이선스에 「AI 학습 금지」).

## 일하는 방식 (하네스 · 기록)

- 📖🔒 **`docs/GDD.md` = 「게임이 무엇인가」 단일 진실원** (세71). **수정에 사용자 허락이 필요하다**(settings.json `ask`).
  **왜**: 진실이 다섯 곳(CLAUDE.md·STATUS·WAND_CIRCLE·PROGRESSION·memory)에 흩어져 서로 어긋났다.
- 🔴 **기획은 위임하지 않는다 — 리드가 `takbon-design` 스킬로 사용자와 대화하며 확정한다** (세71).
  **왜**: 서브에이전트는 구조상 대화를 못 해 **혼자 정한다**(사용자: architect가 *"생각과 다르게"* 냈다).
  architect는 **확정된 설계를 받아 훑는 리뷰어**다 — 방향을 뒤집지 않는다.
- 🔴 **구현은 위임이 기본이다** (세48). 위임은 손을 던다기보다 **설계·리뷰 단계를 강제해 품질을 올리는 장치**다.
  **왜**: 옛 예외 목록(*"회귀 위험·core 스키마·mcp__godot·커밋은 리드"*)이 너무 넓어 **재밌는 작업이 죄다 예외에 걸려** 위임이 안 굴러갔다.
- 🔴 **리드가 절대 안 놓는 것 = 검증 · `--import` · 커밋.** **에이전트의 「그린 나왔습니다」를 근거로 쓰지 마라.**
  **F5·MCP도 리드가 직접 확인한다** (세85 — 「리드는 에디터를 켜지 마라」였던 세71~84 규율이 뒤집혔다).
- 🔴🔴 **초록불을 근거로 쓰지 마라 — 뮤테이션으로 검출력을 증명해라.** 규율 정본 = `takbon-verify` 스킬.
  ⚠ 되돌리기에 **`git checkout` 금지**(워킹트리를 통째로 되돌려 남의 미커밋 작업이 날아간다 — 세85에 3파일 소실).
- **검증 목록을 「손」에서 「파일시스템」으로 옮겼다** (세91). 전 스위트는 `for t in tests/*_auto.gd`로 **파생**한다.
  **왜**: 손으로 유지한 목록이 세51·84·87에 **세 번** 뒤처졌다(한 번은 지난 세 세션의 심장 테스트가 통째로 빠졌다).
  이제 새 테스트가 자동으로 들어 「절반만 돌고 다 돌렸다고 믿는」 실패가 **구조적으로 불가능**하다.
- 🔴 **에이전트는 네 축뿐이다 — architect(설계 리뷰) · dev(코드 전부) · reviewer(커밋 전) · art(그림 전부)** (세92, 사용자 확정).
  **왜**: 여덟이었는데 `ui`·`shader`·`animator`는 dev와, `relight`는 art와 **경계가 실효 없이 갈려** 라우팅만 늘렸다.
  흡수 전에 **고유 지식을 실측해 옮겼다**(ui의 모달 규약·테마 PNG 침묵사, animator의 좌/우 2방향, relight의 재익스포트 원복 함정).
  ⚠ 옛 이름은 설계문서·과거 기록에 그대로 남아 있다 — **해소표는 `CLAUDE.md`와 `takbon-rules` 두 곳**에 있다.
  🔴 **세94에 다섯이 됐다** — 아래 항목이 그 결정이다(넷으로 줄인 판단 자체는 유효하고, vfx만 근거를 갖춰 다시 갈랐다).
- 🔴 **`takbon-vfx`를 다시 갈랐다 — 다섯 축**(세94, 사용자 확정: *"VFX랑 아트 쪽 … 훨씬 빠르고 좋은 퀄리티로"*).
  **왜 세92 각하를 반복하지 않나**: 그때 접은 `shader`·`animator`는 dev와 **같은 파일·같은 지식**을 만져 라우팅만 늘렸다.
  vfx는 셋이 실제로 다르다 — ⓐ **고유 정본**(`docs/VFX_SPEC.md`, 세94 신설) ⓑ **고유 검수 도구**(`tools/vfx_shot.gd` —
  헤드리스 스위트로 대체 불가) ⓒ **고유 실패 양식**(🔴 *"에러 0 · 전 스위트 그린 · 그런데 화면이 밋밋하다"* — 테스트가
  구조적으로 못 잡는다). 🔴 **셋 중 하나라도 무너지면 dev로 되돌려라** — 그 은퇴 조건을 에이전트 파일 머리에 박아 뒀다.
  **경계** = 「돌아가라고 있는 것」(dev) vs 「보이라고 있는 것」(vfx) vs 「도트로 그릴 물건」(art).
- ❌ **애니메이션 축은 세우지 않는다** (세94, 사용자 확정 — vfx와 같은 잣대를 대서 나온 결론이다).
  같은 근거 셋을 애니에 대보니 **하나만 성립**했다: 고유 실패 양식(「에러 0인데 움직임이 어색」)은 있지만
  **고유 정본도 고유 검수 도구도 없었다.** 그 상태로 축을 세우면 세92가 `animator`를 접은 이유를 그대로 반복한다.
  🔴 **애니의 진짜 문제는 에이전트가 아니라 규격 부재였다** — 실측: **적 9종이 전부 `6.0` fps**(`forest_enemy._setup_frames`가
  하드코딩해 데이터를 안 본다). 그래서 **`ART_SPEC` §8(애니메이션)을 신설**하고(박자 기준선·하드 규칙·검수 한계)
  소비자인 `takbon-dev`가 그걸 읽도록 이었다. 실제 수정은 `BACKLOG` **N12**.
  ⚠ **필요해지면 도구부터 만들어라** — `vfx_shot.gd`와 같은 구조로 애니 검수 도구를 만들 수 있고, 그게 생기면 축을 다시 본다.
- 🔴🔴 **에이전트를 늘리는 것으로는 퀄리티가 안 오른다 — 「기준·눈」이 먼저다** (세94, 실측이 만든 결정).
  사용자 요청은 *"에이전트를 만들어서"*였지만, 실측하니 병목이 라우팅이 아니라 **셋**이었다:
  ⓐ **기준 부재** — VFX 정본이 0장이라 새 이펙트를 매번 즉흥으로 정했다(= *"이펙트마다 결이 다름"*).
  ⓑ **눈 부재** — art는 `export_frame scale 8`로 자기 그림을 보는데 VFX는 헤드리스가 못 봐 **확인이 전부 리드로 몰렸다**(= *"만드는 게 느림"*).
  ⓒ **정본이 거짓말** — `ART_SPEC.md`에 **네 세대가 층으로 쌓여** 있었고, 그게 `takbon-art`의 *"시작 전 반드시 Read"* 문서였다.
  🔴 **에이전트는 지식의 그릇일 뿐이다** — 빈 그릇을 더 만들면 같은 결과가 나온다. **순서는 기준 → 눈 → 에이전트다.**
- 🔴 **기록은 세션 서사가 아니라 결정만 남긴다** (세92, 사용자 확정) — **이 파일이 그 그릇이다.**
  **세션 로그(`STATUS.md`)·아카이브(`STATUS_ARCHIVE.md`)·하네스 변경 이력(`HARNESS_LOG.md`)을 전부 없앴다.**
  🔴 남은 문서는 **여섯**이다: **이 파일(결정)** · `BACKLOG.md`(작업) · `GDD.md`(🔒 정체성) · `PROGRESSION.md`(관문) ·
  `ONBOARDING_FLOW.md` · `ART_SPEC.md` — 그리고 `CLAUDE.md`(함정·계약) + `takbon-design/`(설계) + memory(세부).
  ⚠ 아카이브를 지울 때 **세90 서사는 git에도 없어 실제로 증발했다**(사용자 확정) — 그 결정·작업·세부는
  이 파일과 `BACKLOG.md`의 `N0~N10`, memory 두 장(`takbon-village-trimmed-s90`·`takbon-visual-language-s90`)에 이미 추출돼 있었다.

### 하네스가 어떻게 생겼나 (세39~92 · 옛 `HARNESS_LOG.md`에서 핵심만 흡수)

- **자립형이다** — godot-prompter 플러그인을 껐고(세39), 제네릭 Godot 스킬을 `.claude/skills/`로 **복사**해 플러그인 없이 돈다.
  그 스킬들은 **한국어로 번역된 탁본 로컬 포크**라 상류를 안 따라간다(세71에 상류 대조를 접었다 — 영어 원본은 상류 github).
  🔴 **스킬 본문은 상주하지 않는다** — 매 세션 로드되는 건 **frontmatter뿐**이고 본문은 호출될 때만 온다.
  그래서 **「안 쓰는 스킬이 매 세션 비용을 먹는다」는 거짓**이고, 세87에 그 전제로 삭제하려다 실측이 막았다.
- 🔴 **스킬 삭제 = 방향 포기 신호다.** 그래서 지울 땐 「형식상 무관」만 지운다(3D·C#·모바일·XR 등).
  멀티 3종은 사용자가 **방향 자체를 접고 나서야**(세75) 지웠고, `beehave`·`limboai`·`localization`은 아직 유지한다(BT 보스 AI·다국어를 안 접었다).
- 🔴 **에이전트에게 「보고서를 파일로 써라」고 지시해라** — **채팅 최종 보고는 리드에게 안 온다**(idle 알림만 온다).
  세48~49에 4건이 그렇게 증발했다. 특히 architect·reviewer는 **산출물이 보고서뿐**이라 파일로 안 시키면 작업 전체가 사라진다.
- ⚠ **뮤테이션을 시킬 땐 원상복구까지가 지시다** — 되돌린 채 두면 기능이 조용히 죽은 채 커밋된다.
- 🔴🔴 **하네스에서 무언가를 지우기 전엔 「무엇이 사라지나」를 실측해라.** 세87(스킬)·세91(설계문서)·세92(에이전트·memory)에
  **세 번 다 실측이 삭제 논거를 무너뜨렸다.** 방법 = 대상의 백틱 식별자를 뽑아 살아있는 정본에 있는지 대조 → **없는 개수 = 고유 세부의 양.**
  ⚠ 「참조 0건」을 근거로 쓸 땐 **백틱만 세지 마라**(세87에 평문 참조를 못 세 「0건」이 나왔는데 실은 셋 다 실재했다).
