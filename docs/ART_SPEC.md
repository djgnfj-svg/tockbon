## 🔴🔴 아트 방향 전환 (2026-07-16 세션 18) — 퀄리티 목표 = 「숲속의 작은 마녀」급

> 사용자 확정. 아래 §"불변 규칙"의 옛 수치(640×360·32px·16px 타일)는 **이 절이 갱신·대체**한다.
> 목표 톤 정본 = 이 절 + memory `takbon-art-direction-lwitw`.

**조사 결론 (숲마녀 아트의 정체):** 「숲속의 작은 마녀」(Sunny Side Up, Unity) 퀄리티는 **① 극단적 손노동
(풀 스프라이트 프레임 애니, 대표 1인 1만 시간+) ② 부드러운 회화풍 음영(평평 셀셰이딩 아님) ③ 분위기(라이팅·
파티클·배경 밀도)**가 만든다. **실측**: 캐릭터 화면 점유율은 우리와 거의 같다(~9%) → **"크기"가 아니라
디테일·내부해상도·음영이 격차.** 진짜 스크린샷 캐릭터는 **원본 ~50px 안팎**으로 보인다.

**확정 결정:**

1. **내부 렌더 해상도 640×360 → `960×540`** (디테일 2배). 출력 1920×1080에 **×2 정수 배율**(자글거림 없음) +
   `aspect="keep"`로 남는 화면 **검정 레터박스**. **project.godot 적용 완료**(viewport 960×540 · window
   1920×1080 · stretch canvas_items/integer/keep). ⚠ **씬·HUD·스프라이트는 전부 옛 640×360 기준이라
   지금 화면은 작게·흩어져 보인다** — 씬·UI 재배치는 다음 세션 작업(알려진 상태, 버그 아님).

2. **캐릭터/적 32×32 → `48×48`.** 이유(사용자): **장비가 티 나야 한다** + 부드러운 음영을 넣을 픽셀 공간.
   보스·타일·UI 아이콘 새 크기(타일 16→24?, 아이콘 16→24?)는 **캐릭터 톤 확정 후 결정(미정)**.

3. **장비 = 4칸 `지팡이·로브·모자·신발`** (기존 부적 폐지). 캐릭터는 **레이어(페이퍼돌)** 구조로 만든다 —
   기본 몸 + 로브 + 모자 + 지팡이 + 신발을 겹쳐 그려 **착용 장비가 스프라이트에 보이게** 한다.
   ⚠ **코드 미배선** — `GameState.equipment`는 아직 WAND/ROBE/CHARM. 장비 4칸 재정의 + 레이어 합성은 TODO.

4. **팔레트 Apollo 46 하드 제한은 소프트 음영과 충돌** → **완화 검토(미확정).** 골든 샘플은 목표 톤을 위해
   Apollo 밖 색을 썼다. 팔레트 정책은 캐릭터 확정과 함께 재결정.

**검증·산출물 (세션 18, 전부 scratchpad — 게임 미적용):**
- `player_golden.aseprite` — 견습 필경사 48px 정면 골든 샘플(로브+금장식+붓, 구형 소프트 음영). 목표 톤 증거.
- 장비 교체 데모(같은 몸 + 다른 로브·지팡이·부적) → 48px에서 장비가 확실히 구분됨을 확인.
- 엘리(숲마녀 주인공) 48px 스터디 ~90% → **48px에서 숲마녀급 마녀룩 재현 가능** 확인. ⚠ 엘리는 남의
  저작권 캐릭터라 **복제본은 게임에 못 쓴다** — 스타일 참고만. **오리지널 마녀 주인공 디자인은 나중**(미정).

**🔴 다음(아트):** (a) 씬·HUD·스프라이트를 960×540에 맞춰 재배치·재작도. (b) 주인공 최종 디자인 확정(견습
필경사 유지 vs 마녀 전환 — 미정) 후 48px 전신 세트(4방향·걷기·대시·탁본) + 레이어 분리. (c) 장비 4칸
코드 재정의 + 레이어 합성 배선. (d) 팔레트 정책 재결정. (e) 분위기(라이팅·파티클) — 가장 싼 레버.

## ⚠ 미해결 — "자글자글" 노이즈 (세션 5 사용자 지적, 플레이 검증 후 착수)

전체화면에서 **바닥·UI·캐릭터 전반이 자글거린다.** 스케일링은 정상(2560×1440 ÷ 640×360 = 정확히 4배 정수).
원인은 에셋의 **고립된 1픽셀 고대비 노이즈**("소금후추"). 타일셋 실측: 풀 기본 10/256px·명도차 37.7,
풀 변형 11/256·명도차 75.9, 보스존 바닥 25/256. 4배 확대 시 4×4 덩어리가 되어 화면을 뒤덮는다.

**교훈 (다음 에셋 작업 시 반드시 지킬 것):**
- 질감을 **고립된 1픽셀**로 만들지 말 것 — 2~4px 덩어리라야 "의도된 디테일"로 읽히고, 낱픽셀은 노이즈로 읽힌다
- 질감의 **명도차는 12 이내**로. Apollo 녹색 g(103) ↔ e(67)는 명도차 36 — 질감용으론 너무 큼
- **넓은 면(바닥·벽)은 조용해야 한다.** 디테일은 드문 특징 타일(술·꽃·문양)에 몰아줄 것 — 캐릭터·적 가독성 확보
- 검수는 x8 단일 타일이 아니라 **화면 전체(인게임 스크린샷)** 기준으로 — 단일 타일로는 절대 안 보이는 결함이다

## 교체 순서 메모
