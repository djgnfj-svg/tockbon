# 개발지식 — **만들기 전에 읽는 것**

**여기는 한국어다.** 사용자가 읽는 폴더이고, 읽기 쉬운 것이 이 폴더의 목적이다
(2026-08-31, 사용자: 「그 폴더는 한국어로 되어있고 내가 읽기 좋게 되어있는 거예요」).

**폴더 하나가 기술 하나다.** 그 안에는 항상 셋이 있다.

| 파일 | 무엇 |
|---|---|
| `README.md` | **한국어 문서.** 무엇이 어긋나나 · 왜 그러나 · 그래서 무엇을 하나 |
| `그림.svg` | **예제 그림.** 글로 두 문단 걸리는 것을 한 장으로 |
| `예제.gd` · `예제.py` · `예제.gdshader` | **돌아가는 코드 조각.** 베껴서 고쳐 쓰라고 있는 것 |

## 목차

⚠⚠ **아직 하나도 없다.** 무슨 주제를 넣을지는 사용자가 정하고, **한 번에 하나씩** 만든다.

| 번호 | 주제 | 상태 |
|---|---|---|
| **01** | **2D 판때기를 3D 에 넣을 때 어색하지 않게 하는 법** | ⬜ **정해졌고 아직 안 만들었다** (2026-08-31) |

**01 이 갖출 것 넷** — 사용자가 말한 그대로다.

1. **참고자료** — 누가 · 어느 게임에서 · 뭐라고 말했나. 링크와 인용까지
2. **기법 목록** — 자료마다 나오는 「이래서 어색하다 → 이렇게 한다」
3. **구현** — 고도에서 실제로 어떻게 짜는가
4. **켜고 끄는 실험대** — ⚠⚠ **기법이 넷이면 화면은 16 가지다.** 아무것도 안 켠 것 하나, 하나만 넷,
   둘씩 여섯, 셋씩 넷, 넷 다 하나. **씬을 열여섯 개 만드는 게 아니라 씬 하나에 스위치 넷이다**

## 여기 안 쓰는 것

**같은 사실이 두 군데 있으면 반드시 어긋난다.** 그래서 아래 것들은 여기 안 적고 그 자리에 적는다.

| 그 사실이 | 어디로 | 왜 여기가 아닌가 |
|---|---|---|
| **초록인데 거짓말한 검사** | `docs/how-nets-lie.md` | 이미 실측 사례만 587 줄이다 |
| **이 저장소 블렌더 스크립트 쓰는 법** | `tools/blender/README.md` | 함정 다섯, 전부 그 스크립트 것이다 |
| **이 게임의 낱말** | `CONTEXT.md` | 용어집. 한국어 낱말이 곧 이름이다 |
| **왜 그렇게 정해졌나** | `docs/roadmap/log.md` | 사용자가 한 말은 전부 거기 있다 |
| **밖에서 찾아온 자료와 출처** | `docs/reference/` | 날짜별, 질문 하나에 파일 하나, 줄마다 출처 |
| **무엇을 언제 만드나** | `docs/roadmap/README.md` | 지도 |

⚠ **`docs/reference/` 와 여기의 차이 하나** — 그쪽은 **질문 하나에 출처를 붙여 답한 자료**이고,
여기는 **그걸 읽고 「그래서 뭘 지킬 건가」로 줄인 것**이다. 출처가 필요하면 문서 끝에서 그쪽을 가리킨다.

## 문서 하나가 갖춰야 하는 것 넷

| | |
|---|---|
| **실측** | ⚠⚠ **숫자와 그걸 어떻게 쟀는지.** 「알려져 있다」는 실측이 아니다 |
| **오래 감** | 이번 섬, 이번 티켓, 이번 주가 지나도 참이어야 한다 |
| **겹치지 않음** | 위 표의 어느 칸도 이미 들고 있지 않아야 한다 |
| **써먹을 수 있음** | 다음에 뭘 칠지가 바뀌어야 한다. **증상만 있고 지시가 없으면 무용담이다** |

⚠ **틀린 게 나오면 고쳐 쓰되 틀렸던 줄은 남긴다.** 「이 도구는 안 된다」고 적힌 문서가 나흘을 잡아먹은
적이 있다 — **도구가 고장 났다는 문서는 인용할 게 아니라 다시 시험해 볼 것이다.**
