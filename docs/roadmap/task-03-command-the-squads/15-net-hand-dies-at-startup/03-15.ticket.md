### ⚠⚠ What the runner does with a process that dies

**Read from `tests/run_nets.ps1` today.** Every detector that could catch a half-dead net —
the zero-check line and the `run() 이 끝까지 못 갔다` sentinel — **lives inside the process**, in
`tests/run_nets.gd`. **A process that dies at startup outruns all of them.** Outside, in PowerShell, a
net is red when it timed out, when its exit code is non-zero, or when there is undeclared noise on
stderr. **That is the whole list.**

| The shape | What the round does | Caught? |
|---|---|---|
| **Dies with a non-zero exit code** — today's case | **Red row, wrapper exit 1.** ⚠ but what it adds to the `실패` column is **0**, because failures are counted only from lines beginning `x ` and it printed none. **It subtracts 91 from 통과 and adds nothing to 실패** | **yes, as a red — no, as a number** |
| **Dies, or quits, with exit code 0 and prints nothing** | pass 0 · fail 0 · no noise · not timed out ⇒ **not bad.** **A grey `통과 0` row and a green wrapper** | ⚠⚠ **NO** |
| **Its file stops being scanned** (renamed, deleted) | The folder scan simply lists one fewer. **The only guard is「fewer than 5 net files」**, and there are **16** | ⚠⚠ **NO** |

⚠⚠ **The second row is not hypothetical in this repo.** `run_nets.gd`'s own header records a severed
`await` that made a net report `[net] 0 passed` with exit code 0, **and the only thing that caught it was
a human noticing the count fall 5 → 0.**

⇒ **Nothing compares a round's total against the last one.** There is no per-net expected row count and no
stored baseline — the runner keeps each net's seconds between rounds and nothing else, and
`tests/README.md` says the count lives in the log and is written by hand. **So 「통과 1567」 is a label
whose number nobody re-derives**, which is the exact failure `docs/how-nets-lie` is a casebook of.
**Today's red is the good failure. The same crash on the third row's shape is the bad one.**

### ⚠⚠ Amended 2026-09-02 after `adversary` — the guard was closing the wrong hole

**⚠⚠ 「stdout carries no `[net]` line」 does not cover the incident this plan quotes.** `run_nets.gd`
prints its summary **unconditionally** on every path that reaches the end — including the path where the
filter selected nothing and the loop body never ran. **The measured incident printed `[net] 0 passed` and
exited 0**, so the proposed operand reads a `[net]` line and stays grey. ⇒ **The predicate is 「the net
ran no checks」** — a `[net] 0 passed` summary — **not 「no summary at all」.** ⚠ On the old predicate the
operand's exclusive coverage was very close to empty: a parse failure puts `SCRIPT ERROR` on stderr and
the noise verdict already reddens it, and a crash exits non-zero and the exit-code verdict already does.

**⚠ And it goes in BOTH paths.** `$bad` lives only in the parallel aggregation. **`-Serial` computes its
own verdict and exits before reaching it** — and `-Serial` is documented as *the control when the
parallel result is suspect*, which is the exact path somebody reaches for to investigate this defect.

**⚠⚠ The first loop was contaminated and under-recorded. It is being re-run.**

- **It printed 5 exit codes a round out of 16.** The runner only printed a row for a net that failed, had
  noise, or died — and the exit code is **the one detector that caught this on Windows.** ⇒ **Every net's
  exit code, every round, unconditionally**
- **Its verdict did not mirror the wrapper's.** Undeclared stderr counted as clean, and every round
  carries 879 such lines. Under the real wrapper two nets are red every round on noise alone
- **A graphical Godot ran across rounds 8 and 9** — a screenshot check on the same box. **Round 9 is the
  single outlier at 50.5 s against 39.6–42.1 for every other round.** ⇒ **The loop re-runs with nothing
  else on the machine**

**⚠⚠ 「Sixteen on four cores is a harsher test」 is withdrawn.** It ranked two machines on a mechanism this
plan expressly refuses to name, and **the loop's own numbers cut against it**: 20 of 20 rounds came back
bit-identical at 1567 · 4 · 879, while the three Windows rounds this ticket records are 1567, 1566 and
1565. **A box that does not reproduce the suite's ordinary variance is not a harsher probe of anything.**
⇒ **What the Linux loop measures is whether the shape survives the OS change. Nothing more, and the
answer does not travel back to Windows.**

**⚠ The stillness is file stillness, not machine stillness.** Godot's user directory is keyed on the
project name, which is identical in both checkouts — **so both trees share one log directory and race the
same rotation with no lock**, and the rotated files are 0 and 72 bytes, the same size class as this
ticket's 「75 bytes, banner and nothing else」. **That is shared mutable state the worktree does not
isolate, and it is not the `.godot/` this plan named as the lead.**

**⚠ The fingerprint comparison this ticket orders cannot be run across the worktree.** The digest folds
each file's **absolute path** in, so a detached checkout hashes differently from the working tree byte
for byte. **The Linux rounds cannot be lined up against the recorded Windows fingerprints at all.**

**⚠ Shape 3 stays left alone, and the stated reason is replaced.** It said closing it needs a remembered
net count and that only the timings cache could remember one. **The runner already remembers a count with
no shared state — the 「fewer than five net files」 floor** — so the reason was wrong even though the
decision stands. ⇒ **The real reason: the floor is a constant that has to be edited every time the net
count changes, and this repo has already rejected a hand-kept net list.** Raising 5 toward 16 buys one
missing net and costs a number nobody will remember to move.
