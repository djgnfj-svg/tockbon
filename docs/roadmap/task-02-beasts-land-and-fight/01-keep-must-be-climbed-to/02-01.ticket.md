## What this ticket builds

**Nothing yet — this is the decision that comes first, and it is the one thing holding 2 주 shut.**

**The 성채 stands on 눈금 2 and a 늑대 standing on 눈금 0 beside it can hit it anyway.** The bar for this
week is 「막아 내거나 진다」, and **a board where the 계단 can be walked past is a board with no reason to
defend anything.**

### What was measured, in code

| What | Number |
|---|---|
| **성채 자리** | 섬 파일의 (10, 12), 2x2, **네 조각 전부 눈금 2** |
| **성채를 두른 1층 자리** | **여덟 개, 전부 고원 가장자리에 붙어 있다** |
| **1층에서 2층 성채 조각까지** | 평면 1 조각 · 높이 1 조각 → **1.414** |
| **대각선으로 붙어도** | **1.732** |
| **늑대 사거리** | **1.75** (사거리 칸 0 + `REACH_BONUS`) |
| **계단** | **네 조각뿐 — (6,6)·(7,6)·(6,7)·(7,7)**, 성채 반대편이다 |
| **해변에서 이기는 판** | **61 중 24 에서 계단을 안 밟고 이기고, 그쪽이 세 배 빠르다** |

⇒ **성채를 두른 1층 여덟 자리 전부에서 닿는다.**

⚠⚠ **It is not that height is ignored.** `keep_gap` already squares the height difference in and
measures 1.414 correctly — **the reach is simply longer than that.**

### ⚠ Why the reach value cannot be the fix

**1.75 was chosen by measurement so a body on a 계단 can strike an enemy one 눈금 above it.** Lower it and
nobody can strike from a 계단 at all — **26 of 162 runs were lost that way when it was tried.**
`rules.gd`'s own comment already says the fix belongs where the height is known.

## Screen

**none.** Nothing is drawn by this ticket — it decides a rule. ⚠ **If the answer needs a mark on the

## Done when

**The user has said what stops the 성채 burning from 눈금 0.** There are several ways and the user picks.

⚠ **Not done when the model picks one.**

## Implementation plan

**The rule the user chose, 2026-09-01**: *"do it as recommended"* — **a blow cannot cross a 눈금 gap
greater than `Rules.MAX_CLIMB_LEVELS`.** That constant is 1 and it already owns the walking rule, so
the strike rule is the same threshold rather than a new number.

⚠⚠ **Distance cannot separate the two cases and that is why this is a level rule.** 1층 → 성채 and
계단 → 성채 are both **1.414**. What differs is the 눈금 gap: **2 against 1.**

### Seams

**`src/sim/` only** — `Grid` and `Battle` are both constructible with `.new()`, and a net drives the
whole thing headless. **No new seam.**

### Files to touch and why

| File | Why |
|---|---|
| `src/sim/grid.gd` | **`can_strike(from_tile, to_tile)` beside `can_step`** — levels only, no passability and no shoulders. A blow is not a step, so it gets its own name rather than widening `can_step`'s meaning in place |
| `src/sim/battle.gd` | **`keep_gap` skips a 성채 조각 out of the striker's level reach.** `_phase_targeting` and `_phase_attacks` both already go through `keep_gap`, so one change covers choosing a target and landing a blow |
| `tests/nets/net_fight.gd` | The rows that hold the reach behaviour |

### Order

1. `Grid.can_strike`, with its own net rows.
2. `Battle.keep_gap` consults it — the striker's 조각 comes from `_tile_of(p)`, which this file already has.
3. Re-measure the eight 1층 자리 and the four 계단 조각.

### Risk

- ⚠⚠ **The 성채 can come out unkillable, which is the same defect inverted.** Its four 조각 are all
  눈금 2 and the only 눈금 1-or-2 자리 beside them are the plateau and the 계단. **If nothing walks up,
  `keep_hp` never falls and the round cannot be lost.** ⇒ **Run the 61 판 harness after and count how
  many are still lost. If none are, the fix is wrong.**
- **Beasts walk at the 성채 through the flow field**, which already uses `can_step`. They will crowd at
  the plateau foot. That is the pressure toward the 계단 this ticket wants, but it has to be watched
  rather than assumed.
- `net_fight` holds the current reach behaviour. **Read every red row before changing it** — one of
  them may be the row that says a 계단 still works.

### Acceptance

- A 늑대 on any of the eight 1층 자리 around the 성채 has `enemy_target == TARGET_NONE` and `keep_hp`
  stays at 240.
- A 늑대 on a 계단 조각 (눈금 1) beside a 눈금 2 조각 still targets it and still lands a blow.
- Across the 61 판 harness the 성채 still falls in some of them.

### Out of scope

- ⚠ **Body against body across the same gap.** A 늑대 on 눈금 0 and a 검사 on 눈금 2 orthogonally
  adjacent are 1.414 apart and can still hit each other after this. **The same predicate closes it**,
  but this ticket's Done when names the 성채 alone, so it is written down here rather than built.
- **No mark on the ground.** The ticket says a mark is a different ticket and it is made in a tool.

## Answer

**눈금 차이가 2 이상이면 못 때린다** (2026-09-01, the user, choosing the recommendation put to them:
*"do all sixteen of those as recommended"* 「이 위에 열여섯 개 물어봤던 거 다 추천대로 좀 해줘」).

**Why this one and not the others**: the walking rule already says a body crosses at most one 눈금
(`Rules.MAX_CLIMB_LEVELS` = 1). Using the same line for a blow adds no second number to the game, and
the reach value — which cost 26 losses in 162 runs when it was lowered — is not touched.
