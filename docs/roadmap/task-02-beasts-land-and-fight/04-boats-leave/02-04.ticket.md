## What this ticket builds

**A boat that has put its 늑대 on the beach leaves the screen.**

> The user, 2026-09-01: *"after the boat arrives it does not disappear, does it? It does have to
> disappear."* (「배가 도착한 다음에 배가 안 사라지거든? 배가 사라지긴 해야 돼」)

⚠⚠ **THIS REVERSES A LINE THAT WAS DELIBERATE.** 티켓 41 wrote 「배는 쌓인다」 and the code says so in
three places: *"an ARRIVED boat here never leaves"*, *"They pile up on purpose. Nothing removes a boat
this round"*, and *"An emptied boat is not removed."* **The hull arrays only ever grow.**

### What stands today

- **A boat is born every `BOAT_INTERVAL_SEC` = 30 초**, the first at 5 초
- **Nothing erases a hull, ever** — append-only by design
- **The view pools hulls and hides them, never frees them** — the picture follows whatever the sim
  says, and the sim never says gone

## Implementation plan

### What the user answered, 2026-09-01

| Question | Answer |
|---|---|
| **How many seconds is 「몇 초」** | **3 초** |

### Seams

- **`src/sim/`** — a `Battle` built with `.new()` and stepped. The countdown and the flip are measured
  here.
- **`src/view/`** — pooled hull state. The view already pools hulls and hides them rather than freeing
  them, **so this is the sim state it was waiting for.**

### Files to touch and why

| File | Why |
|---|---|
| `src/sim/rules.gd` | `BOAT_LINGER_SEC := 3.0` |
| `src/sim/battle.gd` | **A third `BoatState`, `GONE`, and a per-hull countdown column.** ⚠ The file's header says an enum member no path can enter is a slot a future writer fills by accident — **this one is entered, so it is legal**, and the note beside `BoatState` has to be corrected rather than left saying there are two |
| `src/view/field_view.gd` | `_paint_boats` skips a GONE hull and the pooled node hides |
| `tests/nets/net_boats.gd` | The countdown and the flip |

⚠⚠ **The hull arrays still never shrink.** A row flips to GONE and stays where it is — the same
contract `enemy_alive` and `Army.alive` keep, and for the same reason: **an index is an identity** and
the view holds indices.

### Order

1. `BOAT_LINGER_SEC`.
2. A `boat_linger` column, set at the ARRIVED flip inside `_phase_boats`.
3. Count it down in `_phase_boats`; flip to GONE at zero.
4. `_phase_landings` refuses a GONE hull.
5. The view skips GONE.
6. Nets.

### Risk

- ⚠⚠ **A hull must not vanish with riders still aboard.** `_phase_boats` runs before `_phase_landings`,
  so an ARRIVED hull unloads in the same sub-step it arrives — **confirm the whole load goes at once**
  rather than one rider a sub-step, or three seconds is a number that hides a leak.
- **`boat_riders` counts.** A GONE hull's riders must not be re-landed or double-counted.
- **The view's hull pool is indexed by hull row.** Hiding one by index must not shift the pool, which is
  exactly the shape that makes a second boat wear the first one's position.
- **Three lines in the code say a boat never leaves** — *"an ARRIVED boat here never leaves"*, *"They
  pile up on purpose. Nothing removes a boat this round"*, *"An emptied boat is not removed."*
  **All three are now false and have to be rewritten, not left standing.**

### Acceptance

- Headless: step past the first boat's arrival plus 3 초. `boat_state[0] == GONE` and every rider it
  carried is a living beast standing on the island.
- The hull's pooled node is `visible == false`.
- The hull arrays are the same length before and after — nothing was removed.

### Out of scope

- A fade, a wake that lingers, a boat sailing back out.
- Anything about how many boats or how often — that is 02-05.

## Answer

**3 초 있다가 컷으로 사라진다** (2026-09-01, the user, choosing both recommendations: *"do all sixteen of
those as recommended"* 「이 위에 열여섯 개 물어봤던 거 다 추천대로 좀 해줘」).

**The reasons put with them**: a boat comes every 30 초, so 3 초 is long enough to watch the unloading
and still clear the water before the next one; and the user called the disappearance a game-y allowance
themselves, so a fade would be one shader for a fiction nobody asked to hold up.
