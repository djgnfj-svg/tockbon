## Implementation plan

### What the user answered, 2026-09-01

| Question | Answer |
|---|---|
| **What stays behind the words** | **The island, exactly as it stood** |
| **Does the game stop there** | **Yes** |

### Seams

- **`src/shell/` — `_ready()`.** The shell is the only thing that may read `battle.lost` and tell the
  view; `src/view/` reads `sim` and writes nothing back.
- **`src/view/` — the HUD's `_paint_*` hooks.** `net_draw_leaf` pins each hook's `draw_*` count exactly
  **and reddens any function in `hud_view` it does not name**, so a new hook is red until it is listed.

### ⚠⚠ The lettering is made, never typed

**`draw_string` chrome is what ships if it is written.** The words GAME OVER come out of `tools/pixel/`
or pixellab as one red picture and are loaded. **This is the exact failure `CLAUDE.md` carries by name**
— the island wore a grey button and a digit nobody chose.

### Files to touch and why

| File | Why |
|---|---|
| `tools/pixel/` or pixellab | **One picture: the words GAME OVER, red** |
| `src/look.gd` | The picture's path and where on screen it sits |
| `src/view/hud_view.gd` | **One `_paint_over()` hook**, drawing that one texture and nothing else. `_draw` has been `pass` since 2026-08-28 and this is the first thing back in it |
| `tests/nets/net_draw_leaf.gd` | **Name the new hook or it is red** — that is the net's design, not a defect |
| `src/shell/game.gd` | Reads `battle.lost` and turns the hook on. The island keeps drawing behind it |

### Order

1. The picture.
2. `look.gd`.
3. The hook in `hud_view`.
4. Name it in `net_draw_leaf`.
5. Wire it in the shell.

### Risk

- **The sim already stops itself.** `step` returns early while `lost`, so the board freezes with no help
  from the view. ⚠ **The camera does not** — the shell still takes tilt, zoom and pan input. **「끝」 has
  to mean the board stops answering too**, or the player sits turning a dead island. **Decide it in the
  build and look at it on screen.**
- `hud_view` is a `Node2D` over a 3D field. The picture is screen-space, so it does not move with the
  camera — confirm it survives a window resize rather than assuming `VIEWPORT_W_PX` holds.

### Acceptance

- Drive `keep_hp` to 0 headless: `lost` is true and the shell turns the hook on in the same frame.
- **The island is still drawn behind the words** — the field's surface counts are unchanged.
- `net_draw_leaf` names the hook and its `draw_*` count is exactly one.

### Out of scope

- ⚠ **The stats screen — which 부대 dealt how much.** The user deferred it themselves the same day:
  *"but this is for later, a later ticket."*
- A win screen.
- Anything that restarts the run or returns to the title.

### What went in

| Where | What |
|---|---|

| `src/look.gd` | The picture path, the gap under the lettering, and **`back_to_title_rect_px`** — the rect derived from both pictures' own sizes, the same argument `game_over_origin_px` already makes |

| `src/shell/game.gd` | **`_back_to_title()`**, and the one press that still lands on a lost board |
| `tests/nets/net_draw_leaf.gd` | The two new names. **An unlisted function in this file is red by design** |

### ⚠ What the button does NOT do

**It discards the run.** 시작하기 makes a fresh `Run`, so pressing it after this is a new game and not a
resumed one. **That is what 「타이틀로」 was asked for** — a continue is a different button with a
different word on it, and it is not this ticket.
