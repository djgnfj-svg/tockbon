# 지팡이-마법진 = 자유도 해법 방향 (세션 44 설계 확정)

> 이 문서는 **아직 안 지어진 설계 방향**이다. 정본은 이 문서 + memory `takbon-wand-inscribe-circle`.
> 코어 재미 구멍(memory `takbon-magic-no-freedom`)의 해결 방향으로 세션 44 대화에서 확정됐다.

## 문제 (재확인)

- **자유도를 줬는데 시작하면 모두 똑같다.** 다들 "마법 1번"을 쓰고, 사실상 같다.
- **자유도가 열리는 데 오래 걸린다** (룬 불 하나로 시작 → 물·바람은 해독으로만).
- 세 갈래(늦게 하나씩 열기 / 시작에 다 주기 / 천장을 먼저 보여주기) 중 **하나를 고르는 문제로 보여 애매했다.**
- 그리고 발사 변형을 **장비(`wand_pattern`)로 빼놓은 게 "그리는 재미에 반한다"** — 재미가 그리기 밖으로 샜다.

## 확정된 그림 (사용자 결정)

**바닥 + 즉시 자유의 조합**으로 세 갈래의 애매함을 빠져나간다:

- **바닥(floor) = 기본 매직볼.** 아무것도 없을 때 주는 기본 마법. → "모두 똑같다"는 문제가 아니다.
  그건 **출발선**일 뿐이다.
- **자유(freedom) = 시작하자마자 내 지팡이에 마법진을 그려 넣는다.** 내 방향/루트로 나가는 내 마법.
  → 자유가 **즉시** 열린다 (①학파 = 처음부터 샌드박스).

### 지팡이에 무엇이 박히고, 무엇을 그리나 (사용자 확정)

> *"지팡이 같은 인챈트는 진이 이미 박혀져 있어서, 그때 따라서 본인이 알아서 가진 룬과 문양으로
> 그림을 그려야 되는 거예요. 평타를 그린다기보다는 **방식을 그리는 거지.**"*

- **지팡이 = 진(형태/그릇)이 박혀 있는 인챈트.** 진은 지팡이가 정한다 — 다른 지팡이 = 다른 진.
- **플레이어가 그리는 것 = 자기가 가진 룬 + 문양** — 박힌 진을 따라 그린다 = **"방식을 그린다."**
- 기존 문법과 정합: **진=형태 / 룬=속성 / 문양=구현 방식** (memory `takbon-magic-grammar`).
  바뀐 것은 단 하나 — **진이 지팡이에서 온다** (전엔 "일반진 하나"로 고정).
- **표현 = 지팡이(진) × 내가 그린 룬·문양.**

### 튜토리얼

기본 매직볼을 쥐고 + 자신만의 마법 지팡이(진이 박힌)를 얻어 → 룬·문양을 그려 넣고 → 첫 숲으로.
(세션 41 온보딩 레일에 붙인다.)

## 지금 코드와의 간극 (구현 시 정할 것)

- 지금 **지팡이(`equipment[WAND]`)와 마법진(`ring_designs`/`ring_equipped`)은 딴 물건**이다.
  발사 때 `ring_spell_system._on_ring_cast`가 둘을 합친다: 마법진이 룬+문양+점수를, 지팡이가
  `wand_pattern`(산탄 부채꼴)을 준다. → **새 모델 = 이 둘을 "지팡이에 박힌 진" 하나로 통합.**
- **씨앗은 이미 있다**: `wand_pattern`(SINGLE/MULTI/NOVA)이 곧 "지팡이가 발사 형태를 정한다."
  이걸 숨은 스탯에서 **"지팡이에 박힌 진"으로 끌어올리면** 된다.
- **매직볼 = 바닥**: 슬롯이 비어도(안 그렸어도) 지팡이의 진으로 기본 발사가 나가야 한다.
  지금은 `player_caster.fire()`가 빈 슬롯이면 그냥 거부한다 — 여기가 바닥이 앉을 자리.

## 남은 열린 조건 (B로 이어짐)

- 내 진이 매직볼보다 **"더 세게"가 아니라 "다르게"** 나가야 자유도가 진짜가 된다.
  지금은 문양 조합이 결국 위력(세기)으로 수렴한다(`ring_power.power_of`). **문양이 종류(관통·분열·
  유도·연쇄·설치)를 바꾸는 축**을 여는 게 B. (memory `takbon-magic-no-freedom` §How to apply.)

### 🔴🔴 세션44 발견 — "다르게 나간다" 효과 기계가 **이미 완비돼 있다 (DARK)**

  만드는 게 아니라 「그린 문양 → 이미 있는 effects」로 배선**하는 일. 비용이 훨씬 작다.

  **관통·유도를 그릴 어휘 자체가 없다.**

## 세션47 말 — 사용자가 낸 다음 방향

### ① 문양 = **나가는 모양이 바뀐다.** 여러 개 만들면 된다 (사용자 확정 · 복잡하지 않다)

사용자 확정(세션47 말): *"문양은 여러 개 만들면 되긴 해. 그냥 **나가는 모양이 변경된다**는 것만
알면 됨."*

- **이게 문양 축의 전부다.** 진 안/밖 같은 **층 구분을 세우지 마라** — 대화 중에 그런 말이 오갔고
  리드가 한때 "두 층 = 재배치 필요"로 크게 적었으나 **사용자가 직접 정정했다.** 모델은 단순하다:
  **문양을 그리면 나가는 모양(전투 방식)이 달라진다.**
- 그래서 **세션47이 한 일이 곧 이 방향이다** — 관통·유도·팅김·추진이 정확히 "나가는 모양"이다.
  추가 재설계 없이 **`.tres` + `GlyphCode` + `BOLT_EFFECTS` 한 줄씩으로 계속 늘리면 된다**(위 4번 참조).
- ⚠ **다음 세션 과제가 아니다**(사용자: *"다음 세션에서 할 게 아니야"*). 어휘를 더 늘리고 싶을 때
  꺼내 쓰는 **열린 레인**이지 블로킹 결정이 아니다.
- 늘릴 때 지킬 것: **밑그림 모양을 반드시 갈라라**(손 궤적이 달라야 한다 — 4번의 그 이유).
  memory `takbon-glyph-design-principle`: *"외울 글자를 늘리는 순간 4지선다가 된다."*

### ② 종이 = **자유 배치 + 한 장에 마법진 여러 개** (사용자 확정 방향)

사용자: *"종이에 진을 누르면 **고정된 위치**에 탁본이 생기잖아? 그러지 말고 **내가 원하는 위치**에
그걸 만들 수 있게. 그래서 **두 (마법진)을 한 종이에** 그릴 수 있게도 하면 좋을 거 같아.
그래야 **종이 업그레이드의 이유**도 생기고 나아가 조금 더 재밌는 플레이가 가능할 듯."*

- **A. 자유 배치** — 진을 종이의 **원하는 위치**에 놓고 그린다 (지금은 고정 위치).
- **B. 한 종이에 마법진 N개** — 공간이 허락하는 만큼. → **종이 등급 = 담을 수 있는 수/크기**.
- 🔴 **이미 예고된 설계다** — memory `takbon-ink-economy-design`: *"종이=규모(확대 상한↑ →
  큰 진=데미지↑ + **중첩 마법진 담을 공간**)"*. 즉 새 방향이 아니라 **그 약속을 실제로 지키는 일**.
- ⚠ 딸려 오는 것: `ring_board`의 좌표계(지금 화면 중앙 고정 원)·`RingDesign` 저장(진 1개 전제)·
  채점(`trace_scorer`의 가이드 한 벌)·발사(도안 1개 = 마법 1개). **저장 스키마가 걸리므로 리드 직접.**
- 연결: `takbon-nested-circle-model`(중첩 = 복합/재귀)과 **다른 축**이다. 이건 "한 종이에 여러 장",
  저건 "한 진 안에 진". 섞지 마라.

### ③ 룬 6종으로 (지금 3종)

사용자: *"룬도 한 여섯 개 만들 수 있잖아 속성으로? 그것도 지금 미리 만들어보자."*

- 지금 **불·물·바람 3종** → **6종**으로. `RuneDef`는 `.tres` 한 장 규약이라 데이터는 싸다.
- 🔴🔴 **그 전에 반드시 할 것 = 상태이상 배선.** 세션47 발견: `forest_enemy.take_hit(damage,
  rune_type, **_status, _status_power**)` — 밑줄 = **의도적 미사용**이고 주석이 *"적의 상태이상은
  미구현"*이라 명시한다. **룬이 정한 상태를 투사체가 착탄까지 실어 나르고 `take_hit`이 버린다.**
  → 지금 불·물·바람의 실질 차이 = **색 + base_damage ±15%**(0.9/1.0/0.7)뿐이고 **탄 씬도 셋 다 같다.**
  **이 상태로 룬을 6개로 늘리면 색깔이 6개가 될 뿐이다.**
- 순서: **(1) `take_hit`이 status를 실제로 적용**(화상 DoT·젖음 감속·바람 넉백 등) →
  (2) 룬 6종 데이터 → (3) 밸런스. (1)이 비용 낮고 효과가 제일 크다.
- 곁가지 이득: 세34 룬 해금(E4)이 비로소 의미를 갖고, 세28~29 **특별잉크 경제**(증폭 대상이
  `status_power`)가 되살아난다 — 지금은 증폭할 대상이 버려져 **경제 전체가 무의미**하다.
