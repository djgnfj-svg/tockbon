# 지팡이-마법진 = 자유도 해법 방향 (세션 44 설계 확정)

> 이 문서는 **아직 안 지어진 설계 방향**이다. 정본은 이 문서 + memory `takbon-wand-inscribe-circle`.
> 코어 재미 구멍(memory `takbon-magic-no-freedom`)의 해결 방향으로 세션 44 대화에서 확정됐다.

## 문제 (재확인)

- **자유도를 줬는데 시작하면 모두 똑같다.** 다들 "마법 1번"을 쓰고, 사실상 같다.
- **자유도가 열리는 데 오래 걸린다** (룬 불 하나로 시작 → 물·바람은 해독으로만).
- 세 갈래(늦게 하나씩 열기 / 시작에 다 주기 / 천장을 먼저 보여주기) 중 **하나를 고르는 문제로 보여 애매했다.**
- 그리고 발사 변형을 **장비(`wand_pattern`)로 빼놓은 게 "그리는 재미에 반한다"** — 재미가 그리기 밖으로 샜다.

## 확정된 그림 (사용자 결정)

**바닥 + 즉시 자유의 조합**으로 세 갈래의 애매함을 빠져나간다:

- **바닥(floor) = 기본 매직볼.** 아무것도 없을 때 주는 기본 마법. → "모두 똑같다"는 문제가 아니다.
  그건 **출발선**일 뿐이다.
- **자유(freedom) = 시작하자마자 내 지팡이에 마법진을 그려 넣는다.** 내 방향/루트로 나가는 내 마법.
  → 자유가 **즉시** 열린다 (①학파 = 처음부터 샌드박스).

### 지팡이에 무엇이 박히고, 무엇을 그리나 (사용자 확정)

> *"지팡이 같은 인챈트는 진이 이미 박혀져 있어서, 그때 따라서 본인이 알아서 가진 룬과 문양으로
> 그림을 그려야 되는 거예요. 평타를 그린다기보다는 **방식을 그리는 거지.**"*

- **지팡이 = 진(형태/그릇)이 박혀 있는 인챈트.** 진은 지팡이가 정한다 — 다른 지팡이 = 다른 진.
- **플레이어가 그리는 것 = 자기가 가진 룬 + 문양** — 박힌 진을 따라 그린다 = **"방식을 그린다."**
- 기존 문법과 정합: **진=형태 / 룬=속성 / 문양=구현 방식** (memory `takbon-magic-grammar`).
  바뀐 것은 단 하나 — **진이 지팡이에서 온다** (전엔 "일반진 하나"로 고정).
- **표현 = 지팡이(진) × 내가 그린 룬·문양.**

### 튜토리얼

기본 매직볼을 쥐고 + 자신만의 마법 지팡이(진이 박힌)를 얻어 → 룬·문양을 그려 넣고 → 첫 숲으로.
(세션 41 온보딩 레일에 붙인다.)

## 지금 코드와의 간극 (구현 시 정할 것)

- 지금 **지팡이(`equipment[WAND]`)와 마법진(`ring_designs`/`ring_equipped`)은 딴 물건**이다.
  발사 때 `ring_spell_system._on_ring_cast`가 둘을 합친다: 마법진이 룬+문양+점수를, 지팡이가
  `wand_pattern`(산탄 부채꼴)을 준다. → **새 모델 = 이 둘을 "지팡이에 박힌 진" 하나로 통합.**
- **씨앗은 이미 있다**: `wand_pattern`(SINGLE/MULTI/NOVA)이 곧 "지팡이가 발사 형태를 정한다."
  이걸 숨은 스탯에서 **"지팡이에 박힌 진"으로 끌어올리면** 된다.
- **매직볼 = 바닥**: 슬롯이 비어도(안 그렸어도) 지팡이의 진으로 기본 발사가 나가야 한다.
  지금은 `player_caster.fire()`가 빈 슬롯이면 그냥 거부한다 — 여기가 바닥이 앉을 자리.

## 남은 열린 조건 (B로 이어짐)

- 내 진이 매직볼보다 **"더 세게"가 아니라 "다르게"** 나가야 자유도가 진짜가 된다.
  지금은 문양 조합이 결국 위력(세기)으로 수렴한다(`ring_power.power_of`). **문양이 종류(관통·분열·
  유도·연쇄·설치)를 바꾸는 축**을 여는 게 B. (memory `takbon-magic-no-freedom` §How to apply.)

### 🔴🔴 세션44 발견 — "다르게 나간다" 효과 기계가 **이미 완비돼 있다 (DARK)**

- `src/spell/projectile.gd`에 **팅김(BOUNCE)·관통(PIERCE)·유도(HOMING)·추진(THRUST)** 효과가
  **완전 구현**돼 있다(`_setup_effects`·`_step_bounce`·`_step_homing`·`_hit_enemy` 관통 분기).
  `BalanceData`에 수치 기본값도 다 있다(`glyph_pierce_max=4`·`glyph_reach_min/max`·`glyph_homing_*`…).
- **그런데 한 번도 실행 안 된다** — 유일 호출자 `ring_spell_system._spawn_bolt`가 `effects={}`(빈
  사전)로만 부른다(projectile.gd:6~10 주석이 "미배선 설계 자산"이라 명시). 즉 B = **새 행동을
  만드는 게 아니라 「그린 문양 → 이미 있는 effects」로 배선**하는 일. 비용이 훨씬 작다.
- ⚠ 두 문양 개념이 갈라져 있다: **GlyphCode**{GATHER=0,RADIATE=1}=착탄 전개(살아있음) vs
  **GlyphType**{BOUNCE,PIERCE,HOMING,THRUST}=탄 행동(DARK). `data/glyphs`엔 gather·radiate 둘뿐 —
  **관통·유도를 그릴 어휘 자체가 없다.**

### B 첫 수직 슬라이스 = 관통 문양 (사용자 확정 "문양 1개를 종류로")

1. `Enums.GlyphCode`에 `PIERCE = 2` 추가 (발사 계약 확장 — test_ring_assembly가 지킴).
2. `data/glyphs/pierce.tres` 한 장 (code=2, "관통") → **팔레트 셀 자동 추가**(`Db.all_glyphs` code순을
   책이 열거). "새 문양 = .tres 한 장"이 팔레트 쪽은 성립.
3. `ring_board.GLYPH_NAMES`에 "관통" 추가 + code 2 문양 밑그림(이중 화살촉 등).
4. `ring_spell_system._deploy_now`: `g == PIERCE`면 발산처럼 탄을 쏘되 `effects={GlyphType.PIERCE: reach}`
   를 실어 `_spawn_bolt` → 탄이 여럿을 뚫는다. (reach = 고정값으로 시작, 나중에 문양 크기 축과 연결.)
5. `ring_carrier._draw`에 code 2 문양 그리기(날아가는 진에 보이게).
6. 검증: test_ring_assembly(코드2 유효)+test_ring_spell(관통이 적 2+ 관통) · 🔴팔레트 클릭은 실게임 push_input.
- 모델 결정(확정 필요): **관통 = 발산 계열 + 관통 효과 = 새 GlyphCode**(응집/발산과 나란한 3번째 어휘).

## 순서 / 진행

1. ✅ **A-min — 매직볼 바닥 (세션44 완료·실게임 검증).** `player_caster.fire()`가 빈 슬롯이면
   거부 대신 `RingAssembly` 초기 상태(빈 고리=매직볼, score 없음→기본 위력)를 쏜다. 맨손에서도
   단발 매직볼(그전엔 "슬롯 비어 거부"). 검증: 빈 슬롯 발사→캐리어 생성+마나 소모+피해 8.1(불).
   실제 좌클릭 push_input도 확인. ⚠ **지팡이 지급은 뺐다** — 세션37 빈 시작과 충돌 + 맨손 매직볼로
   충분. 지팡이(세 갈래·둘레=다른 진)는 "얻는 것"으로 남김(현재 획득 경로 없음 = 후속).
   A-full(진을 그리기에서 빼 지팡이로 완전 이관)은 사용자가 "얇게" 골라 **보류**.
2. ✅ **B 첫 슬라이스 — 관통 문양 (세션44 완료·실게임 검증).** `Enums.GlyphCode.PIERCE=2` +
   `data/glyphs/pierce.tres`(팔레트 자동) + `GLYPH_NAMES`/가이드 방향 + `ring_spell_system._deploy_now`가
   `{GlyphType.PIERCE: glyph_reach_max}`를 탄에 실어 **이미 있던 관통 기계를 켠다** + 캐리어 그리기.
   🔴 **검증(뮤테이션식 대조)**: 일렬 허수아비 3개에 정면 발사 → **관통=3 관통(x150/250/350 다 맞음),
   발산=첫 적에서 멈춤(250·350=0)**. 같은 발사인데 **그린 문양이 전투 방식을 종류로 가른다** —
   자유도 구멍(`takbon-magic-no-freedom`)에 첫 실질 균열. 팔레트에 관통 셀 렌더도 스샷 확인.
   reach는 지금 고정(최대) — 문양 크기 축과 연결은 후속.

3. ✅ **A-full — 진이 도안의 일부가 됐다 (세션44 완료·실게임 검증).** 사용자 재확정 모델:
   **지팡이 = 진(형태), 여러 개 보유, 책에서 골라 룬·문양을 그린다 → 마법이 자기 진에 묶인다.**
   - **M1 백본**: `JinDef.pattern`(단발/산탄/둘레)+진 3종 데이터(jin_single/fork/ring, plain 삭제)+
     `RingDesign.jin`(라운드트립·저장)+`ring_assembly._jin`+**발사가 도안의 진으로 형태 결정**
     (`ring_spell_system`, 장착 지팡이 대신 폴백)+시작 진 3개 시드(codex). 검증: 장비 없이
     둘레진=8발·단발진=1발.
   - **M2 UI**: 책 **진 탭 = 보유 진 셀에서 선택**(룬 탭 미러, codex 해금 필터)→`jin_selected(id)`→
     `choose_jin(JinDef)`→`assembly.jin`. 검증: 3진 셀 렌더+둘레진 선택→assembly.jin=jin_ring+밑그림.
   - ⚠ **진은 아직 손으로 긋는다**(트레이스 유지) — 사용자 설계는 "진 안 긋기"였으나 size(규모)
     휠이 진 트레이스에 묶여 있어 **저위험 우선**으로 트레이스를 남겼다. "진 안 긋기"=규모 휠 이관이
     필요한 별도 단계(다음 후보). 지금도 "여러 진 중 골라 그린다+마법이 진에 묶인다"는 다 됨.
   - ⚠ 옛 WAND 장비 슬롯의 `wand_pattern`은 진 없는 도안의 **폴백**으로만 남음(사실상 레거시).
