## Phase 1 — 병렬 모듈 5개

### 모듈 A — 드로잉 & 인식 (`src/drawing/`) ★ 게임의 심장
- **범위:** 드로잉 캔버스(Line2D 잉크 렌더, 필압), 획 캡처, 인식 파이프라인(원 기하 판정 → 조준진 꼬리 → $1 룬 4종 → 화살표 파라미터 추출, TECH_SPEC §6), 자동보정 버튼, 필체 라이브러리(스탬프 저장·재배치·보정 보존), 잉크 소모 계산, SpellDesign 생성·저장
- **의존:** core 스키마만
- **완료 기준(DoD):** test_drawing.tscn에서 — 원+꼬리+룬+화살표를 그리면 올바른 SpellDesign이 생성·저장되고, 룬 4종 인식률이 손그림 기준 체감 90%+, ~/◎ 오인식 없음. `design_created` 시그널 발신
- **주의:** 물~ vs 바람◎ 구분이 1주차 최우선 검증 (GDD 리스크 1)

### 모듈 B — 스펠 컴파일 & 발사 (`src/spell/`)
- **범위:** SpellDesign → 발사 실행(cast_requested 수신 → 투사체 스폰), 고정진=절대각/조준진=에임 상대각 로직, 투사체(위력·크기=magnitude), 룬 효과 4종(화상 DoT·넉백·젖음 둔화+갑주 무력화·바람 밀어내기), 마나 차감, cast_executed/failed 발신, RuneDef .tres 4종 작성
- **의존:** core 스키마 + Phase 0 샘플 도안 (A 불필요)
- **DoD:** test_spell.tscn에서 — 샘플 도안 3종을 키 입력으로 캐스팅하면 각각 노바/조준 산탄/단발이 올바른 각도로 나가고, 허수아비 타깃에 룬 상태이상이 적용된다

### 모듈 C — 필드 & 전투 (`src/field/`)
- **범위:** 플레이어(WASD+에임+대시+기본 완드 약공격), 적 5종 AI(재생 덩굴·숲 사냥개·수액 슬라임 떼·안개 정령·갑주 갑충 — EnemyDef .tres 포함), 낮/밤(CanvasModulate+2D 라이트, 밤 강화), 탁본 모션(1~2초 무방비), 채집 노드, 출구 게이트(귀환=extraction_success), 사망(bag_lost), 프로토 맵 1장
- **의존:** core 스키마. 투사체 피격은 enemy_hit 시그널 계약으로 — B 없이도 더미 대미지로 개발
- **DoD:** test_field.tscn에서 — 이동·대시·약공격으로 적 5종과 교전 가능, 밤 전환 시 시야·강화 변화, 엘리트 처치→탁본→게이트 귀환 루프가 돈다

### 모듈 D — 거점 & 경제 (`src/base/`)
- **범위:** 거점 씬(작업대·창고·연구소 상호작용), 자원 원장(GameState 연동: 잉크 3종·종이 3등급·재료), 정제(재료→잉크), 종이 제작, 수리(원본 잉크 소량+응급 수리), 연구(해독 ~10분 플레이시간 진행, research_completed), 취침(아침 스킵+마나 회복), ItemDef .tres 작성
- **의존:** core 스키마
- **DoD:** test_base.tscn에서 — 재료로 잉크 정제, 손상 도안 수리, 조각 해독 완료→research_completed 발신, 취침으로 하루 넘김이 동작

### 모듈 E — UI (`src/ui/`)
- **범위:** HUD(체력·마나·장착 4장·시계), 아침 게시판(오늘의 적+약점 표기), 장착 4장 선택 화면, 도감(해금 룬·적 정보), 일시정지/설정 최소, resources_changed·phase_changed 구독
- **의존:** core 스키마 + 샘플 도안
- **DoD:** test_ui.tscn에서 — 목 데이터로 전 화면 렌더·전환 동작, 장착 4장 선택이 GameState에 반영

## Phase 2 — 통합 (리드 단독 또는 순차)

통합 순서: **A+B** (그린 도안이 실제 발사) → **+C** (필드에서 적에게 적중·상태이상) → **+D** (귀환→정제→수리→해독 루프) → **+E** (전 UI 연결)

**통합 시나리오 테스트 (= 데모 축소판):**
1. 거점에서 도안을 그린다 (조준진+불△+화살표 3개)
2. 장착 4장 선택 → 출격
3. 낮 필드에서 사냥, 엘리트 처치 → 탁본 (무방비 연출 확인)
4. 저녁 귀환 판단 → 게이트 귀환 (또는 사망 시 가방 손실 확인)
5. 밤 거점: 해독 → 도감 등록, 도안 수리, 취침
6. 다음 날 아침 게시판 갱신 확인

**Phase 2 완료 = GDD 1개월차 검증 준비 완료** → 테스터 5명 투입, "시키지 않아도 두 번째 도안을 그리는가" 관찰

## 충돌 방지 규칙 (전 에이전트 공통)

1. 자기 모듈 폴더 + `tests/` 내 자기 씬 + `data/` 내 자기 담당 .tres만 수정
2. `src/core/`·`project.godot`·`Main.tscn`·`docs/` 수정 금지 — 필요하면 리드에게 변경 요청을 보고로 남김
3. 스키마가 부족해도 임의 확장 금지 — `params: Dictionary` 활용 또는 리드에 요청
4. 타 모듈 코드 직접 호출·preload 금지 — EventBus와 core 스키마만
5. 결과 보고에 반드시 포함: 만든 파일 목록 / DoD 자가 검증 결과 / 스키마·시그널 변경 요청 사항

## 리스크 메모

- 에이전트 병렬 작업은 같은 파일을 안 건드려도 .godot 캐시·uid 충돌이 날 수 있음 → 씬(.tscn) 공유 금지가 핵심 방어선
- A의 인식 품질이 프로젝트 전체의 관문 (GDD 리스크 1) — A만은 결과를 사람이 태블릿으로 직접 검증할 것
- 모듈 크기 불균형: A > C > B ≈ D > E. A가 오래 걸리면 B·C 통합을 먼저 진행
