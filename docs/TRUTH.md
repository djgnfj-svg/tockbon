## 1. 마법진 = 지팡이 + 진 + 룬 + 문양 (4축) ★ 게임의 심장

> ⚠ **이 §1은 옛 자유드로잉 모델이다** (상단 배너 참조). 고리 조립 전환 후에도 **살아남는 뼈대**는
> 진=투사체의 몸·룬=속성·문양=효과·"진 안=룬 / 진과 사이=문양"이라는 **역할 분담**이다. **죽는 것**은
> 획 인식·자유 조준 회전·"그리는 순서 강제"다(칸 클릭 조립이 대체). 지팡이 축(방향·발수)이 고리 칸
> 채우기와 어떻게 합쳐지는지는 **#17 미정**. 아래는 현재 코드 기준으로 읽되, 새 작업 방향으로 삼지 말 것.

**마법진 = 진 1개 + 룬(진 안, 종류별 1개) + 문양 N개** — 반드시 이 순서로 **그린다**.
**여기에 지팡이 1개가 더해져 발사된다** — 지팡이는 그리는 게 아니라 **장착**하는 부품이다.

> 🔴 **마법을 읽는 한 문장 문법 (사용자 확정 2026-07-15):** *"이런 **속성**의 룬을, 이런 **문양**들로
> 구현해서, **진** 형태로 구현한다."* — 해석 순서 = **룬(속성) → 문양(구현 방식) → 진(형태·그릇)**.
> 지팡이는 이 문장 밖(어디로·몇 발을 더한다).

플레이어가 그리는 것은 이펙트가 아니라 **마법 그 자체**다. 그러려면 부품들이 **서로 다른 질문**에
답해야 한다 — 한 부품이 남의 축을 먹으면 그 부품은 정체성을 잃는다.

| 부품 | 답하는 질문 | **모양 = 무엇을** | **크기 = 얼마나** (÷ 진) | 상태 |
|---|---|---|---|---|
| **지팡이** | **어디로 · 몇 발** | 발사 패턴 — 단발·산탄·전방위 | — | ✅ 3종 구현 |
| **진** (1개) | **어떤 마법인가** | **투사체의 몸** — 탄의 생김새 + 히트박스 | **규모** — 위력·탄 크기·기준 사거리 | ✅ 구현 |
| **룬** (진 안 1개) | **무엇으로 때리나** | **속성** — 원소·상태이상 | **농도** — 상태이상 세기 | ✅ 구현 |
| **문양** (N개) | **어떤 효과가 붙나** | **효과** — 날아가는 동안(팅김⚡·유도∿·관통‖) / 맞은 다음(화살표=충격파 방향) | **세기** — 사거리 배율·반사 횟수… | ✅ 3종+기본 구현 |

> **진단법** (축을 나눌 때 쓴다): "이 부품을 **크게·다르게** 그리면 무슨 일이 일어나는가?" 답이
> "아무 일도 안 일어난다"면 그 부품은 표현 수단이 아니라 **세금**이다. 세 병을 구별하라 — **세금**
> (아무 일도 안 함) · **월권**(축 밖의 일을 함) · **무의미**(바꿔도 그대로). 진단이 다르면 처방도 다르다.

### 1.1 그리는 순서 — 진 → 룬(들) → 문양(들)

**순서는 규칙이 아니라 문법이다.** 인식기는 **진의 안/밖**으로 룬과 문양을 가른다 (룬은 진 안에
머물고, 문양은 진을 뚫고 나간다). 진이 없으면 그 판정 자체가 불가능하다.

- 캔버스가 순서를 **강제**한다 — 단계에 맞지 않는 획은 무효(획 사라짐, **잉크는 소모 안 됨** = 실수 대가 0)
- 🔴 **맺힘은 명시적이다** (F1, 2026-07-15): 진+룬+문양이 다 서면 **초안**(확정 대기)일 뿐, 화살표 하나로 자동 완성되지 않는다. **Enter(또는 ✓완성 버튼)를 눌러야** 종이가 뜯기고 도안이 실재한다(`design_created`). 그전까지 먹선은 보이되 종이 미소모·수정 자유. 이미 맺힌 종이의 이후 고쳐 그리기는 자동·공짜(`design_updated`). 캔버스: `commit_design()`/`can_commit()`/`commit_state_changed`
- **룬 단계에서 룬 여러 개, 문양 단계에서 문양 여러 개**를 그린다. 첫 문양이 진을 뚫으면 문양 단계로 넘어간다
- **체크리스트가 상시 표시**되어 다음 차례를 알린다. 튜토리얼이 가르치는 순서와 동일하다
- ⚠ **문양 단계는 거부하지 않는다** — 진을 뚫은 획은 글자로 인식 안 돼도 **기본 탄**이다. 거부는 "진을 안 뚫었다"일 때뿐

### 1.2 지팡이 — 방향 + 발수

**지팡이는 기존 완드(WAND) 슬롯 위에 얹힌다 — 새 장비 종류가 아니다.** 스키마도 새로 안 만들었다:
`ItemDef.params["wand_pattern"]` 하나 (`Enums.WandPattern { SINGLE, MULTI, NOVA }`). 새 지팡이는
`.tres` 하나 추가하면 끝 — **코드가 안 바뀐다**.

| 지팡이 | 패턴 | 발수 | 비고 |
|---|---|---|---|
| **wand_basic** (기본) | SINGLE | 1발 · 에임 방향 | 시작 장비 |
| **wand_fork** "세 갈래 붓대" | MULTI | 3발 · 24도 부채꼴 (에임이 한가운데) | 산탄 |
| **wand_ring** "둘레의 지팡이" | NOVA | 8발 · 균등 전방위 | 에임이 바뀌면 통째로 돌 뿐, 벌어진 각도는 안 변한다 |

- **에임(마우스 방향)이 발사각의 유일한 기준이다.** 도안 전체 회전은 없다 — 마법진은 그린 자세 그대로 날아간다
- `spell_system._wand_shots(aim_angle) -> Array[float]`가 발수·방향의 **유일한 출처**다
- **수급 = 거점 제작** ✅ 확정 (2026-07-15): 필드 드롭이 아니라 **거점에서 재료로 만든다**(연구소 제법 + 작업대 — 종이·잉크 경제와 같은 결). 시작은 `wand_basic`, 나머지 2종은 제작으로 연다. ⚠ 제작 재료·해금 조건은 미정(만드는 세션에서)
- **등 뒤 견제는 없다** ✅ 확정 (2026-07-15): v2.0에서 회전이 사라지며 후방 견제탄이 없어졌다 — **후방 패턴 지팡이를 만들지 않는다.** 잃은 자리를 명시적으로 비워 둔다

### 1.3 진 — 투사체의 몸 + 규모

**진의 모양이 곧 날아가는 탄의 생김새다. 진의 크기가 곧 마법의 규모다.**

- **규모**: 위력 배율 · 투사체 크기 · 기준 사거리 — 셋 다 진 크기(`circle_radius`)가 정한다. 히트박스도 진 반지름에 비례
- **대가**: 잉크(제작) + 마나(시전). 큰 진은 종이의 잉크 상한을 잡아먹어 룬·문양 여유가 줄고, 쏠 때 마나를 더 문다 → **작고 여러 발 vs 크고 한 방**
- 🟢 **진 모양 = 탄의 생김새 + 히트박스 모양** ✅ 확정 (2026-07-15): 별을 그리면 **별 모양 탄에 별 모양 히트박스**가 된다 — 그린 것과 맞는 것이 일치한다 (지금은 늘 원 히트박스라 보이는 모양과 맞는 모양이 달랐다). ⚠ 히트박스를 원 아닌 모양으로 어떻게 잴지는 구현 과제
- **진도 탁본으로 배운다** — 룬에 이은 두 번째 어휘 (별·용의 진). ⚠ **지금은 원 하나만 구현** (별·용은 `$P` 인식기 대기, §4-E)

### 1.4 룬 — 속성 + 농도

> ⚠ **v2.2에서 충격이 룬을 떠난다** (§4 세션 14): 룬 = 순수 원소(불·물·바람)만, "힘/추진"은 문양으로.
> 아래는 구현 시까지의 현재 스펙(충격 포함).

**불△**(화상·지속딜) / **충격>**(넉백·점타격) / **물~**(둔화·젖음 — 원소반응 없음, 둔화+갑주무력화만) / **바람◎**(흐름·확산·면제어).

- **진 안에는 룬만.** 구조 글자를 진 안에 넣는 안은 기각됐다 (진은 좁고 룬 농도를 깎아먹는다)
- **농도 = 룬이 진을 얼마나 채우는가**(`rune_fill`, 룬 반경 ÷ 진 반경). 진을 꽉 채운 룬 = 깊이 물든다 / 작게 그린 룬 = 옅게 스친다. 정하는 것은 **세기**(화상 초당 피해·젖음 둔화율·넉백 거리·흐름 세기)이지 위력이 아니다
- **정확도 = 순도**(`rune_accuracy`) — 잘 그린 룬일수록 속성이 진하게. 위력은 **진만** 정한다 (정확도를 위력에서 뗀 것이 v1.7)
- **같은 진 안 같은 종류 룬은 하나뿐** — 불△ 두 번 그려 농도 뻥튀기 불가. **서로 다른 종류(불+바람 등)는 함께** 가능
- 🟢 **상극(불↔물) = 수증기, 그리고 그건 결과다** ✅ 확정 (2026-07-15): *"진 안의 고유 룬 1개가
  있으니까, 여러(중첩) 진 안에 물·불이 있고 그게 화살표로 각각 바라보고 있으면 수증기가 될듯."*
  「같은 진에 둘 넣으면 즉시 증발」이 **아니다** — **서로 다른/중첩 진에 각각 든 물 룬·불 룬을,
  화살표를 마주 보게 그어 두 충격파가 만나면 수증기가 된다.** **기둥과 정확히 같은 창발**(§1.5) —
  규칙이 아니라 결과이고, 성격은 벌이 아니라 **보상**(그 자리에 수증기가 남는다).
  - ⚠ **코드에 "불+물 = 증발" 규칙을 적지 말 것.** 기둥과 같은 함정("몇 개부터/어떤 조합부터")이 따라온다 —
    충격파가 각자 자기 룬 속성을 싣고 가다 **만나면 반응이 나온다**는 것 하나뿐이다
  - ⚠ **아직 성립할 수 없다** — 룬 N개(§4-B2) + 중첩 진(§4-D2) + 충격파가 속성을 싣는 구현이 있어야 한다. 이번 세션엔 안 만든다(정비 세션)
- 🟢 **속성마다 특수 효과가 있어야 한다** ✅ 방향 확정 (2026-07-15): *"결국 속성에 대한 특수 효과가
  있어야 할 듯."* 충격파가 자기 룬 속성을 싣고 가되, **속성마다 고유한 특수 효과**를 낸다 —
  BACKLOG에 "폐기된 가설"로 눕혀 뒀던 **룬별 착탄 연출**(불=터진다 / 물=고인다 / 충격=밀어낸다 /
  바람=빨아들인다)이 되살아났다. 상태이상(§ 화상·젖음·넉백·흐름) 위에 얹히는 층이고, 상극이 만나면
  수증기 같은 반응이 나오는 것도 이 위에서 성립한다. **설계는 아직 안 됐다** — §4-B3
- 위력 계수 = `fill` 가중 평균 (룬 1개일 때 지금과 정확히 같다 → 하위 호환)

### 1.5 문양 — 효과 + 세기 (두 층)

**문양은 진을 뚫고 나가는 획이고, 그 글자가 탄에 붙는 효과를 정한다.** 마법의 생애가 두 층으로 갈린다:

| 층 | 무엇이 정하나 |
|---|---|
| **날아가는 동안** | 팅김⚡ · 유도∿ · 관통‖ (아래 어휘 표) |
| **맞은 다음** | 🔴 **곧은 화살표(BASIC)만 = 충격파 하나가 가는 방향** ✅ 확정 (2026-07-15): 팅김·유도·관통 획은 충격파를 뿜지 않는다 — 그린 것과 나가는 것을 눈으로 재기 쉽게, 두 층을 깔끔히 가른다 |

**어휘 (MVP 3종 + 기본):**

| 문양 | 효과 | 길게 그으면 | 상태 |
|---|---|---|---|
| **기본** (직선 획) | **착탄 충격파의 방향** (아래) | 사거리 + **충격파 세기(개수)** | 폴백 (인식 실패도 이 취급) |
| **팅김 ⚡** | 벽에 반사된다 | 반사 횟수 ↑ | ✅ 구현 |
| **유도 ∿** | 적을 따라간다 | 추적 지속 ↑ | ✅ 구현 |
| **관통 ‖** | 적을 뚫고 지나간다 | 뚫는 수 ↑ | ✅ 구현 |
| **추진**(신설) | **빠르게 날아간다** (탄의 속도) | 속도 ↑ | ✅ 메커니즘(2a) — 옛 "충격"의 힘이 여기로. ⚠ 손 인식은 2b(F1과 합류) |

> ✅ **증폭·응집은 어휘가 아니다** (확정 2026-07-15): *"결국 화살표라는 문양으로 합쳐진거지."*
> 모아 그으면 응집(기둥), 밖으로 뻗치면 증폭(폭발)이 **이미 화살표 충격파에서 나온다** — 별도 글자로
> 만들지 않는다. 대원칙("어휘를 늘리지 말고 조합을")대로 어휘를 하나도 안 늘리고 표현이 늘었다.

- **N개 = 한 탄에 효과 N개.** 방향이 지팡이로 갔으므로 문양마다 탄을 만들면 겹쳐 나간다 → 발수는 지팡이가 갖고, 문양은 **그 한 탄에 동시에 얹힌다**. 팅김+관통+증폭을 한 장에 그리면 **튕기면서 뚫는 강화탄 하나**
- **같은 글자 여럿 = 세기 합산** (팅김 둘 = 더 튕긴다). 단 **사거리 배율은 `reach` 최댓값** (합이면 "문양은 무조건 많이"가 정답이 됨)
- **길이 = 사거리 배율 + 그 효과의 세기** — `reach = 문양 뻗은 거리 ÷ 진 반지름`. 룬 `rune_fill`과 정확히 대칭인 문법. ⚠ **"뻗은 거리"이지 획 총연장이 아니다** — 총연장이면 "얼마나 구불구불한가"를 재게 되어 지그재그로 사거리를 공짜로 얻는다
- **문양도 탁본으로 배운다** — 세 번째 어휘

#### 🔴 착탄 후 — 화살표 하나 = 충격파 하나 (기둥은 규칙이 아니라 결과다)

> **"화살표 하나하나가 착탄 후 충격이 어디로 가는가를 정하는 거임. 그 충격파끼리 맞으면 기둥이
> 되는 거임."** — 사용자, 2026-07-15

**규칙은 하나뿐: "화살표 = 충격파 하나가 가는 방향."** 기둥·폭발은 **코드로 정의하지 않는다** —
충격파끼리 부딪히면 저절로 나온다.

```
밖을 겨눈 화살표 8개  → 진 둘레에서 사방으로 뻗음        (= 폭발)
룬을 겨눈 화살표 8개  → 전부 진 중심으로 모임 → 만난다   (= 기둥)
오른쪽에만 3개        → 그쪽으로만 충격파               (= 방향성)
2개만                → 같은 것, 약하게                 (개수 = 세기)
```

> ⚠ **"수렴하면 기둥"이라고 코드에 규칙으로 적지 말 것.** 그 순간 창발이 아니라 규칙이 되고
> "몇 개부터 기둥인가"라는 답 없는 질문이 따라온다. **만나면 만나는 거고 어긋나면 안 만난다.**
> **여기(이 문서)에도 기둥 규칙을 적지 말 것.**

- **탄이 곧 진**이므로 적에 닿는 순간 진이 히트 지점에 놓이고, 진 위 화살표들이 **각자 제자리에서 제 방향으로** 뿜는다 — 종이 위의 배치가 그대로 착탄 그림이다
- **방위 기준 = 탄이 가던 방향**: 종이 위쪽 = 앞 = 탄이 가는 쪽. 위로 그은 화살표는 적을 **밀어내고**, 아래는 나에게 **끌어온다** (종이 절대 기준이면 적 위치에 따라 뜻이 바뀌어 통제 밖이 된다)
- **리드 실측**: 밖 겨눔 8개 → 충격파 8·기둥 0 / 룬 겨눔 8개 → 충격파 8·기둥 2 (중심에서 저절로 만남)

#### 🔴 문양 설계의 대원칙 — 어휘를 늘리지 말고 조합을 늘려라

> **"룬을 감싸는 작은 도형마다의 힘이 있고, 그걸 조합하는 자유도가 목적."** — 사용자

문양을 하나씩 늘리면 "글자 하나 = 효과 하나"짜리 **메뉴에서 고르기**가 된다 — v1.7이 룬에서 이미
겪은 실패다. **문양 추가 전에 이 셋을 물어라:**

| 질문 | 아니라면 |
|---|---|
| 이게 **도형 하나의 힘**인가, **새로 외울 글자**인가? | 외울 글자를 늘리는 쪽이면 멈추고 다시 생각한다 |
| 여러 개를 그렸을 때 **서로 무엇을 하는가?** | "각자 따로 논다"면 조합이 아니다 |
| **배치**(어디에·어느 쪽을 겨누고)가 결과를 바꾸는가? | 안 바꾸면 도형이 아니라 **스위치**다 |

✅ v2.1 충격파가 이 원칙의 성공 사례다 — 규칙 하나에서 기둥·폭발·방향성이 전부 나왔고, **증폭·응집이라는
어휘 둘을 흡수했다**(모으면 응집, 밖으로 뻗치면 증폭). 어휘를 하나도 안 늘리고 표현이 늘었다.

### 1.6 예산 — 잉크(제작) + 마나(시전)

| 자원 | 공식 | 원칙 |
|---|---|---|
| **잉크** | `∫ 붓 굵기 ds` = 통에서 실제로 나온 양 (길이 × 굵기) | **할증 없음.** 큰 진은 둘레가 길어 이미 더 먹는다 (진 크기 가산 = 이중 과금이라 폐기). 숫자 하나가 종이 상한·제작 비용 두 곳에 그대로 |
| **마나** | 룬 + 진 규모 + 발수 + 룬 농도 + 문양 사거리 | 각 축이 공짜면 "언제나 최대한 크게"가 유일한 정답이 된다. 같은 축을 삼중 처벌하진 않는다 (제작 1회·시전 1회) |

- **잉크 상한이 조합을 만든다**: 종이 한 장의 잉크는 유한하고 **진·룬·문양이 그 안에서 경쟁**한다. 배분이 곧 설계다. 상위 종이 = 더 많은 축을 동시에 만족
- ⚠ **"발수"는 이제 지팡이의 것**(v2.0). 다발·전방위 지팡이가 마나를 더 무는지는 **미정** — 지금은 도안의 `mana_cost`가 그대로 쓰인다

## 2. 게임 (컨셉 · 루프 · 경제 · 지식 · 적 · 범위)

### 2.1 세계관 & 톤 — 동화풍 미스터리

세계의 모든 마법진을 쓴 **고대 서기관**이 사라진 뒤, 글자들이 숲 생명들 몸에 무늬로 스며들었다.
주인공은 숲 어귀 오두막의 **견습 필경사**. 스승이 사라지고 "숲의 글자를 모아라"는 메모만 남았다.
낮엔 무늬를 품은 존재에게서 글자를 탁본하고, 밤엔 먹을 갈아 해독하고 그린다 — 서기관의 서고를 향해.

**톤**: 낮 숲=따뜻하지만 기묘 / 밤 오두막=등불·먹 가는 소리·붓 사각임(ASMR급 포근함) / 처치·사망=간결한 폭발·팝(무겁지 않게).

### 2.2 하루 루프

```
아침  게시판(오늘의 적 정보) → 장착 4장 선택
낮    출격: 사냥·탁본·채집 (내구 소모)
저녁  귀환 판단 — 밤 재료를 노릴까? 살아 돌아갈까?
밤    [필드] 적 강화·시야↓ + 밤 전용 희귀 재료(상위 종이·잉크 원료)
      [거점] 도감 등록 → 드로잉·수리·연구 → 시험 발사
```

- 시간은 상시 진행(거점 포함). **밤은 공유 자원** — 필드에 쓰면 희귀 재료, 거점에 쓰면 드로잉·연구
- 조작: WASD + 마우스 에임 + 대시 + 기본 완드 약공격(마나 0). **MVP 발동은 전부 즉발**. 출격 1회 10~15분
- **도안 임시저장**(밤 안에 못 끝내면 이어 그리기) · **취침**(아침 스킵 + 마나 완전 회복)
- **죽음**: 장착 4장 보존(손상→수리비) / 가방 전리품·조각 손실 / 도감·거점 영구

### 2.3 자원 & 경제

| 자원 | 역할 |
|---|---|
| 잉크 | 제작·위력 예산. 몬스터·채집 원료 정제 ("잡은 놈이 곧 물감") |
| 종이 | 캔버스 크기(잉크 상한)·마나 감면·내구도. 연구소 제법 해금 + 파밍으로 제작 |
| 마나 | 사용 비용 (전투 페이스, 자연 회복). 장비·종이가 보정 |
| 내구도 | 수명. 소진=손상 → 수리(원본 잉크 소량). 응급 수리로 최소 보장 |

**잉크 3종 / 종이 3등급**(24/32/48 상한) · **장비 3부위**: 완드(=지팡이)/로브(마나·체력)/부적(특수) — 획득: 필드 드롭. 시작 물자는 튜토리얼에서 지급.

### 2.4 지식 습득 — 탁본 2단계

1. **탁본 조각 획득**: 엘리트/보스 처치 → 무늬가 바닥에 남음 → 다가가 탁본(1~2초 무방비 = 긴장). **가방 소지품 = 죽으면 손실**
2. **연구소 해독**: 플레이시간 ~10분 → 도감 영구 등록

**배우는 어휘는 셋**: 룬(속성) · 진(모양 — 별·용) · 문양(효과 — 팅김·유도·관통). 지식 습득이 룬
하나에 걸려 있던 문제가 세 갈래로 분산됐다. ⚠ **지팡이는 이 셋에 안 낀다** — 습득 경로 미정(§4-C1).

### 2.5 적 5종 = 설계 문제 (약한 카운터)

재생 덩굴(불) / 숲 사냥개(충격→**바람** v2.2 §4) / 수액 슬라임 떼(다발 도안) / 안개 정령(바람) / 갑주 갑충(물).
갑주 갑충은 **젖음이 갑주를 무력화해야** 피해가 들어가고, 재생 덩굴은 **화상 지속딜이 재생을 넘겨야**
죽는다 → 위력보다 농도가 먼저인 상대. 중간보스: 바람을 품은 존재 → 바람 룬 조각.

### 2.6 데모 & EA 범위

- **데모 (5개월, Next Fest)**: 튜토(불·충격) → 출격 2~3회 → 물 조각 회수·해독 → 신작 도안으로 갑충 격파 → 중간보스 컷. 40~60분
- **EA (6개월)**: 숲 1막 완결 — 중간보스(바람) 격파 → 에필로그 탐색 → 스승의 단서
- **정식 (9~12개월)**: 문양 확장·원소 반응·대서고 바이옴·고대 서기관(최종 보스)

## 3. 기술 계약 (지금 유효한 것만) — 코드의 유일한 진실

> 변경은 리드만. 스키마·시그널을 바꾸면 **이 문서를 먼저 갱신**한 뒤 코드. 물리 레이어:
> 1=world 2=player 3=enemy 4=player_projectile 5=enemy_projectile 6=pickup 7=interaction.

### 3.1 아키텍처

- **오토로드**: `EventBus`(시그널 허브) / `GameState`(자원·HP·장착 4장·가방·도감) / `Clock`(낮밤) / `Db`(data/ 레지스트리) / `SaveManager`(user://save, 자동 저장)
- **모듈 폴더 = 소유권**: `src/drawing`($1 인식·캔버스) · `src/spell`(도안→발사) · `src/field`(전투·낮밤·탁본·보스) · `src/base`(거점 경제) · `src/ui`(HUD·도감) · `src/quest` · `src/tutorial` · **`src/core`는 리드 전용**
- 모듈 간 통신은 **EventBus 시그널 + core 스키마만**. 타 모듈 직접 preload/get_node 금지
- 밸런스 수치는 전부 **`data/balance.tres`**(BalanceData). 코드에 수치 금지

### 3.2 핵심 스키마 (`src/core/schemas/`)

**enum은 전부 `src/core/enums.gd`(class_name Enums)에** — 모듈이 매직 넘버를 각자 만들지 않는다.

```gdscript
# spell_design.gd — 도안 (게임의 중심 데이터. A가 만들고 B가 소비하고 D가 수리하고 E가 표시)
class_name SpellDesign extends Resource
@export var id: StringName
@export var display_name: String
@export var circle_type: int      # CircleType.FIXED/AIMED — 🔴 v2.0 소비 중단(회전 없음). 렌더·구세이브용
@export var circle_radius: float  # 0..1 규모 축 — 위력·탄 크기·사거리·히트박스를 전부 이 값이 정한다
@export var aim_axis: float       # 🔴 v2.0 소비 중단. 개념은 상수 UP_AXIS(-PI/2)로만 살아난다
@export var rune_type: int        # RuneType.FIRE/IMPACT/WATER/WIND
@export var rune_fill: float      # 0..1 룬 반경÷진 반경 = 속성 농도 축. 구세이브 기본 0.5
@export var rune_accuracy: float  # 0..1 = 속성 순도 (위력 아님). 스탬프 시 저장 시점 값 보존
@export var arrows: Array[ArrowData]
@export var strokes: Array[StrokeData]   # 원본 전체 획 (렌더·수리·재편집용)
@export var paper_grade: int      # 1..3
@export var ink_cost: Dictionary  # {ink_id: amount} — 수리비 산정 기준
@export var mana_cost: float
@export var durability_max: int
@export var durability: int

# arrow_data.gd
class_name ArrowData extends Resource
@export var glyph: Enums.GlyphType = Enums.GlyphType.BASIC
    # 효과 종류 — 한 탄에 여러 개가 동시에 얹힌다. BASIC = 폴백(인식 실패=거부 아님) + 착탄 충격파 방향
@export var reach: float = 1.0
    # 뻗은 거리 ÷ 진 반지름. rune_fill과 대칭. 소비: 그 효과의 세기(같은 글자 여럿이면 합산)
    #   + 사거리 배율은 문양 중 최댓값 하나. ⚠ reach=1.0의 사거리 배율은 1.0이 아니라 0.85 (배율 1.0은 reach=1.4)
@export var direction: float      # rad. 캔버스 절대각. 🔴 v2.1: 충격파가 가는 방향 (착탄 시 부활)
@export var origin: Vector2       # 진 중심 기준·진 반지름=1.0 정규화. 🔴 v2.1: 충격파 시작 자리 (착탄 시 부활)
@export var magnitude: float      # 획 길이 0..1. 전투 스탯 아님(규모는 진). 소비 금지(잉크·렌더·기록용)
@export var path: PackedVector2Array  # 그린 화살표 곡선. 🔴 궤적 아님 → 먹선 렌더 전용(비주얼). 비면 직선 폴백

# stroke_data.gd — 원본 획
class_name StrokeData extends Resource
@export var points: PackedVector2Array      # 캔버스 정규 좌표 (0..1)
@export var pressures: PackedFloat32Array
@export var role: int                       # StrokeRole.CIRCLE/RUNE/ARROW/TAIL/DECOR

# rune_def.gd (data/runes/*.tres) · enemy_def.gd (data/enemies/*.tres) · item_def.gd (data/items/*.tres)
class_name RuneDef  extends Resource   # type, display_name, base_damage, status, status_power, projectile_scene
class_name EnemyDef extends Resource   # id, display_name, hp, counter_rune, has_counter, params, is_elite, drops[], night_buff
class_name ItemDef  extends Resource   # id, kind(ItemKind), grade, display_name, params:Dictionary
```

**ArrowData 방향·세기는 `InkRender`의 세 함수가 소유한다 — 끝점도 총연장도 안 쓴다:**

| 함수 | 정의 | 왜 |
|---|---|---|
| `arrow_tip()` | 시작점에서 가장 먼 점 (지터 대비 상위 3% 평균) | 방향·세기가 **같은 점**을 겨눈다 |
| `arrow_heading()` → `direction` | 시작점 → tip의 각도 | 끝점 기준이면 관통‖ 화살촉이 뒤로 꺾여 평균 14.6도 틀어진다 (손그림 200회 실측) |
| `arrow_extent()` → `reach` | 시작점 → tip의 거리 | 총연장이면 "구불구불함"을 재게 된다 |

⚠ **회전은 발사(또는 착탄) 때 한 번만.** `direction`은 캔버스 절대각이다 — 여기에 `aim_axis`를 미리
빼면 두 번 빠져 **90도 틀어진다**(세션 7 버그). 착탄 충격파 변환:
```gdscript
var rotate_by := travel_angle - UP_AXIS          # UP_AXIS = -PI/2
충격파 시작 = 히트지점 + (arrow.origin * 탄반지름px).rotated(rotate_by)
충격파 방향 = arrow.direction + rotate_by
```

**ItemDef.params 키 규약:**

| kind | 키 | 의미 |
|---|---|---|
| WAND | `wand_pattern` | 🔴 발사 패턴 (SINGLE/MULTI/NOVA) |
| WAND | `attack_cooldown_mult` / `wand_damage_add` | 약공격 쿨다운 배율 / 피해 가산 |
| ROBE | `mana_max_add` / `hp_max_add` | 마나·HP 상한 가산 |
| CHARM | `dash_cooldown_mult` | 대시 쿨다운 배율 |
| PAPER | `ink_capacity` / `mana_discount` / `durability_bonus` | 잉크 상한(24/32/48) / 마나 감면(0/.1/.2) / 내구 가산(0/5/12) |

**GameState API**: `equipment`(착용 중 id) · `equip_gear(id)` · `unequip_gear(kind)` · `gear_param(kind,key,default)` · `mana_max()` · `hp_max()` · `wand_pattern()`. balance 직접 참조 금지, 전부 getter.

### 3.3 EventBus 시그널

```gdscript
# 드로잉/도안 (A→B·D·E)
design_created(design) · design_updated(design) · recognition_result(role, matched, score)
# 캐스팅 (C→B, B→C·E)  — 검사 순서: INVALID→BROKEN→NO_MANA
cast_requested(design, origin, aim_dir) · cast_executed(design, mana_spent) · cast_failed(design, reason)
# 전투 (B↔C) — enemy_hit은 적 take_hit 내부 1곳에서만 발신 (약점 반영 최종 피해)
enemy_hit(enemy, damage, rune_type) · enemy_died(enemy_def, position)
player_damaged(amount) · player_hp_changed(hp, hp_max) · player_died
# 탁본·익스트랙션 (C→D·E)
rubbing_started(fid) · rubbing_completed(fid) · extraction_success · bag_lost
# 시간 · 도감 · 거점 · 장비 · 씬
phase_changed(phase) · day_started(day) · codex_unlocked(unlock_id)
research_completed(unlock_id) · design_repaired(design) · resources_changed
equipment_changed · scene_changed(scene_id) · scene_change_requested(scene_id)
# 온보딩 (거점 시험장 ↔ 튜토리얼)
training_hit(rune_type, damage) · tutorial_focus(target_id)   # 거점 허수아비는 enemy_hit 발신 안 함
```

**unlock_id 규약**: `rune_<명>` · `recipe_<id>` · `enemy_<id>` · `quest_<n>` · `cut_<id>` · `tutorial_done`.
시작 해금: `rune_fire`·`rune_impact` (🔴 v2.2 §4: `rune_impact` 폐지 → `rune_fire`+`glyph_thrust`). **새 게임 시작 도안은 0장** — 첫 도안은 튜토리얼에서 직접 그린다.

### 3.4 인식기 (모듈 A)

획 하나가 끝날 때마다 판정: 1. **원**(기하 — 시작·끝 거리 + 원형도) → 2. **탈출 판정**(진 안/밖) → 3. **룬**($1 유니스트로크) → 4. **직진성 폴백**.

- **룬 vs 문양 구별 = "진을 뚫고 나가는가"** (직진성 아님 → 곡선 문양 허용). 탈출 3조건: 끝점이 진 밖(`ARROW_ESCAPE_R=1.20`) + 시작보다 충분히 멀다(`ARROW_ESCAPE_GAIN=0.25×r`) + 감김 1.5바퀴 미만(바람◎ 차단). 🔴 **v2.2 F1 조임**(1.05·0.12 → 1.20·0.25): "확실히 뚫은 획만 화살표". **진이 있으면 화살표는 오직 탈출(관통)로만 인정** — 직진성 게이트는 진이 없을 때만 쓴다(진 안 곧은 획이 화살표로 새던 창구를 닫았다). 소속 판정은 별도 상수 `CIRCLE_CONTAIN_R=1.05`로 분리
- **문양 글자는 $1로 읽는다** — 점수 미달이면 BASIC(`GLYPH_MIN_SCORE`). BASIC↔유도 겹침은 **이탈도**(`GLYPH_MIN_BOW=0.08`)로 가른다 (직진성으로는 못 가른다)
- ⚠ **룬·문양 템플릿 배열은 분리** — 두 enum 정수값이 겹친다(`FIRE=0=BASIC`). 섞으면 조용히 서로 먹는다
- ⚠ **U턴 형태 글자 금지** — 끝점이 시작 근처로 오면 룬으로 오인. 모든 문양은 전진하며 끝난다
- 물~ vs 바람◎: 리샘플 64pt + 총 회전각(감김) 피처 별도 게이트. **세션 7 실측 룬 99.5% · 문양 100%**
- 정확도 → `rune_accuracy`(하한 0.6). 자동보정 = 템플릿 형태로 스냅하되 accuracy는 현재값 유지. 스탬프 = 저장 시점 보정 보존

### 3.5 먹선 렌더 · 썸네일 (`src/core/`, 리드 소유)

**`ink_render.gd`가 도안 렌더의 유일한 지점** — 드로잉룸·캐스팅 마법진·투사체·UI 썸네일이 전부
이걸 preload. `SpellDesign.strokes`(원본 획)를 새 에셋 없이 그대로 렌더.

- `unit_px(balance)` = `circle_radius_px × 2` (**이 관계를 깨면 마법진과 발사 기점이 따로 논다**)
- `build_design(design, px, opts)` → 먹선 Line2D 트리 (기본 필터 CIRCLE·RUNE·TAIL·DECOR — 화살표 제외). strokes 비면 null 반환 → 호출자 폴백
- `tail_line` / `arrow_line` / `arrow_tip` / `arrow_heading` / `arrow_extent` — 책자·종이·투사체가 **전부 같은 함수**. 갈라지면 그린 그림과 날아가는 방향이 어긋난다
- 썸네일은 `design_thumb.gd`(Control) 하나. 폴백 모양은 **호출자가 주입**(core가 모듈 스타일을 preload하면 의존 방향이 뒤집힌다)

### 3.6 저장

`user://save/`에 JSON — 영구부(도감·거점·창고·제법)와 하루 상태(장착·가방) 분리. `SpellDesign`은
`user://designs/*.tres`(strokes 포함). ⚠ **중첩 진·룬 N개가 오면 세이브 마이그레이션 1회** — 그때
`circle_radius`도 배열로 함께 열면 공짜(§4-D2). **진 1개를 코드 곳곳에 하드코딩하지 말 것.**

### 🔴 세션 14 추가 결정 (2026-07-15) — 충격이 룬을 떠난다 (v2.2 재정렬, 미구현)

> **"충격은 사실 문양이어야 하는 건가?"** — 사용자. 룬 복합을 파다가 *"돌 응집 + 충격으로 빠르게"*
> 처럼 **하나가 다른 것에 작용하는** 비대칭 자유도를 원했는데, 블렌드 복합으론 안 나온다는 걸 짚었다.
> 진단: 블렌드 복합은 배치가 무의미 = **스위치**(§1.5 문양 대원칙 3번 질문 위반).

**경계 재정의 — 룬은 속성(적에게 무슨 일이), 문양은 힘(탄이 어떻게 행동하나):**
- **룬 = 속성/원소**: 불=화상 · 물=둔화 · 바람=흐름
- **문양 = 동사/효과**: 팅김·유도·관통 · **추진(신설, 빠르게 날아간다=속도)** · 화살표=충격파

**바뀌는 것 (7):**
1. **충격이 룬에서 빠진다.** 충격만 원소가 아니었고(불·물·바람=원소, 충격=물리력), 넉백은 이미
   화살표 충격파가 한다(§1.5 "위로 그은 화살표=밀어냄") → 중복. → `RuneType {FIRE, WATER, WIND}`
2. **추진 문양 신설** — "빠르게 날아간다"(탄의 행동=속도). `GlyphType`에 THRUST 추가. 그동안 임자
   없던 **투사체 속도 축**(§4 열린 축)이 여기 붙는다
3. **넉백은 화살표 충격파가 담당** — 충격 룬 상태이상 제거로 중복 해소 (`Status.KNOCKBACK` enum은 충격파용으로 유지)
4. 🟢 **룬 복합 = 대등 블렌드로 확정** — 비대칭 자유도가 룬끼리가 아니라 **룬(질료)×문양(동사)**으로
   빠졌으니, 룬끼리는 원소가 섞이기만 하면 된다(수증기 반응 담당). 아래 룬 N개 모델(fill 가중평균 +
   상태이상 각각)이 **그대로 맞다** — 오히려 단순해졌다
5. **시작 = 불 룬 + 추진 문양** — 튜토리얼이 "룬×문양"(속성 vs 효과) 대비를 처음부터 가르친다.
   시작 해금 `rune_fire`·**`rune_impact` 폐지** → `rune_fire` + `glyph_thrust` (둘째 시작 룬 없음)
6. **숲 사냥개 카운터 = 충격 → 바람** (§2.5 — 재빠른 사냥개엔 흐름/면제어가 어울림)
7. **흙/돌 룬은 나중** (원소 확장 때). 사용자 예시 "돌 응집"은 그때 성립. 지금은 3원소 유지
