# 몸이 계단을 뚫고 지나간다 — 아직 남아 있다

## 무엇이 되면 끝인가

**계단을 오르내리는 몸이 어느 프레임에서도 계단 안으로 들어가지 않는다.**

## 어디서 왔나

**2026-08-29, 사용자가 화면을 보고** — 「뚫고 가는데?」. ⚠ **그날 계단 관련으로 넷을 고친 뒤에도 남았다.**

## ⚠ 이 라운드에 이미 고친 것 — 다시 하지 말 것

| 무엇이었나 | 어떻게 고쳤나 |
|---|---|
| **그림은 6단, 발 높이는 매끄러운 비탈** | `Grid.surface_h` 가 `Rules.STAIR_TREADS` 단으로 떨어진다. 비탈로 되돌리면 `net_tiers` 가 스물한 지점 중 열여덟에서 빨개진다 |
| **계단 그림과 발 높이가 서로 다른 방향으로 올랐다** | 모서리 계단의 「입」을 두 파일이 각자 골랐다. `Grid.STAIR_MOUTH_ORDER` 와 `island_build.py` 가 같은 우선순위를 쓴다 |
| **발 높이를 반 조각 옆에서 읽었다** | 픽셀 좌표를 나눠 쓰던 것을 계산의 조각 좌표로 바꿨다 |
| **계단 옆구리로 올라탔다** | `Grid._stair_face_open` — 계단과 바깥은 오르는 축 방향으로만 오간다 |

## ⚠⚠ 남은 후보 — **어느 것인지 아직 안 쟀다**

- **난간이다.** 2026-08-29 에 계단 양옆에 턱을 세웠는데(`STAIR_RAIL_W` · `STAIR_RAIL_H`), **난간은 그림일 뿐이고 계산은 그것을 모른다.** 몸이 난간 자리로 걸어가면 뚫는다. ⚠ 조각 한가운데는 난간 밖이라 정상이면 안 닿아야 하는데, 흔들림·런지·넉백이 몸을 옆으로 민다
- **몸의 그림 크기다.** 스프라이트 안의 여백만큼 발이 실제 발밑보다 아래에 놓인다 (`BODY_LIFT_PX` 가 그것을 보정하는 값이다)
- **계단을 오르는 도중의 보간이다.** `Battle._walk` 은 조각 중심에서 중심으로 미끄러지는데, 그 사이 높이는 `surface_h` 가 매 프레임 다시 답한다 — 단 사이를 지날 때 한 프레임 어긋날 수 있다

## 무엇을 먼저 하나

**사용자에게 「난간을 뚫는지, 계단 단을 뚫는지」를 물어서 갈래를 하나로 줄인다.** 둘은 고치는 데가 다르다.
