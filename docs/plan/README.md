# docs/plan — **무엇을 할 것인가**가 사는 곳

⚠ **2026-08-27 에 `.scratch/island-hold/` 에서 옮겨 왔다.** 그 이름은 안 쓰기로 한 스킬이 쓰던 자리라서
붙은 것이고, 근거가 사라졌다. ⚠⚠ **git 은 그전에도 계속 추적하고 있었다** — 버리는 곳이었던 적이 없고,
이름만 그렇게 읽혔다.

## 파일 셋, 그리고 각자 하나씩만 한다

| 파일 | 무엇 | 여기 없는 것 |
|---|---|---|
| **`roadmap.md`** | **무엇을 · 언제 · 끝났나.** 주마다 날짜와 할 일과 **상태 표시**, 그리고 덩어리마다 **끝나는 조건** 한 줄 | ⚠⚠ **왜 그렇게 정해졌나, 그리고 인용** — 2026-08-27 에 전부 `log.md` 로 내렸다 |
| **`log.md`** | **왜 그렇게 됐나.** 결정과 뒤집힘의 기록, 사용자의 말 그대로 | 이번 주에 뭘 하나 |
| **`tickets/NN-이름.md`** | **일 하나.** 질문 하나 또는 작업 하나 | 여러 개를 한 파일에 |

⚠⚠ **같은 것을 두 곳에 적지 않는다.** 앞서 이 저장소는 같은 숫자를 세 곳에 적어 두고 **셋 다 틀린** 적이
있다. **이번 주에 뭘 하는지 물으면 로드맵을 본다.**

## 티켓 맨 위 세 줄이 상태 전부다

```markdown
Type: grilling          ← grilling(결정) · task(작업)
Status: open            ← open · claimed · resolved
Blocked by: 01, 03      ← 없으면 이 줄을 뺀다
```

- **결정 티켓** — 답이 **「무엇을 만들지」**다. **사용자가 대화에서 답한다**
- **작업 티켓** — 답이 **코드**다. `build-loop` 이 가져간다
- **지금 잡을 수 있는 것** = 열려 있고, 안 막혔고, 안 잡힌 것. **번호 빠른 순**
- **파일은 폴더 사이를 옮겨 다니지 않는다.** 상태는 파일 안의 줄이다
- **슬러그는 영문, 본문은 한국어**

## 누가 읽고 쓰나

| 스킬 | 무엇을 하나 |
|---|---|
| **`compass`** | 로드맵의 이번 주와 티켓을 읽어 **「지금 뭐 하지」**에 답한다 |
| **`breakdown`** | 덩어리 하나를 티켓 여럿으로 쪼갠다. **먼저 `survey`(안)와 `scout`(바깥)을 보내고, 사용자와 모양을 정한 뒤에** 쓴다 |
| **`build-loop`** | 작업 티켓 하나를 계획 → 구현 → 검증까지 |
| **`wrap-up`** | 끝난 것을 여기에 반영하고 커밋한다 |
| **`roadmap`** | 로드맵을 실제 커밋과 대조한다 — 드리프트 · 구멍 · 남은 것 |
