이름만 그렇게 읽혔다.

**사용자**: 「티켓이 뭐 이렇게 많아. 진짜 존나 많다. 다 지워도 되겠다. 그럼 깔끔한 상태가 되잖아.
이렇게 관리하면 힘들고」.

⇒ **`tickets/` 는 지금 비어 있다.** 마흔다섯 중 스물넷이 열려 있었고, 한 사람이 한 번에 훑을 수 있는
양을 넘었다. **관리 비용이 티켓이 주는 값보다 커졌다는 것이 지운 이유다.**

⚠ **전부 `git log` 에 있다.** 되살릴 일이 생기면 거기서 꺼낸다.
⚠⚠ **다음 티켓은 `grilling` 으로 사용자와 깊이 이야기한 뒤에 하나씩 쓴다** (2026-08-30, 사용자:
「그릴링에서 태스크 하나 티켓 하나를 나랑 깊숙이 대화한 그릴링을 써서 문서화를 해야 돼」).
**로드맵이 주를 들고, 그 주를 쪼갠 것이 티켓이다** — 티켓 하나가 주 하나만큼 커지면 안 된다.

## 파일 셋, 그리고 각자 하나씩만 한다

| 파일 | 무엇 | 여기 없는 것 |
|---|---|---|
| ~~**`roadmap.md`**~~ | ⚠⚠ **`docs/roadmap.md` 로 올라갔다** (2026-08-30, 사용자: 「로드맵 문서는 docs 최상단에 있게 해줘」) — **이 폴더보다 윗급이라 한 칸 위에 선다** | — |
| **`log.md`** | **왜 그렇게 됐나.** 결정과 뒤집힘의 기록, 사용자의 말 그대로 | 이번 주에 뭘 하나 |
| **`tickets/NN-이름.md`** | **일 하나.** 질문 하나 또는 작업 하나 | 여러 개를 한 파일에 |

⚠⚠ **같은 것을 두 곳에 적지 않는다.** 앞서 이 저장소는 같은 숫자를 세 곳에 적어 두고 **셋 다 틀린** 적이
있다. **이번 주에 뭘 하는지 물으면 로드맵을 본다.**

## 티켓 맨 위 세 줄이 상태 전부다

```markdown
Type: grilling          ← grilling(결정) · task(작업)
Status: open            ← open · claimed · resolved
Blocked by: 01, 03      ← 없으면 이 줄을 뺀다
```

- **결정 티켓** — 답이 **「무엇을 만들지」**다. **사용자가 대화에서 답한다**
- **작업 티켓** — 답이 **코드**다. `build-loop` 이 가져간다
- **지금 잡을 수 있는 것** = 열려 있고, 안 막혔고, 안 잡힌 것. **번호 빠른 순**
- **파일은 폴더 사이를 옮겨 다니지 않는다.** 상태는 파일 안의 줄이다
- **슬러그는 영문, 본문은 한국어**
