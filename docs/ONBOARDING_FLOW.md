# 온보딩 흐름 설계 (스탠다드 튜토리얼)

> 🔴 **왜 이 문서가 생겼나 (세션 40 대화):** 사용자가 직접 플레이한 결과 —
> *"그냥 시작하고 마녀 하나 덩그러니 있습니다 하고 끝. 어떤 유도도 없어."*
> 시스템은 다 있는데(경제·퀘스트·룬·원정) **하나의 리듬으로 안 꿰여** 중구난방이다.
> 원인 진단: 이 게임 심장은 **그리기**인데, 현재 첫 퀘스트가 "사냥 5마리"이고
> 그리기는 **숨은 선행조건**이라(새 게임 = `ring_equipped` 0장) 코어가 온보딩 첫 비트가 아니다.
>
> 방침: **흐름을 먼저 정하고 → 개발.** 순서 안 정하고 시스템부터 얹어서 중구난방이 됐으니,
> 이번엔 반대로 간다. 아래 흐름을 **세션 단위로 하나씩, 검증하면서** 구현한다.

---

## 목표 흐름 — 처음부터 끝까지

세 구간(A 이동 → B 마법 만들기 → C 나가기)으로 나눈다.
각 단계에 🆕(신규 개발) / ✅(이미 있음) 를 표시.

### 구간 A — 이동 튜토리얼 (베이스 이전, 신규 진입 씬)
> 게임을 켜면 베이스가 아니라 **이동 튜토 씬**부터 시작. 조작만 가르치고 전투는 안 시킨다.
> **설명 팝업이 아니라 "길이 막혀서 배우게" 만든다** — 문에 닿으려면 움직여야 하고,
> 균열을 넘으려면 굴러야 한다. 손이 먼저 배운다.

**튜토 방 구성 (사용자 확정 세션40):** 침대 하나 + 문 하나 + 중간에 균열.
1. 🆕 **침대에서 깨어남** (게임 시작 = 이동 튜토 전용 씬. 타이틀 → 여기 → 베이스 순으로 진입점 변경)
2. 🆕 **WASD 이동** — `"WASD로 움직여봐"`, 움직이면 안내 사라짐. 문으로 가려면 움직여야 함(강제)
3. 🆕 **Shift 구르기(dodge roll)** — 문 가는 길 중간 **균열/무너진 바닥**(못 걸어 넘음) → `"Shift로 굴러 넘어"`
   → 구르기가 **길을 막는 걸 넘는 도구**로 처음 쓰임(강제로 배움). ⚠ **새 전투 메커니즘. 지금 게임에 없다.**
   - 스펙(잠정, 손맛 보며 조임): **무적 프레임 있음**(회피 핵심) · 대시 ~120px · 쿨다운 ~0.6s · **마나 소모 없음**
4. 🆕 문 도착 → **문 열림** → 베이스캠프로 씬 전환
5. 🆕 기본 마법 하나 **지급** (장착된 상태로 — 새 게임이 마법 0장이던 걸 채운다. 지급 시점은 구간 B와 조율 — 열린 질문 4)
6. ⚠ **허수아비 등 처치는 안 시킴** (사용자 정정: *"허수아비는 치지 말고"* — 이동만 익힌다)

### 구간 B — 베이스 + 마법 만들기 튜토리얼
> 코어(그리기)를 **첫 강제 경험**으로 세운다. = 위 진단 A의 해결.

1. ✅ 베이스 진입. **안내 NPC** 하나 (이미 있음 — `base.tscn` `Npc`)
2. 🆕 NPC 퀘스트: **"작업대(책상)로 가라"** 유도 (현재는 유도 없이 방치)
3. ✅ 작업대 E → **마법 만들기(그리기)** (이미 있음 — `ring_forge_panel`)
4. 🆕 마법 완성 → **튜토 퀘스트 완료 → 보상** (신규 퀘스트 `q00_first_draw`, 정산은 기존 배선 재사용)

### 구간 C — 나가기(원정) 튜토리얼
> "왜 나가나"를 NPC가 말로 심고, 원정을 한 바퀴 돌려 본다.

1. 🆕 마법 튜토 완료 → NPC가 다시 말 검
2. 🆕 **NPC 동기 대사** — *"더 좋은 마법엔 새 룬이 필요하다. 가장 약한 숲에서 룬을 가져와라."*
   (세계관·동기 부여. 현재 NPC는 대사 없이 패널만 연다 → **대사 시스템 신규**)
3. 🆕 *"이게 필요할 거야"* 하며 **물품/먹을 것(소모품) 지급**
   — ⚠ **세션 35 결정과 충돌**: 당시 허기는 *"먹는 것 없음 = A안"*으로 확정했다.
   먹을 걸 주려면 **소모품·회복 아이템 시스템이 신규**고, 허기 설계를 다시 봐야 한다. (열린 질문 참조)
4. ✅ 숲으로 감 (이미 있음 — 숲길 E → `forest.tscn`)
5. 🆕 숲에서 **M키 → 지도** (신규)
6. 🆕 지도에 **마커 표시**(플레이어가 직접) → 목표 지점으로 이동 (신규)
7. ✅ 적과 싸워 **드롭 획득** (이미 있음 — `forest_enemy` 드롭)
8. ✅ **귀환** (이미 있음 — 남쪽 출구 E)
9. ✅ 기지 복귀 → **정산** (이미 있음 — NPC 턴인)
   — ⚠ 사용자 표현 *"캐스트를 완료하는 것까지"*의 정확한 의미 확인 필요(정산=완료로 해석).

**여기까지가 "아주 기본적인 스탠다드한 튜토리얼".**

## 열린 질문 / 결정 필요

1. **먹을 것(소모품) vs 세션35 "먹는 것 없음"** — 소모품·회복 시스템을 새로 넣을지,
   아니면 지급 물품을 "재료/룬" 같은 비소모 아이템으로 바꿀지. 허기 설계에 직결.
2. **Shift 구르기 스펙** — 무적 프레임? 쿨다운? 거리? 마나 소모? (전투 손맛에 큰 영향)
3. **M 지도 범위** — 자동 탐사 맵인지, 고정 미니맵인지, "마커 직접 찍기"의 UX.
4. **이동 튜토에서 준 마법이 베이스에서 그린 마법과 겹치나** — 튜토 마법은 임시고
   구간 B에서 처음 "진짜" 마법을 그리는 건지, 순서 정리 필요.
5. **"캐스트 완료"의 정확한 의미** (정산=완료로 잠정 해석).

## ① 구현 기록 (세션41) — 이동 튜토 + Shift 구르기

  `forest_enemy`가 접촉 피해 전 `is_rolling()` 확인 → 구르는 중이면 피해 흘림. `dash` 액션 Space→Shift.
  수치는 `balance`(dash_speed 640·duration 0.2·cooldown 0.6 — **잠정, 손맛 나중에 한 방에**).
- **튜토 방** `src/tutorial/intro.tscn`(+`intro.gd`): 침대(스폰) → WASD로 걷기 → 잔해(굴러야 통과) → 문 → 베이스.
  ⚠ **은퇴했다 (세87 실측)** — `src/tutorial/` 폴더가 **없고** `title.gd`에 튜토 참조가 0건이다.
  지금 [새로하기]는 **마을 직행**이고, 조작은 마을 온보딩 대사가 가르친다. 아래 두 줄은 세41 시점의 기록이다.
  🔴 잔해 통과 = **구르기 무적과 같은 술어**: 잔해 = layer 8 StaticBody, 플레이어 마스크에 8을 얹고

문 닿음→base 전환 · 에러 0. 🔴 **손맛(거리·속도·쿨·무적 길이)은 미조정 — 온보딩 다 얹고 한 방에.**

**남은 것(구간 A):** 침대에서 "깨어남" 연출(지금은 그냥 스폰) · 기본 마법 지급 시점(열린 질문 4) · 아트(플레이스홀더 도형).

## ③ 구현 기록 (세션41) — NPC가 그리기 개념을 대사로 가르침

🔴 **스코프 변경(사용자 확정):** *"따로 재료 없이 가자. 지금은 NPC가 마법진 그리는 튜토리얼 만들자."*
→ 원정 준비물(소모품/재료)·동기 대사는 **보류**(세션35 허기 충돌 회피). 대신 **그리기 개념을 NPC가
가르치는** 데 집중. 그리기 패널은 이미 단계마다 스스로 안내(`ring_forge_panel._say`)하므로, 빈칸은
**패널 열기 전의 개념**(마법진=진·룬·문양을 손으로 그린다)이었다.

**만든 것:**
- **재사용 대사 상자** `src/hud/dialogue_box.gd`+`.tscn` (takbon-ui 제작): `open(lines, speaker)` → 한 줄씩,
  [E]/좌클릭/▶로 넘김, 마지막에 `finished`. ESC 건너뛰기. 🔴 모달 규약(`ui_modal_open` 토글=플레이어 멈춤) +
  mouse_filter(root STOP·밴드 IGNORE·닫히면 invisible). CanvasLayer(layer 8).
- **base.gd 배선**: NPC 대화 시 — **첫 마법 전**(q00 미완료 & ring_designs 빔 & 이번 방문 첫 대화)이면
  개념 대사 5줄(진·룬·문양·따라긋기·분석/주입·책상으로) → 끝나면 닫고 책상으로. **그 후엔 정상**(정산+시트).
  🔴 E 넘김이 NPC를 재트리거 안 함 = `interact_zone`의 `if ui_modal_open: return` 가드가 이미 막는다.

**검증:** 헤드리스 `test_dialogue_box_auto` OK + 전체 스위트 **12/12 그린**(core enums/game_state 건드려 전수) ·
**실게임 exec/스샷**: 새 게임 NPC 대화→대사 렌더(하단 밴드·이름표·글씨 확인)·플레이어 멈춤(modal) →
[E] 5회로 줄 넘겨 닫힘·플레이어 풀림·**시트 오발 안 뜸**(E/존 충돌 없음) → 2차 대화=대사 재현 안 하고 시트 정상.

**남은 것:** NPC 대사 톤·줄 수 튜닝 · (보류)원정 준비물·동기 대사는 필요해지면 별도 결정.

## ④ 구현 기록 (세션41) — 숲 M 지도 + 마커

> ⚠🔴 **통째로 은퇴했다 (세87 실측)** — `src/hud/map_panel.gd`·`forest.gd`·`map` 액션(project.godot) **전부 없다.**

> 아래는 세41 기록이다. 🔴 단 마지막 「함정 기록」(`push_input` 좌표가 윈도우 픽셀 = 캔버스의 2배)은 **지금도 유효한 검증 함정**이다.

**만든 것:**
- **재사용 지도 패널** `src/hud/map_panel.gd`+`.tscn` (takbon-ui 제작): `open(data)` — data={bounds,player,
  enemies,extract,marker}. 숲 도식(경계·나·적·귀환점) `_draw` 렌더 · **클릭→월드 좌표 역변환→`marker_placed`**
  (place-and-stay, 지도 밖 무시) · M(`map`)/ESC=`closed`. 🔴 좌표 왕복(`world_to_map`/`map_to_world`)이 단일

## 비주얼(아트)은 언제 챙기나 — 결정

**흐름 먼저, 아트는 흐름이 "산다"로 확정된 직후. 그리고 온보딩 구간을 아트 1순위로.**

근거:
- 🔴 **아트는 되돌리기 비싼 함정**(memory `takbon-magic-needs-purpose`·반복 지적). 흐름이 바뀌면 그린 게 버려진다. 지금은 흐름이 확정 전이라 그리면 낭비 위험이 크다.
- 지금 노잼은 *"안 예뻐서"*가 아니라 *"흐름이 없어서"*다. **아트는 있는 재미를 증폭하지, 없는 재미를 만들지 않는다.** 네모·동그라미여도 흐름이 명료하면 재밌을 수 있다.
- 단, **온보딩 = 첫인상**이라 아트 민감 구간이다("마녀 하나 덩그러니"의 일부는 비주얼 빈곤이기도). 그래서 흐름 확정 후 **제일 먼저 아트를 입힐 구간 = 온보딩**.
- 마녀 스프라이트는 이미 있다(세션38). 완전 무비주얼은 아니다 — 적·타일·이펙트가 플레이스홀더.

**순서: 위 ①~⑤로 흐름을 플레이스홀더로 완성 → 처음~끝 플레이해서 "산다" 확인 → 온보딩부터 아트 패스.**
