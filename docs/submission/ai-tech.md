# AI 활용 기술 문서 — 탁본 (Tockbon)

플레이 https://djgnfj-svg.github.io/tockbon/ · 소스 https://github.com/djgnfj-svg/tockbon · 영상 `(URL)`

**AI에게 코드를 빨리 쓰게 하지 않았다. AI가 거짓말을 못 하게 만드는 장치를 먼저 짓고, 그 위에서 개발을 시켰다.**

**1인 개발, 9일.** 첫 커밋 2026-08-02, 제출 2026-08-10, 커밋 152개.
`src/` 약 18,400줄 중 사람이 직접 타이핑한 코드는 거의 없다.
사람이 쓴 시간은 전부 판정 장치에 들어갔다 — `tests/`가 약 28,400줄로 **본 코드의 1.5배**다.
넷(net) 35개가 검사 8,423개를 30초에 돌린다.

그런데 제출 당일, 그 검사가 전부 초록인 채로 웹 빌드의 한국어가 전부 `□□□`였다.
브라우저 콘솔 에러는 0줄이었다.

**이 문서는 그 두 문장 사이에 대한 것이다.** 그리고 이 문서의 목적은 자랑이 아니라 **공개**다 —
여기 적힌 하네스는 전부 공개 저장소에 파일로 들어 있고, 그대로 가져가 쓸 수 있다.

*(수치는 2026-08-10 측정. 저장소가 공개이므로 전부 재현할 수 있다.)*

## 1. AI 아키텍처

![하네스 전체 구조. 사람은 맨 위에서 결정하고 판정한다](img/ai-arch.png)

LLM에게 게임 기능을 시키면 세 가지가 반복해서 나왔다. 전부 이 프로젝트에서 실제로 겪은 것이다.

- **가짜 코드** — 스텁을 "완료"로 보고. 이 입력에만 맞는 하드코딩. 에러를 삼켜서 성공처럼 보이게 함
- **가짜 테스트** — 테스트는 초록인데 아무것도 재지 않음
- **화면과 시뮬의 분리** — 시뮬은 정확한데 화면이 안 따라옴. 이전 프로토타입이 정확히 이렇게 죽었다

세 번째가 가장 비쌌다. **"돌아간다"는 보고를 믿을 수 없다**는 것이 이 구조의 출발점이다.

### 에이전트 여섯 — `.claude/agents/`

각 파일이 그 에이전트의 시스템 프롬프트다. 한 줄씩이면 이렇다.

| 에이전트 | 역할 | 금지 |
|---|---|---|
| spec | 설계 문서를 구현 계획으로 바꾼다 | 코드를 쓰지 않는다 |
| builder | 계획에 적힌 것만 구현한다 | 계획도, 측정도, 완료 선언도 하지 않는다 |
| verify-run | 헤드리스로 돌려 계획의 「인수 조건」을 값으로 확인한다 | 코드를 읽지 않는다 |
| verify-look | 게임을 띄워 계획의 「화면」과 눈으로 대조한다 | 수치로 판정하지 않는다 |
| verify-read | 코드를 적대적으로 읽어 반증하고, 넷을 일부러 부순다 | 게임을 띄우지 않는다 |
| harness-manager | 넷이 느려지거나 헛돌면 재고 고친다 | 기능 코드를 건드리지 않는다 |

**금지 열이 설계의 본체다.** 각 에이전트가 무엇을 못 하는지가 경계를 만든다.
검증자를 셋으로 나눈 이유도 같다 — verify-run은 실행하면 실패하는 것을, verify-read는 이 경우에만 되는 것을,
verify-look은 시뮬은 맞는데 화면에 안 나오는 것을 잡는다. 하나라도 빼면 그 구멍으로 샌다.
실제로 verify-look은 "물 재질과 색은 다 들어갔는데 그리라고 부르는 곳이 없어서 한 칸도 안 나온" 상태를 잡았다.

### 스킬 넷 — `.claude/skills/`

에이전트가 「누구」라면 스킬은 「언제 무엇을」이다. 절차서 한 장씩이고, 사용자의 한마디가 이걸 부른다.

| 스킬 | 역할 |
|---|---|
| game-planning | 사용자와 대화하며 기능을 설계하고 `1.ready/`에 문서로 떨군다 |
| build-feature | 그 문서 하나를 팀으로 구현한다. 다섯 에이전트를 띄우고 조율한다 |
| harness-audit | 하네스를 점검해 문제만 보고한다. 아무것도 고치지 않는다 |
| wrap-up | 실제로 끝난 것만 문서에 반영하고, 넷을 돌리고, 커밋한다 |

**게임을 만드는 스킬은 둘뿐이고 나머지 둘은 하네스와 기록을 지킨다.** 그 비율이 이 프로젝트의 성격이다.

### 프롬프트는 대화가 아니라 파일이다

`CLAUDE.md`는 모든 세션과 모든 에이전트에 자동으로 실린다. 여기 적힌 것이 곧 전역 규칙이다.
대화창에 그때그때 친 문장은 그 세션과 함께 사라지지만, 파일에 박힌 규칙은 다음 세션의 첫 줄부터 다시 실린다.
**그래서 이 프로젝트에서 프롬프트 엔지니어링은 파일을 고치는 일이다.** 전문은 §9와 공개 저장소에 있다.

## 2. 한 세션을 길게 도는 법

한 세션이 몇 시간씩 이어진다. "에이전트를 여러 개 띄운다"는 쉽고,
**동시에 오래 돌려도 결과가 무효가 안 되게 만드는 것**이 어렵다.
아래는 전부 이 프로젝트에서 부딪히고 규칙으로 굳힌 것이다.

| 함정 | 굳은 규칙 |
|---|---|
| 에이전트를 다시 부르면 새 인스턴스가 코드를 처음부터 다시 읽는다 | 스폰은 한 번, 이후는 전부 메시지. 유휴는 죽음이 아니다 |
| 팀원의 최종 텍스트는 메인 대화에 도달하지 않는다 | 모든 지시 끝에 "결과를 main으로 보내라"를 붙인다 |
| 컨텍스트는 스폰 순간에 얼어붙는다 | 세션 도중 설계 문서를 고치면 직접 알린다 |
| 검증자가 builder의 편집 순간을 밟으면 그 검증은 전부 무효 | 검증 중 builder를 동결한다. 실제로 세 번 밟았다 |
| 병렬 뮤테이션이 같은 파일을 부수면 양쪽 측정이 다 무효 | 검증자마다 git worktree를 따로 판다 |
| 되돌림이 반복되면 builder가 검증을 통과하려고 코드를 구부린다 | 3회에서 멈추고 사람에게 간다 |
| 워크트리는 자동으로 안 지워진다 | 하룻밤에 700MB가 쌓였다. 검증이 끝나면 강제로 지운다 |

### 세션의 끝을 스킬이 맡는다

긴 세션의 마지막에 반드시 무너지는 것이 **기록**이다. 코드는 남는데 왜 그렇게 했는지가 사라진다.
그래서 마무리도 절차서로 만들었다(`wrap-up`).
사용자가 "확인했다"고 말한 순간 그 문장은 그 자리에서 설계 문서의 `Accepted`에 박힌다.
**대화는 사라지고 저장소는 남는다. 다음 세션의 AI가 보는 것은 저장소뿐이다.**

기각된 갈래를 적어두는 폴더가 이 구조의 핵심이다 — 설계 16개, **기각 19개**, 계획 35개.
없으면 다음 세션의 AI가 이미 기각된 설계를 자신 있게 다시 제안한다. 반복해서 겪었다.

### 세션 자체를 갈라서 돌린다

에이전트를 병렬로 돌리는 것과 별개로, **세션을 통째로 갈라 각자 브랜치에서 돌리고 나중에 합친다.**
아직 많이 쓰지는 않았고, 지금도 한 축은 이 방식으로 돌아가고 있다.

검증자에게 git worktree를 따로 파는 규칙이 그 축소판이다 —
이 저장소에는 지금도 에이전트용 워크트리 브랜치가 **9개** 남아 있다.
같은 파일을 동시에 부수는 뮤테이션이 서로의 측정을 무효로 만들기 때문에, **격리가 곧 측정의 조건이다.**

한 갈래가 실패해도 다른 갈래가 살아 있고, 합치는 순간에만 사람이 판단하면 된다.
9일이라는 기간은 이 갈라짐 없이는 안 나온다.

### 모델도 역할에 맞춘다

판단이 결과를 바꾸는 자리(설계 · spec · 검증)는 상위 모델, 계획을 실행하는 builder는 중위,
값 읽기 같은 기계적 작업은 하위. **검증을 아끼려고 낮추지 않는다.**
대표적 실패가 "도는 척"이고, 그걸 잡는 게 검증자다.

## 3. MCP — Godot을 고른 이유

**엔진 선택의 첫 번째 기준이 "AI가 이 엔진을 직접 볼 수 있는가"였다.**

`godot-mcp`는 에디터 애드온과 로컬 서버 한 쌍이다. 이것이 붙으면 AI가 할 수 있는 일이 이렇게 늘어난다.

| 무엇 | 왜 필요했나 |
|---|---|
| 씬과 노드를 읽고 고친다 | 코드가 아니라 씬에만 있는 배선을 확인한다 |
| 게임을 띄우고 입력을 주입한다 | "플레이하면 이렇게 된다"를 사람 없이 재현한다 |
| 게임 시간을 멈추고 한 프레임씩 민다 | 프레임 단위 판정을 잰다 |
| 실행 중인 게임 안에서 GDScript를 실행한다 | 보스 앞까지 걸어가지 않고 그 상황만 세운다 |
| 런타임 상태를 텍스트 요약으로 받는다 | 스크린샷보다 훨씬 싸다. 값 확인은 전부 이쪽 |
| 에디터가 자기 뷰포트를 캡처한다 | 마지막에 눈으로 볼 때만 |

**화면을 봐야만 잡히는 결함이 실제로 있다.** 물 재질과 색이 다 들어갔는데 그리라고 부르는 곳이 없어서
한 칸도 안 나온 상태, 그리고 §4의 폰트 사고가 그것이다. 넷을 아무리 더 짜도 그 둘은 안 잡힌다.

### 대신 공유 자원 하나가 병렬성을 깨뜨린다

에디터 브릿지는 클라이언트를 하나만 받는다. 그런데 에이전트마다 자기 MCP 서버 인스턴스가 붙고,
유휴 상태가 돼도 그 연결이 끊기지 않는다. "검증자 셋 동시" 원칙이 여기서 깨졌다.

프롬프트로 "쓰지 마"라고 금지해서는 못 막는다. 클라이언트는 도구 호출과 무관하게 세션 시작 시점에 생기고,
에디터가 없는 30분 동안 살아 있다가 에디터가 뜨자 즉시 포트를 잡았다.
에디터를 재시작해 경쟁을 다시 붙여도 같은 놈이 이겼다.
**유일하게 확실한 해법은 브릿지를 쓰는 에이전트 외에는 그 MCP 서버를 아예 안 붙이는 것이었다.**
그래서 verify-run과 verify-read의 정의에 "헤드리스 전용"이 박혀 있고, 화면을 보는 것은 verify-look 하나뿐이다.

### 1인 개발이라 사람과 AI가 같은 기계를 쓴다

전역 키 주입을 시도했다가 키가 사용자가 보고 있던 브라우저로 들어간 사고가 있었다.
그 뒤로 창 포커스와 키 주입은 금지가 됐다.
에이전트가 화면을 보는 방법은 **에디터가 자기 뷰포트를 직접 캡처하는 것뿐이다.**

## 4. 초록이 거짓말한 사례들

넷은 Godot 헤드리스로 각자 독립 프로세스에서 병렬 실행된다.
한 프로세스에서 전부 돌리면 332초다. 속도 차이는 크지만 그게 이유가 아니다 —
한 넷이 선언한 에러 사면(amnesty)이 다른 넷까지 덮어버리는 것을 막기 위해서다.
프로세스를 분리하면 사면이 자기 넷 안에 갇힌다.

### "N개 통과"는 초록이 아니다

Godot의 `load()`는 파싱 실패에도 non-null을 반환한다. `src/`가 깨져도 통과 개수는 그대로 유지된다.
그래서 러너 위에 래퍼를 한 겹 올렸다 — 러너의 숫자가 아니라 stderr에 엔진 에러 블록이 있었는지로 판정한다.
검사를 하나도 안 돌린 넷도 실패로 친다. 조용히 사라지는 것이 실패의 가장 흔한 모습이기 때문이다.

### 뮤테이션 — 새 검사는 반드시 뒤집어 본다

검사를 추가하면 그 검사가 지키는 코드를 일부러 부순다. 빨개지지 않으면 그 검사는 헛돈다.
이 규칙이 실제로 잡아낸 것:

- 셰이더가 통째로 깨졌는데 39개 검사가 전부 초록 — A/B 비교는 "달라졌다"는 잡아도 "사라졌다"는 못 잡는다
- 0번 도는 정착 루프 — 조건이 처음부터 거짓이라 검사 본문이 한 번도 실행되지 않았는데 통과
- 순서 계약을 최종 상태로만 잰 검사 — 반복 순서를 뒤집었는데 최종 상태가 같아서 초록 유지
- 화면 안내 문구가 크기 0으로 그려져도 검사 320개가 통과 — 기능이 눈에 안 보이는데 넷은 조용했다
- 파일을 grep하는 검사 5개가 전부 회피당했다 — 미끼 줄, 항 하나 추가, 선언 위치 이동,
  다른 파일에서의 같은 쓰기, 두 줄 사이의 이른 `return`. 규칙이 "값을 직접 구동하라"로 바뀐 자리다
- 씬 빌드에 실패한 검사는 실패하지 않고 사라진다 — 조용히 반환하고, 통과 수만 줄고, 아무도 안 짖는다

**뮤테이션의 산출물은 "빨개졌다"가 아니라 "무엇을 못 잡는지"다.** 초록으로 남은 뮤테이션이 곧 그물의 구멍이다.

### 그리고 그 장치 전체가 통과시킨 것

제출 당일, 검사 8,423개가 전부 초록인 채로 배포된 웹 빌드의 한국어가 전부 `□□□`였다.
체력 · 연구대 · 조립대 · 재료 이름. 콘솔 에러는 0줄.

원인은 폰트였다. Godot 내장 폰트는 라틴 글자만 들고 있고,
데스크톱에서는 OS의 시스템 폰트로 조용히 폴백해서 한글이 멀쩡히 나온다.
**웹 빌드에는 폴백할 시스템 폰트가 없다.**

| 검증 경로 | 이 결함을 잡는가 |
|---|---|
| 넷 8,423개 (헤드리스) | 못 잡는다 — 문자열 값은 정확히 맞다. 글리프가 없는 것뿐이다 |
| 에디터에서 눈으로 (verify-look) | 못 잡는다 — 데스크톱은 시스템 폰트로 폴백한다 |
| 브라우저에서 배포본 열기 | 잡는다. 그리고 이 경로만 잡는다 |

Noto Sans KR을 번들해 고쳤다. 남는 것은 폰트가 아니라 경계다 —
**넷을 더 짜서 막을 수 있는 종류의 결함이 아니었다.** 테스트 묶음은 "거짓이 아니다"까지 보증하고,
"배포된 형태로 사람이 열어봤다"는 그 바깥에 있다.

## 5. 구조가 검증을 가능하게 한다

폴더가 계약이다. AI가 어디에 무엇을 쓸지 헷갈릴 여지를 구조로 없앴다.

| 폴더 | 계약 |
|---|---|
| `src/sim/` | 정수 결정론. `float` · `Vector2` · `sqrt` · `sin` · `randi` 금지. 씬 트리를 모른다 |
| `src/actor/` | float 허용. 여전히 씬 트리를 모른다 |
| `src/view/` | 화면만. 시뮬을 읽되 절대 쓰지 않는다 |
| `src/stage/` | 껍데기 — 틱 루프 · 입력 · HUD |

**정수 결정론은 멀티플레이 때문에 고른 제약이지만, AI 검증에 그대로 이득이 된다.**
부동소수점이 없으면 같은 입력에 같은 출력이 바이트 단위로 보장되고,
그러면 "돌려보니 맞더라"가 아니라 "이 값이어야 한다"를 검사에 박을 수 있다. 결정론 검사 하나가 193개 검사로 그것을 지킨다.

넷은 폴더를 재귀 스캔한다. 손으로 관리하는 등록부가 없어서, 파일을 추가하면 자동으로 계약 검사에 걸린다.
정수 세계로 들어가는 문은 함수 하나다. 문이 하나면 AI가 우회로를 만들었는지 한 곳만 보면 된다.

## 6. 아트 파이프라인 — 로컬 우선, 사람이 고른다

그림도 전량 AI로 만들었다. 다만 **어디서 뽑느냐를 나눴다.**

| 무엇 | 어디서 | 왜 |
|---|---|---|
| 마법진 UI · 문양 · 룬 · 몬스터 정지 프레임 | 로컬 ComfyUI (이 PC의 GPU) | 크레딧이 안 든다. 배치로 마음껏 뽑는다 |
| 네발짐승 걷기 애니메이션 | PixelLab | 로컬 워크LoRA가 사람용이라 동물 걷기는 로컬 경로가 없다 |

흐름은 이렇다.

```
프롬프트 + 프리셋 → ComfyUI 배치 8장 → 한 장의 시트로 붙임 → 사람이 눈으로 하나 고름
   → 배경 컷 → assets/ 로 이동 → (움직여야 하면) PixelLab animate_image → 시트 + GIF
```

**말로는 안 갈린다.** 후보를 배치로 뽑아 시트 한 장에 붙여 놓고 사람이 고르는 단계가 파이프라인의 중심이다.
프리셋 한 항목이 문체 · LoRA 강도 · 크기를 함께 들고 있다. 스타일이 갈라지는 것을 막는 자리다.

여기서 나온 실측들:

- 비정수 축소는 선이 깨진다. **정확히 2배 크기로 생성**해야 한다
- MCP 클라이언트는 3,000자 넘는 base64를 **조용히 자른다.** 팔레트 png로 양자화해야 통과한다
- 몬스터는 크로마 초록 바닥을 달고 나온다. 정확한 색 일치로 지우면 **초록 테두리**가 남고,
  어두운 배경 위에서 그 테두리가 화면에서 제일 밝다. "초록이 우세한 픽셀"로 잘라내는 도구를 따로 만들었다
- 고리 문양은 안쪽 구멍도 크림색이라 테두리에서 흘려보내는 방식으로는 안 지워진다.
  밝기를 알파로 뒤집어 넣는 세 번째 경로가 필요했다

**참고 이미지는 넣지 않았다.** 레퍼런스를 스타일 참조로 넣으면 그 그림 자체를 거의 복제한다는 것이
파이프라인 문서에 측정으로 적혀 있고, 남의 아트를 그렇게 쓰지 않는다는 규칙을 지켰다.

## 7. 게임 안의 AI — 지금과 다음

**지금 게임에 들어 있는 것은 규칙 기반 몬스터 AI다.** 과장하지 않는다.
동시 20마리, 모든 자연법칙이 그대로 적용되고, 보스는 상태 기계다.
전부 정수 결정론 안에 있어서 멀티플레이에서 그대로 재현된다.

본선에서 갈 방향은 이 게임의 구조에서 자연스럽게 나온다:

- **마법진을 조립하는 동료 AI.** 문양은 조합이 아니라 순열이라 탐색 공간이 사람에게도 어렵다.
  AI 동료가 다른 순열을 고르는 것만으로 협동의 결이 생긴다
- **팀킬이 의도된 재미인 게임에서의 위치 판단.** AI 동료의 가치는 강함이 아니라 어디에 서느냐다
- **판정 가능한 AI.** 시뮬이 정수 결정론이므로 AI 동료의 행동도 검사로 잴 수 있다 —
  "같은 상황에서 같은 판단을 하는가"가 테스트 가능한 명제가 된다. 이 프로젝트가 가진 특이한 자산이다

### 외부 에셋 — 폰트 하나를 빼면 없다

| 종류 | 개수 | 출처 |
|---|---|---|
| 이미지 (`assets/` 아래 png) | 85 | 전량 자체 생성 — 로컬 ComfyUI, 일부 애니메이션만 PixelLab |

AI 생성물은 로컬 ComfyUI와 PixelLab API로 만들었고, 생성 결과물의 권리는 각 서비스 이용약관에 따라 이용자에게 귀속된다.

### 라이선스 준수

- Godot Engine — MIT. 엔진 바이너리는 저장소에 커밋하지 않는다
- Noto Sans KR — SIL OFL 1.1. 폰트 파일과 라이선스 전문을 함께 배포하며, 폰트 이름을 바꾸지 않았다
- ComfyUI — GPL-3.0. **로컬에서 도구로 실행할 뿐 코드를 배포물에 넣지 않는다.** 본체와 모델은 저장소 밖에 있다
- godot-mcp — npm 패키지를 실행 시점에 내려받아 쓰고, 에디터 애드온은 저장소에 그대로 둔다.
  빌드에서 빼지 않는다 — 애드온 안의 스크립트를 자동로드가 참조하고 있어서, 부분 제외는 부팅을 깨뜨린다
- PixelLab — 유료 API. 사용료는 참가자 부담
- MCP 설정 파일은 커밋하지 않는다 — API 키가 평문으로 들어가고 실행 경로가 이 PC의 절대경로다.
  공개 전환 전에 전체 커밋 히스토리를 훑어 시크릿 0건을 확인했다

### 만든 것 — 전부 공개 저장소에 있다

에이전트 정의 6개 · 절차 스킬 4개 · 전역 규칙 파일 · 넷 러너와 침묵 감지 래퍼 · 넷 35개 ·
에셋 생성 도구 · 손으로 그린 PNG를 4px 셀 지형으로 굽는 왕복 도구 · 이 제출 문서를 PDF로 굽는 도구.

핵심은 프롬프트가 아니라 프롬프트에 박힌 실패 사례다. 검증자 정의가 들고 있는 "넷이 죽는 모양" 목록은

## 9. 실제 지시문

아래는 발췌이며, 전문은 공개 저장소의 `CLAUDE.md`와 `.claude/`에 있다.

### 모든 세션과 모든 에이전트에 자동으로 실리는 규칙

> **가짜 코드 금지.** 돌아가는 척하는 코드는 안 돌아가는 코드보다 나쁘다.
> - 이 입력에만, 이 테스트에만 맞는 하드코딩
> - 계산하는 대신 그럴듯한 값을 반환하기
> - 스텁을 완료로 보고하기
> - 에러를 삼켜서 성공처럼 보이게 하기
> - 화면은 바뀌는데 시뮬은 안 바뀌는 것(또는 그 반대)
>
> **못 하겠으면 못 하겠다고 말해라.**

> **가짜 넷 금지.** 라벨이 검사보다 많은 것을 주장하면 그 초록은 거짓 보증이다.
> 새 검사는 전부 뒤집어 봐라. 뒤집었는데 안 물면, 검사를 의심하기 전에 뮤테이션이 실제로 먹혔는지부터 확인해라.

> **파일을 grep하는 검사는 그 파일의 텍스트를 잴 뿐, 무엇을 계산하는지는 절대 못 잰다.**
> 한 기능에서 5개의 스캔이 나갔고 전부 회피당했다. **값을 직접 구동해라.**

### 구현 담당에게

> **값을 관찰하지 마라. 화면을 보지 마라.** 그건 전부 검증자의 관찰이다. 헤드리스든 눈이든 상관없다 —
> **재는 순간 판정한 것이다.** 자기 작업을 자기가 재면 언제나 유리하게 읽힌다.
> "대체로 맞는 것 같다"가 정확히 여기서 나오고, 그게 돌아가는 척하는 코드의 출생지다.

> **완료를 선언하지 마라.** 그건 verify-run과 verify-read의 몫이다.
> 너는 "계획대로 썼다"까지만 말하고 멈춘다. 자신 없는 곳을 숨기지 마라 —
> 말하는 것이 검증자를 그리로 먼저 보내는 방법이다.

### 검증 담당에게

> **"돌아간다"는 통과 근거가 아니다. 왜 돌아가는지 설명할 수 있을 때 통과다.**
> 자세는 적대적이다. 코드가 맞다는 걸 확인하려 들지 말고, 틀렸다는 걸 증명하려고 읽어라.
> 문제가 없으면 없다고 말해라. **없는 문제를 만들어내지 마라.**

### 팀 운영 절차

> **검증자에게 builder의 소감을 전달하지 마라.** "빌더가 잘 됐다고 한다"가 전달되는 순간
> 그들은 닻을 내리고 더 이상 독립적인 눈이 아니다.
> 전달할 것은 무엇을 어디에 썼는지와 builder가 자신 없다고 말한 곳뿐이다.

### 이미지 생성

```
python tools/pixel/gen.py "eight straight rays radiating from a center point inside a hexagon" \
    --name glyph_spread --preset glyph --batch 8
```

아이콘류는 `no slots no frames`, `evenly spaced apart`를 넣어야 조각으로 분리돼 나온다.
