## 1번 — 빌드와 소스

**`.exe`는 받지 않는다.** 요강 원문: "보안 상의 이유로 PC 실행 파일(.exe 등) 직접 제출은 받지 않습니다."
⇒ **웹 빌드가 정답이다.** 이미 나와 있다.

```powershell
New-Item -ItemType Directory -Force build\web
.\Godot_v4.7.1-stable_win64.exe --headless --export-release "Web"
```

산출물 `build/web/` — 약 39MB (`index.wasm` 37.7 + `index.pck` 1.5).
**스레드 없는 빌드**라 COOP/COEP 헤더 없이 GitHub Pages에서 그대로 돈다.
로컬 확인은 `python -m http.server 8123 --directory build\web`.

### 요강이 요구하는 저장소 조건

- **전체 소스 코드를 같은 저장소에 포함**
- **커밋 기록 유지** — 122개 커밋이 그대로 증거가 된다. squash 금지
- **공개(public) 권장.** 비공개면 심사 계정 `dl_gameai_reviewer@nhn.com` 초대

### 공개 전 확인 (중요)

- **`.mcp.json`은 gitignore돼 있다** — PixelLab API 키가 평문으로 들어 있다. 공개 전 `git log`에
  과거 커밋된 적이 없는지 확인할 것
- `build/`도 gitignore. GitHub Pages는 `gh-pages` 브랜치나 별도 배포로 올린다

## 2번 — **30~60초** 영상

요강 원문: "30~60초 분량으로, **실제 게임 플레이 장면을 중심**으로 제작해 주세요."
"**AI를 이용한 조작·합성이나 타인 영상의 도용은 불가**합니다. 실제 플레이 화면 그대로 담아야 합니다."

⇒ **하네스 화면이나 개발 과정을 넣을 자리가 없다.** 60초 전부 플레이 화면이다.
AI 이야기는 4번 문서가 전담한다.

### 60초 구성안

| 시간 | 화면 |
|---|---|
| 0:00–0:12 | **`퍼짐→폭발`과 `폭발→퍼짐`을 연달아.** 같은 글리프, 순서만 바꿔서. 자막 두 줄만 |
| 0:12–0:25 | 지형이 4px 단위로 파이고, 그 구멍으로 물이 쏟아지고, 불이 나무에만 붙는다 |
| 0:25–0:40 | 나무벽에 막힘 → 구덩이 → 황소 → **불 룬 획득** → 벽을 태우고 통과 |
| 0:40–0:55 | 거대 닭 보스, 물이 차오르는 탈출 |
| 0:55–1:00 | 게이트 통과 |

**첫 12초가 전부다.** 순서가 결과를 바꾸는 것이 이 게임에서 한 눈에 보이는 유일한 차별점이다.
설명하지 말고 화면 둘을 붙여서 보여준다.

**공개 또는 일부 공개(링크 공유)로 업로드.** 심사 종료까지 접근 가능해야 한다.
