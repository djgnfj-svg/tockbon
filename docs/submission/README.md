## 1번 — 빌드와 소스

**`.exe`는 받지 않는다.** 요강 원문: "보안 상의 이유로 PC 실행 파일(.exe 등) 직접 제출은 받지 않습니다."
⇒ **웹 빌드가 정답이다.** 이미 나와 있다.

```powershell
New-Item -ItemType Directory -Force build\web
.\Godot_v4.7.1-stable_win64.exe --headless --export-release "Web"
```

산출물 `build/web/` — **44.1MiB** (`index.wasm` 37.68 + `index.pck` **6.10** + 나머지 0.3).
**2026-08-10 11:17 실측** (`Get-ChildItem build\web | Measure-Object Length -Sum`).
익스포트 자체는 **6.1초**, 종료 코드 0, stderr 깨끗함.
pck가 1.5 → 2.31 → **6.39MB**로 자란 것은 그림이 44 → 85장이 됐고 **한글 폰트 4.6MB가 들어갔기** 때문이다.
**wasm은 템플릿 고정이라 안 변한다** — 세 번 재배포하는 동안 바이트가 같았다.
**스레드 없는 빌드**라 COOP/COEP 헤더 없이 GitHub Pages에서 그대로 돈다.
로컬 확인은 `python -m http.server 8123 --directory build\web`.

### 배포한 방식 (재현용)

`gh-pages` **orphan 브랜치**에 `build/web/`의 내용만 올린다. `.nojekyll`을 넣어야
Jekyll이 파일을 건드리지 않는다.

```powershell
git worktree add --detach C:\temp\ghp
cd C:\temp\ghp; git checkout --orphan gh-pages
# 내용을 비우고 build/web/. 를 복사, .nojekyll 생성
git add -A; git commit -m "웹 빌드 배포"; git push -f origin gh-pages
gh api repos/<user>/<repo>/pages -f "source[branch]=gh-pages" -f "source[path]=/"
git worktree remove --force C:\temp\ghp; git worktree prune
```

**워크트리는 반드시 지운다** — 자동 정리는 거의 안 걸린다(하룻밤에 700MB, 실측).

### 요강이 요구하는 저장소 조건 — 전부 충족

- **전체 소스 코드를 같은 저장소에 포함** — `main` 브랜치
- **커밋 기록 유지** — **147개** 커밋(2026-08-10 11:20 측정, `git rev-list --count HEAD`). squash하지 않았다
- **공개(public)** — 전환 완료. 심사 계정 초대 불필요

### 공개 전 시크릿 검사 (완료)

`.mcp.json`에 PixelLab API 키가 평문으로 들어 있어서 **전체 히스토리를 훑었다.**

```bash
git rev-list --all | xargs -n 50 git grep -lE "Bearer [a-f0-9]{8}-|gho_|ghp_|sk-[A-Za-z0-9]{20}"
```

**결과 0건.** 과거에 커밋된 `.mcp.json`은 godot·aseprite만 있던 버전이고,
PixelLab이 추가된 뒤로는 gitignore에 걸려 한 번도 올라가지 않았다.

## 3·4번 — PDF 변환

**변환기가 리포에 있다. 한 줄이면 두 개가 같이 나온다.**

```powershell
python tools\submission\md2pdf.py
```

산출물 `build/submission/` — **`plan.pdf` 8쪽 · `ai-tech.pdf` 13쪽** (2026-08-10 12:26 실측).
**이 폴더는 커밋하지 않는다** — 소스는 마크다운이고 PDF는 그것의 출력이다.

| 단계 | 무엇 |
|---|---|
| 마크다운 → HTML | `python-markdown` + `tables` · `fenced_code` · `md_in_html` |
| HTML → PDF | **설치된 Chrome을 `--headless --print-to-pdf`로 부른다.** A4 · 여백 16mm |

**왜 `npx md-to-pdf`가 아닌가**: 이 문서들은 **표가 대부분이고 전부 한국어**다.
기성 변환기는 표 확장이 기본으로 꺼져 있거나 **한글 폰트를 안 싣는다** —
**그게 정확히 이 프로젝트가 웹 빌드에서 당한 결함이다.** Chrome은 OS 폰트 스택에서 인쇄한다.
`Malgun Gothic`이 PDF에 **서브셋으로 임베드된 것을 확인했다**(`fitz`로 폰트 목록을 읽어 확인).

**인쇄에서만 드러난 것 두 개** — 스크립트가 후처리로 고친다:

- **`<details>`가 접힌 채 인쇄된다.** 종이에는 펼칠 삼각형이 없으므로 `plan.md` 첫 페이지의
  "소스에서 직접 빌드하려면" 블록이 **통째로 사라졌다.** 전부 `open`으로 강제한다
- `| | |`로 쓴 키/값 표가 **빈 헤더 줄**을 회색 띠로 남긴다. 빈 `<thead>`를 지운다

**PDF 첫 페이지에 플레이 링크와 영상 링크를 박는다.** 요강이 3번 문서에 요구하는 항목이고,
두 문서 다 첫 표가 그것이다. **⚠ 영상 URL 칸은 아직 `(업로드 후 기입)`이다 —
업로드하면 두 마크다운을 고치고 위 명령을 다시 돌린다.**

**문서 안의 상대 링크(`review.md` 등)는 PDF에서 죽으므로** 변환기가 공개 저장소 URL로 바꿔서 넣는다.

  `스테이지 1 클리어` 정산 화면 · 개발 종료 안내 — **구현됐고 넷은 초록이지만 눈이 닿은 적이 없다.**
  검증 중 **개발 종료 안내가 크기 0으로 그려져도 검사 320개가 통과**하는 구멍이 실제로 나왔다(수정됨).
  ⇒ **초록인 넷은 「본 게임」이 아니다.** 촬영이 사실상 첫 육안 검증이 된다
- ~~HUD에 개발용 안내 두 줄이 항상 떠 있다~~ — **닫혔다. 그리고 이 항목은 두 번 틀렸다.**
  「두 줄」이 아니라 **열다섯 줄**이었고, 그건 **이 문서를 쓴 뒤 이미 F3 뒤로 들어가 부팅 때 꺼져 있었다.**
  오늘 닫은 건 그 다음 구멍이다 — **readout은 숨었는데 키는 살아 있었다.**
  M 한 번이면 심사자 머리 위에 황소가 서고, 1 한 번이면 조립이 바뀌고, R 한 번이면 런이 날아간다.
  셋 다 「키를 눌렀다」로 안 읽히고 **게임이 깨진 걸로 읽힌다.**
  ⇒ **F3가 개발자 모드가 됐다** (`stage_input._debug_on`). 게이트 뒤: 1~6 · M/N/B/C/V · T · G · L · R · 줌.
  게이트 앞(플레이어 키): 이동 · 점프 · 발사 · Tab · P · ESC · **F(상호작용)**.
  `net_render._developer_keys_are_gated_behind_f3`가 실제 키 이벤트로 잰다
- **사운드가 하나도 없다** — 영상에서 무음이 된다. 확인함: 오디오 파일 0개
- **스테이지가 하나뿐이다.** GDD는 첫 빌드를 두 스테이지로 적고 있다.
  셸에 스테이지 식별자 자체가 없고 맵은 구운 상수 하나다 —
  구조 조사 결과는 Track D/E가 들고 있다
