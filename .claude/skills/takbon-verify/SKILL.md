# 탁본 검증 규율

이 프로젝트에서 제일 비싸게 배운 것 = **"테스트가 그린이다"는 "동작한다"가 아니다.** 세션 22·23·25·26이 전부 초록불을 믿었다가 사용자가 직접 플레이해서 버그를 찾았다. 아래는 그 반복을 막는 규율이다.

## 0. 원칙 한 줄

> **사용자가 "안 된다"고 하면 초록불보다 사용자가 옳다.** 검증이 계층을 건너뛰었을 가능성을 먼저 의심해라 (세션 25: 리드가 "발사 정상"이라고 여러 번 틀리게 말했다 — 검증이 전부 Control 계층을 우회했기 때문).

## 1. 전체 테스트 스위트 (반드시 Bash에서)

PowerShell은 자식 프로세스 stdout을 안 보여준다 — **테스트는 Bash 툴로 돌려라.**

🔴🔴 **돌릴 땐 손으로 적은 목록을 쓰지 마라 — 파일시스템에서 파생시켜라.** 이 프로젝트가 **세51·세84·세87에 세 번** 밟은 게 「목록이 뒤처져 절반만 돌고도 전 스위트를 돌렸다고 믿는」 것이다(세84엔 지난 세 세션의 **심장 테스트 넷**이 빠져 있었다). 아래 루프는 `tests/`를 직접 읽으므로 **새 테스트가 자동으로 들고, 영영 안 낡는다**:

### ⓐ 러너 한 줄 (세104 신설 — 평소엔 이걸 써라)

```bash
./Godot_v4.7.1-stable_win64.exe --headless --path . -s res://tools/run_tests.gd
./Godot_v4.7.1-stable_win64.exe --headless --path . -s res://tools/run_tests.gd -- realtime   # 옛 동작과 동일(가장 보수적)
./Godot_v4.7.1-stable_win64.exe --headless --path . -s res://tools/run_tests.gd -- ring       # 이름 필터
```

`tools/run_tests.gd`도 **`tests/`를 직접 훑어** 목록을 만든다(손 목록이 아니라 안 낡는다). **약 204s → 57s**.

🔴 **빠른 이유는 부팅이 아니라 `--fixed-fps 60`이다**(세104 실측이 「전 스위트 러너 204s→58s」 서술을 정정했다): 부팅은 41회 합쳐도 **14%**뿐이고, 시간을 먹은 건 **`await physics_frame`이 벽시계 60Hz에 묶인 것**이었다(느린 9개가 58%). `--fixed-fps`는 델타를 고정해 프레임을 CPU 속도로 돌린다 — **게임 시간은 그대로**다.
🔴🔴 **그런데 벽시계(`Time.get_ticks_msec`)를 읽는 테스트는 거기서 「거짓 빨강」이 난다.** 러너가 **소스를 스캔해** 그런 것만 실시간으로 돌린다(손 목록이 아니라 새 테스트에도 자동 적용된다 — 세104에 새 테스트 하나가 추가되자 스캔이 알아서 실시간에 넣었고, 열어 보니 정말 벽시계를 읽는 테스트였다. ⚠ 그 예시 파일은 **세112에 시야와 함께 삭제됐다** — 스캔 방식 자체는 그대로 유효하다).
⚠ **커밋 직전 최종 확인은 `-- realtime`으로 한 번 더** 돌려라.

🔴🔴 **세112 신설 — 요약 아래의 「엔진 ERROR:」 줄을 봐라.** `ERROR:`는 **`SCRIPT ERROR:`가 아니라서** 이 러너를 오래 그냥 통과했다(세112 단계 2·3·4가 **연달아** 이 사각에 걸렸다 — 물리 flush 중 `add_child` · 씬 노드가 사라진 뒤의 `push_error` · 방 밖 스폰. 전부 **엔진이 짖는데 전 스위트가 그린**이었다).
- 🔴 **판정에는 안 들어간다 — 세어서 보고만 한다.** 종료 잡음이 거의 모든 테스트에 떠서 판정에 넣으면 무더기가 빨개지고, 그러면 사람이 빨강을 무시하기 시작한다(그게 그물 전체를 죽인다 — 러너가 종료 코드를 버린 것과 같은 이유).
- 🔴 **기준선 = 3건이고 셋 다 테스트가 일부러 태우는 것**이다(없는 챕터 · 없는 지점 · Node2D 아닌 루트). ⇒ **4건이 되면 그게 새로 생긴 것**이다. ⚠ **그 셋을 잡음 목록에 넣지 마라** — 문구가 바뀌면 필터가 낡고 그 필터가 진짜 에러를 가린다.
- ⚠ **`push_error`도 `ERROR:`로 찍힌다**(실측 — `USER ERROR:`가 아니다).
- 🔴 **어떤 종류는 그물로 영영 못 잡는다**: 물리 콜백 `add_child`는 실측상 **노드가 정상으로 붙고 Area도 감지하며 로그 한 줄만 다르다** ⇒ 지연/직접이 **같은 결과**라 어떤 단언도 둘을 못 가른다. **그래서 이 줄이 유일한 눈이다.**
⏳ **미결(세104)**: 전체 실행에서 `test_ring_assembly_auto`가 **종료 코드만 0이 아닌** 채 FAIL로 찍힌 적이 있다(단독·필터 실행은 OK · `SCRIPT ERROR` 0). **테스트 간 `user://save_test/save.json` 공유가 유력**하다(`TODO.md` 「테스트 세이브 격리」) — 재현되면 그쪽부터 봐라.

### ⓑ 낱개 루프 (러너를 의심할 때 · 폴백)

```bash
for t in tests/*_auto.gd; do
  echo "=== $t"
  ./Godot_v4.7.1-stable_win64.exe --headless --path . -s "res://$t" 2>&1 | grep -E '_OK|_FAIL|SCRIPT ERROR:'
done
```

⚠ `_OK`만 grep하지 마라 — **`SCRIPT ERROR:`와 `_FAIL`을 같이** 본다(§3). 실패 집계는 이 프로젝트 형식인 **`TEST_*_FAIL`**이지 `fail=N`이 아니다(§4-3).
🔴 **콜론까지 붙여라**(세104 실측 — 위 루프는 고쳐 뒀다). 콜론이 없으면 `test_landmark_road_auto`가 **자기 출력에 적은 설명 문장**(*"…`SCRIPT ERROR`와 다르다"*) **3건**을 매번 잡아 **거짓 양성**이 난다. 엔진의 실제 형식은 `SCRIPT ERROR:`다.

🔴 **한 개만 돌리거나 그물(테스트) 자체를 고칠 땐 → [`references/test_contracts.md`](references/test_contracts.md)** — 「각 테스트가 무엇을 재는가」의 정본이 거기 있다(단독 실행 명령도 같이). **여기로 베껴 오지 마라** — 두 벌이 되면 갈라진다(세51·84·87).

🔴 실행은 위 루프가 `tests/`에서 파생시키므로 **목록이 뒤처져 절반만 도는 일은 이제 구조적으로 안 생긴다.** 남는 위험은 「설명이 낡는 것」뿐이라, 디스크와 계약 목록을 대조한다:

```bash
D=.claude/skills/takbon-verify/references/test_contracts.md
for t in tests/*_auto.gd; do grep -q "$(basename "$t")" "$D" || echo "설명 누락: $(basename "$t")"; done
grep -oE 'test_[a-z_]+_auto\.gd' "$D" | sort -u | while read -r n; do [ -f "tests/$n" ] || echo "유령: $n"; done
# 출력이 비어야 한다 (누락 = 새 테스트에 설명을 안 씀 · 유령 = 삭제·개명된 테스트가 설명에 남음)
```

**설명에서 빠진 테스트는 낡아 죽는다** — 세션 7이 문법을 바꾸며 두 테스트가 "목록에 없다"는 이유로 조용히 깨진 채 방치됐다(세션 8에 발견). 새 테스트를 더하면 **`references/test_contracts.md`에 「무엇을 재는가」 한 줄**을 같이 써라.

✅ **스위트는 실세이브를 못 건드린다** (세59에 격리됐다 — 그전엔 스위트 한 번에 타이틀 「이어하기」가 사라져 사용자가 실제로 밟았다). `SaveManager`가 `-s` 부팅(헤드리스 테스트)을 감지하면 세이브 뿌리를 **`user://save_test`**로 가른다(`save_manager`의 `_save_root` 선언 + `_is_test_boot()`). 그래서 테스트의 `wipe_save()`는 **테스트 세이브만 지우는 뒷정리**다. 격리 그물 = `test_save_auto [0]`(`-s` 부팅이면 `save_root()`에 `save_test` — 격리 로직이 지워지면 여기가 빨개진다, 뮤테이션 확인됨).

🔴🔴 **그러나 격리는 「뿌리」까지다 — 테스트끼리는 그 파일을 공유한다** (세98 실측 · 선재 버그를 이렇게 캤다).
`test_floating_wand_auto`가 **지팡이를 낀 채 끝나자** → `equipment_changed`가 **자동 저장 트리거**(세84 #1)라 `user://save_test/save.json`에 박히고 → 뒤에 도는 **`test_workshop_auto`가 그걸 로드해** 「맨손 기준값」이 오염돼 **2건이 빨갛다.**

- 🔴 **파일 하나만 돌리면 그린이라 안 보인다** — **전 스위트로 돌 때만, 그것도 순서에 의존해** 난다. 그래서 「내 갈래 테스트만 돌려 그린」은 근거가 약하다.
- 🔴 **장비·창고를 만지는 테스트는 뒷정리가 계약이다** — 끝에 상태를 되돌리고 **프레임을 2개 흘려라**(저장이 `call_deferred`라 안 흘리면 안 쓰인다).
- ⚠ 빨간 테스트를 만나면 **「그 파일이 틀렸나」보다 「앞 테스트가 뭘 남겼나」를 먼저 의심해라.** 범인이 다른 파일이라 그 안을 아무리 봐도 안 나온다.

🔴 **남는 진짜 주의 = 실게임은 격리가 없다.** F5·에디터 run·익스포트·MCP는 `-s`가 없어 **진짜 `user://save`를 쓴다** — 세65에 리드가 실게임 `new_game()`으로 실세이브를 덮어 실제로 날렸다. 🔴 **세이브를 건드리기 전 무조건 백업해라 — 경로는 `%APPDATA%/Godot/app_userdata/tockbon`이고, 이 한 줄이 백업 경로의 정본이다**(세65·85 — 세86도 이 절차로 도안 6장 실세이브를 살렸다). §2-4·§7이 여기를 가리킨다.

## 2. 헤드리스가 못 잡는 것 (실게임으로만 확인된다)

### 2-1. "클릭이 닿는다" — `push_input` + 실게임
🔴🔴 **헤드리스는 마우스가 Control에 닿는지 모른다.** 세션 25: 화면을 덮는 `Ground`(ColorRect)의 `mouse_filter`가 기본값 **STOP**이라 바닥이 좌클릭을 다 먹어 **발사가 통째로 죽었는데 전 스위트가 그린이었다.** 에러도 경고도 없다. 리드 검증이 전부 `_fire()` 직접 호출·`attack_basic` 액션 주입이라 Control 계층을 건너뛰어 두 세션을 못 잡았고, `push_input` 테스트를 새로 써도 헤드리스에선 그냥 통과했다(렌더가 없어 히트 테스트가 실제와 다르다).

- **화면을 덮는 Control을 새로 깔았으면 `mouse_filter = 2`(IGNORE)를 적었는지 확인하고, 에디터로 띄운 실제 게임에 `viewport.push_input(InputEventMouseButton)`을 밀어 0회→1회를 확인해라.** 액션 주입은 이 버그를 못 잡는다.
- 이건 베이스만의 얘기가 아니다 — **새 씬을 만들 때마다 되살아난다**(세션 26 숲에서 재발).

### 2-2. "보인다" — MCP 스샷
헤드리스는 "존재"만 확인하고 "보인다"는 못 본다(탁본 `z_index=-1`로 안 보였던 사례). **렌더·레이아웃을 건드렸으면 에디터로 띄워 스샷으로 확인해라.** 룬 탭·`refine_panel`/`workshop_panel`/`shop_panel` 렌더 · Tab 패널 레이아웃(탭 목록의 정본은 `tab_panel.TAB_NAMES` — 지금 **4탭**, 개수를 여기 베끼지 마라) · 완성 연출(`RingBoard.play_finish()`)은 전부 스샷으로만 검증된다. ⚠ **`decode_panel`은 세85에 은퇴했다**(해독대 + q05 한 세트) — 없는 패널을 확인하러 가지 마라.

🔴🔴 **「보인다」는 그물이 굳혀줄 수 없다 — 리드가 눈으로 봐야 한다**(세104): **전 스위트 45/45 그린인데 늑대가 뒷걸음질로 달렸다.** 그물이 오독을 **굳히고 있었다**(스프라이트 방향을 테스트가 반대로 단언했고, 그래서 고칠 때마다 빨개졌다). **「존재」는 헤드리스, 「보인다」는 눈**이다 — 화면에 나타나는 계약은 초록불 개수와 무관하다.

### 2-3. 소리가 난다 — 버스 라우팅
헤드리스는 오디오 드라이버가 없어 소리가 실제로 나는지 못 잡는다. `playing==true`·버스 라우팅은 에디터 실게임 exec로 확인.

### 2-4. 시간이 흐른다 — 마나 회복·DoT 틱·자동 저장
발사 연사 차단은 `fire()`를 거쳐야, **마나 회복**(`balance.mana_regen_per_sec`)·**상태이상 DoT 틱**·**자동 저장 틱**(`Clock.day_started` → SaveManager)은 시간이 흘러야 드러난다. 테스트가 우회하면 검출력 0 → 실게임 좌클릭·경과로 확인(세션 35는 이 확인을 못 해서 미검증으로 남았다). ⚠ **허기는 세58에 은퇴했다**(`game_state.gd`가 「읽는 곳이 0」이라 적어 뒀다) — 옛 예시였다.
🔴 **종료 시 저장은 이 항목의 최악 사례다**(세84): 트리거가 셋 있어도 **창 닫기 훅이 0건**이면 마을 작업이 **에러 없이 롤백**되는데 **헤드리스 검출력이 0**이다. 재는 법 = 게임만 독립 실행(`--path .`) → 실행 중 세이브 파일을 지우고 `CloseMainWindow()`(= X 버튼의 `WM_CLOSE`) → **파일이 재생성되나 + 프로세스가 실제로 죽나**(세85에 이렇게 잡았다). ⚠ **세이브를 건드리기 전 백업**(경로 = §1 끝).

## 3. `-s` 스크립트의 침묵 통과

🔴 **`-s` SceneTree 테스트는 런타임 에러가 나도 "OK"를 찍을 수 있다.** 세션 22: `test_ring_trace_auto`가 리팩터로 옮겨간 내부 필드(`_slots`)를 더듬다 에러로 함수가 **중단**됐는데 `failures=0`이라 통과로 보였다. 세션 23 재발(`_deploy_now` 옛 인자 수).

- **grep을 `_OK`만 하지 말고 `SCRIPT ERROR`도 같이 봐라.**
- `_check`가 **실패할 때만 출력**하면 침묵이 곧 통과다 — 함수가 죽어도 조용하다.
- **테스트는 공개 API로만 검증해라.** 내부 필드(`_슬롯`)는 리팩터 때 옮겨 다니는 물건이라 계약이 아니다.

## 4. 초록불을 근거로 쓰지 마라 — 뮤테이션으로 검출력 증명

🔴🔴 **고친 코드를 일부러 되돌려 정확히 몇 개가 실패하는지 확인한다.** 세션 22·23이 전부 이 방식으로 잡았다. 세션 23의 기존 테스트 하나(`정밀도 < 0.8`)는 **옛 관대한 판정도 통과**해 검출력이 0이었다 — 그린이지만 아무것도 안 지키고 있었다.

- 규칙을 바꿨으면: 규칙을 어긴 입력을 넣어 테스트가 **빨개지는지** 봐라. 안 빨개지면 그 테스트는 그 규칙을 검증하지 않는다.

### 4-1. 🔴🔴 뮤테이션 되돌리기에 `git checkout <file>`을 쓰지 마라 (세85 — 리드가 실제로 밟았다)

그 명령은 「뮤테이션만」이 아니라 **워킹트리를 통째로 HEAD로 되돌린다.** 병렬 갈래가 도는 세션에선 그 한 줄이 **남의 미커밋 작업을 지운다**(세85에 에이전트 3갈래의 파일 3개가 날아가 재작업했다). `git restore`·`git reset`도 같다.

- 반드시 **`cp f f.bak` → 뮤테이션 → `cp f.bak f` → `rm f.bak`** + **md5 대조**로 원상복구를 증명해라.
- 🔴 더 무서운 건 **복구 뒤 전 스위트가 그대로 그린이었다는 것**이다 — 날아간 게 「아직 그물이 없는 신규 기능」이면 **초록불이 소실을 덮는다**. 즉 소실 여부를 초록불로 판정할 수 없다.

### 4-2. 🔴 뮤테이션이 **적용됐는지부터** 확인해라 (세86)

python/sed 치환이 **조용히 실패**했는데 확인을 안 해 「검출 0」이라는 **거짓 결론**을 냈다(멀쩡한 그물을 헐겁다고 판정할 뻔). 이후 `grep -c`로 적용을 확인하자 같은 자리에서 6건이 검출됐다.

- 뮤테이션 직후 **`grep -c '<바뀐 문자열>' <파일>`**로 실제로 바뀌었는지 재고 나서 테스트를 돌려라.
- 🔴 이건 세85의 「도구가 틀리면 근거가 안 된다」가 **한 세션 만에 재현**된 것이다.

### 4-3. 🔴 fail 집계를 이 프로젝트 형식으로 해라 (세85)

리드가 실패 수를 `fail=N`으로 셌는데 **이 프로젝트는 `TEST_*_OK` / `TEST_*_FAIL`로 찍는다** → 뮤테이션 3건이 전부 「검출 실패」로 보였고, 멀쩡한 그물을 헐겁다 판정하며 에이전트의 정확한 보고를 뒤집을 뻔했다. **빨간불도 도구가 틀리면 근거가 안 된다.**

### 4-4. 🔴 「결과 값이 같다」는 「같은 길로 왔다」가 아니다 (세86)

UI 갈래 뮤테이션이 **그물이 헐거워 통과**했다 — 배열(`ring_equipped`)에 **직접 대입**해도 최종 값이 같아 보여 전부 그린이었다. **`equipment_changed` 발신 횟수**를 세고서야 빨개졌다.

- 「올바른 경로를 지났나」를 재려면 값이 아니라 **신호 발신 횟수·호출 횟수**를 세라.
- ⚠ 짝: **내가 만든 검사도 틀릴 수 있다**(세86 — 아이콘 「배치 각도」 검사가 반경 의존 편차로 **거짓 빨강**을 냈다. 검사 자체가 틀렸다). 빨개졌을 때도 「무엇이 빨개졌나」를 한 번 더 확인해라.

### 4-5. 🔴🔴 에이전트의 뮤테이션 보고를 「같은 이름으로 다시」 걸어 봐라 — 대상이 다를 수 있다 (세105)

에이전트가 *"「`ambush_mult`→1.0」으로 흔들었고 1건 검출"*이라 보고했고, 리드가 **같은 이름으로** 다시 걸었더니 **전부 그린**이었다. 둘 다 정직했다 — **흔든 대상이 달랐다**: 에이전트는 **기계**(코드의 상수·계산)를, 리드는 **데이터**(`.tres` 값)를 흔들었다.

- 🔴 **「기계」와 「데이터」는 그물이 두 개다.** 값이 데이터로 빠져 있으면 코드 뮤테이션이 그 그물을 안 건드리고, 반대도 같다.
- ⇒ **뮤테이션을 지시할 땐 「무엇을」이 아니라 「어느 파일의 어느 줄을」로 못 박아라.** 이름만 같은 두 자리가 있으면 보고가 서로를 반박하는 것처럼 보인다.

## 5. balance 수치를 런타임에 흔들어 검증할 수 없다

🔴 GDScript는 static 함수 안의 `const BAL.프로퍼티`를 **컴파일 타임에 굳힌다**. `RP.BAL.ring_stability_min`을 0.8로 바꿔도 `RP.threshold()`는 0.65를 돌려준다(같은 인스턴스인데도, 실측 확인). 게임엔 무해하지만 테스트는 조용히 거짓 통과한다.

- 대신 **두 함수의 경계가 어긋나지 않는지 전 구간을 훑어라**(`test_ring_design_auto`의 「사용 불가⇔펑」 방식). 이것도 뮤테이션으로 검출력을 확인했다.

## 6. 채점·손맛 수치는 헤드리스로 못 검증한다

테스트가 가이드 좌표를 그대로 찍으면 이탈이 0이라 **판정 반경을 뭘로 바꾸든 정밀도 100**이다 — 그린 게 아니라 아무것도 안 잰 것이다(세션 23의 착각). 손맛(챕터 보스방 손맛·문양 손맛·판정 반경·65점 기준선·드롭률 체감·피격 손맛 수치·완성 연출이 은은한가)은 **사용자가 마우스로 직접 그려/때려 봐야** 정해진다. 리드의 흔들림 시뮬레이션도 시뮬레이션이다.

## 9. 커밋 범위 — 이 리포는 세션이 여럿 돈다 (세103, 사용자 확정)

🔴🔴 **기획 세션과 구현 세션이 같은 워킹트리를 동시에 만진다.** 그래서 `git status`에 뜬 변경 중 **내 것이 아닌 게 늘 섞여 있다.** 사용자 확정: *"자기가 작업한 것과 관련 없으면 커밋 안 하도록."*

**실측(세103)**: 이 절을 쓰는 **한 대화 동안** 워킹트리가 **5건 → 12건**으로 늘었다. 옆 세션이 아트 레퍼런스 하네스를 짓느라 `CLAUDE.md`·`.gitignore`·`takbon-art.md`를 만지는 중이었다 — **`git add -A` 한 번이면 남의 미완성 하네스가 내 커밋으로 히스토리에 박힌다.**

- 🔴 **`git add -A`·`git add .`·`git commit -a[m]` 금지.** 경로를 하나씩 명시해서 add해라.
- **커밋 직전 절차** — 스테이지가 아니라 **워킹트리 전체**부터 본다:
  1. `git status --porcelain` — 지금 트리에 무엇이 있나
  2. 이번 세션이 만진 것만 `git add <경로>` — **기억나지 않으면 내 것이 아니다**
  3. `git diff --cached --stat` — 스테이지된 목록을 **눈으로** 확인하고 커밋
  4. 남은 변경은 **그대로 둔다** (§4-1 — `stash`·`checkout`·`restore`·`reset`은 남의 작업을 지운다)
- 🔴🔴 **파일 단위 add로 못 막는 게 있다 — 「같이 쓰는 문서」다.** `CLAUDE.md`·`BACKLOG.md`·`DECISIONS.md`·`PROGRESSION.md`·`.gitignore`는 두 세션이 **같은 파일의 다른 줄**을 쓴다. add 전에 **`git diff <파일>`로 내 줄만인지 봐라.** 섞였으면 **`git add -p`로 내 hunk만** 고른다.
- 🔴 **편집 위치도 골라라.** 남이 만진 줄 **바로 옆**에 쓰면 diff가 한 hunk로 묶여 `add -p`로도 못 가른다. 세103에 실제로 그랬다 — CLAUDE.md **최상단 표**에 옆 세션이 행을 더하고 있어서, 같은 표를 고치는 대신 **아래 「위임」 절에 썼다.**
- ⚠ **`git add -p`는 이 하네스에서 못 쓴다** — Bash 도구가 인터랙티브 git(`-p`·`-i`)을 막는다. 위에서 권하는 `add -p`는 **사람이 터미널에서 직접 할 때**의 얘기다. 에이전트가 갈라야 하면 ↓.
- 🔴🔴 **위치를 못 고를 때의 처방 — 「임시로 떼었다 되돌린다」** (세101 실측). *"남이 만진 줄 옆을 피해라"*가 안 통하는 경우가 있다: **내가 고쳐야 하는 줄이 곧 그 자리**일 때다(작업 목록의 「지점을 열면 재료가 쏟아진다」를 닫아야 하는데 옆 세션이 **바로 아래**에 새 항목(시야)을 넣어 둔 상태였다 — 항목을 다른 데로 옮겨 쓸 수는 없다).
  ⚠ **`git diff -U0`로도 안 갈린다** — 컨텍스트를 0으로 줄여도 git은 **인접한 변경을 한 hunk로 묶는다**(실측: 내 한 줄 수정 + 남의 4줄 삽입 → `@@ -72 +72,5 @@` 하나).
  🔴 **되는 절차**: ① 남의 줄을 **잘라내 임시 파일에 보관**(파일 전체 백업과 별개로, **그 줄만**) ② 내 줄만 남은 상태에서 `git add <파일>` → `git diff --cached --stat`이 **내 줄 수와 맞는지 눈으로 보고** 커밋 ③ 보관한 줄을 **원래 자리에 그대로 삽입** ④ 🔴 **`git diff <파일>`이 커밋 전과 같은 hunk인지 확인**(예: `@@ -72,0 +73,4 @@`가 그대로면 남의 작업이 손실 없이 돌아온 것이다).
  🔴 **`git stash`로 손을 뻗지 마라** — §4-1이 금지한 그 명령이고, 남의 미커밋 작업을 **통째로 들어올린다**. 여기서 필요한 건 「전부 치우기」가 아니라 **「몇 줄만 잠시 빼기」**다.
- ⚠ **diff가 0인데 `M`으로 뜨는 파일을 add하지 마라.** `git diff --stat`에 안 나오면 내용 변화가 없고 **개행(CRLF)만** 바뀐 것이다(세103에 `project.godot`이 그랬다). 넣으면 커밋이 노이즈로 부풀고 **남의 다음 diff가 시끄러워진다.**
- ⚠ **커밋 메시지도 내 작업만 말해라.** 딸려온 파일을 메시지에 끼워 정당화하려는 순간, 이미 범위가 샌 것이다.
- 🔴 짝: **남의 것을 지우지도 마라** — 되돌리기·정리 명령의 함정은 §4-1에 있다. **이 절은 「커밋한다」쪽, §4-1은 「지운다」쪽**이고 원인은 하나다(트리를 나 혼자 쓴다고 믿는 것).
