# 탁본 아트 레퍼런스 — 말로 설명하지 말고 그림을 줘라

## 🔴🔴 이 스킬이 존재하는 이유

세91에 아트 작업이 **규격 검사를 7/7 통과하고도 각하됐다**(*"굉장히 별로네"*).
`takbon-art`는 그 원인을 「생성기가 만든 것이라 계산돼 보였다」로 정리했지만, **더 깊은 원인이 하나 더 있었다**:

> **「좋다」의 기준이 말로만 존재했다.**

*"소프트 도트"*·*"숲마녀급"*·*"빛을 삼킨 짐승"* — 전부 **글자**다. 에이전트는 그 글자를 읽고
자기 머릿속 그림을 그렸고, 그게 사용자 머릿속 그림과 같을 이유가 없었다.

**레퍼런스 이미지 한 장이 형용사 백 개보다 정확하다.** 그래서 아트는 **예시부터** 간다.

⚠ **memory에 적어 두는 것으로 해결하려 하지 마라** — 사용자 실측 지적(2026-07-28):
*"메모리는 자주 무시하더라고."* 맞다. 그래서 이 규율은 **세 곳**에 있다:
① 이 스킬(절차) ② `.claude/agents/takbon-art.md`의 **하드 게이트**(레퍼런스 없으면 에이전트가 거부한다) ③ `CLAUDE.md` 포인터.

## 절차

### 0. 🔴 우리 것을 **먼저** 봐라 (이 순서를 지켜라)

**레퍼런스는 우리 것과 나란히 놓아야 의미가 있다.** 남의 그림만 잔뜩 보면 방향이 그쪽으로 끌려가고,
정작 **지금 무엇이 문제인지**를 모른 채 고른다.

- 기존 PNG를 **Read로 직접 봐라**(시트 전체가 한눈에 들어온다).
- 딸린 `.tres`의 `params`도 봐라 — `size`·`tint`·`anim_fps`가 **화면에 보이는 것을 이미 바꾸고 있다**.
- 여기서 나온 **한 줄 진단**이 검색어가 된다.

> 실례(세102): `hound_alpha`가 바탕 늑대와 **같은 PNG**에 `tint` 보라만 곱해져 있었고,
> 바탕 늑대를 직접 보니 *"「빛을 삼킨 짐승」보다 순한 들개"*였다. **이 진단이 없었으면
> 검색어를 못 짠다.** ⚠ 리드가 이번에 이 순서를 틀려서 레퍼런스를 두 번 헛뽑았다.

### 1. 이미 못박힌 제약을 확인해라

사용자가 **과거에 이미 각하한 것**을 레퍼런스로 들고 오면 그 자리에서 죽는다.
`docs/BACKLOG.md`·`docs/ART_SPEC.md`·설계 문서·memory에서 그 대상의 확정 제약을 찾아라.

> 실례: 우두머리 늑대 = *"눈으로 봤을때 차이가 있는데 **몸에서 빛이나는거 까진 별로임**"*.
> 그런데 「다크 판타지 늑대」 검색 결과는 **거의 전부 빛나는 눈**이었다.
> 🔴 **그걸 알고도 그냥 넘기면 안 된다** — 보여줄 때 *"이건 발광이라 제외 대상"*이라고 **명시해라.**

### 2. 검색 — **두 갈래**로 나눠 뽑아라

한 검색어로 둘 다 잡으려 하면 둘 다 놓친다.

| 갈래 | 무엇을 얻나 | 검색어 결 |
|---|---|---|
| **결·분위기** | 무엇을 목표로 하나(실루엣·색조·자세) | `dark fantasy <대상> concept` — 도트가 아니어도 된다(일러스트가 더 잘 나온다) |
| **도트 기법** | 어떻게 구현하나(프레임 수·음영 층·외곽선) | `pixel art <대상> sprite sheet <뷰>` |

⚠ **우리 뷰를 검색어에 넣어라.** 이 게임은 탑다운이지만 **캐릭터·적은 측면/정면 그림**이다
(`player`는 정면 + `flip_h` 2방향). `top down`을 넣으면 **엉뚱한 각도**가 나온다.

💡 **덤으로 노려라**: `pixel art <대상> tutorial`을 섞으면 *Rough Shape → Outline → Shading → Polish*
같은 **단계별 튜토리얼 이미지**가 걸린다 — 세94 규율(「생성기는 밑그림까지, 완성은 손질」)과 같은 절차라
에이전트에게 **작업 절차 레퍼런스**로 줄 수 있다.

### 3. 🔴 핀터레스트는 **브라우저로만** 된다 (실측)

| 경로 | 되나 | 비고 |
|---|---|---|
| `WebFetch`로 핀터레스트 | ❌ | 로그인 벽 + JS 렌더링. 이미지 URL이 **하나도** 안 잡힌다 |
| `claude-in-chrome` 브라우저 | ✅ | 사용자 Chrome이라 **로그인이 살아 있다**. 검색 결과가 그대로 뜨고 리드가 직접 본다 |
| `WebSearch` + `WebFetch` + `curl` | ✅ | itch.io·OpenGameArt 같은 **공개 사이트**용. 이미지 URL을 뽑아 내려받아 Read |

**절차** (`claude-in-chrome` 스킬을 먼저 켠다):

1. `tabs_context_mcp{createIfEmpty:true}` → 새 탭 확보
2. `navigate` → `https://www.pinterest.com/search/pins/?q=<URL 인코딩한 검색어>`
3. ⚠ **이미지가 lazy load다** — 바로 찍으면 **색 사각형 플레이스홀더만** 나온다.
   `wait 3초` 또는 `scroll down 2`로 로딩을 촉발한 뒤 찍어라.
4. `computer{action:"zoom", region:[40,70,1530,480], save_to_disk:true}` — 결과 밴드만 크게 떠서 **파일로 저장**
5. `SendUserFile`로 사용자께 띄운다

### 4. 🔴🔴 사용자가 **직접 사이트를 본다** — 스크린샷으로 대신하지 마라

사용자 확정(2026-07-28): ***"내가 좀 보고 싶은데… 결국 니만 알고 있어. 지금 사이트 봐주세요하고 확인 받아야지."***

🔴 **리드가 `zoom`으로 뜬 격자는 「리드가 고른 프레임」이다.** 거기서 사용자가 고르면
사용자 취향이 아니라 **리드 취향의 부분집합**에서 고르는 게 된다 — 그건 이 스킬이 없애려는 문제 그 자체다.
(같은 날 리드가 실제로 이 실수를 했다: 검색 결과를 혼자 훑고 *"이 둘이 좋겠다"*까지 정해 에이전트에 넘겼다.)

**절차:**

1. 검색 URL을 **텍스트로 준다**(사용자가 클릭해서 직접 연다).
   브라우저 탭을 이미 열어 뒀으면 *"그 창을 보시면 됩니다"*라고 안내한다 — 사용자 Chrome이라 그대로 보인다.
2. 🔴 **"이 사이트 좀 봐주세요" 하고 멈춘다.** 리드가 먼저 골라 두지 마라.
3. 사용자가 훑고 고른다. 받는 방법 셋(편한 걸로 고르시게 안내):
   - 사용자가 **이미지를 대화에 붙인다** (가장 확실)
   - 사용자가 화면에 띄워 두고 알려주면 **리드가 그 화면을 찍는다**(`computer{action:"zoom", save_to_disk:true}`)
   - 사용자가 핀·페이지 **URL을 준다**

⚠ 스크린샷은 **보조**다 — *"제가 보기엔 이런 것도 있습니다"* 정도로 곁들이는 건 좋지만
**그걸로 선택을 대신하지 마라.**

⚠ **검색어가 빗나갔으면 그것도 사용자가 안다** — 결과가 엉뚱하면 사용자가 검색어를 바꿔 달라고 하거나
직접 핀터레스트에서 검색한다. 리드가 혼자 검색어를 다섯 번 바꾸며 헤매지 마라.

### 4-b. 🔴🔴 고른 핀은 **열어서 원본을 받아라** — 격자 스샷은 레퍼런스가 아니다

사용자 확정(2026-07-28): ***"검색만해서 거기서 스샷을 찍는거임 하나하나 보는게아니라?"***

🔴 **검색 결과 격자를 `zoom`으로 뜬 건 「훑기용 미리보기」다.** 거기선 도트가 썸네일로 뭉개져
**픽셀·음영 층수·외곽선 굵기를 하나도 못 읽는다** — 리드도, 에이전트도 마찬가지다.
격자는 **후보를 찾는 데까지만** 쓰고, **정한 핀은 반드시 열어서 원본을 받아라.**

**원본 받는 절차** (실측 검증됨):

1. 격자에서 그 핀을 `left_click` → 상세 페이지로 간다(URL이 `/pin/<숫자>/`로 바뀐다)
2. `javascript_tool`로 가장 큰 이미지의 주소를 뽑는다:
   ```js
   Array.from(document.querySelectorAll('img'))
     .map(i => ({src: i.src, w: i.naturalWidth, h: i.naturalHeight}))
     .filter(o => o.src.includes('pinimg') && o.w > 150)
     .sort((a,b) => b.w - a.w).slice(0, 5)
   ```
3. `curl -sL -o <경로> "<그 src>"` 로 내려받는다 (`i.pinimg.com`은 공개 CDN이라 로그인 없이 받힌다)
4. **`Read`로 직접 봐라** — 여기서 비로소 픽셀이 읽힌다

⚠ **실측 함정**: 주소의 `/736x/`를 `/originals/`로 바꾸면 더 클 것 같지만 **XML 에러가 온다.**
`736x`가 실질 최대다(≈735px 폭). 그거면 도트를 읽기에 충분하다.
⚠ **핀터레스트 원본은 `.jpg`다** — 도트에 압축 노이즈가 낀다. **색을 스포이드로 뽑지 마라**(팔레트가 오염된다).
읽을 것은 **실루엣 비율·명암 단수·외곽선 처리**이지 정확한 색값이 아니다(색은 TAKBON 60에서 고른다).

### 5. 결이 여러 갈래면 그때 `AskUserQuestion`

이미지가 아니라 **결**을 물어라(*"검은 털 / 잿빛 / 헌 몸"*) — 이미지 번호는 다음 세션에 안 남는다.
🔴 **채택은 사람이 정한다**(`takbon-art`의 성공 기준과 같은 문장이다).

### 6. 고른 것을 **파일 경로로** 넘겨라

🔴 **이게 이 스킬의 진짜 산출물이다.** 에이전트는 채팅 이미지를 못 본다 — **파일만** 본다.

- 저장 = **`docs/_refs/<주제>/`** (⚠ `.gitignore` — 라이선스가 불명한 남의 그림을 리포에 커밋하지 마라)
- `takbon-art` 프롬프트에 **절대 경로를 박아라** + *"작업 전에 Read로 봐라"*를 명시
- 🔴 **검색 URL을 보고서/설계문서에 텍스트로 남겨라** — 이미지는 gitignore라 사라져도 **URL이면 다시 뽑는다**

### 7. 결과도 레퍼런스와 **나란히** 검수해라

에이전트가 낸 PNG를 레퍼런스 옆에 놓고 봐라. *"규격 통과"*는 바닥이지 천장이 아니다(세91).
