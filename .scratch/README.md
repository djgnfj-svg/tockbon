# .scratch — 지도와 티켓이 사는 곳

**2026-08-22에 `docs/plans/`를 없애고 여기로 왔다.** `wayfinder`가 쓰는 자리이고, 그 스킬과 함께 들어온
로컬 트래커 규약을 그대로 따른다.

⚠ **이름이 「scratch」지만 버리는 곳이 아니다.** git이 추적한다. **계획은 여기서만 산다.**

---

## 생김새

```
.scratch/
  <일-이름>/
    map.md                    ← 지도 하나. 목적지 · 메모 · 지금까지의 결정 · 안개 · 범위 밖
    issues/
      01-<이름>.md            ← 티켓 하나 = 질문 하나
      02-<이름>.md
```

**티켓 파일 맨 위 세 줄이 상태 전부다.**

```markdown
Type: grilling          ← grilling · research · prototype · task
Status: open            ← open · claimed · resolved
Blocked by: 01, 03      ← 없으면 이 줄을 뺀다
```

- **막힘이 풀렸다** = 여기 적힌 티켓이 전부 `resolved`
- **지금 잡을 수 있는 것(프론티어)** = 열려 있고, 안 막혔고, 안 잡힌 것. **번호 빠른 순**
- **잡기** = 일 시작 **전에** `Status: claimed`로 바꾸고 저장
- **풀기** = 맨 아래 `## Answer`에 답을 쓰고 `Status: resolved`, 그리고 **지도의 「지금까지의 결정」에 한 줄**

---

## 왜 폴더로 상태를 안 나누나

**전에는 `1.ready` `2.active` `3.done` 세 폴더를 옮겨 다녔다.** 그 색인이 스스로 적어둔 문장이
***「문서를 옮기는 건 세 군데를 고치는 일이고, 링크는 매번 샌다」***였고, **실제로 샜다.**

Kiro도 spec-kit도 이 트래커도 **전부 파일을 안 옮기고 파일 안의 한 줄로 상태를 적는다.**

⚠ **대신 약점이 생겼다.** 폴더는 `ls` 한 번으로 상태가 보이는데 `Status:` 줄은 **고치는 걸 잊어도
아무도 모른다.** `wayfinder`가 「일 시작 전에 먼저 바꾸고 저장하라」고 못 박아둔 게 그 때문이다.

띄우라고 하는데, 이 세션은 에이전트 호출이 막혀 있었다. **안 돈 것이지 없는 것이 아니다.**
