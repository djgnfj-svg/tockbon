# ⚠⚠ 지형이 2D 로 읽힌다 — 칸이 안 보이고 판판하다

## Question

**계산으로 만든 지형이 3D 로 읽히게 할 수 있나, 아니면 조각을 만들어야 하나?**

## 어디서 왔나

**2026-08-25, 사용자가 손으로 그린 첫 섬을 보고** (`idea-inbox` 325):

> ***"지금 너무 이상해. 큐브형투처럼 블록 블록이 있었으면 좋겠는데. 너무 이게 2D처럼 보인다까?
> 이 캐릭터만 2D로 보여야 되는데 ... 아싸리 조명과 큐브 형태의 맵을 만들어야 될 거 같은데?"***

**그 뒤로 세 번 더 같은 자리를 짚었다**:
- ***"칸이 너무 작게 촘촘하게 왜 만들어진 느낌?"*** — 칸을 키우라는 말을 세 번 했다
- ***"그림으로 그리는 타일이 한계가 온 거 거 같아"***
- ***"칸에 병사가 4마리정도 들어간걸 기준 한번 만들어볼래?"***

## ✅ Bad North 가 실제로 어떻게 하는지 — **강연 둘의 자막을 받아 읽었다**

**EPC2018(알고리즘)과 Konsoll 2018(아트).** WebFetch · 자막 사이트 · 브라우저가 전부 막혀서
`yt-dlp` 로 받았다. 얻은 것 중 이 티켓이 쓰는 것:

| 무엇 | 강연이 말한 것 |
|---|---|
| **타일** | **Maya 로 모델링한 3D 조각 400 개.** ⚠⚠ **처음엔 열 개로 시작했다** — 2 년에 걸쳐 쌓였고, *"기본 느낌을 잡을 때는 열 개면 됐다"* |
| **격자** | **큰 조각이 여러 칸에 걸친다.** 격자 티를 깨는 주된 장치이고 **계단은 이것 없이는 불가능**하다 |
| **섬의 구성** | **걸을 수 있는 곳 · 못 걷는 곳 · 절벽, 셋뿐.** *"바위 텍스처가 바위라고 반복해 말할 필요 없다. 플레이어가 궁금한 건 어디로 갈 수 있나다"* |
| ⚠⚠ **디테일** | **면이 아니라 면이 만나는 자리에 있다.** 잔디 텍스처는 정보를 안 준다. 크랙도 절벽 옆면이 아니라 **모서리**에 넣는다 |
| **네비게이션** | **모듈에 붙어 있다** — 3D 형상이 아니라 **「여기서 어디로 갈 수 있나」 그래프**. 생성기가 그걸 읽어 걸을 수 있는 섬을 넓히는 쪽으로 타일을 고른다 |
| **조명** | 섬에서 **저해상도 복셀 공간**을 만들고 간이 레이마칭으로 그늘을 구워 **3D 텍스처**에 넣는다. 몸과 연출이 그걸 찍어 쓴다 |
| **외곽선** | 메시를 **두 번 그린다** — 뒤집어 한 겹 밀어 어둡게, 그다음 제대로 |
| **모서리** | **45 도가 아니라 살짝 기울어져 있다** — 기둥을 쌓으면 뾰족하거나 뭉툭해져서 **잡동사니 없이 반복이 깨진다** |
| **유닛** | 2D 판때기, 방향 둘(좌우 미러). ⚠ **방패 · 활 · 창만 3D** — 방향을 말해야 하는 것만 |
| **움직임** | *"AI 를 짤 때가 스프라이트를 애니메이션할 때보다 더 애니메이션하는 느낌"* — 줌아웃돼 있어서 **개별 동작보다 무리가 어떻게 흐르는가**가 크다 |

⚠⚠ **Bad North 의 섬은 절차 생성이다** — Wave Function Collapse 로 조각을 배치한다. **모델을 사서
얻는 그림이 아니다.** ⇒ **격자에 맞는 CC0 사각 블록 지형 킷은 없다**(Kenney 것은 육각이거나 2D
스프라이트). **만드는 쪽이고, Blender 5.1 이 이 PC 에 깔려 있다.**

## ✅ 2026-08-25 에 지어진 것 — **계산은 한 줄도 안 건드렸다**

**전부 보이는 것만 바꿨다.** `rules.gd` 가 제 머리말에 적어 둔 대로 **몸 반지름은 계산에 없다.**

| | 무엇 | 왜 |
|---|---|---|
| **칸 테두리** | 타일 윗면을 **안쪽 판 + 어두운 테두리**로 나눠 그린다 | 「한 칸이 안 보인다」. 평평한 타일에서 두 영역이 만나는 자리는 칸 가장자리다 |
| **테두리 차등** | 변마다 다르다 — **평지끼리 옅게 · 높이가 갈리면 진하게 · 물가 진하게** | 한 값이면 165 칸이 전부 같은 선을 받아 **바둑판**이 된다. 강연이 경고한 반복이다 |
| **평평한 윗면** | 모서리를 이웃과 평균내던 것을 그만뒀다 | 모서리를 공유하면 **섬 위의 어떤 모서리도 타일 모서리가 아니게 된다** |
| **언덕 사다리** | 언덕 높이를 **0.5 타일 단위로 스냅** | 안 하면 520 칸이 520 높이를 갖는 계단밭 — **2026-08-24 에 사용자가 거절한 그 판** |
| **해안 평탄** | 해안 타일은 언덕을 **하나도 안 받는다** | ***"갑자기 배가 도착해야 될 곳에 층이 생겼는데, 이러면 안 되고"*** |
| **칸 안의 색** | 모서리마다 색이 다르다 — **모래가 타일 안에서 잔디로 이어진다** | ***"해안에서 잔디로 이어지는 형태가 돼야 되는데, 지금은 그냥 잔디 덩어리"*** |
| **섬 크기** | **26x20 → 20x15 → 16x12** | 칸 수가 줄면 화면에서 한 칸이 커진다. 사용자가 세 번 말했다 |
| **몸 크기** | 반지름 비율을 **0.35 → 0.22**(늑대) | **한 칸에 넷이 2x2 로 선다.** 여유 한 뼘은 넷이 넷으로 읽히게 하려는 것 |
| **바다 높이** | 0.15 → -2.00 → -1.10 → **-0.45** | 처음엔 섬이 물 위로 **0.85 타일**만 솟아 판때기였다. 내렸다가 ***"바다랑 넘 떨어져 있는데? 붙여주고"*** 로 다시 올렸다 |
| **벽 법선** | 네 방향 벽이 전부 **안쪽을 향하고 있었다** | 고원 남쪽 면이 새까맸다. ⚠⚠ **그림자를 꺼도 그대로여서 원인이 잡혔다** |
| **소환 띠** | 최소 6 칸 → **3 칸** | 섬이 16x12 가 되면서 바다가 다섯 줄뿐이라 **배를 놓을 자리가 0 칸**이었다 |

### ⚠⚠ 버린 것 하나 — **Bad North 의 외곽선 방식이 이 지형에는 안 먹는다**

**메시를 뒤집어 한 겹 밀어 그리는 그 방법을 넣었고, 화면이 하나도 안 바뀌었다.** 두께를 네 배로
키워도 그대로였다. **원인은 그 방식이 부드러운 노멀을 전제한다는 것**이다 — 저쪽 타일은 사람이
모델링해서 노멀이 이어져 있고, **이 지형은 평평한 윗면과 각진 벽이라 삼각형마다 노멀이 따로 논다.**
`grow` 는 면을 바깥으로 미는 대신 **서로 벌려 놓기만 한다.** ⇒ **칸 테두리로 갈아탔다.**

## ⚠⚠ 아직 안 된 것

1. ⚠⚠ **그물이 빨갛다.** 섬이 26x20 에서 16x12 가 되면서 **그 섬을 재던 숫자가 전부 옛것**이다 —
   상륙지 수 · 고원 칸 수 · 층 경계 모서리 · 「첫 섬이 20 줄」 · 지형 메시 정점 수 · 소환 슬롯 좌표
2. ⚠⚠ **검사 하나가 사용자 판정과 정면으로 부딪힌다** — 「늑대가 한 칸(40px)보다 넓다」가 지금
   **30.8px** 로 깨진다. 그 검사는 **사용자가 두 번 「너무 작다」고 거절한 34px 로 안 돌아가게** 박아
   둔 것이다. **이번 세션의 「칸에 넷」과 그 판정 중 무엇이 이기는지는 사용자만 정한다**
3. **조각을 하나도 안 만들었다.** 여러 칸에 걸친 조각 · 비대칭 모서리 · 크랙은 전부 조각 일이다
4. **AO 도 외곽선도 없다.** 강연이 든 장치 중 이 저장소에 들어온 것은 「경계에서 일한다」 하나뿐이다
5. **다른 섬 일곱은 손도 안 댔다** — 층도 없고 크기도 옛것이다

## 안 짓는 것

- **WFC.** 섬이 여덟이고 손으로 그린다. 배치 알고리즘은 조각이 열 개 넘게 생긴 날의 문제다
- **육각 격자.** 계산 전체가 사각이다
- **3D 몸.** 사용자가 ***"캐릭터는 판때기어도 돼"*** 라고 못을 박았다
