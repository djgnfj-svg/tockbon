# 전투 화면을 3D 공간으로 옮긴다

## Question

**2D 캔버스에 손으로 그리던 전투 화면을, 상자 지형과 판때기 짐승이 사는 3D 공간으로 옮긴다.**

**판정은 티켓 04에서 받는다** — 이 티켓은 옮기는 일이고, 「애매함이 줄었나」는 거기서 묻는다.

## 왜 여는가

**사용자, 2026-08-24**: ***"일단 3D로 바꾸는 게 다음 목표기네."***

**티켓 07이 재본 것이 근거다.** 2D 로 눕히기는 넣었는데 판정이 「잘 모르겠네」였고, **보이게 만드는 것이
회전과 가림인데 둘 다 2D 에서는 비싸다.** 3D 에서는 공짜다.

## 이미 확인된 것 — **탐침 둘, 그림 넷**

| 무엇 | 확인 |
|---|---|
| **진짜 섬이 3D로 선다** | 섬 1번 48 x 32 = 1536칸. 글자 격자를 그대로 읽었다 |
| **늑대는 판때기로 서고 늘 정면을 본다** | 카메라를 돌려도 그림은 한 장 |
| **도트가 안 뭉개진다** | 확대 방식 `NEAREST` |
| **그림자가 공짜다** | 빛 하나가 드리운다 |
| **줄 수가 거의 같다** | 2D 쪽 97줄 대 3D 86줄 (둘 다 주석 뺀 코드 줄) |

⚠ **3D 오브젝트는 하나도 안 만든다.** 지형은 글자에서 나온 상자고, 짐승은 지금 쓰는 2D 그림 그대로다.

## 옮기는 것과 안 옮기는 것

**안 건드린다**: `sim` 전부 — 규칙 · 전투 · 격자 · 섬 · 지도 · 카드 · 정비.
**다시 짓는다**: 전투 화면이 그리는 것 전부 — 지형 · 몸 · 체력바 · 링 · 배 · 항로 · 이펙트 · 소환 띠.

## ⚠⚠ 진짜 값은 줄 수가 아니라 그물이다

**2841개 중 2D로 그리는 데 매인 것이 약 1000개다**(`shell` 490 · `fx_view` 227 · `slots` 151 ·
`draw_leaf` 119 · `camera` 46). **몇 개가 살아남는지 아직 안 세어 봤고, 그게 이 티켓의 첫 걸음이다.**

⇒ **첫 걸음은 코드가 아니라 세는 일이다**: 저 다섯 그물을 훑어서 **「사실을 재는 것」과 「2D로 그리는
방식을 재는 것」**으로 가른다. **앞쪽은 그대로 살고, 뒤쪽은 3D 로 다시 써야 한다.**

## 오늘 넣은 것 중 버려지는 것

- **판을 40도로 눕힌 것** — 엔진의 카메라가 대신 한다
- **바닥 그림자** — 빛이 대신 한다
- ⚠ **늑대 그림은 그대로 쓴다.** 그리고 **「그림자와 가림이 눕은 것을 보이게 한다」는 답도 그대로 산다**

## What is actually open

1. **한 번에 옮기나, 지형부터 붙이고 몸을 나중에 옮기나** — 반쯤 옮긴 화면이 돌아가는지가 갈린다
2. **소환 띠와 내릴 자리 미리보기를 3D 에서 어떻게 그리나** — 바닥에 눕는 것들이다
3. **그물을 어디까지 다시 쓰나** — 위의 가르는 일이 끝나야 안다
